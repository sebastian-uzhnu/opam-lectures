## Тема 1. Алгоритми. Властивості алгоритмів. Блок-схеми

### Критично

- **Псевдокоду в лекції немає, а ДЗ на ньому побудоване.** `docs/topic_1/subtopic1.md`, розділ «Способи запису алгоритмів», перелічує рівно два способи: блок-схеми та алгоритмічні мови. Псевдокод згадано лише один раз — як приклад «мови для алгоритмічного моделювання» у класифікації. При цьому `docs/topic_1/practice.md` містить чотири завдання з псевдокодом (питання 10, 11, 12, міні-задача 4, 6), а ДЗ прямо вимагає: «той самий алгоритм, записаний псевдокодом українською, з відступами». Студент ніде не бачив, як псевдокод виглядає і за якими правилами пишеться. Потрібен окремий розділ «Псевдокод» із конвенціями (`якщо…то…інакше`, `поки`, відступи) — і тоді практика стане узгодженою.
- **Немає розділу про трасування**, хоча `practice.md` має цілу групу питань «### Читання алгоритмів: трасування» і міні-задачу «Таблиця трасування» з формулюванням «для алгоритму з питання 11». Трасувальної таблиці як прийому в лекції немає.
- **Опис теми вимагає «Приклади простих алгоритмів: лінійні, розгалужені, циклічні»** — у трьох підрозділах немає жодного прикладу лінійного/розгалуженого/циклічного алгоритму, окрім трьох рядків «сортування трьох чисел» у `subtopic2.md`.

## Тема 2. Основні поняття мови C#. Середовище Visual Studio

### Критично

- **Незакритий блок коду ламає рендеринг.** `docs/topic_2/visual_studio/topic3.md` закінчується так:
  ```
  ```csharp
  using System;
  namespace MyApplication { … }
  ```
  — закривальних трьох лапок немає, файл просто обривається. Docusaurus проковтне решту або впаде на build.
- **Обсяг: 13 підрозділів на 2 години лекції.** STYLE: «На тему — 3–5 підрозділів», «2 години лекції = intro + 2–3 підрозділи». Тут у 4–5 разів більше, причому частина — важкі теми (Garbage Collector на 11.5 КБ з поколіннями, Mark-and-Sweep, компактуванням, LOH; компіляція з IL/JIT/AOT/CLR). Для першої зустрічі з мовою це перевантаження: студент ще не написав жодного рядка коду, а вже читає про Large Object Heap.
- **Блок «Системи числення» не належить темі 2.** `docs/topic_2/number_systems/topic1.md` і `topic2.md` (11.8 КБ) — це окрема тема. В описі теми 2 (`_category_.json`) систем числення немає взагалі: там «Алфавіт мови, синтаксис. Структура програми. Класифікація операцій та даних. Основні стандартні типи даних… Visual Studio». Або винести в додаток/окрему тему, або дописати в опис теми.
- **Неправильний математичний запис.** `docs/topic_2/number_systems/topic2.md`: `25<sub>10</sub> = 11001<sup>2</sup>` — основа двійкової системи має бути **нижнім** індексом, а не степенем. Запис читається як «11001 у квадраті». Плюс це HTML-теги, які STYLE забороняє.
- **LaTeX без плагіна.** Той самий файл далі переходить на `$255_{10} = FF_{16}$`, `$1 \times 16^2 = 256$` тощо. Якщо в проєкті не підключено `remark-math` + `rehype-katex`, це або відрендериться як сирий текст, або MDX спробує витлумачити `{10}` як JS-вираз і зламає build (STYLE: «Не використовувати фігурні дужки `{ }` у звичайному тексті»). У межах одного файлу співіснують три різні нотації: `1101₂`, `<sub>10</sub>`, `$255_{10}$`.

## Тема 3. Змінні і типи даних

### Критично

- **Перелічувані типи (enum) є в описі теми, але підрозділу немає.** `_category_.json` теми 3 закінчується словами «**Перелічувані типи.**». У лекції enum згадується тричі мимохідь: у списку value-типів (`subtopic3.md`, `subtopic9.md`) і як `[Flags] enum Settings` у прикладі побітових операцій (`subtopic7.md`) — без жодного пояснення, що це, навіщо і як оголошується. У `practice.md` про enum немає жодного питання, тобто прогалина подвійна.
- **Помилка в таблиці.** `docs/topic_3/subtopic1.md`, «Числа з плаваючою комою»: колонка названа **«Розмір (байт)»**, а значення в ній — 32, 64, 128. Це біти. У сусідній таблиці цілих типів колонка правильно названа «Розмір (біт)». Студент, який читає підряд, отримає, що `float` займає 32 байти.
- **Фактична помилка в класифікації типів.** Там само, таблиця «Спеціальні типи (Reference Types)» містить чотири рядки: `object`, `string`, `dynamic`, `var`, а під таблицею стоїть: «Усі ці типи — **reference types**». Це неправильно: `var` — узагалі не тип, а спосіб оголошення, і `var x = 5;` дає `int`, тобто **значимий** тип. Наступний підрозділ `subtopic2.md` це сам спростовує («компілятор розпізнає тип як int»).
- **Код, що не компілюється.** `docs/topic_3/subtopic6.md`, розділ «4. Порівняльні оператори»:
  ```csharp
  bool isEqual = a == b // isEqual дорівнює false
  ```
  Немає крапки з комою. Це саме той приклад, який студент копіює першим.
- **Обсяг: 10 підрозділів на 2 години лекції** (норма STYLE — 3–5). Тема містить і стек/купу, і GC-сусідні речі, і повний підрозділ про побітові операції на 8.3 КБ, який потім ще раз повторюється в темі 6.

### Варто виправити

- **Приклад із `default` не компілюється як цілісний блок.** `subtopic1.md`:
  ```csharp
  int i = default(int);   // …
  int i = default;        // у тому ж блоці — повторне оголошення i
  ```
  У межах одного блоку коду п'ять змінних оголошено двічі. Треба або розбити на два блоки, або перейменувати змінні.
- **Префікс і постфікс ніде не пояснені.** `subtopic6.md` пункт 2 показує лише `x++;` і каже «x тепер дорівнює 6». Але власне питання самоперевірки цього ж файлу (№2: «У чому різниця між префіксною та постфіксною формами?») і питання 15 у `practice.md` (`int y = x++ + ++x;`) вимагають розуміння різниці. Матеріалу немає.
- **Неточність у таблиці пріоритетів.** `subtopic6.md`, «Пріоритет основних операторів»: пункт 7 «Логічні оператори: `&&`, `||`» подає їх як один рівень, хоча `&&` має вищий пріоритет за `||` — і саме на цьому будується питання 5 у `practice.md` теми 6. - **Внутрішня суперечність у `subtopic5.md`.** Розділ «Різниця в продуктивності»:
  ```

  - Span<T>: ~95% (майже однакова швидкість)

  ```
