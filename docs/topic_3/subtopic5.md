# Перетворення типів і переповнення

У строго типізованій мові значення одного типу не можна просто так покласти у змінну
іншого. Але на практиці це потрібно постійно: користувач вводить текст, а нам треба
число; ділимо цілі, а хочемо дріб. Механізм, що це забезпечує, називається
**перетворенням типів**.

Перетворення бувають двох видів, і різниця між ними — у безпеці.

## Неявне перетворення (розширення)

**Неявне перетворення** відбувається автоматично, коли значення гарантовано
вміщається в новий тип без втрати даних.

```csharp
int number = 42;
long bigNumber = number;     // ✅ int завжди вміщається в long

int count = 7;
double average = count;      // ✅ 7.0
```

Правило просте: **з меншого в більше — автоматично**.

```
byte → short → int → long → float → double
                  ↘ decimal
```

Компілятор дозволяє такі перетворення мовчки, бо втратити дані неможливо.

## Явне перетворення (звуження)

**Явне перетворення** потрібне, коли дані можуть загубитися. Компілятор вимагає,
щоб ви підтвердили намір — оператором приведення `(тип)`.

```csharp
double pi = 3.14159;
int intPi = (int)pi;         // 3 — дробова частина ВІДКИДАЄТЬСЯ

long big = 5_000_000_000;
int small = (int)big;        // ⚠️ не вміщається — результат неправильний
```

```csharp
double d = 9.99;
int a = d;                   // ❌ помилка компіляції
int b = (int)d;              // ✅ 9 — ви підтвердили, що згодні на втрату
```

:::warning[Приведення не округлює]
`(int)9.99` дає `9`, а не `10`. Дробова частина просто відкидається.
Щоб округлити, потрібен `Math.Round`:

```csharp
int rounded = (int)Math.Round(9.99);   // 10
```
:::

### Що станеться при переповненні

```csharp
int largeNumber = 300;
byte smallNumber = (byte)largeNumber;
Console.WriteLine(smallNumber);        // 44, а не 300
```

Число 300 не вміщається у 8 бітів. Старші біти відкидаються, залишається
`300 − 256 = 44`. Програма не падає й нічого не повідомляє — класична **логічна**
помилка.

## Перевірка переповнення: `checked` і `unchecked`

За замовчуванням арифметичне переповнення в C# **ігнорується**: результат обрізається
і виконання триває. Це швидко, але небезпечно.

Блок **`checked`** змушує середовище перевіряти переповнення й кидати виняток:

```csharp
int max = int.MaxValue;

// Без перевірки — тихо неправильний результат
int wrong = max + 1;
Console.WriteLine(wrong);           // -2147483648 (!)

// З перевіркою — явна помилка
checked
{
    int right = max + 1;            // ❌ OverflowException
}
```

Блок **`unchecked`** робить протилежне — явно вимикає перевірку:

```csharp
unchecked
{
    int x = int.MaxValue + 1;       // дозволено, результат обрізається
}
```

:::tip[Коли що застосовувати]
`checked` доречний там, де неправильне число гірше за аварійну зупинку:
фінансові розрахунки, підрахунок залишків на складі, будь-які гроші.

`unchecked` потрібен рідко — переважно в алгоритмах хешування, де переповнення
є частиною задуму.
:::

## Перетворення рядка в число

Це найчастіше перетворення в навчальних програмах, бо `Console.ReadLine()`
**завжди** повертає `string`.

### `Parse` — просто, але падає на поганих даних

```csharp
string text = "42";
int number = int.Parse(text);        // 42

string bad = "сорок два";
int n = int.Parse(bad);              // ❌ FormatException — програма падає
```

### `TryParse` — надійний спосіб

`TryParse` не кидає виняток: він повертає `bool` — вдалося чи ні — а сам результат
записує у змінну через `out`.

```csharp
string input = Console.ReadLine();

if (int.TryParse(input, out int number))
{
    Console.WriteLine($"Ви ввели число {number}");
}
else
{
    Console.WriteLine("Це не число!");
}
```

:::tip[Правило на весь курс]
Для даних від користувача завжди використовуйте **`TryParse`**, а не `Parse`.
Користувач рано чи пізно введе букву замість цифри — і питання лише в тому,
чи передбачили ви це, чи програма аварійно завершиться.
:::

Повний приклад із повторним запитом:

```csharp
int age;

while (!int.TryParse(Console.ReadLine(), out age))
{
    Console.WriteLine("Помилка. Введіть ціле число:");
}

Console.WriteLine($"Вам {age} років");
```

### `Convert` — універсальний перетворювач

```csharp
int a = Convert.ToInt32("42");
double b = Convert.ToDouble("3.14");
bool c = Convert.ToBoolean("true");
string s = Convert.ToString(42);
```

Відмінність від `Parse`: `Convert.ToInt32(null)` поверне `0`, тоді як
`int.Parse(null)` кине виняток.

:::note[`Convert` округлює, а приведення — ні]
```csharp
double value = 9.7;

Console.WriteLine((int)value);              // 9  — відкидання
Console.WriteLine(Convert.ToInt32(value));  // 10 — округлення
```

Одна з тих відмінностей, які легко не помітити й отримати розбіжність у розрахунках.
:::

## Перетворення числа в рядок

```csharp
int number = 42;

string s1 = number.ToString();        // "42"
string s2 = $"{number}";              // "42" — інтерполяція
string s3 = "Значення: " + number;    // неявне перетворення при склеюванні
```

З форматуванням:

```csharp
double price = 1234.5678;

Console.WriteLine(price.ToString("F2"));    // 1234.57  — два знаки
Console.WriteLine($"{price:F2}");           // 1234.57
Console.WriteLine($"{price:C}");            // ₴1,234.57 — валюта
Console.WriteLine($"{255:X}");              // FF — шістнадцятковий
```

## Зведена таблиця

| Завдання | Спосіб | Ризик |
|----------|--------|-------|
| `int` → `double` | Автоматично | Немає |
| `double` → `int` | `(int)value` | Втрата дробової частини |
| `double` → `int` з округленням | `(int)Math.Round(value)` | Немає |
| `string` → `int` (надійно) | `int.TryParse` | Немає |
| `string` → `int` (коротко) | `int.Parse` | Виняток на поганих даних |
| Будь-що → `string` | `.ToString()` | Немає |
| Контроль переповнення | Блок `checked` | Виняток замість тихої помилки |

## Висновок

- **Неявне** перетворення (розширення) відбувається автоматично і безпечне;
  **явне** (звуження) вимагає оператора `(тип)` і може втратити дані.
- Приведення `(int)` **відкидає** дробову частину, `Convert.ToInt32` — **округлює**.
- За замовчуванням переповнення **ігнорується**; блок **`checked`** перетворює
  його на виняток `OverflowException`.
- `Console.ReadLine()` завжди повертає **рядок** — число з нього треба отримувати
  перетворенням.
- Для введення користувача використовуйте **`TryParse`**, а не `Parse`:
  він не падає на некоректних даних.
