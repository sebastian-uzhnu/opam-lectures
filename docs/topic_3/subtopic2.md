# Неявно типізовані змінні (`var`)

Якщо тип змінної очевидний з того, що їй присвоюють, його можна не писати —
компілятор виведе тип сам. Для цього існує ключове слово **`var`**.

```csharp
var number = 5;           // компілятор виводить int
var message = "Hello";    // string
var price = 19.99;        // double
var isReady = true;       // bool
```

## `var` — це не динамічна типізація

Найпоширеніше непорозуміння: студенти вважають, що `var` робить змінну «безтиповою»,
як у Python чи JavaScript. Це не так.

Тип визначається **на етапі компіляції** і далі **не змінюється**:

```csharp
var x = 5;        // x має тип int — назавжди
x = 10;           // ✅ інше ціле
x = "текст";      // ❌ помилка компіляції: неможливо перетворити string на int
```

Ці два рядки після компіляції дають **абсолютно однаковий** код:

```csharp
var a = 5;
int a = 5;
```

Різниця лише в тому, хто пише слово `int` — ви чи компілятор. Жодного впливу
на швидкодію чи розмір програми `var` не має.

:::note[Чим `var` відрізняється від `dynamic`]
```csharp
var a = 5;
a = "текст";        // ❌ помилка компіляції

dynamic b = 5;
b = "текст";        // ✅ дозволено — тип перевіряється під час виконання
```

`dynamic` — це справді динамічна типізація з усіма її ризиками: помилка виявиться
не при компіляції, а під час роботи програми. У цьому курсі `dynamic` не знадобиться.
:::

## Правила використання

### Ініціалізація обов'язкова

Компілятор виводить тип зі значення — отже, значення має бути:

```csharp
var x;              // ❌ помилка: неможливо визначити тип
var y = null;       // ❌ помилка: null не має типу
```

### Тільки для локальних змінних

`var` не можна використовувати для полів класу, параметрів методів
і типів, що повертаються:

```csharp
class Person
{
    var name = "Іван";          // ❌ поле класу не може бути var
}

void Print(var value) { }       // ❌ параметр не може бути var
```

## Коли `var` доречний

### 1. Тип очевидний із правої частини

```csharp
var count = 10;                          // очевидно int
var name = "Олена";                      // очевидно string
var student = new Student();             // очевидно Student
```

### 2. Тип задовгий, щоб писати двічі

Порівняйте:

```csharp
Dictionary<string, List<int>> data = new Dictionary<string, List<int>>();
var data = new Dictionary<string, List<int>>();     // ✅ те саме, удвічі коротше
```

### 3. Анонімні типи

Тут `var` не альтернатива, а **єдина можливість** — у такого типу просто немає імені,
яке можна написати:

```csharp
var person = new { Name = "Олена", Age = 20 };

Console.WriteLine(person.Name);   // Олена
Console.WriteLine(person.Age);    // 20
```

Анонімні типи знадобляться в темі 12 при роботі з LINQ.

## Коли `var` шкодить

Головний критерій — **чи зрозуміє читач тип, не запускаючи середовище розробки**.

```csharp
var result = Calculate();        // ⚠️ що повертає Calculate? Невідомо
int result = Calculate();        // ✅ зрозуміло одразу
```

```csharp
var x = GetData()[0].Items.First();   // ⚠️ тип не вгадати взагалі
```

:::warning[Небезпечний випадок із числами]
```csharp
var a = 5;         // int
var b = 5.0;       // double
var c = 5m;        // decimal

var result = a / 2;      // 2, а не 2.5 — бо a має тип int!
```

Коли тип написаний явно, ця пастка помітна. Коли він прихований за `var` —
ні. Саме тому для числових змінних тип часто краще вказувати явно.
:::

## Практичне правило

| Ситуація | Рекомендація |
|----------|--------------|
| `new Dictionary<string, List<int>>()` | `var` — тип уже написаний справа |
| `new Student()` | `var` — очевидно |
| Анонімний тип | `var` — обов'язково |
| Результат виклику методу | Явний тип — читачу не видно, що повернеться |
| Числові обчислення | Явний тип — щоб не пропустити цілочисельне ділення |
| `Console.ReadLine()` | Байдуже, але явний `string` зрозуміліший |

:::tip
Пишіть код так, щоб його зрозумів однокурсник, читаючи роздруківку без комп'ютера.
Якщо тип не вгадується за один погляд — напишіть його явно. `var` економить
натискання клавіш, але читають код значно частіше, ніж пишуть.
:::

## Висновок

- **`var`** дозволяє не писати тип — компілятор виводить його зі значення
  **на етапі компіляції**.
- Це **не** динамічна типізація: тип фіксується назавжди, `var x = 5; x = "текст";`
  не скомпілюється.
- Змінна з `var` **обов'язково** ініціалізується при оголошенні; `var x;`
  і `var y = null;` — помилки.
- `var` можна застосовувати лише до **локальних** змінних.
- Доречний, коли тип очевидний справа або задовгий; для **анонімних типів** —
  єдиний можливий варіант.
- Шкідливий, коли ховає тип результату методу або маскує цілочисельне ділення.
