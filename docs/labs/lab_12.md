## Теоретичні відомості

### 1. Чому масиву не вистачає

Масив — надійна й швидка структура, але має властивість, яка на практиці заважає: **його довжина задається при створенні й не змінюється**. Ви вже стикалися з цим у лабораторній роботі №11: щоб прочитати CSV-файл у масиви, доводилося спершу порахувати рядки, потім створити масиви «із запасом» і вести окрему змінну `count` — скільки з цього запасу реально заповнено. Коли записи додаються під час роботи програми, масив стає незручним відразу за трьома напрямками:

1. **Розширення.** Щоб додати 11-й елемент у масив на 10 елементів, треба створити новий масив більшого розміру й перекопіювати в нього старий (`Array.Resize` робить саме це).
2. **Видалення з середини.** Масив не вміє «викидати» елемент: доводиться вручну зсувати всі наступні елементи на одну позицію вліво й зменшувати `count`.
3. **Пошук за ключем.** Щоб за кодом бренду отримати його назву, доводиться писати цикл по всьому масиву.

**Колекція** — це клас, який зберігає групу об'єктів і сам дбає про виділення пам'яті, зсуви й перерахунок розмірів. Колекції .NET живуть у просторі імен `System.Collections.Generic`.

### 2. Простір імен System.Collections.Generic

У .NET є два покоління колекцій. **Старі, нетипізовані** (`System.Collections`): `ArrayList`, `Hashtable`. Вони зберігають усе як `object`, тому в них можна покласти одночасно число, рядок і дату, а діставати доводиться з приведенням типу; компілятор при цьому нічим не допомагає, і помилка проявиться лише під час виконання. У новому коді їх не використовують. **Сучасні, узагальнені** (`System.Collections.Generic`): `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`, `Queue<T>`, `Stack<T>`. Саме з ними працюють у .NET 8. У проєктах .NET 8 увімкнено **неявні підключення просторів імен** (`ImplicitUsings` у файлі `.csproj`), тому директиву `using System.Collections.Generic;` писати не потрібно — вона підключається автоматично. Якщо ви бачите цей рядок у старому коді, це не помилка, просто в новому проєкті він зайвий.

### 3. Узагальнені типи: навіщо потрібен параметр типу

Уявіть, що вам треба написати «список, що росте»: для цілих чисел, для рядків, для дат — три однакові класи, які відрізняються лише типом елемента. Писати їх окремо безглуздо. **Узагальнений (генеричний) тип** — це тип, у якого частина оголошення винесена в **параметр типу** (позначається `T`, від *type*). Реальний тип підставляється в момент використання:

```csharp
var numbers = new List<int>();      // список цілих чисел
var names = new List<string>();     // список рядків
var dates = new List<DateTime>();   // список дат
```

Клас `List<T>` написаний у бібліотеці один раз, а працює з будь-яким типом. Що це дає: **контроль типів на етапі компіляції** (у `List<int>` не можна покласти рядок — програма просто не скомпілюється, і помилку ви побачите одразу, а не користувач); **відсутність пакування** — значеннєвим типам (`int`, `double`, `DateTime`, кортежам) не доводиться перетворюватися на `object` і назад, а **пакування** (boxing) коштує часу й пам'яті; **читабельність** — тип `List<(int Id, string Name)>` сам розповідає, що всередині.

Читається `List<int>` як «список цілих», `Dictionary<int, string>` — «словник, де ключ ціле число, а значення — рядок».

### 4. Клас `List<T>`

`List<T>` — динамічний список: упорядкована послідовність елементів, довжина якої змінюється під час роботи. Створення:

```csharp
var scores = new List<int>();                  // порожній список
var cities = new List<string> { "Львів", "Київ", "Одеса" };   // з початковими даними
List<double> temps = [12.5, 14.0, 9.75];       // колекційний вираз, C# 12
```

Основні члени:

| Член | Що робить | Приклад |
|---|---|---|
| `Add(item)` | додає елемент у кінець | `scores.Add(90);` |
| `Insert(i, item)` | вставляє елемент на позицію `i` | `cities.Insert(0, "Рівне");` |
| `Remove(item)` | видаляє **перше** входження значення, повертає `bool` | `cities.Remove("Київ");` |
| `RemoveAt(i)` | видаляє елемент за індексом | `scores.RemoveAt(2);` |
| `Contains(item)` | чи є таке значення у списку | `if (cities.Contains("Львів"))` |
| `IndexOf(item)` | індекс першого входження або `-1` | `int i = cities.IndexOf("Одеса");` |
| `Count` | скільки елементів зараз у списку | `for (int i = 0; i < scores.Count; i++)` |
| `Clear()` | видаляє всі елементи | `scores.Clear();` |
| `Sort()` | упорядковує за зростанням | `scores.Sort();` |
| `Reverse()` | перевертає порядок | `scores.Reverse();` |
| `[i]` | доступ до елемента за індексом | `scores[0] = 100;` |

Приклад:

```csharp
var queueOfNames = new List<string> { "Петренко", "Іванчук", "Ковальчук" };

queueOfNames.Add("Мельник");            // у кінець
queueOfNames.Insert(0, "Гнатюк");       // на початок
queueOfNames.Remove("Іванчук");         // за значенням

Console.WriteLine($"У черзі {queueOfNames.Count} осіб:");
for (int i = 0; i < queueOfNames.Count; i++)
    Console.WriteLine($"  {i + 1}. {queueOfNames[i]}");

queueOfNames.Sort();                    // за алфавітом
Console.WriteLine($"Перший за алфавітом: {queueOfNames[0]}");
Console.WriteLine($"Чи є Мельник: {queueOfNames.Contains("Мельник")}");
Console.WriteLine($"Позиція Ковальчука: {queueOfNames.IndexOf("Ковальчук")}");
```

**Вивід:**

```
У черзі 4 осіб:
  1. Гнатюк
  2. Петренко
  3. Ковальчук
  4. Мельник
Перший за алфавітом: Гнатюк
Чи є Мельник: True
Позиція Ковальчука: 1
```

Перебір списку робиться так само, як перебір масиву, — циклом `foreach`, коли індекс не потрібен, і циклом `for`, коли потрібен. **Важливе правило.** Не можна додавати або видаляти елементи колекції всередині `foreach` по цій самій колекції — програма аварійно завершиться з повідомленням про змінену колекцію. Якщо треба видаляти під час перебору, ідіть циклом `for` **з кінця до початку**:

```csharp
for (int i = scores.Count - 1; i >= 0; i--)
    if (scores[i] < 60)
        scores.RemoveAt(i);
```

Чому з кінця: коли ви видаляєте елемент, усі наступні зсуваються вліво, і при русі вперед ви пропустите сусідній елемент.

### 5. Як List влаштований усередині: Count і Capacity

Усередині `List<T>` — звичайний масив. Коли він заповнюється, список створює новий масив удвічі більший і копіює туди дані. Тому в списку є дві різні характеристики:

- **`Count`** — скільки елементів реально зберігається;
- **`Capacity`** — скільки елементів уміщується без перевиділення пам'яті.

```
  list.Add(10);        внутрішній масив
                       ┌────┬────┬────┬────┐
                       │ 10 │    │    │    │   Count = 1   Capacity = 4
                       └────┴────┴────┴────┘
                         ▲    ▲── вільне місце ──▲

  + 20, 30, 40         ┌────┬────┬────┬────┐
                       │ 10 │ 20 │ 30 │ 40 │   Count = 4   Capacity = 4
                       └────┴────┴────┴────┘   масив заповнено вщерть

  list.Add(50);   ← місця немає: створюється новий масив на 8,
                    старі елементи копіюються, старий віддається
                    збирачеві сміття
                       ┌────┬────┬────┬────┬────┬────┬────┬────┐
                       │ 10 │ 20 │ 30 │ 40 │ 50 │    │    │    │
                       └────┴────┴────┴────┴────┴────┴────┴────┘
                                             Count = 5   Capacity = 8
```

Практичний висновок: якщо ви заздалегідь знаєте приблизну кількість елементів, задайте її в конструкторі — `new List<int>(1000)`. Це не змінює `Count` (він лишається 0), але позбавляє програму десятка перевиділень пам'яті. Для навчальних обсягів різниця непомітна, але звичка корисна.

### 6. Клас `Dictionary<TKey, TValue>`

`Dictionary<TKey, TValue>` — **словник**, набір пар «ключ — значення». Ключ унікальний; за ключем значення знаходиться майже миттєво, незалежно від того, тисяча записів у словнику чи мільйон. Це головна причина, чому словники існують: пошук за ключем не вимагає циклу.

Типові застосування: довідник кодів, підрахунок кількостей за категоріями, кеш уже обчислених значень.

| Член | Що робить |
|---|---|
| `dict[key] = value` | додає пару або **замінює** значення наявного ключа |
| `dict[key]` (читання) | повертає значення; якщо ключа немає — помилка `KeyNotFoundException` |
| `Add(key, value)` | додає пару; якщо ключ уже є — помилка `ArgumentException` |
| `ContainsKey(key)` | чи є такий ключ |
| `TryGetValue(key, out value)` | безпечне читання: повертає `bool`, значення кладе у змінну |
| `Remove(key)` | видаляє пару за ключем |
| `Count` | кількість пар |
| `Keys` | набір усіх ключів |
| `Values` | набір усіх значень |

```csharp
var brands = new Dictionary<int, string>
{
    [1] = "Lenovo",
    [2] = "Asus",
    [3] = "Acer"
};

brands.Add(4, "HP");          // додали ще один бренд
brands[2] = "ASUS";           // замінили значення наявного ключа

Console.WriteLine($"Брендів у довіднику: {brands.Count}");

// Безпечне читання: ключа може й не бути
if (brands.TryGetValue(3, out string? found))
    Console.WriteLine($"Код 3 — це {found}");

if (!brands.ContainsKey(9))
    Console.WriteLine("Бренду з кодом 9 немає.");

// Перебір: кожен елемент словника — пара KeyValuePair
foreach (KeyValuePair<int, string> pair in brands)
    Console.WriteLine($"  {pair.Key} — {pair.Value}");

// Лише ключі або лише значення
foreach (int code in brands.Keys)
    Console.Write($"{code} ");
Console.WriteLine();
```

**Вивід:**

```
Брендів у довіднику: 4
Код 3 — це Acer
Бренду з кодом 9 немає.
  1 — Lenovo
  2 — ASUS
  3 — Acer
  4 — HP
1 2 3 4
```

Два зауваження, на яких зазвичай спотикаються. **Перше:** `Add` і присвоєння через індексатор поводяться по-різному при повторному ключі — `Add` кидає виняток, індексатор мовчки перезаписує. Обирайте свідомо: якщо повтор ключа — це помилка в даних, беріть `Add`; якщо нормальна ситуація — індексатор. **Друге:** порядок перебору словника **не гарантований** — він не збігається ні з порядком додавання, ні з порядком сортування ключів. Якщо потрібен упорядкований вивід, зберіть ключі у `List` і відсортуйте:

```csharp
var codes = new List<int>(brands.Keys);
codes.Sort();
foreach (int code in codes)
    Console.WriteLine($"{code} — {brands[code]}");
```

Класичний прийом — **підрахунок кількостей за допомогою словника**:

```csharp
string[] words = ["Asus", "Acer", "Asus", "HP", "Acer", "Asus"];
var counts = new Dictionary<string, int>();

foreach (string word in words)
{
    if (counts.ContainsKey(word))
        counts[word] = counts[word] + 1;
    else
        counts[word] = 1;
}

foreach (KeyValuePair<string, int> pair in counts)
    Console.WriteLine($"{pair.Key}: {pair.Value}");
```

**Вивід:**

```
Asus: 3
Acer: 2
HP: 1
```

Запам'ятайте цю конструкцію — вона знадобиться в підсумковому звіті вашого проєкту.

### 7. HashSet, Queue і Stack — коротка довідка

Ці три колекції в цій роботі не обов'язкові, але знати про них треба.

**`HashSet<T>`** — множина унікальних значень. Повторне додавання того самого значення нічого не змінює, а метод `Add` повертає `false`. Перевірка `Contains` — миттєва. Зручно, коли треба відповісти на питання «чи траплялося вже таке значення».

```csharp
var usedCodes = new HashSet<string>();
Console.WriteLine(usedCodes.Add("AB-1234"));   // True — додано
Console.WriteLine(usedCodes.Add("AB-1234"));   // False — уже є
Console.WriteLine(usedCodes.Count);            // 1
```

**`Queue<T>`** — черга, правило «перший прийшов — перший вийшов»: `Enqueue` кладе в кінець, `Dequeue` забирає з початку, `Peek` дивиться, не забираючи. Модель живої черги клієнтів. **`Stack<T>`** — стек, правило «останній прийшов — перший вийшов»: `Push` кладе зверху, `Pop` знімає зверху. Модель стосу документів або скасування дій.

```csharp
var queue = new Queue<string>();
queue.Enqueue("Коваль");
queue.Enqueue("Гнатюк");
Console.WriteLine(queue.Dequeue());   // Коваль — обслужили першого

var stack = new Stack<string>();
stack.Push("крок 1");
stack.Push("крок 2");
Console.WriteLine(stack.Pop());       // крок 2 — скасовуємо останню дію
```

### 8. Кортежі: тимчасова заміна класу

Одна заявка на ремонт — це сім значень різних типів, які завжди йдуть разом. Зберігати їх у семи паралельних списках було б так само незручно, як у семи паралельних масивах. Правильний інструмент — власний клас, але класів ви ще не писали (це наступна робота). До того часу цю роль виконує кортеж.

**Кортеж** — легкий тип, що об'єднує кілька значень в одне. Оголошується просто перерахуванням типів у круглих дужках:

```csharp
(string, int) pair = ("Lenovo", 5);
Console.WriteLine($"{pair.Item1}: {pair.Item2}");   // Lenovo: 5
```

Звертання `Item1`, `Item2` нечитабельні, тому полям дають **імена**:

```csharp
(string Brand, int Count) stat = ("Lenovo", 5);
Console.WriteLine($"{stat.Brand}: {stat.Count}");   // Lenovo: 5
```

Кортеж можна **деконструювати** — розкласти на окремі змінні одним рядком: `(string brand, int count) = stat;` або коротше `var (b, c) = stat;`.

Кортеж зручно повертати з методу, коли результатів кілька:

```csharp
(decimal Min, decimal Max, decimal Average) Analyze(List<decimal> values)
{
    decimal min = values[0], max = values[0], sum = 0;
    foreach (decimal v in values)
    {
        if (v < min) min = v;
        if (v > max) max = v;
        sum += v;
    }
    return (min, max, sum / values.Count);
}

var prices = new List<decimal> { 1250m, 780m, 2400m, 990m };
var result = Analyze(prices);
Console.WriteLine($"Мін: {result.Min}, макс: {result.Max}, середнє: {result.Average:F2}");
```

**Вивід:**

```
Мін: 780, макс: 2400, середнє: 1355,00
```

І головне для нашого проєкту — **список кортежів**:

```csharp
var orders = new List<(int Id, string Owner, string Brand, decimal Cost)>();
orders.Add((1, "Коваль О.", "Lenovo", 1250m));
orders.Add((2, "Гнатюк І.", "Asus", 2400m));

foreach (var order in orders)
    Console.WriteLine($"№{order.Id} {order.Owner}: {order.Brand}, {order.Cost} грн");
```

**Два обмеження кортежу, які варто знати вже зараз.** Перше: кортеж — **значеннєвий тип**, тому індексатор списку повертає його **копію**. Рядок `orders[0].Cost = 999m;` не скомпілюється: ви намагалися б змінити копію, і компілятор чесно про це попереджає. Щоб змінити запис, його треба **замінити цілком**:

```csharp
var item = orders[0];
orders[0] = (item.Id, item.Owner, item.Brand, 999m);
```

Друге: у кортежі неможливо описати перевірку значень («вартість не може бути від'ємною») і неможливо дати йому власний метод чи власне подання у вигляді рядка. Тип `List<(int Id, string OwnerName, string Brand, string Model, DateTime ReceivedDate, decimal RepairCost, bool IsDone)>` доводиться виписувати повністю щоразу, коли він потрібен.

Подивіться на цей рядок уважно — і запам'ятайте відчуття. У наступній лабораторній він перетвориться на одне слово `RepairOrder`, а перевірки значень оселяться всередині типу. Саме тому кортеж тут — тимчасове рішення, а не остаточне.

### 9. Яку колекцію коли обирати

| Структура | Коли обирати | Типова задача |
|---|---|---|
| Масив `T[]` | розмір відомий і не змінюється, потрібна максимальна швидкість | матриця, буфер фіксованої довжини |
| `List<T>` | упорядкований перелік, який росте й зменшується; доступ за номером | перелік записів застосунку, результати пошуку |
| `Dictionary<TKey, TValue>` | потрібно знаходити значення за унікальним ключем | довідник кодів, підрахунок кількостей за категоріями |
| `HashSet<T>` | важлива лише унікальність і перевірка «чи вже було» | набір використаних номерів, множина без повторів |
| `Queue<T>` | обробка в порядку надходження | черга клієнтів, черга завдань на друк |
| `Stack<T>` | обробка в зворотному порядку | історія дій, скасування останнього кроку |

Найчастіша помилка початківця — шукати по `List` циклом там, де потрібен `Dictionary`. Якщо в коді з'явився цикл, єдина мета якого — знайти елемент за унікальним ідентифікатором, і цей цикл виконується часто, це сигнал: тут потрібен словник.

## Приклад виконання

**Умова.** Розробити першу версію застосунку «Облік ноутбуків у сервісному центрі». Головна сутність — **заявка на ремонт** із полями: номер заявки, прізвище власника, бренд, модель, дата прийому, вартість ремонту, ознака виконання. Заявки зберігати в `List` кортежів, довідник брендів — у `Dictionary<int, string>`. Реалізувати консольне меню з чотирьох дій: додати заявку, показати всі, знайти за брендом, видалити за номером.

**Аналіз.**

Полів у заявки сім, і вони різних типів, тому один запис описуємо кортежем із іменованими полями. Колекція заявок — `List` таких кортежів; вона змінюється під час роботи, тому масив тут не підходить.

Бренд користувач не вводить руками: помилка в написанні («Асус» кирилицею замість «Asus») зіпсувала б подальший пошук і звіт. Замість цього показуємо довідник і просимо **код** бренду. Довідник — `Dictionary<int, string>`, бо звертання до нього — це класичний пошук за ключем. Номер заявки програма призначає сама: тримаємо змінну-лічильник `nextId`, яка збільшується після кожного додавання; видалення заявки лічильник **не зменшує**, інакше номери почали б повторюватися.

Кожен пункт меню оформлюємо окремим методом (**локальною функцією** — методом, оголошеним усередині програми з операторами верхнього рівня). Локальна функція бачить змінні, оголошені вище, тому список `orders` і словник `brands` не треба передавати параметрами. Введення користувача перевіряємо завжди: `int.TryParse` для чисел, `DateTime.TryParseExact` для дати, перевірка на порожній рядок для тексту.

**Код.**

```csharp
using System.Globalization;
using System.Text;

Console.OutputEncoding = Encoding.UTF8;

// --- Довідник брендів: код -> назва. Пошук за ключем, тому Dictionary. ---
var brands = new Dictionary<int, string>
{
    [1] = "Lenovo",
    [2] = "Asus",
    [3] = "Acer",
    [4] = "HP",
    [5] = "Dell"
};

// --- Головна колекція: перелік заявок. Один запис — кортеж із семи полів. ---
var orders = new List<(int Id, string OwnerName, string Brand, string Model,
                       DateTime ReceivedDate, decimal RepairCost, bool IsDone)>();

int nextId = 1;   // лічильник для автонумерації заявок

// Демонстраційні дані, щоб не вводити все руками при кожному запуску
orders.Add((nextId++, "Коваль О.", "Lenovo", "IdeaPad 3",
            new DateTime(2025, 10, 14), 1250m, true));
orders.Add((nextId++, "Гнатюк І.", "Asus", "VivoBook 15",
            new DateTime(2025, 11, 2), 2400m, false));
orders.Add((nextId++, "Марчук С.", "Acer", "Aspire 5",
            new DateTime(2025, 11, 5), 780m, false));

bool running = true;
while (running)
{
    Console.WriteLine();
    Console.WriteLine("=== Сервісний центр: облік ноутбуків ===");
    Console.WriteLine("1 — додати заявку");
    Console.WriteLine("2 — показати всі заявки");
    Console.WriteLine("3 — знайти заявки за брендом");
    Console.WriteLine("4 — видалити заявку за номером");
    Console.WriteLine("0 — вихід");
    Console.Write("Ваш вибір: ");

    string choice = (Console.ReadLine() ?? "").Trim();

    switch (choice)
    {
        case "1": AddOrder(); break;
        case "2": PrintAll(); break;
        case "3": FindByBrand(); break;
        case "4": DeleteById(); break;
        case "0": running = false; break;
        default: Console.WriteLine("Немає такого пункту меню."); break;
    }
}

Console.WriteLine("Роботу завершено.");

// ---------- Дія 1: додати заявку ----------
void AddOrder()
{
    Console.WriteLine("--- Нова заявка ---");

    Console.Write("Прізвище власника: ");
    string owner = (Console.ReadLine() ?? "").Trim();
    if (owner.Length == 0)
    {
        Console.WriteLine("Прізвище не може бути порожнім. Заявку не додано.");
        return;
    }

    // Перебираємо словник, щоб показати довідник брендів
    Console.WriteLine("Доступні бренди:");
    foreach (KeyValuePair<int, string> pair in brands)
        Console.WriteLine($"   {pair.Key} — {pair.Value}");

    Console.Write("Код бренду: ");
    if (!int.TryParse(Console.ReadLine(), out int brandCode) || !brands.ContainsKey(brandCode))
    {
        Console.WriteLine("Бренду з таким кодом немає. Заявку не додано.");
        return;
    }
    string brand = brands[brandCode];   // ключ точно існує, тому індексатор безпечний

    Console.Write("Модель: ");
    string model = (Console.ReadLine() ?? "").Trim();
    if (model.Length == 0)
    {
        Console.WriteLine("Модель не може бути порожньою. Заявку не додано.");
        return;
    }

    Console.Write("Дата прийому (дд.мм.рррр): ");
    bool dateOk = DateTime.TryParseExact(Console.ReadLine(), "dd.MM.yyyy",
                                         CultureInfo.InvariantCulture,
                                         DateTimeStyles.None, out DateTime received);
    if (!dateOk)
    {
        Console.WriteLine("Дату не розпізнано. Потрібен формат 05.11.2025. Заявку не додано.");
        return;
    }
    if (received > DateTime.Today)
    {
        Console.WriteLine("Дата прийому не може бути в майбутньому. Заявку не додано.");
        return;
    }

    Console.Write("Орієнтовна вартість ремонту, грн: ");
    // Кому замінюємо на крапку, щоб приймати і 1250,50, і 1250.50
    string costText = (Console.ReadLine() ?? "").Trim().Replace(',', '.');
    bool costOk = decimal.TryParse(costText, NumberStyles.Number,
                                   CultureInfo.InvariantCulture, out decimal cost);
    if (!costOk || cost < 0)
    {
        Console.WriteLine("Вартість має бути невід'ємним числом. Заявку не додано.");
        return;
    }

    orders.Add((nextId, owner, brand, model, received, cost, false));
    Console.WriteLine($"Додано заявку №{nextId}.");
    nextId++;   // наступна заявка отримає інший номер
}

// ---------- Дія 2: показати всі заявки ----------
void PrintAll()
{
    if (orders.Count == 0)
    {
        Console.WriteLine("Заявок поки немає.");
        return;
    }

    Console.WriteLine();
    Console.WriteLine("  № | Власник      | Бренд   | Модель       | Прийнято   |   Вартість | Стан");
    Console.WriteLine("----+--------------+---------+--------------+------------+------------+---------");

    decimal total = 0;
    foreach (var order in orders)
    {
        string state = order.IsDone ? "готово" : "в роботі";
        Console.WriteLine($"{order.Id,3} | {order.OwnerName,-12} | {order.Brand,-7} | " +
                          $"{order.Model,-12} | {order.ReceivedDate:dd.MM.yyyy} | " +
                          $"{order.RepairCost,10:F2} | {state}");
        total += order.RepairCost;
    }

    Console.WriteLine($"Усього заявок: {orders.Count}, на суму {total:F2} грн.");
}

// ---------- Дія 3: знайти заявки за брендом ----------
void FindByBrand()
{
    Console.Write("Бренд для пошуку: ");
    string wanted = (Console.ReadLine() ?? "").Trim();

    // Збираємо не самі заявки, а їхні індекси — так не треба
    // вдруге виписувати довжелезний тип кортежу
    var foundIndexes = new List<int>();

    for (int i = 0; i < orders.Count; i++)
        if (string.Equals(orders[i].Brand, wanted, StringComparison.OrdinalIgnoreCase))
            foundIndexes.Add(i);

    if (foundIndexes.Count == 0)
    {
        Console.WriteLine($"Заявок на ноутбуки «{wanted}» не знайдено.");
        return;
    }

    Console.WriteLine($"Знайдено заявок: {foundIndexes.Count}");
    decimal sum = 0;
    foreach (int i in foundIndexes)
    {
        var order = orders[i];
        Console.WriteLine($"   №{order.Id}: {order.OwnerName}, {order.Brand} {order.Model}, " +
                          $"{order.RepairCost:F2} грн");
        sum += order.RepairCost;
    }
    Console.WriteLine($"Сума за знайденими заявками: {sum:F2} грн.");
}

// ---------- Дія 4: видалити заявку за номером ----------
void DeleteById()
{
    Console.Write("Номер заявки для видалення: ");
    if (!int.TryParse(Console.ReadLine(), out int id))
    {
        Console.WriteLine("Номер має бути цілим числом.");
        return;
    }

    int index = -1;
    for (int i = 0; i < orders.Count; i++)
        if (orders[i].Id == id)
        {
            index = i;
            break;
        }

    if (index == -1)
    {
        Console.WriteLine($"Заявки №{id} у списку немає.");
        return;
    }

    var removed = orders[index];      // запам'ятали до видалення, щоб показати користувачеві
    orders.RemoveAt(index);           // список сам зсуне решту елементів
    Console.WriteLine($"Видалено заявку №{removed.Id} " +
                      $"({removed.OwnerName}, {removed.Brand} {removed.Model}).");
}
```

**Що тут варто помітити.** Пошук за брендом нечутливий до регістру завдяки `StringComparison.OrdinalIgnoreCase` — користувач увів `asus`, а знайшлися заявки з брендом `Asus`; порівнювати рядки оператором `==` тут було б помилкою, бо для користувача це те саме слово. Після видалення заявки №3 номери **не перенумеровуються**: заявка №4 лишається четвертою. Це правильно — номер є ідентифікатором запису, а не його позицією в списку; якщо номери «з'їжджатимуть», з ними неможливо буде працювати. Жодне неправильне введення не завершує програму аварійно: у кожному місці стоїть `TryParse` або перевірка, і в разі помилки метод просто повертає керування в меню.

І найголовніше: довжелезний тип кортежу не має жодної перевірки значень і не вміє показувати себе рядком, а виписувати його доводиться повністю щоразу. Це болюча точка поточної версії, і саме її ми лікуємо в наступній роботі.

Реалізуйте чотири дії окремими локальними функціями: **додати** (з перевіркою всіх полів і вибором значення з довідника), **показати всі** (таблицею з вирівняними колонками й підсумковим рядком), **знайти за умовою** (пошук за текстовим полем без урахування регістру), **видалити за номером** (із повідомленням, коли такого номера немає).

9. Протестуйте програму на граничних випадках: порожній список, порожній рядок замість тексту, літери замість числа, неіснуючий код довідника, дата в майбутньому, видалення неіснуючого номера. Занесіть результати в таблицю тестування для звіту.

10. Зробіть коміт із повідомленням `Лабораторна 12: колекції, меню, базові операції`. Перевірте командою `git log --oneline`, що в історії тепер два коміти.

## Завдання за вашою темою

Тема проєкту — за вашим номером у списку групи з переліку 40 тем. Цього тижня до проєкту потрібно додати таке.

1. **Структура запису.** Опишіть головну сутність своєї теми кортежем із іменованими полями. Використайте **всі** поля, перелічені для вашої теми. Типи добирайте осмислено: гроші — `decimal`, дати — `DateTime`, кількості — `int`, ознаки «так/ні» — `bool`. Поле, яке в описі теми позначене як обчислюване, у кортежі **не зберігайте** — його треба рахувати під час виведення.

2. **Колекція.** Перелік записів зберігайте в `List<...>` цього кортежу. Ніяких паралельних масивів чи паралельних списків.

3. **Довідник.** Оберіть у своїй темі поле з обмеженим набором значень і винесіть його в `Dictionary<int, string>`. При додаванні запису користувач обирає значення **кодом** із довідника, а не вводить текст руками.

4. **Автонумерація.** Перше поле запису (номер, код, артикул, інвентарний номер) призначає програма з лічильника. Видалення записів лічильник не зменшує.

5. **Меню з чотирьох дій:**
   - *додати запис* — покрокове введення з перевіркою кожного поля: текст не порожній, число розпізнається й лежить у розумних межах, дата розпізнається й не суперечить здоровому глузду;
   - *показати всі* — таблиця з вирівняними колонками, рядок-заголовок, підсумковий рядок із кількістю записів і сумою (або іншою підсумковою величиною, доречною у вашій темі);
   - *знайти за умовою* — пошук за текстовим полем без урахування регістру; якщо збігів немає, зрозуміле повідомлення; якщо є — список знайденого й кількість;
   - *видалити за номером* — із повідомленням про те, який саме запис видалено, або про те, що такого номера немає.

6. **Стійкість до помилок.** Жодне введення користувача не має завершувати програму аварійно. Усі числа читаються через `TryParse`, усі дати — через `TryParseExact`, усі ключі словника перевіряються через `ContainsKey` або `TryGetValue`.

7. **Коміт.** Після виконання зробіть коміт із повідомленням `Лабораторна 12: колекції, меню, базові операції`.

Приклад виконання цих вимог на темі «Облік ноутбуків у сервісному центрі» наведено вище. Копіювати його дослівно немає сенсу: у вашій темі інші поля, інший довідник і інша підсумкова величина.

## Додаткове завдання (на вищу оцінку)

Додайте в меню п'ятий пункт — **«Звіт за категоріями»**.

Звіт будується на словнику `Dictionary<string, int>` (і, якщо в темі є гроші або кількості, ще й `Dictionary<string, decimal>`): програма один раз проходить список записів, накопичує кількість і суму за кожним значенням поля-категорії, а потім виводить таблицю. Ключі перед виведенням відсортуйте: зберіть їх у `List<string>` і викличте `Sort()`, бо порядок перебору словника не гарантований. У звіті також виведіть загальну кількість записів і загальну суму, частку кожної категорії у відсотках від загальної кількості та категорію з найбільшою сумою.

Додатково скористайтеся `HashSet<string>`, щоб показати, скільки **різних** значень зустрічається в ще одному текстовому полі вашої теми (наприклад, скільки різних авторів, майстрів, водіїв, виробників). Поясніть у звіті, чому для цієї задачі `HashSet` зручніший за `List` із перевіркою `Contains`.

## Контрольні питання

1. Чому масив не підходить для зберігання переліку записів, кількість яких змінюється під час роботи програми? Наведіть три конкретні незручності.
2. Що таке узагальнений тип і що означає запис `List<T>`? Які дві переваги дає параметр типу порівняно зі зберіганням усього як `object`?
3. Чим `Count` відрізняється від `Capacity` у `List<T>`? Що відбувається зі списком у момент, коли `Count` досягає `Capacity`?
4. Чим відрізняються `Remove` і `RemoveAt`? Що поверне `Remove`, якщо такого значення в списку немає?
5. Чому не можна видаляти елементи зі списку всередині `foreach` по цьому ж списку? Як правильно видалити всі елементи, що відповідають умові?
6. Чим відрізняється `dict.Add(key, value)` від `dict[key] = value`, якщо такий ключ уже є у словнику? Коли який спосіб доречний?
7. Навіщо потрібен `TryGetValue`, якщо значення можна отримати індексатором `dict[key]`? Що станеться, якщо звернутися індексатором до неіснуючого ключа?
8. Чому не можна покладатися на порядок перебору `Dictionary`? Як вивести вміст словника впорядковано за ключем?
9. Що таке кортеж і чим він відрізняється від класу? Чому рядок `orders[0].RepairCost = 500m;` не компілюється і як усе-таки змінити вартість у записі списку?
10. Для кожної із задач назвіть найдоречнішу колекцію й поясніть вибір: (а) перелік заявок із можливістю видалення; (б) визначення назви категорії за її кодом; (в) перевірка, чи використовувався вже такий інвентарний номер; (г) обслуговування клієнтів у порядку надходження.

## Зміст звіту

1. Титульна сторінка: назва закладу, дисципліна, номер і тема роботи, група, прізвище та ім'я студента, **номер і назва теми проєкту**, прізвище викладача.
2. Мета роботи.
3. Опис теми проєкту: головна сутність, повний перелік полів із зазначенням типу кожного та обґрунтуванням вибору типу (чому `decimal`, а не `double`; чому `DateTime`, а не рядок).
4. Оголошення кортежу й колекції, а також вміст довідника-словника — у блоці коду.
5. Схема меню застосунку: пункти й що робить кожен.
6. Повний лістинг програми з коментарями українською мовою.
7. Вивід програми: сеанс роботи, у якому послідовно задіяно всі чотири дії.
8. Таблиця тестування граничних випадків: порожній список, порожнє введення тексту, літери замість числа, неправильний формат дати, неіснуючий код довідника, видалення неіснуючого номера — очікуваний і фактичний результат.
9. Знімок або текстовий вивід команди `git log --oneline` із комітами цієї роботи.
10. Відповіді на 3 контрольні питання, номери яких вказує викладач.
11. Висновок: 3–5 речень, зокрема про те, які обмеження кортежу ви відчули на практиці.
