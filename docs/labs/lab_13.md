# Лабораторна робота №13

## Тема
Створення власних класів. Поля, властивості, методи, конструктори

## Мета
Навчитися описувати власні типи даних за допомогою класів і створювати їх об'єкти. Закріпити розуміння різниці між полем і властивістю та навчитися перевіряти коректність значень у сеттерах. Набути навичок написання конструкторів, обчислюваних властивостей і перевизначення методу `ToString()`. Виконати другий крок наскрізного проєкту: замінити кортеж на власний клас, не переписуючи решту застосунку.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор і термінал, система контролю версій Git.

## Що було на попередньому кроці

Після лабораторної роботи №12 ваш проєкт виглядає так: один запис предметної області описано **кортежем** з іменованими полями; перелік записів зберігається в `List` таких кортежів; поле з обмеженим набором значень винесено в довідник `Dictionary<int, string>`; номер запису призначає програма з лічильника `nextId`; працює циклічне консольне меню з чотирьох дій — додати, показати всі, знайти за умовою, видалити за номером; дані живуть лише в пам'яті й зникають після виходу з програми.

У демонстраційній темі «Облік ноутбуків у сервісному центрі» це був список такого вигляду:

```csharp
var orders = new List<(int Id, string OwnerName, string Brand, string Model,
                       DateTime ReceivedDate, decimal RepairCost, bool IsDone)>();
```

## Що змінюємо

Цього тижня **кортеж перетворюється на клас**. Це **рефакторинг** — зміна внутрішньої будови програми без зміни її поведінки для користувача: меню лишається тим самим, ті самі чотири дії, той самий вигляд таблиці; змінюється те, що всередині. Що ми виграємо, замінивши кортеж класом:

| Проблема кортежу | Як її розв'язує клас |
|---|---|
| Тип доводиться виписувати повністю щоразу | Тип має ім'я: `RepairOrder`, `Book`, `Order` |
| Немає перевірки значень: вартість може бути від'ємною | Валідація живе у сеттері властивості й спрацьовує завжди |
| Номер запису доводиться вести зовнішньою змінною | Автонумерація живе у статичному лічильнику самого класу |
| Обчислюване поле треба рахувати в кожному місці виведення | Обчислювана властивість рахує його сама |
| Виведення запису доводиться складати вручну | Перевизначений `ToString()` знає, як показати об'єкт |
| Запис не можна змінити «на місці» в списку | Об'єкт класу — посилальний тип, його поля змінюються прямо в списку |

Після цієї роботи колекція проєкту має стати такою: `var orders = new List<RepairOrder>();`. Порівняйте цей рядок із попереднім — і ви побачите весь сенс роботи.

## Теоретичні відомості

### 1. Клас і об'єкт

**Клас** — опис нового типу даних: які дані в ньому зберігаються і що з ними можна робити. Клас сам по собі даних не містить, це креслення. **Об'єкт** (екземпляр класу) — конкретний «виріб за кресленням»: ділянка пам'яті, заповнена конкретними значеннями. Класів у програмі одиниці, об'єктів — скільки завгодно.

```csharp
class Student
{
    public string Name;      // поле
    public int Year;         // поле
}

Student s1 = new Student();                           // створили об'єкт
s1.Name = "Коваль";
s1.Year = 2;
var s2 = new Student { Name = "Гнатюк", Year = 1 };   // ініціалізатор об'єкта

Console.WriteLine($"{s1.Name}, {s1.Year} курс");
Console.WriteLine($"{s2.Name}, {s2.Year} курс");
```

**Вивід:**

```
Коваль, 2 курс
Гнатюк, 1 курс
```

Клас описують або в окремому файлі (`RepairOrder.cs` — так робити правильно), або в кінці файлу з операторами верхнього рівня. Одне ім'я файлу — один клас: так проєкт лишається читабельним.

### 2. Поля й модифікатори доступу

**Поле** — змінна, оголошена всередині класу; вона існує в кожному об'єкті окремо: змінили `s1.Name` — `s2.Name` не змінився. **Модифікатор доступу** визначає, звідки поле або метод видно:

| Модифікатор | Звідки видно |
|---|---|
| `public` | звідусіль |
| `private` | лише зсередини цього класу (це значення за замовчуванням) |
| `protected` | зсередини класу та його нащадків (знадобиться в наступній роботі) |
| `internal` | у межах цього проєкту (збірки) |

Головне правило проєктування: **поля роблять закритими (`private`), а доступ до них дають через властивості**. Це називають **інкапсуляцією** — приховуванням внутрішньої будови за зрозумілим зовнішнім інтерфейсом. Якщо поле відкрите, будь-хто може записати в нього що завгодно (`s1.Year = -500;`), і клас не встигне цьому завадити.

### 3. Властивості

**Властивість** — член класу, який зовні виглядає як поле, а всередині складається з двох методів доступу: `get` (читання) і `set` (запис). У `set` доступна неявна змінна `value` — значення, яке намагаються присвоїти. **Повна властивість** має закрите поле-сховище (**backing field**) і сама вирішує, чи приймати значення, — саме так зроблено властивість `Price` у прикладі нижче. **Автовластивість** — скорочення для випадку, коли жодної перевірки не потрібно: компілятор сам створює приховане поле.

```csharp
public string Name { get; set; }          // читання й запис
public int Id { get; private set; }       // ззовні лише читання, змінює сам клас
public int Id { get; }                    // лише для читання, ставиться в конструкторі
public DateTime Created { get; init; }    // ставиться при створенні й більше ніколи
```

`init` — акцесор, який дозволяє присвоїти значення **тільки під час створення об'єкта** (у конструкторі або в ініціалізаторі), а потім робить властивість незмінною. Це зручно для полів, які не мають змінюватися: дата прийому, інвентарний номер, дата народження.

**Обчислювана властивість** нічого не зберігає — вона рахує значення щоразу, коли до неї звертаються: `public int Age => DateTime.Today.Year - BirthYear;`. Запис `=>` тут є скороченням для властивості лише з `get`. Правило просте: **якщо значення можна вивести з інших полів, його не зберігають, а обчислюють**, інакше воно рано чи пізно розійдеться з рештою даних. Приклад усього разом:

```csharp
class Product
{
    private decimal price;

    public string Name { get; set; } = "";
    public int Quantity { get; set; }

    public decimal Price
    {
        get => price;
        set
        {
            if (value < 0)
                throw new ArgumentException("Ціна не може бути від'ємною.");
            price = value;
        }
    }

    public decimal Total => Price * Quantity;   // обчислювана властивість
}

var item = new Product { Name = "Клавіатура", Price = 850m, Quantity = 3 };
Console.WriteLine($"{item.Name}: {item.Quantity} шт. × {item.Price} = {item.Total} грн");
```

**Вивід:**

```
Клавіатура: 3 шт. × 850 = 2550 грн
```

### 4. Конструктори

**Конструктор** — спеціальний метод, який виконується під час створення об'єкта. Його ім'я збігається з іменем класу, і він не має типу результату (навіть `void`). Якщо конструкторів не написати, компілятор сам додає порожній конструктор без параметрів; щойно ви оголосили хоча б один свій, автоматичного більше немає.

```csharp
class Student
{
    public string Name { get; set; }
    public int Year { get; set; }
    public DateTime EnrolledAt { get; init; }

    // Конструктор з параметрами
    public Student(string name, int year)
    {
        Name = name;            // присвоюємо через властивість, щоб спрацювала перевірка
        Year = year;
        EnrolledAt = DateTime.Today;
    }

    // Конструктор без параметрів: викликає попередній через ланцюжок this(...)
    public Student() : this("Невідомо", 1) { }
}
```

Запис `: this("Невідомо", 1)` — **ланцюжок конструкторів**: один конструктор передає роботу іншому. Це позбавляє дублювання коду: уся логіка створення живе в одному місці, решта конструкторів лише підставляють значення за замовчуванням.

```csharp
var a = new Student("Коваль", 2);
var b = new Student();
Console.WriteLine($"{a.Name} — {a.Year} курс");   // Коваль — 2 курс
Console.WriteLine($"{b.Name} — {b.Year} курс");   // Невідомо — 1 курс
```

Ключове слово **`this`** означає «поточний об'єкт». Воно потрібне у двох ситуаціях: коли параметр має те саме ім'я, що й поле (`this.name = name;`), і коли один конструктор викликає інший (`: this(...)`).

### 5. Статичні члени й лічильник об'єктів

**Статичний член** (`static`) належить **класу**, а не окремому об'єкту: він існує в єдиному екземплярі, скільки б об'єктів ви не створили. Звертаються до нього через ім'я класу: `Ticket.Issued`, а не `t1.Issued`. Класичне застосування — **автонумерація**: клас сам роздає номери своїм об'єктам, і зовнішня змінна `nextId` більше не потрібна.

```csharp
class Ticket
{
    private static int counter = 0;     // спільний для всіх об'єктів

    public int Number { get; }          // лише для читання
    public string Passenger { get; set; }

    public Ticket(string passenger)
    {
        counter++;                      // збільшили спільний лічильник
        Number = counter;               // об'єкт отримав власний номер
        Passenger = passenger;
    }

    public static int Issued => counter;   // скільки квитків видано всього
}

var t1 = new Ticket("Коваль");
var t2 = new Ticket("Гнатюк");
var t3 = new Ticket("Марчук");

Console.WriteLine($"{t1.Number} — {t1.Passenger}");
Console.WriteLine($"{t3.Number} — {t3.Passenger}");
Console.WriteLine($"Видано квитків: {Ticket.Issued}");
```

**Вивід:**

```
1 — Коваль
3 — Марчук
Видано квитків: 3
```

Зверніть увагу: `Number` у кожного квитка свій, `counter` — один на всіх.

### 6. Об'єкт у пам'яті: посилання у стеку, дані в купі

Клас — **посилальний тип**: змінна класу зберігає не сам об'єкт, а **посилання** (адресу), за яким об'єкт лежить у **купі** — області динамічної пам'яті. Кортеж і `int` — **значеннєві типи**, вони зберігаються там, де оголошені.

```
        СТЕК                              КУПА
  (змінні методу)                  (об'єкти класів)
  ┌──────────────┐              ┌──────────────────────────┐
  │ s1  ●────────┼─────────────▶│ Student №1               │
  └──────────────┘              │   Name = "Коваль"        │
                                │   Year = 2               │
  ┌──────────────┐              └──────────────────────────┘
  │ s2  ●────────┼──────┐       ┌──────────────────────────┐
  └──────────────┘      ├──────▶│ Student №2               │
  ┌──────────────┐      │       │   Name = "Гнатюк"        │
  │ s3  ●────────┼──────┘       │   Year = 1               │
  └──────────────┘              └──────────────────────────┘
     s3 = s2;  ← скопійовано ПОСИЛАННЯ, а не об'єкт:
                 s2 і s3 вказують на той самий об'єкт
```

З цієї схеми випливають два практичні наслідки. **Перший:** після `s3 = s2;` зміна `s3.Year = 4;` змінить і `s2.Year`, бо це один і той самий об'єкт; для кортежів було б інакше, там копіюється значення. **Другий, важливий для проєкту.** У списку кортежів рядок `orders[0].RepairCost = 500m;` не компілювався. У списку об'єктів `orders[0].RepairCost = 500m;` працює: список зберігає посилання, а ви змінюєте той самий об'єкт, на який воно вказує. Саме тому дія «змінити запис» після переходу на клас стає тривіальною.

### 7. Перевизначення ToString()

Кожен клас у .NET успадковує від типу `object` метод `ToString()`. За замовчуванням він повертає повне ім'я типу, тобто рядок `Student`, — не надто корисно. Метод викликається автоматично в `Console.WriteLine(obj)`, в інтерполяції рядка і в `string.Join`, тому варто написати власну версію — **перевизначити** метод ключовим словом `override`:

```csharp
public override string ToString() => $"{Name} ({Year} курс)";

var students = new List<Student> { new("Коваль", 2), new("Гнатюк", 1) };
foreach (var s in students)
    Console.WriteLine(s);                   // ToString() викликається сам
Console.WriteLine(string.Join("; ", students));
```

**Вивід:**

```
Коваль (2 курс)
Гнатюк (1 курс)
Коваль (2 курс); Гнатюк (1 курс)
```

Зверніть увагу на запис `new("Коваль", 2)` — тип можна не повторювати, якщо він зрозумілий із контексту (**цільово-типізований `new`**, C# 9).

### 8. Валідація значень і ArgumentException

**Валідація** — перевірка того, що значення має сенс, у момент його присвоєння. Місце для неї — сеттер властивості або конструктор: сеттер спрацює **завжди**, звідки б значення не прийшло — з клавіатури, з файлу чи з іншої частини програми. Якщо значення неприпустиме, метод **кидає виняток**:

```csharp
public decimal Price
{
    get => price;
    set
    {
        if (value < 0)
            throw new ArgumentException("Ціна не може бути від'ємною.", nameof(Price));
        price = value;
    }
}
```

`ArgumentException` — стандартний виняток «переданий неприпустимий аргумент». Другий параметр `nameof(Price)` підставляє ім'я властивості рядком: якщо властивість колись перейменують, повідомлення оновиться автоматично. Той, хто створює об'єкт, зобов'язаний бути готовим до винятку:

```csharp
try
{
    var item = new Product { Name = "Миша", Price = -100m };
}
catch (ArgumentException ex)
{
    Console.WriteLine($"Не вдалося створити товар: {ex.Message}");
}
```

**Вивід:**

```
Не вдалося створити товар: Ціна не може бути від'ємною. (Parameter 'Price')
```

Правило розподілу обов'язків просте: **перевірка формату вводу** («чи це взагалі число») — це `TryParse` у меню; **перевірка змісту** («чи може ціна бути від'ємною») — це сеттер класу. Обидві потрібні, вони не замінюють одна одну.

### 9. Коротко про record

Для типів, які лише перевозять дані й не мають поведінки, у C# є коротший запис — **`record`**. Оголошення `record Point(int X, int Y);` завдовжки в один рядок дає повноцінний тип: властивості лише для читання, конструктор, готовий `ToString()`, порівняння **за значеннями** (два записи з однаковими полями вважаються рівними) і вираз `with` для створення зміненої копії.

```csharp
record Point(int X, int Y);

var p1 = new Point(3, 5);
var p2 = p1 with { Y = 9 };
Console.WriteLine(p1);                      // Point { X = 3, Y = 5 }
Console.WriteLine(p2);                      // Point { X = 3, Y = 9 }
Console.WriteLine(p1 == new Point(3, 5));   // True
```

`record` — чудовий вибір для незмінних структур даних. Але в нашому проєкті запис змінюється (заявку позначають виконаною, вартість уточнюють), потрібна валідація у сеттерах, а в наступній роботі від класу ще й успадковуватимуть нащадків. Тому далі ми пишемо звичайний `class`. Знати про `record` варто, щоб не винаходити його руками там, де він доречний.

## Приклад виконання

**Умова.** Перевести застосунок «Облік ноутбуків у сервісному центрі» з кортежів на власний клас `RepairOrder`. Клас має містити: властивості для всіх полів заявки з перевіркою значень, два конструктори, автонумерацію через статичний лічильник, обчислювану властивість «днів у ремонті» та перевизначений `ToString()`. Меню й склад дій не змінювати.

**Аналіз.**

Поля заявки поділяємо на три групи. `Id` — призначається класом, ззовні лише читається, тому `public int Id { get; }`. `ReceivedDate` — не має змінюватися після створення, тому `init` із перевіркою «не в майбутньому». Решта текстових і числових полів потребують перевірки, тому це повні властивості із закритим полем-сховищем. `IsDone` жодної перевірки не потребує — звичайна автовластивість.

Днів у ремонті **не зберігаємо**: це різниця між сьогоднішньою датою й датою прийому, тобто обчислювана властивість `DaysInService`. Конструкторів два: основний приймає всі значущі поля, скорочений приймає лише власника, бренд і модель, а дату ставить сьогоднішню й вартість нульову (заявку прийняли, вартість визначить майстер). Скорочений викликає основний через `: this(...)`.

Меню лишається дослівно тим самим. Змінюються лише два місця: `orders` тепер `List<RepairOrder>`, а створення заявки загорнуте в `try/catch`, бо тепер неправильні дані відхиляє сам клас.

**Код (файл `RepairOrder.cs`).**

```csharp
class RepairOrder
{
    // --- статичний лічильник: один на весь клас, роздає номери заявкам ---
    private static int counter = 0;

    // --- закриті поля-сховища для властивостей із перевіркою ---
    private string ownerName = "";
    private string brand = "";
    private string model = "";
    private DateTime receivedDate;
    private decimal repairCost;

    // --- номер призначає клас, ззовні тільки читання ---
    public int Id { get; }

    // --- ознака виконання: перевіряти нічого, тому автовластивість ---
    public bool IsDone { get; set; }

    // Три текстові поля перевіряються однаково, тому перевірку винесено
    // в закритий допоміжний метод: один опис правила замість трьох
    private static string Required(string value, string label, string field)
    {
        if (string.IsNullOrWhiteSpace(value))
            throw new ArgumentException($"Поле «{label}» не може бути порожнім.", field);
        return value.Trim();
    }

    public string OwnerName
    {
        get => ownerName;
        set => ownerName = Required(value, "Прізвище власника", nameof(OwnerName));
    }

    public string Brand
    {
        get => brand;
        set => brand = Required(value, "Бренд", nameof(Brand));
    }

    public string Model
    {
        get => model;
        set => model = Required(value, "Модель", nameof(Model));
    }

    // init: дату можна задати лише при створенні об'єкта
    public DateTime ReceivedDate
    {
        get => receivedDate;
        init
        {
            if (value > DateTime.Today)
                throw new ArgumentException("Дата прийому не може бути в майбутньому.",
                                            nameof(ReceivedDate));
            receivedDate = value;
        }
    }

    public decimal RepairCost
    {
        get => repairCost;
        set
        {
            if (value < 0)
                throw new ArgumentException("Вартість ремонту не може бути від'ємною.",
                                            nameof(RepairCost));
            repairCost = value;
        }
    }

    // --- обчислювана властивість: нічого не зберігає, рахує при кожному звертанні ---
    public int DaysInService => (DateTime.Today - receivedDate).Days;
    // --- скільки заявок створено за час роботи програми ---
    public static int Created => counter;

    // --- основний конструктор ---
    public RepairOrder(string ownerName, string brand, string model,
                       DateTime receivedDate, decimal repairCost)
    {
        counter++;
        Id = counter;                 // номер заявки
        OwnerName = ownerName;        // присвоюємо через властивості,
        Brand = brand;                // щоб спрацювали всі перевірки
        Model = model;
        ReceivedDate = receivedDate;
        RepairCost = repairCost;
        IsDone = false;               // нова заявка завжди в роботі
    }

    // --- скорочений конструктор: дата сьогоднішня, вартість іще не визначена ---
    public RepairOrder(string ownerName, string brand, string model)
        : this(ownerName, brand, model, DateTime.Today, 0m) { }

    // --- як заявка показує себе рядком ---
    public override string ToString()
    {
        string state = IsDone ? "готово" : "в роботі";
        return $"{Id,3} | {OwnerName,-12} | {Brand,-7} | {Model,-12} | " +
               $"{ReceivedDate:dd.MM.yyyy} | {DaysInService,4} | " +
               $"{RepairCost,9:F2} | {state}";
    }
}
```

void AddOrder()
{
    Console.WriteLine("--- Нова заявка ---");
    Console.Write("Прізвище власника: ");
    string owner = Console.ReadLine() ?? "";

    Console.WriteLine("Доступні бренди:");
    foreach (KeyValuePair<int, string> pair in brands)
        Console.WriteLine($"   {pair.Key} — {pair.Value}");

    Console.Write("Код бренду: ");
    if (!int.TryParse(Console.ReadLine(), out int code) || !brands.ContainsKey(code))
    {
        Console.WriteLine("Бренду з таким кодом немає. Заявку не додано.");
        return;
    }

    Console.Write("Модель: ");
    string model = Console.ReadLine() ?? "";
    Console.Write("Дата прийому (дд.мм.рррр): ");
    bool dateOk = DateTime.TryParseExact(Console.ReadLine(), "dd.MM.yyyy",
                                         CultureInfo.InvariantCulture,
                                         DateTimeStyles.None, out DateTime received);
    if (!dateOk)
    {
        Console.WriteLine("Дату не розпізнано. Потрібен формат 05.11.2025. Заявку не додано.");
        return;
    }

    Console.Write("Орієнтовна вартість ремонту, грн: ");
    string costText = (Console.ReadLine() ?? "").Replace(',', '.');
    if (!decimal.TryParse(costText, NumberStyles.Number,
                          CultureInfo.InvariantCulture, out decimal cost))
    {
        Console.WriteLine("Вартість має бути числом. Заявку не додано.");
        return;
    }

    // Формат уже перевірено; зміст перевірить сам клас і кине ArgumentException
    try

        var order = new RepairOrder(owner, brands[code], model, received, cost);
        orders.Add(order);

void FindByBrand()
{
    Console.Write("Бренд для пошуку: ");
    string wanted = (Console.ReadLine() ?? "").Trim();

    var found = new List<RepairOrder>();      // тепер тип пишеться одним словом
    foreach (RepairOrder order in orders)
        if (string.Equals(order.Brand, wanted, StringComparison.OrdinalIgnoreCase))
            found.Add(order);

    if (found.Count == 0)
    {
        Console.WriteLine($"Заявок на ноутбуки «{wanted}» не знайдено.");
        return;

    Console.WriteLine($"Знайдено заявок: {found.Count}");
    decimal sum = 0;
    foreach (RepairOrder order in found)
    {
        Console.WriteLine($"   {order}");
        sum += order.RepairCost;
    }
    Console.WriteLine($"Сума за знайденими заявками: {sum:F2} грн.");
}

// ---------- Дія 4: видалити заявку за номером ----------
void DeleteById()
{
    Console.Write("Номер заявки для видалення: ");
    if (!int.TryParse(Console.ReadLine(), out int id))
    {
        Console.WriteLine("Номер має бути цілим числом.");
        return;
    }

    int index = -1;
    for (int i = 0; i < orders.Count; i++)
        if (orders[i].Id == id) { index = i; break; }

    if (index == -1)
    {
        Console.WriteLine($"Заявки №{id} у списку немає.");
        return;
    }
    RepairOrder removed = orders[index];
    orders.RemoveAt(index);
    Console.WriteLine($"Видалено заявку №{removed.Id} ({removed.OwnerName}, " +
                      $"{removed.Brand} {removed.Model}).");
}

## Додаткове завдання (на вищу оцінку)

Додайте до проєкту **п'ятий пункт меню — «Змінити запис»**, який тепер став простим завдяки тому, що об'єкти зберігаються за посиланням.

Користувач вводить номер запису; програма знаходить об'єкт у списку й виводить його поточний стан. Далі показується перелік полів, доступних для зміни (лише тих, у яких є `set` — поля з `init` змінити неможливо, і це слід показати користувачеві окремим повідомленням). Користувач обирає поле, вводить нове значення, програма присвоює його властивості всередині `try/catch`: якщо валідація відхилила значення, запис лишається незміненим, а користувач бачить причину. Обов'язково продемонструйте у звіті три сценарії: успішну зміну, зміну, відхилену валідацією, і спробу змінити поле з `init`.

Додайте також у клас метод `Clone()`, який повертає новий об'єкт із тими самими значеннями полів (але з новим номером), і пункт меню «дублювати запис». У звіті поясніть, чому `var copy = original;` **не** створює копію об'єкта, і покажіть це на прикладі.

4. Чим `get; init;` відрізняється від `get; set;` і від `get;`? Для яких полів вашої теми доречний саме `init`?
5. Що таке обчислювана властивість? Чому обчислювану величину шкідливо зберігати в окремому полі — що станеться з даними згодом?
6. Навіщо класу кілька конструкторів? Що робить запис `: this(...)` і чим він кращий за копіювання коду з одного конструктора в інший?
7. Чим статичний член класу відрізняється від звичайного? Скільки існує екземплярів статичного поля, якщо створено 50 об'єктів класу?
8. Де виконується перевірка коректності даних у вашій програмі — у меню чи в класі? Чому перевірку в сеттері не можна замінити перевіркою при введенні з клавіатури?
9. Навіщо перевизначати `ToString()`, якщо цей метод і так є в кожного класу? У яких трьох ситуаціях він викликається без явного звертання?
10. Чому в списку кортежів рядок `orders[0].RepairCost = 500m;` не компілювався, а в списку об'єктів працює? Що станеться після виконання `var a = orders[0]; a.IsDone = true;`?

## Зміст звіту

1. Титульна сторінка: назва закладу, дисципліна, номер і тема роботи, група, прізвище та ім'я студента, номер і назва теми проєкту, прізвище викладача.
2. Мета роботи.
3. Опис спроєктованого класу у вигляді таблиці: назва члена, вид (поле, автовластивість, повна властивість, обчислювана властивість, конструктор, метод), тип, призначення, перевірка (якщо є), а також обґрунтування, чому кожне поле зроблено саме таким і яку величину винесено в обчислювану властивість.
4. Повний лістинг файлу класу з коментарями українською мовою та фрагмент `Program.cs`, у якому видно зміни щодо попередньої роботи: оголошення колекції й створення об'єкта у блоці `try/catch`.
5. Вивід програми: сеанс роботи з усіма чотирма діями, і таблиця тестування валідації — для кожної перевірки в сеттерах введене значення, очікуване й фактичне повідомлення.
6. Вивід команди `git log --oneline` із комітами всіх виконаних робіт проєкту.
7. Відповіді на 3 контрольні питання, номери яких вказує викладач.
8. Висновок: 3–5 речень, зокрема про те, що саме стало простішим після заміни кортежу на клас.

## Критерії оцінювання

| Бали | Критерій |
|---|---|
| 6 | Клас спроєктовано правильно: закриті поля, властивості з обґрунтованим вибором акцесорів, щонайменше три змістовні перевірки у сеттерах із `ArgumentException`, два конструктори з ланцюжком `: this(...)`, статична автонумерація, обчислювана властивість, перевизначений `ToString()`. Меню не переписано, застосунок працює як раніше й коректно відхиляє неправильні дані. Виконано додаткове завдання. Коміт зроблено, звіт повний. |
| 5 | Клас повний і працює, усі обов'язкові елементи присутні. Додаткове завдання виконано частково (наприклад, є зміна запису, але немає `Clone`). Дрібні недоліки: одна з перевірок формальна, `ToString()` не використовується в усіх місцях виведення. Коміт зроблено. |
| 4 | Клас створено, колекція переведена на `List<ВашКлас>`, програма працює. Але частина вимог не виконана: лише один конструктор, або валідація лише в одному полі, або обчислювану величину зберігають у полі, або автонумерація лишилася зовнішньою змінною. Додаткове завдання не виконано. |
| 3 | Клас складається з відкритих полів без властивостей і без перевірок, `ToString()` не перевизначено. Програма працює лише на коректних даних. Замість рефакторингу меню переписано наново. |
| 2 | Клас оголошено, але застосунок на нього не переведено (частина коду досі працює з кортежами) або програма не компілюється без виправлень. Звіт неповний, таблиці тестування немає. |
| 0 | Роботу не виконано, здано чужий код або студент не може пояснити призначення жодного члена власного класу. |
