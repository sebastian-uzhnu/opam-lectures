# Лабораторна робота №1

## Тема
Середовище розробки. Створення, запуск та налагодження першої консольної програми

## Мета
Ознайомитися з призначенням платформи .NET 8 і мови C# та зі складом консольного проєкту.
Навчитися створювати, збирати й запускати програму за допомогою командного рядка `dotnet`
та засобами середовища розробки. Закріпити базову структуру програми й виведення тексту
на екран. Набути початкових навичок читання повідомлень про помилки компіляції
та покрокового налагодження.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор
разом із терміналом, система контролю версій Git.

## Теоретичні відомості

### 1. Що таке .NET 8 і C#

**C#** — мова програмування високого рівня: нею людина записує алгоритм у зрозумілому
для себе вигляді. Процесор мови C# не розуміє, тому текст програми потрібно перекласти.

**.NET 8** — платформа виконання: набір бібліотек, компілятор і середовище, яке запускає
готову програму. Саме .NET перетворює написаний вами текст на робочий застосунок
і забезпечує його роботу під час виконання.

Шлях від тексту до результату має три етапи:

```
Program.cs          компіляція           Lab01.dll           виконання
(текст C#)   ───────────────────────►  (проміжний код)  ───────────────────►  результат
             компілятор Roslyn                            середовище .NET
```

Важливі поняття цього ланцюжка:

- **Компіляція** — перетворення тексту програми на проміжний код (**IL**, intermediate
  language). Виконує компілятор, який входить до складу SDK.
- **SDK** (Software Development Kit) — комплект розробника: компілятор, бібліотеки,
  утиліта командного рядка `dotnet`. Потрібен тому, хто пише програми.
- **Runtime** — середовище виконання. Потрібне тому, хто лише запускає готову програму.
  SDK містить runtime усередині себе, тому окремо встановлювати його не треба.

Перевірити, що SDK встановлено, можна однією командою:

```
dotnet --version
```

Вивід:

```
8.0.404
```

Якщо замість номера версії з'явилося повідомлення, що команду не знайдено, — SDK
не встановлено або шлях до нього не прописано в системі.

### 2. Консольний застосунок

**Консольний застосунок** — програма без графічних вікон: вона спілкується з користувачем
тільки текстом у вікні терміналу. Це найпростіший вид програми, тому весь перший семестр
ми працюємо саме з ним: нічого не відволікає від алгоритму.

У консольного застосунку є три стандартні потоки:

| Потік | Призначення | Засіб у C# |
|---|---|---|
| Стандартне виведення | те, що програма показує користувачеві | `Console.Write`, `Console.WriteLine` |
| Стандартне введення | те, що користувач вводить із клавіатури | `Console.ReadLine` |
| Потік помилок | повідомлення про аварійні ситуації | `Console.Error.WriteLine` |

У цій роботі використовується лише виведення.

### 3. З чого складається проєкт

Створимо проєкт командою:

```
dotnet new console -n Lab01
```

Утвориться папка `Lab01` такого складу:

```
Lab01/
├── Lab01.csproj      опис проєкту: тип, версія платформи, налаштування
├── Program.cs        текст програми
├── bin/              результат збирання (з'являється після dotnet build)
└── obj/              службові файли компілятора
```

**Файл `.csproj`** (project file) — паспорт проєкту у форматі XML. Компілятор читає
його першим, щоб дізнатися, що саме збирати. Типовий вміст:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```

Значення елементів:

| Елемент | Що означає |
|---|---|
| `OutputType` | `Exe` — застосунок, який можна запустити; `Library` — бібліотека |
| `TargetFramework` | версія платформи, під яку збирається проєкт (`net8.0`) |
| `ImplicitUsings` | автоматично підключати найуживаніші простори імен |
| `Nullable` | вмикає перевірку можливих порожніх посилань |

**Папка `bin`** (binary) містить готовий до запуску результат: `bin/Debug/net8.0/Lab01.dll`
і супровідні файли. **Папка `obj`** (object) — тимчасові файли, потрібні компілятору
під час збирання. Обидві папки створюються автоматично й не зберігаються в репозиторії:
у файлі `.gitignore` для них є відповідні правила. Якщо видалити `bin` і `obj`,
наступна збірка створить їх заново — нічого не втрачається.

**Файл `.sln`** (solution) — **розв'язок**, тобто список проєктів, що працюють разом.
Для одного навчального проєкту він не обов'язковий, але коли проєктів кілька
(застосунок плюс бібліотека плюс тести), розв'язок дає змогу зібрати їх однією командою:

```
dotnet new sln -n Semester1
dotnet sln Semester1.sln add Lab01/Lab01.csproj
```

```
Semester1.sln
├── Lab01/Lab01.csproj
├── Lab02/Lab02.csproj
└── Lab03/Lab03.csproj
```

### 4. Основні команди `dotnet`

| Команда | Дія |
|---|---|
| `dotnet new console -n Назва` | створити консольний проєкт у папці `Назва` |
| `dotnet new sln -n Назва` | створити файл розв'язку |
| `dotnet build` | скомпілювати проєкт, не запускаючи його |
| `dotnet run` | скомпілювати (якщо потрібно) і запустити |
| `dotnet clean` | видалити результати попереднього збирання |
| `dotnet --info` | показати відомості про встановлені SDK і runtime |

Команди `dotnet build` і `dotnet run` виконують із папки проєкту — тієї, де лежить
файл `.csproj`. Успішне збирання виглядає так:

```
Determining projects to restore...
  Lab01 -> /home/student/Lab01/bin/Debug/net8.0/Lab01.dll

Build succeeded.
    0 Warning(s)
    0 Error(s)
```

Рядок `Build succeeded` означає, що помилок немає. Попередження (`Warning`) не зупиняють
збирання, але їх варто читати: зазвичай вони вказують на потенційну проблему.

### 5. Структура найпростішої програми

У C# є два способи записати початкову точку програми.

**Спосіб 1 — класичний `Main`.** Кожна програма починає виконання з методу `Main`.
Це домовленість платформи: середовище виконання шукає саме такий метод.

```csharp
using System;                       // підключення простору імен із класом Console

namespace Lab01                     // простір імен — логічна група типів
{
    class Program                   // клас — контейнер для коду
    {
        static void Main(string[] args)   // точка входу в програму
        {
            Console.WriteLine("Перша програма");
        }
    }
}
```

Вивід:

```
Перша програма
```

Розбір заголовка `static void Main(string[] args)`:

| Частина | Значення |
|---|---|
| `static` | метод належить класу, а не окремому об'єкту; викликається без створення об'єкта |
| `void` | метод не повертає значення |
| `Main` | зарезервоване ім'я точки входу, саме з великої літери |
| `string[] args` | масив аргументів командного рядка, переданих програмі під час запуску |

**Спосіб 2 — інструкції верхнього рівня** (top-level statements). Починаючи з C# 9
дозволено не писати клас і метод — компілятор додає їх сам:

```csharp
Console.WriteLine("Перша програма");
```

Вивід:

```
Перша програма
```

Саме такий файл `Program.cs` створює команда `dotnet new console` у .NET 8.
Обидва варіанти цілком рівноцінні: компілятор перетворює другий на перший.
Правила використання інструкцій верхнього рівня:

- у розв'язку такий файл може бути **лише один** — двох точок входу не буває;
- інструкції верхнього рівня мають стояти **до** оголошень класів у файлі;
- масив аргументів доступний під неявним іменем `args`.

Перші роботи можна виконувати будь-яким способом. Рекомендація: спробуйте обидва,
щоб бачити, що «магії» немає — є лише скорочений запис.

### 6. Виведення тексту: `Write` і `WriteLine`

**`Console`** — клас стандартної бібліотеки для роботи з консоллю.

| Метод | Дія |
|---|---|
| `Console.WriteLine(текст)` | вивести текст і перейти на новий рядок |
| `Console.Write(текст)` | вивести текст без переходу на новий рядок |
| `Console.WriteLine()` | вивести порожній рядок |

```csharp
Console.Write("Місто: ");
Console.Write("Львів");
Console.WriteLine();
Console.WriteLine("Область: Львівська");
Console.WriteLine();
Console.WriteLine("Кінець довідки");
```

Вивід:

```
Місто: Львів
Область: Львівська

Кінець довідки
```

Текст у подвійних лапках називається **рядковим літералом**. Щоб вивести символи,
які мають службове значення, застосовують **керуючі послідовності** — пари символів,
що починаються зі зворотної скісної риски:

| Послідовність | Результат |
|---|---|
| `\n` | перехід на новий рядок |
| `\t` | символ табуляції |
| `\"` | подвійні лапки |
| `\\` | зворотна скісна риска |

```csharp
Console.WriteLine("Ім'я:\tОлена");
Console.WriteLine("Група:\tІПЗ-21");
Console.WriteLine("Девіз: \"Спочатку алгоритм, потім код\"");
Console.WriteLine("Шлях: C:\\Projects\\Lab01");
```

Вивід:

```
Ім'я:	Олена
Група:	ІПЗ-21
Девіз: "Спочатку алгоритм, потім код"
Шлях: C:\Projects\Lab01
```

Якщо у тексті багато зворотних скісних рисок, зручніше **дослівний рядок** —
літерал із префіксом `@`, у якому керуючі послідовності не діють:

```csharp
Console.WriteLine(@"C:\Projects\Lab01\bin\Debug");
```

Вивід:

```
C:\Projects\Lab01\bin\Debug
```

### 7. Кодування й псевдографіка

Щоб у консолі коректно відображалися українські літери й символи рамок, на початку
програми варто явно задати кодування виведення:

```csharp
Console.OutputEncoding = System.Text.Encoding.UTF8;
```

**Псевдографіка** — набір символів Unicode, якими малюють рамки й таблиці в тексті:

| Символ | Призначення | Символ | Призначення |
|---|---|---|---|
| `─` | горизонтальна лінія | `═` | подвійна горизонтальна |
| `│` | вертикальна лінія | `║` | подвійна вертикальна |
| `┌ ┐ └ ┘` | кути одинарної рамки | `╔ ╗ ╚ ╝` | кути подвійної рамки |
| `├ ┤ ┬ ┴ ┼` | з'єднання ліній | `*` `=` `+` | проста рамка з ASCII |

Приклад рамки:

```csharp
Console.OutputEncoding = System.Text.Encoding.UTF8;
Console.WriteLine("┌────────────────────────┐");
Console.WriteLine("│   Розклад на понеділок │");
Console.WriteLine("└────────────────────────┘");
```

Вивід:

```
┌────────────────────────┐
│   Розклад на понеділок │
└────────────────────────┘
```

Щоб рамка не «розсипалася», усі рядки мають бути однакової довжини **в символах**,
а шрифт консолі — моноширинним.

### 8. Коментарі

**Коментар** — текст у програмі, який компілятор ігнорує. Він потрібен людині:
пояснити задум, позначити незрозуміле місце, тимчасово вимкнути рядок коду.

| Вид | Запис | Застосування |
|---|---|---|
| Однорядковий | `// текст` | коротке пояснення до рядка |
| Багаторядковий | `/* текст */` | опис блоку, тимчасове вимкнення коду |
| Документаційний | `/// текст` | опис методу, який показує середовище розробки |

```csharp
// Заголовок візитівки
Console.WriteLine("=== Візитівка ===");

/*
   Наступні два рядки виводять
   основні відомості про студента.
*/
Console.WriteLine("Іваненко Олена");
Console.WriteLine("Група ІПЗ-21");

// Console.WriteLine("Цей рядок вимкнено й не виконається");
```

Вивід:

```
=== Візитівка ===
Іваненко Олена
Група ІПЗ-21
```

Правило доброго тону: коментар пояснює **навіщо**, а не переказує **що** написано.
Коментар `// вивести ім'я` перед `Console.WriteLine(name)` не додає нічого нового.

### 9. Помилки компіляції і як читати їх текст

**Помилка компіляції** — порушення правил мови, через яке компілятор не може перетворити
текст на програму. Програма при цьому взагалі не запускається. Це відрізняє її від
**помилки виконання**, яка виникає вже під час роботи готової програми.

Зробимо навмисну помилку — забудемо крапку з комою:

```csharp
Console.WriteLine("Перевірка")
```

Вивід:

```
Program.cs(1,32): error CS1002: ; expected [/home/student/Lab01/Lab01.csproj]

Build FAILED.
    0 Warning(s)
    1 Error(s)
```

Повідомлення читається за частинами:

| Частина | Значення |
|---|---|
| `Program.cs` | файл, у якому виявлено помилку |
| `(1,32)` | рядок 1, позиція 32 |
| `error` | саме помилка, а не попередження |
| `CS1002` | код помилки; за ним шукають пояснення в документації |
| `; expected` | суть: очікувалася крапка з комою |

Найчастіші помилки початківця:

| Код | Текст | Причина |
|---|---|---|
| CS1002 | `; expected` | пропущено крапку з комою |
| CS1003 | `Syntax error, ',' expected` | пропущено кому в списку аргументів |
| CS0103 | `The name 'consol' does not exist` | помилка в імені; C# розрізняє великі й малі літери |
| CS1061 | `does not contain a definition for 'WritLine'` | помилка в імені методу |
| CS1026 | `) expected` | не закрито дужку |
| CS0029 | `Cannot implicitly convert type` | несумісні типи (буде в наступній роботі) |

Порядок дій при помилці:

1. Читайте **перше** повідомлення, а не останнє: далі часто йдуть наслідки першої помилки.
2. Відкрийте вказаний рядок і подивіться на нього **та на попередній**.
3. Перекладіть текст помилки — він описує саме те, чого бракує.
4. Виправте одну помилку й запустіть збирання знову.

### 10. Перші кроки налагодження

**Налагодження** (debugging) — покрокове виконання програми з можливістю зупинити її
й подивитися стан. Потрібне тоді, коли програма компілюється, але працює не так,
як задумано.

Три поняття, спільні для всіх середовищ розробки:

- **Точка зупинки** (breakpoint) — позначка на рядку коду; дійшовши до нього, програма
  призупиняється, не завершуючись. Ставиться клацанням на полі ліворуч від номера рядка.
- **Крок з обходом** (step over) — виконати поточний рядок цілком і зупинитися
  на наступному. Якщо в рядку є виклик методу, метод виконається повністю, і всередину
  ви не потрапите.
- **Крок із заходом** (step into) — зайти всередину методу, який викликається в рядку,
  і зупинитися на його першому рядку.
- **Вікно локальних змінних** — панель, що показує імена змінних, доступних у поточній
  точці, їхні поточні значення й типи. Оновлюється на кожному кроці.
- **Продовжити виконання** — зняти паузу й працювати далі до наступної точки зупинки
  або до кінця програми.

Типовий сеанс налагодження:

```
1. Поставити точку зупинки на першому рядку, що виводить текст.
2. Запустити програму з налагодженням
   (у більшості середовищ це окрема команда «Почати налагодження»).
3. Програма зупиняється; рядок підсвічується — він ЩЕ НЕ виконаний.
4. Крок з обходом → рядок виконався, у консолі з'явився текст.
5. Подивитися вікно локальних змінних.
6. Продовжити виконання → програма доходить до кінця.
```

Важливо розрізняти запуск **із налагодженням** і **без налагодження**: у другому випадку
точки зупинки ігноруються, програма просто виконується. Команда `dotnet run` у терміналі —
це запуск без налагодження.

## Приклад виконання

### Умова

Скласти програму, яка виводить у консоль візитівку навчальної групи у вигляді
подвійної рамки. Усередині рамки — назва закладу, спеціальність, група й навчальний рік.
Під рамкою — рядок із розділювачем і дата останнього оновлення.

### Аналіз

Задача повністю зводиться до послідовного виведення текстових рядків.
Змінних, обчислень і введення даних тут немає — виконується проста послідовність дій.

Потрібно визначити ширину рамки. Найдовший внутрішній рядок — «Спеціальність 121 Інженерія
програмного забезпечення», у ньому 52 символи. Додамо по два пробіли з кожного боку:
внутрішня ширина дорівнює 56 символам. Отже, верхній рядок — це `╔`, 56 символів `═` і `╗`.

Щоб рядки різної довжини не зіпсували рамку, кожен із них доповнюється пробілами
до тих самих 56 символів.

Оскільки у виведенні є символи псевдографіки й українські літери, першим рядком
програми встановлюємо кодування UTF-8.

### Код

```csharp
using System;
using System.Text;

// Налаштування кодування: без цього рядка символи рамки
// в деяких терміналах відображаються як запитання
Console.OutputEncoding = Encoding.UTF8;

// Верхня межа рамки: 56 символів подвійної лінії між кутами
Console.WriteLine("╔════════════════════════════════════════════════════════╗");

// Порожній рядок усередині рамки — відступ зверху
Console.WriteLine("║                                                        ║");

// Назва закладу
Console.WriteLine("║          ФАХОВИЙ КОЛЕДЖ ІНФОРМАЦІЙНИХ ТЕХНОЛОГІЙ       ║");
Console.WriteLine("║                                                        ║");

// Внутрішній розділювач
Console.WriteLine("╟────────────────────────────────────────────────────────╢");
Console.WriteLine("║                                                        ║");

// Відомості про групу
Console.WriteLine("║  Спеціальність: 121 Інженерія програмного забезпечення  ║");
Console.WriteLine("║  Група:         ІПЗ-21                                 ║");
Console.WriteLine("║  Навчальний рік: 2025/2026                             ║");
Console.WriteLine("║  Дисципліна:    Основи програмування                   ║");
Console.WriteLine("║                                                        ║");

// Нижня межа рамки
Console.WriteLine("╚════════════════════════════════════════════════════════╝");

// Підпис під рамкою: символ переходу на новий рядок додає порожній рядок
Console.WriteLine("\n--------------------------------------------------------");
Console.Write("Оновлено: ");
Console.WriteLine("1 вересня 2025 р.");
```

### Що варто помітити

Рядок зі спеціальністю виявився на один символ довшим за інші — права межа рамки
в ньому зсунулася. Це типова помилка при роботі з псевдографікою: компілятор її
не побачить, бо синтаксично все правильно. Знаходять такі неточності лише візуально,
дивлячись на реальний вивід. У своєму варіанті вирівняйте всі рядки точно.

## Хід роботи

1. Перевірте, що SDK встановлено: виконайте в терміналі `dotnet --version`.
   Запишіть у звіт номер версії. Якщо команда не знайдена, зверніться до викладача.

2. Створіть папку для робіт семестру й перейдіть у неї. Створіть проєкт командою
   `dotnet new console -n Lab01`. Перегляньте, які файли й папки з'явилися.

3. Відкрийте папку проєкту в середовищі розробки. Знайдіть в оглядачі проєкту файли
   `Lab01.csproj` і `Program.cs`. Відкрийте `.csproj` і випишіть у звіт значення
   `TargetFramework` та `OutputType`.

4. Запустіть проєкт без змін: `dotnet run`. Переконайтеся, що в консолі з'явився
   текст типового шаблону. Після цього виконайте `dotnet build` і знайдіть у папці
   `bin/Debug/net8.0` файл `Lab01.dll`.

5. Замініть вміст `Program.cs` на класичний варіант із `namespace`, `class Program`
   і методом `Main`. Переконайтеся, що програма так само працює. Потім поверніть
   запис через інструкції верхнього рівня. Обидва варіанти наведіть у звіті.

6. Внесіть навмисну помилку: приберіть крапку з комою наприкінці рядка. Виконайте
   `dotnet build`, скопіюйте повний текст повідомлення у звіт і поясніть кожну його
   частину: файл, рядок, позицію, код помилки. Виправте помилку.

7. Реалізуйте свій варіант індивідуального завдання. Дотримуйтеся вимог:
   на початку програми встановіть кодування UTF-8, додайте щонайменше три
   змістовні коментарі, вирівняйте рамку по ширині.

8. Поставте точку зупинки на першому рядку виведення й запустіть програму
   з налагодженням. Виконайте чотири кроки з обходом, спостерігаючи, як текст
   з'являється в консолі рядок за рядком. Відкрийте вікно локальних змінних
   і запишіть у звіт, що саме там показано. Продовжте виконання до завершення.

9. Порівняйте вивід програми з еталоном у своєму варіанті. Виправте розбіжності
   у ширині рамки та відступах.

10. Оформіть звіт: код програми, знімок або текстова копія виводу, текст помилки
    з кроку 6 із поясненням, відповіді на контрольні питання.
