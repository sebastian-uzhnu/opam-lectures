# Лабораторна робота №16

## Тема
Делегати, події та лямбда-вирази

## Мета
Навчитися працювати з методом як зі значенням: зберігати його у змінній, передавати в інший метод параметром і викликати через делегат. Закріпити вбудовані узагальнені делегати `Action`, `Func`, `Predicate` та `Comparison` і сучасний запис лямбда-виразом. Набути навичок побудови подієвої взаємодії: оголосити подію у класі-видавці, підписати на неї передплатника й отримати журнал змін, який ведеться сам собою.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор і термінал, система контролю версій Git.

## Що було на попередньому кроці

Це п'ятий крок наскрізного проєкту. Після лабораторної роботи №15 ваш застосунок має такий вигляд.

- Базовий клас головної сутності **абстрактний**, у ньому є абстрактний метод, який перевизначено в кожному з нащадків.
- Клас реалізує `IComparable<T>` (природний порядок) і власний `IHasId`; є окремий клас-порівнювач `IComparer<T>`.
- Оголошено власний інтерфейс `IRepository<T>` з членами `Add`, `GetAll`, `GetById`, `Remove`, `Save`, `Load` і написано його реалізацію `CsvRepository`, яка читає й пише CSV-файл з обробкою помилок.
- `Program` працює лише через змінну типу інтерфейсу; дані переживають закриття програми.
- Меню — довгий `switch` із пунктами: додати, показати всі, знайти, видалити, два види сортування, вихід.

У демонстраційній темі викладача «Облік ноутбуків у сервісному центрі» це абстрактний клас `RepairOrder` з нащадками `WarrantyRepair`, `PaidRepair`, `Diagnostics`, абстрактним `GetTotal()` і сховищем `CsvRepository`.

## Що змінюємо

У проєкті накопичилися дві типові вади, які цього тижня й лікуємо.

**Вада перша: методи-близнюки.** Щоб знайти заявки за прізвищем, за маркою, за станом «виконано», за сумою більше за N, за кількістю днів у ремонті, доводиться писати п'ять майже однакових методів: цикл, `if`, додавання у результат. Відрізняється лише умова всередині `if`. Умову можна винести **параметром** — і тоді метод пошуку лишиться один.

**Вада друга: журнал доводиться вести вручну.** Якщо треба записувати кожну зміну у файл `log.txt`, рядок `WriteLog(...)` доведеться вставити в кожен метод, який щось змінює, і не забути про нього надалі. Замість цього сховище лише **повідомляє**, що запис змінився, а хто саме на це повідомлення відреагує — вирішує той, хто підписався.

Тому цього тижня:

1. п'ять методів пошуку замінюються **одним** методом із параметром `Predicate<T>`;
2. сортування за різними полями робиться через `Comparison<T>` без нових класів-порівнювачів;
3. у сховищі з'являється **подія** `OrderChanged`, на яку підписано запис у файл `log.txt`;
4. меню зі `switch` перетворюється на `Dictionary<string, Action>`.

LINQ (`Where`, `Select`, `OrderBy`) у цій роботі **не використовується**: це тема другого семестру. Усі колекції обробляємо циклами й методами `List`.

## Теоретичні відомості

### 1. Делегат — тип, що зберігає метод

Змінна типу `int` зберігає число, змінна типу `string` — текст. **Делегат** — це тип, змінна якого зберігає **метод**: не результат його роботи, а сам метод, який можна викликати пізніше.

```
      ЗВИЧАЙНА ЗМІННА                        ЗМІННА-ДЕЛЕГАТ
  ┌───────────────────────┐          ┌──────────────────────────┐
  │  int x                │          │  Operation op            │
  │  ┌─────────────────┐  │          │  ┌────────────────────┐  │
  │  │       42        │  │          │  │  посилання на      │  │
  │  └─────────────────┘  │          │  │  метод Add ────────┼──┼──▶ static int Add(int a, int b)
  └───────────────────────┘          │  └────────────────────┘  │        {  return a + b;  }
        x + 1  ──▶ 43                └──────────────────────────┘
                                          op(2, 3)  ──▶ 5
```

Навіщо це потрібно? Щоб **параметром методу була дія**. Метод сортування не знає, як порівнювати ваші об'єкти, — ви передаєте йому правило порівняння. Метод пошуку не знає, що саме ви шукаєте, — ви передаєте йому умову. Кнопка не знає, що має статися після натискання, — програміст передає їй метод-обробник.

### 2. Оголошення власного делегата

Делегат оголошується як тип — поза методом, поряд із класами. Оголошення описує **сигнатуру**: типи параметрів і тип результату.

```csharp
// тип «метод, що приймає два int і повертає int»
public delegate int Operation(int a, int b);

public static class MathOps
{
    public static int Add(int a, int b) => a + b;
    public static int Multiply(int a, int b) => a * b;
}
```

```csharp
Operation op = MathOps.Add;      // без дужок: беремо сам метод, а не його результат
Console.WriteLine(op(2, 3));     // виклик через делегат

op = MathOps.Multiply;           // та сама змінна тепер зберігає інший метод
Console.WriteLine(op(2, 3));
```

**Вивід:**

```
5
6
```

Присвоїти делегатові можна будь-який метод із **такою самою** сигнатурою — неважливо, статичний він чи ні, у якому класі описаний і як називається. Метод `double Divide(int a, int b)` присвоїти вже не вийде: не збігається тип результату.

### 3. Передавання методу в метод параметром

Це і є головне застосування делегатів. Порівняйте два підходи.

```csharp
// БУЛО: два майже однакові методи
public static List<int> SelectEven(List<int> source)
{
    var result = new List<int>();
    foreach (int x in source)
        if (x % 2 == 0) result.Add(x);
    return result;
}

public static List<int> SelectPositive(List<int> source)
{
    var result = new List<int>();
    foreach (int x in source)
        if (x > 0) result.Add(x);        // відрізняється лише цей рядок
    return result;
}
```

```csharp
// СТАЛО: один метод, умова — параметр
public static List<int> Select(List<int> source, Predicate<int> condition)
{
    var result = new List<int>();
    foreach (int x in source)
        if (condition(x)) result.Add(x);   // виклик переданого методу
    return result;
}
```

```csharp
var numbers = new List<int> { -4, -1, 0, 3, 8, 15 };
Console.WriteLine(string.Join(", ", Select(numbers, x => x % 2 == 0)));
Console.WriteLine(string.Join(", ", Select(numbers, x => x > 0)));
Console.WriteLine(string.Join(", ", Select(numbers, x => x > 0 && x % 3 == 0)));
```

**Вивід:**

```
-4, 0, 8
3, 8, 15
3, 15
```

Один метод замість трьох — і третій варіант умови не потребував жодного нового рядка в самому методі `Select`.

### 4. Вбудовані узагальнені делегати

Оголошувати власний делегат щоразу не потрібно: у .NET є готові узагальнені типи на всі поширені випадки.

| Тип | Сигнатура | Коли застосовують |
|---|---|---|
| `Action` | нічого не приймає, нічого не повертає | дія без параметрів: пункт меню, кнопка |
| `Action<T>` | приймає `T`, повертає `void` | дія над об'єктом: надрукувати, зберегти |
| `Func<TResult>` | нічого не приймає, повертає `TResult` | обчислення без вхідних даних |
| `Func<T, TResult>` | приймає `T`, повертає `TResult` | перетворення: з об'єкта дістати число чи рядок |
| `Predicate<T>` | приймає `T`, повертає `bool` | умова відбору, фільтр, пошук |
| `Comparison<T>` | приймає два `T`, повертає `int` | правило порівняння для сортування |

`Func` може мати до 16 параметрів: `Func<int, int, string>` — це «приймає два `int`, повертає `string`». Останній параметр у кутових дужках завжди означає **тип результату**.

```csharp
Action<string> show = text => Console.WriteLine($">> {text}");
Func<double, double> square = x => x * x;
Predicate<string> isEmpty = s => string.IsNullOrWhiteSpace(s);
Comparison<string> byLength = (a, b) => a.Length.CompareTo(b.Length);

show("привіт");
Console.WriteLine(square(2.5));
Console.WriteLine(isEmpty("   "));

var words = new List<string> { "ноутбук", "мишка", "клавіатура" };
words.Sort(byLength);                    // List.Sort уміє приймати Comparison<T>
Console.WriteLine(string.Join(", ", words));
```

**Вивід:**

```
>> привіт
6,25
True
мишка, ноутбук, клавіатура
```

Зверніть увагу: `Predicate<T>` і `Func<T, bool>` мають однакову сигнатуру, але це **різні типи**, тому просто присвоїти одне одному не можна. Історично `Predicate<T>` старший; методи `List<T>` (`Find`, `FindAll`, `RemoveAll`, `Exists`) приймають саме його.

### 5. Анонімні методи й лямбда-вирази

Спочатку в C# метод для делегата треба було описувати окремо. Потім з'явилися **анонімні методи** — метод без імені прямо в місці передавання:

```csharp
// C# 2.0, історичний запис — сьогодні так не пишуть
Predicate<int> isPositive = delegate (int x) { return x > 0; };
```

Сучасний запис — **лямбда-вираз**: параметри, стрілка `=>`, тіло.

```csharp
Predicate<int> isPositive = x => x > 0;                 // тіло-вираз, return не пишуть
Func<int, int, int> add = (a, b) => a + b;              // два параметри — у дужках
Action<string> log = message =>                          // тіло-блок, якщо дій кілька
{
    Console.WriteLine($"[{DateTime.Now:HH:mm}] {message}");
    Console.WriteLine("---");
};
```

Правила запису: один параметр — дужки не обов'язкові; тип параметра компілятор виводить із типу делегата; якщо тіло — один вираз, його значення й буде результатом.

**Захоплення змінних.** Лямбда-вираз бачить змінні того методу, у якому його написано, і **запам'ятовує** їх — навіть якщо викликається пізніше.

```csharp
decimal limit = 1000;
Predicate<decimal> isExpensive = sum => sum > limit;   // limit захоплено

Console.WriteLine(isExpensive(1500));     // True
limit = 2000;                             // змінили змінну вже після створення лямбди
Console.WriteLine(isExpensive(1500));     // False: лямбда бачить нове значення
```

**Вивід:**

```
True
False
```

Захоплюється не копія значення, а сама змінна. Це зручно, але буває джерелом несподіванок: якщо лямбду створено в циклі й вона захопила лічильник, усі створені лямбди бачитимуть одне й те саме кінцеве значення. Тому в циклі значення копіюють у локальну змінну.

### 6. Багатоадресні делегати

Змінна-делегат може зберігати **не один метод, а список методів**. Додають метод оператором `+=`, прибирають `-=`. Виклик такої змінної виконує всі методи по черзі, у порядку додавання.

```csharp
Action<string> notify = text => Console.WriteLine($"Консоль: {text}");
notify += text => Console.WriteLine($"Файл:    {text}");
notify += text => Console.WriteLine($"Пошта:   {text}");

notify("заявку закрито");

notify -= text => Console.WriteLine($"Пошта:   {text}");   // так НЕ спрацює
```

**Вивід:**

```
Консоль: заявку закрито
Файл:    заявку закрито
Пошта:   заявку закрито
```

Останній рядок нічого не прибрав: дві однакові з вигляду лямбди — це два різні об'єкти. Щоб відписатися, треба передати **той самий** метод, що й підписували, тому передплатників зазвичай оформляють іменованими методами.

Якщо делегат із кількох методів повертає значення, ви отримаєте результат лише **останнього** з них. Тому багатоадресність має сенс для `Action`, а не для `Func`.

### 7. Події: видавець і передплатник

Багатоадресний делегат — це вже майже подія. Але зроблений полем делегат небезпечний: будь-який зовнішній код може не тільки підписатися, а й **затерти всіх** передплатників присвоєнням `=` або самочинно викликати делегат, вдавши, що подія сталася.

Слово **`event`** перед оголошенням делегата це забороняє. Ззовні класу дозволено рівно дві дії: `+=` і `-=`. Присвоїти або викликати подію можна **лише всередині** класу, який її оголосив.

**Видавець** (publisher) — клас, у якому оголошено подію й який її збуджує. **Передплатник** (subscriber) — метод, який на подію підписано.

```
   ВИДАВЕЦЬ                                     ПЕРЕДПЛАТНИКИ
┌────────────────────┐        подія          ┌────────────────────────┐
│  CsvRepository     │  OrderChanged  ──┬───▶│ Logger.Write(...)      │─▶ log.txt
│                    │                  │    └────────────────────────┘
│  Add / Remove      │                  │    ┌────────────────────────┐
│  викликають        │                  └───▶│ Screen.Show(...)       │─▶ консоль
│  OnOrderChanged()  │                       └────────────────────────┘
└────────────────────┘
   знає лише про те, що подія сталася;      кожен сам вирішує, що робити,
   хто підписаний — не його справа          і може відписатися будь-коли
```

Стандартний зразок .NET: тип події — `EventHandler<TArgs>`, де `TArgs` — клас із даними події, успадкований від `EventArgs`.

```csharp
// 1. Клас аргументів події: що саме сталося
public class OrderChangedEventArgs : EventArgs
{
    public string Action { get; }
    public string Description { get; }
    public DateTime Moment { get; }

    public OrderChangedEventArgs(string action, string description)
    {
        Action = action;
        Description = description;
        Moment = DateTime.Now;
    }
}
```

```csharp
// 2. Видавець
public class Publisher
{
    public event EventHandler<OrderChangedEventArgs>? Changed;

    // Метод-збудник. Знак ?. — перевірка «чи є хоч один передплатник»:
    // без неї виклик події без передплатників дає NullReferenceException.
    protected virtual void OnChanged(string action, string description) =>
        Changed?.Invoke(this, new OrderChangedEventArgs(action, description));

    public void DoWork() => OnChanged("робота", "щось змінилося");
}
```

```csharp
// 3. Передплатник — звичайний метод із сигнатурою (object?, TArgs)
static void Report(object? sender, OrderChangedEventArgs e) =>
    Console.WriteLine($"[{e.Moment:HH:mm:ss}] {e.Action}: {e.Description}");

var publisher = new Publisher();
publisher.Changed += Report;        // підписка
publisher.DoWork();
publisher.Changed -= Report;        // відписка
publisher.DoWork();                 // тепер нічого не виводиться
```

**Вивід:**

```
[14:05:11] робота: щось змінилося
```

Видавець нічого не знає про передплатників: він не викликає ані запис у файл, ані вивід на екран. Саме це й дає потрібний ефект — щоб додати ще один спосіб реагувати на зміну, у класі сховища не доведеться змінити жодного рядка.

## Приклад виконання

**Умова.** Перевести демонстраційний проєкт «Облік ноутбуків у сервісному центрі» на делегати й події: один метод пошуку з `Predicate<RepairOrder>`, сортування через `Comparison<RepairOrder>`, подія `OrderChanged` із записом у `log.txt`, меню у вигляді `Dictionary<string, Action>`.

**Аналіз.** Класи `RepairOrder`, `WarrantyRepair`, `PaidRepair`, `Diagnostics` не змінюються взагалі. Змінюються сховище (додається подія й методи `Find`, `GetSorted`) і `Program` (зникає `switch`, зникають методи-близнюки пошуку). Оскільки нові члени не входять до `IRepository<T>`, змінна `repo` цього тижня оголошена типом `CsvRepository`; за бажання `Find` і `GetSorted` можна додати й до інтерфейсу.

**Файл `OrderChangedEventArgs.cs`** — дані події.

```csharp
namespace ServiceCenter;

// Що передається передплатникам разом із подією.
public class OrderChangedEventArgs : EventArgs
{
    public string Action { get; }            // "Додано", "Видалено", "Збережено"
    public string Description { get; }       // короткий опис запису
    public DateTime Moment { get; }          // коли саме сталося

    public OrderChangedEventArgs(string action, string description)
    {
        Action = action;
        Description = description;
        Moment = DateTime.Now;
    }
}
```

**Файл `CsvRepository.cs`** — доповнення до класу з ЛР15 (решта методів без змін).

```csharp
namespace ServiceCenter;

public class CsvRepository : IRepository<RepairOrder>
{
    // ... items, path, конструктор, GetAll, GetById, Save, Load, Parse — з ЛР15

    // ПОДІЯ. Модифікатор event означає: ззовні дозволено лише += та -=.
    public event EventHandler<OrderChangedEventArgs>? OrderChanged;

    // Метод-збудник. Оператор ?. рятує від NullReferenceException,
    // коли на подію ніхто не підписався.
    protected virtual void OnOrderChanged(string action, RepairOrder order) =>
        OrderChanged?.Invoke(this, new OrderChangedEventArgs(
            action, $"№{order.Id} {order.Kind} {order.OwnerName} {order.Brand}"));

    public void Add(RepairOrder item)
    {
        if (item is null)
            throw new ArgumentNullException(nameof(item));
        if (item.Id <= 0) item.Id = NextId();
        items.Add(item);
        OnOrderChanged("Додано", item);          // сховище лише повідомляє
    }

    public bool Remove(int id)
    {
        var found = GetById(id);
        if (found is null) return false;
        items.Remove(found);
        OnOrderChanged("Видалено", found);
        return true;
    }

    // ОДИН метод пошуку замість п'яти. Умову передають параметром.
    public List<RepairOrder> Find(Predicate<RepairOrder> match)
    {
        if (match is null) throw new ArgumentNullException(nameof(match));
        var result = new List<RepairOrder>();
        foreach (var order in items)
            if (match(order)) result.Add(order);
        return result;
        // те саме одним рядком: return items.FindAll(match);
    }

    // Сортування за будь-яким правилом, без окремого класу-порівнювача.
    public List<RepairOrder> GetSorted(Comparison<RepairOrder> comparison)
    {
        var copy = new List<RepairOrder>(items);
        copy.Sort(comparison);
        return copy;
    }
}
```

**Файл `Program.cs`** — меню-словник і пошук лямбдами.

```csharp
using System.Text;

namespace ServiceCenter;

internal static class Program
{
    private static readonly CsvRepository repo = new CsvRepository("orders.csv");
    private static readonly Dictionary<string, Action> menu = new();
    private static bool running = true;

    private static void Main()
    {
        Console.OutputEncoding = Encoding.UTF8;

        // Підписка двох передплатників на одну подію.
        var logger = new Logger("log.txt");
        repo.OrderChanged += logger.Write;        // пише у файл
        repo.OrderChanged += Logger.Show;         // виводить на екран

        repo.Load();
        BuildMenu();

        while (running)
        {
            Console.WriteLine("\n=== Сервісний центр: журнал заявок ===");
            foreach (string line in MenuLines)
                Console.WriteLine(line);
            Console.Write("Ваш вибір: ");

            string choice = Console.ReadLine() ?? "";
            if (menu.TryGetValue(choice, out Action? action))
                action();                          // виклик збереженого методу
            else
                Console.WriteLine("Немає такого пункту меню.");
        }
    }

    // Підписи пунктів — окремим масивом: словник не гарантує порядку перебору.
    private static readonly string[] MenuLines =
    {
        "1 — додати заявку", "2 — показати всі", "3 — пошук за власником",
        "4 — пошук: незавершені понад 7 днів", "5 — пошук: сума понад задану",
        "6 — сортувати за датою прийому", "7 — сортувати за сумою (спадання)",
        "8 — сортувати за прізвищем власника", "9 — видалити заявку",
        "0 — зберегти й вийти",
    };

    // Меню — словник «клавіша → дія». Додати пункт тепер означає
    // дописати один рядок, а не нову гілку switch.
    private static void BuildMenu()
    {
        menu["1"] = AddOrder;
        menu["2"] = () => Show(repo.GetAll());
        menu["3"] = FindByOwner;
        menu["4"] = () => Show(repo.Find(o => !o.IsDone && o.DaysInService > 7));
        menu["5"] = FindByTotal;
        menu["6"] = () => Show(repo.GetSorted((a, b) => a.ReceivedDate.CompareTo(b.ReceivedDate)));
        menu["7"] = () => Show(repo.GetSorted((a, b) => b.GetTotal().CompareTo(a.GetTotal())));
        menu["8"] = () => Show(repo.GetSorted((a, b) =>
                        string.Compare(a.OwnerName, b.OwnerName, StringComparison.CurrentCulture)));
        menu["9"] = RemoveOrder;
        menu["0"] = () => { repo.Save(); running = false; };
    }

    // Пошук за підрядком у прізвищі: умова — лямбда, що захоплює введений текст.
    private static void FindByOwner()
    {
        Console.Write("Прізвище або його частина: ");
        string text = (Console.ReadLine() ?? "").Trim();
        Show(repo.Find(o => o.OwnerName.Contains(text, StringComparison.CurrentCultureIgnoreCase)));
    }

    // Пошук за сумою: лямбда захоплює локальну змінну limit.
    private static void FindByTotal()
    {
        Console.Write("Сума понад: ");
        if (!decimal.TryParse(Console.ReadLine(), out decimal limit))
        {
            Console.WriteLine("Потрібне число.");
            return;
        }
        Show(repo.Find(o => o.GetTotal() > limit));
    }

    private static void Show(List<RepairOrder> list)
    {
        if (list.Count == 0) { Console.WriteLine("Нічого не знайдено."); return; }
        decimal sum = 0;
        foreach (var order in list)
        {
            Console.WriteLine(order);
            sum += order.GetTotal();
        }
        Console.WriteLine($"Знайдено заявок: {list.Count}, на суму {sum:F2} грн");
    }

    private static void RemoveOrder()
    {
        Console.Write("Номер заявки: ");
        if (int.TryParse(Console.ReadLine(), out int id))
            Console.WriteLine(repo.Remove(id) ? "Заявку видалено." : "Заявку не знайдено.");
    }

    // AddOrder — з ЛР15 без змін: створює потрібного нащадка й викликає repo.Add(order).
    // Повідомлення в журнал тепер з'являється саме собою, бо Add збуджує подію.
}
```

## Додаткове завдання (на вищу оцінку)

Реалізуйте **складені умови пошуку**, не змінюючи методу `Find`. Напишіть три допоміжні методи, які приймають предикати й повертають новий предикат:

```csharp
public static Predicate<T> And<T>(Predicate<T> a, Predicate<T> b) => x => a(x) && b(x);
public static Predicate<T> Or<T>(Predicate<T> a, Predicate<T> b)  => x => a(x) || b(x);
public static Predicate<T> Not<T>(Predicate<T> a)                 => x => !a(x);
```

Додайте в меню пункт «розширений пошук», де користувач послідовно обирає одну-дві прості умови й спосіб їх поєднання, після чого програма складає з них один предикат і передає його в `Find`.

Другою частиною додаткового завдання зробіть **скасування останньої дії**: сховище зберігає останній видалений запис, а окремий пункт меню повертає його назад (подія при цьому збуджується з дією «Відновлено»). У звіті поясніть, чому метод, який повертає предикат, теж є лямбда-виразом, і що саме він захоплює.
