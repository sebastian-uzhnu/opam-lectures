# Лабораторна робота №9

## Тема
Реалізація алгоритмів пошуку та сортування

## Мета
Навчитися виділяти повторювану частину програми в окремий метод із параметрами
та значенням, що повертається. Закріпити роботу з масивами через реалізацію
класичних алгоритмів пошуку (лінійного та бінарного) і сортування (бульбашкою,
вибором, вставками). Набути навичок вимірювання трудомісткості алгоритму
підрахунком порівнянь і перестановок та оцінювання складності у позначенні
«О велике».

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий
редактор і термінал, система контролю версій Git.

## Теоретичні відомості

### 1. Навіщо потрібні власні методи

У попередніх роботах уся програма містилася в одному потоці інструкцій. Щойно
задача вимагає виконати ту саму дію над трьома різними масивами, доводиться
копіювати десяток рядків — і після кожного виправлення шукати, чи всюди ви його
внесли. Саме тому будь-яку завершену дію оформлюють як **метод** — іменований
фрагмент коду, який викликають за іменем скільки завгодно разів, передавши йому
вхідні дані.

Оголошення методу складається з модифікаторів, типу результату, імені та списку
параметрів у дужках; оператор `return` повертає значення й одразу завершує метод.
Якщо метод нічого не повертає, типом результату є `void`.

```csharp
// Метод, що повертає значення
static int Sum(int[] data)
{
    int total = 0;
    foreach (int x in data)
    {
        total += x;
    }
    return total;      // повертає результат і завершує метод
}

// Метод, що нічого не повертає, а лише виконує дію
static void PrintArray(string title, int[] data)
{
    Console.WriteLine($"{title}: {string.Join(", ", data)}");
}

int[] marks = [5, 4, 5, 3];
PrintArray("Оцінки", marks);
Console.WriteLine($"Сума = {Sum(marks)}");
```

Вивід:

```
Оцінки: 5, 4, 5, 3
Сума = 17
```

Розрізняйте терміни: **параметр** — змінна в оголошенні методу (`int[] data`),
**аргумент** — значення, передане під час виклику (`marks`). Слово `static`
означає, що метод належить самій програмі, а не окремому об'єкту; власні класи
й нестатичні методи з'являться у ЛР13.

### 2. Як передаються аргументи

| Спосіб | Оголошення | Що відбувається |
|---|---|---|
| За значенням | `int x` | у метод іде копія; зміни всередині не видно ззовні |
| Масив | `int[] a` | копіюється **посилання**; зміни елементів видно ззовні |
| `ref` | `ref int x` | метод працює з тією самою змінною; вона має бути ініціалізована |
| `out` | `out int x` | те саме, але метод **зобов'язаний** присвоїти значення |

Масив завжди передається як посилання, тому метод, який змінює `data[0]`,
змінює масив викликача — окреме слово `ref` для цього не потрібне.

```csharp
static void Swap(ref int first, ref int second)
{
    (first, second) = (second, first);
}

// Два результати з одного методу — класичний випадок для out
static void FindMinMax(int[] data, out int min, out int max)
{
    min = data[0];
    max = data[0];
    for (int i = 1; i < data.Length; i++)
    {
        if (data[i] < min) min = data[i];
        if (data[i] > max) max = data[i];
    }
}

int x = 10, y = 20;
Swap(ref x, ref y);
Console.WriteLine($"x = {x}, y = {y}");
FindMinMax([7, 2, 9, 4], out int low, out int high);
Console.WriteLine($"min = {low}, max = {high}");
```

Вивід:

```
x = 20, y = 10
min = 2, max = 9
```

Різниця проста: `ref` вимагає, щоб змінна вже мала значення до виклику, а `out` —
щоб метод обов'язково присвоїв їй значення перед виходом. Саме тому знайомий вам
`int.TryParse(текст, out число)` оголошено з `out`.

### 3. Лінійний пошук

**Лінійний (послідовний) пошук** перебирає елементи від початку, поки не знайде
потрібний. Це єдиний спосіб, якщо про порядок даних нічого не відомо.

```csharp
static int LinearSearch(int[] data, int key, out int comparisons)
{
    comparisons = 0;
    for (int i = 0; i < data.Length; i++)
    {
        comparisons++;
        if (data[i] == key)
        {
            return i;          // знайшли — одразу виходимо
        }
    }
    return -1;                 // домовленість: -1 означає "не знайдено"
}

int[] queue = [41, 17, 88, 5, 23, 60];
int pos = LinearSearch(queue, 23, out int steps);
Console.WriteLine($"Індекс = {pos}, порівнянь = {steps}");
pos = LinearSearch(queue, 99, out steps);
Console.WriteLine($"Індекс = {pos}, порівнянь = {steps}");
```

Вивід:

```
Індекс = 4, порівнянь = 5
Індекс = -1, порівнянь = 6
```

Найкращий випадок — елемент перший, одне порівняння. Найгірший — елемент
останній або його немає взагалі: `n` порівнянь. У середньому — приблизно `n / 2`.

### 4. Бінарний пошук

**Бінарний (двійковий) пошук** щоразу відкидає половину діапазону, порівнюючи
шуканий елемент із серединним. Працює **лише на впорядкованому масиві** — інакше
висновок «шукане менше за середній елемент, отже, воно ліворуч» не має підстав.

```csharp
static int BinarySearch(int[] sorted, int key, out int comparisons)
{
    comparisons = 0;
    int left = 0;
    int right = sorted.Length - 1;

    while (left <= right)
    {
        int middle = left + (right - left) / 2;  // так безпечніше, ніж (left+right)/2
        comparisons++;

        if (sorted[middle] == key) return middle;
        if (sorted[middle] < key) left = middle + 1;   // шукане праворуч
        else right = middle - 1;                       // шукане ліворуч
    }
    return -1;
}

int[] prices = [5, 17, 23, 41, 60, 88, 95, 120];
Console.WriteLine(BinarySearch(prices, 88, out int c) + $", порівнянь {c}");
```

Вивід:

```
5, порівнянь 2
```

Покроковий розбір пошуку числа 88 у масиві з восьми елементів:

```
 індекси:   0    1    2    3    4    5    6    7
 значення:  5   17   23   41   60   88   95  120

 крок 1: left=0, right=7, middle=3, sorted[3]=41 < 88  -> шукаємо праворуч
 крок 2: left=4, right=7, middle=5, sorted[5]=88 = 88  -> знайдено, індекс 5

 Лінійний пошук витратив би 6 порівнянь, бінарний — 2. Для масиву
 з 1 000 000 елементів: лінійний — до 1 000 000, бінарний — до 20.
```

Кількість кроків бінарного пошуку — це кількість разів, яку `n` можна поділити
навпіл до одиниці, тобто приблизно `log₂ n`. Плата за швидкість — вимога
впорядкованості: сортувати спеціально заради одного пошуку невигідно, сортування
окупається тоді, коли пошуків багато.

### 5. Сортування бульбашкою

**Сортування обміном (бульбашкою)** порівнює сусідні елементи й міняє їх місцями,
якщо вони стоять неправильно. За один прохід найбільший елемент «спливає» в кінець.

```csharp
static void BubbleSort(int[] data, out int comparisons, out int swaps)
{
    comparisons = 0;
    swaps = 0;
    for (int i = 0; i < data.Length - 1; i++)
    {
        bool swapped = false;                       // прапорець: чи був обмін
        for (int j = 0; j < data.Length - 1 - i; j++)
        {
            comparisons++;
            if (data[j] > data[j + 1])
            {
                (data[j], data[j + 1]) = (data[j + 1], data[j]);
                swaps++;
                swapped = true;
            }
        }
        if (!swapped) break;                        // масив уже впорядкований
    }
}
```

Покроковий розбір на масиві `[5, 1, 4, 2]`:

```
 Прохід 1 (межа j < 3):
   5 1 4 2   5 і 1 -> обмін
   1 5 4 2   5 і 4 -> обмін
   1 4 5 2   5 і 2 -> обмін
   1 4 2 5   найбільший (5) став на місце
 Прохід 2 (межа j < 2):
   1 4 2 5   1 і 4 -> без обміну
   1 4 2 5   4 і 2 -> обмін
   1 2 4 5   другий за величиною (4) на місці
 Прохід 3 (межа j < 1):
   1 2 4 5   1 і 2 -> без обміну; обмінів не було -> достроковий вихід

 Разом: 6 порівнянь, 4 обміни.
```

Зверніть увагу на `- 1 - i` у межі внутрішнього циклу: `i` останніх елементів
уже стоять на місцях. Прапорець `swapped` дозволяє завершити роботу достроково —
саме завдяки йому бульбашка на готовому масиві робить лише один прохід.

### 6. Сортування вибором

**Сортування вибором** на кожному кроці шукає мінімум серед елементів, що
залишилися, і ставить його на поточну позицію одним обміном.

```csharp
static void SelectionSort(int[] data, out int comparisons, out int swaps)
{
    comparisons = 0;
    swaps = 0;
    for (int i = 0; i < data.Length - 1; i++)
    {
        int minIndex = i;
        for (int j = i + 1; j < data.Length; j++)
        {
            comparisons++;
            if (data[j] < data[minIndex]) minIndex = j;
        }
        if (minIndex != i)
        {
            (data[i], data[minIndex]) = (data[minIndex], data[i]);
            swaps++;
        }
    }
}
```

```
 [5, 1, 4, 2]

 i=0: мінімум серед [5 1 4 2] -> 1 на позиції 1 -> обмін 5 <-> 1 => 1 5 4 2
 i=1: мінімум серед    [5 4 2] -> 2 на позиції 3 -> обмін 5 <-> 2 => 1 2 4 5
 i=2: мінімум серед      [4 5] -> 4 вже на місці  -> обміну немає => 1 2 4 5
 Разом: 6 порівнянь, 2 обміни.
```

Головна перевага цього методу — мінімальна кількість обмінів, не більше ніж `n - 1`.
Це важливо, коли переставляти елементи дорого (великі записи, а не числа).
Кількість же порівнянь незмінна завжди — навіть на впорядкованому масиві.

### 7. Сортування вставками

**Сортування вставками** будує впорядковану частину на початку масиву: черговий
елемент виймається й «вставляється» на своє місце серед уже впорядкованих,
які для цього зсуваються праворуч. Так людина розкладає карти в руці.

```csharp
static void InsertionSort(int[] data, out int comparisons, out int shifts)
{
    comparisons = 0;
    shifts = 0;
    for (int i = 1; i < data.Length; i++)
    {
        int current = data[i];      // виймаємо елемент
        int j = i - 1;
        while (j >= 0 && data[j] > current)
        {
            comparisons++;
            data[j + 1] = data[j];  // зсуваємо праворуч
            shifts++;
            j--;
        }
        if (j >= 0) comparisons++;  // останнє порівняння, яке зупинило цикл
        data[j + 1] = current;      // ставимо на звільнене місце
    }
}
```

```
 [5, 1, 4, 2]   вертикальна риска — межа впорядкованої частини

 i=1: беремо 1   | 5 | 1 4 2   5 більше за 1 -> зсув   => 1 5 | 4 2
 i=2: беремо 4   | 1 5 | 4 2   5 більше за 4 -> зсув   => 1 4 5 | 2
                                1 менше за 4 -> стоп
 i=3: беремо 2   | 1 4 5 | 2   5 і 4 більші -> два зсуви => 1 2 4 5 |
                                1 менше за 2 -> стоп
 Разом: 5 порівнянь, 4 зсуви.
```

Вставками вигідно сортувати майже впорядковані дані: внутрішній цикл тоді майже
не працює, і метод наближається до `n` дій. Саме тому його використовують
як допоміжний у «промислових» бібліотечних алгоритмах.

### 8. Обчислювальна складність простими словами

**Обчислювальна складність** — це відповідь на питання «як швидко зростає час
роботи алгоритму, коли зростає обсяг даних `n`». Її записують у позначенні
**«О велике»**, залишаючи тільки найшвидше зростаючий доданок: `3n² + 5n + 100`
перетворюється на `O(n²)`, бо саме квадрат визначає поведінку на великих `n`.

| Позначення | Назва | Поведінка | Приклад |
|---|---|---|---|
| `O(1)` | стала | не залежить від `n` | звернення `a[i]` |
| `O(log n)` | логарифмічна | `n` зросло вдвічі — робота зросла на один крок | бінарний пошук |
| `O(n)` | лінійна | `n` зросло вдвічі — робота зросла вдвічі | лінійний пошук, сума |
| `O(n²)` | квадратична | `n` зросло вдвічі — робота зросла вчетверо | прості сортування |

Кількість дій для різних `n`: при `n = 100` це 7 кроків для `O(log n)`,
100 для `O(n)` і 10 000 для `O(n²)`; при `n = 10 000` — відповідно 14, 10 000
і 100 000 000. Якщо квадратичний алгоритм на 10 000 елементів працює секунду,
то на 100 000 він працюватиме близько ста секунд, а не десяти.

Саме тому всі три вивчені сортування — `O(n²)` — придатні для навчальних
і невеликих задач, але не для мільйонів елементів. Промислові алгоритми
працюють за `O(n log n)`.

### 9. Порівняння алгоритмів

| Алгоритм | Найкращий випадок | Середній | Найгірший | Обміни | Стійкий |
|---|---|---|---|---|---|
| Бульбашка з прапорцем | `O(n)` | `O(n²)` | `O(n²)` | до `n²/2` | так |
| Вибором | `O(n²)` | `O(n²)` | `O(n²)` | до `n - 1` | ні |
| Вставками | `O(n)` | `O(n²)` | `O(n²)` | до `n²/2` | так |
| Лінійний пошук | `O(1)` | `O(n)` | `O(n)` | — | — |
| Бінарний пошук | `O(1)` | `O(log n)` | `O(log n)` | — | — |

**Стійке сортування** — таке, що зберігає відносний порядок елементів з однаковими
значеннями. Для чисел це непомітно, але важливо, коли сортують записи за одним
полем і хочуть зберегти порядок за іншим.

### 10. Бібліотечні аналоги

Писати сортування вручну потрібно, щоб розуміти, як воно працює. У робочому коді
користуються готовими методами, які реалізовані ефективніше.

| Виклик | Складність | Примітка |
|---|---|---|
| `Array.Sort(a)` | `O(n log n)` | змінює сам масив |
| `Array.BinarySearch(a, key)` | `O(log n)` | масив має бути впорядкованим |
| `Array.IndexOf(a, key)` | `O(n)` | лінійний пошук, порядок не потрібен |

```csharp
int[] a = [60, 17, 95, 5, 41];
Array.Sort(a);
Console.WriteLine(string.Join(", ", a));

int found = Array.BinarySearch(a, 41);
int missing = Array.BinarySearch(a, 50);
Console.WriteLine($"41 -> {found};  50 -> {missing}");
```

Вивід:

```
5, 17, 41, 60, 95
41 -> 3;  50 -> -4
```

Якщо елемента немає, `Array.BinarySearch` повертає **від'ємне** число — доповнення
до позиції, куди елемент треба було б вставити (для `-4` це позиція 3). Ніколи
не перевіряйте результат умовою «дорівнює -1» — перевіряйте «менше за нуль».

### 11. Типові помилки

| Помилка | Прояв | Як уникнути |
|---|---|---|
| Бінарний пошук у невпорядкованому масиві | елемент «не знайдено», хоча він є | сортувати перед пошуком |
| `while (left < right)` замість `<=` | не знаходить елемент у кінці діапазону | межа `left <= right` |
| Обмін без тимчасової змінної чи кортежу | обидва елементи стають однаковими | `(a, b) = (b, a)` |
| Межа `j < n` у бульбашці | звернення до `data[n]`, виняток | `j < n - 1 - i` |

## Приклад виконання

**Умова.** Спортивна школа зберігає результати забігу (час у секундах) у масиві.
Реалізувати методами: заповнення масиву випадковими числами, вивід, сортування
вибором і вставками з підрахунком порівнянь та перестановок, лінійний і бінарний
пошук із підрахунком порівнянь. Порівняти обидва сортування на однакових даних
і обидва пошуки на впорядкованому масиві, звести результати в таблицю для масивів
розміром 10, 100 і 1000 елементів.

**Аналіз.** Кожна дія — окремий метод, тому головна частина програми стає коротким
сценарієм. Оскільки сортування змінює масив, а порівнювати треба на однакових даних,
кожному алгоритму передаємо **копію** вихідного масиву через `Clone()`. Лічильники
повертаємо через `out`: метод має віддати дві величини на додачу до основної роботи.

**Код.**

```csharp
// Лабораторна робота №9. Приклад виконання.
// Порівняння сортувань і пошуків на результатах забігу.

int[] sizes = [10, 100, 1000];

Console.WriteLine($"{"n",6}{"вибір: пор.",14}{"вибір: обм.",13}" +
                  $"{"вставки: пор.",16}{"вставки: зсув.",16}");

foreach (int n in sizes)
{
    int[] original = CreateRandom(n, 900, 3600);   // час забігу в секундах

    int[] forSelection = (int[])original.Clone();
    SelectionSort(forSelection, out int selCompare, out int selSwap);

    int[] forInsertion = (int[])original.Clone();
    InsertionSort(forInsertion, out int insCompare, out int insShift);

    Console.WriteLine($"{n,6}{selCompare,14}{selSwap,13}{insCompare,16}{insShift,16}");
}

Console.WriteLine($"  бінарний пошук: індекс {binaryIndex}, порівнянь {binarySteps}");

static int[] CreateRandom(int size, int minValue, int maxValue)
{
    int[] result = new int[size];
    for (int i = 0; i < result.Length; i++)
    {
        result[i] = Random.Shared.Next(minValue, maxValue + 1);
    }
    return result;
}

static void PrintArray(string title, int[] data)
{
    Console.WriteLine($"{title}: {string.Join(", ", data)}");
}

static void SelectionSort(int[] data, out int comparisons, out int swaps)
{
    comparisons = 0;
    swaps = 0;
    for (int i = 0; i < data.Length - 1; i++)
    {
        int minIndex = i;
        for (int j = i + 1; j < data.Length; j++)
        {
            comparisons++;
            if (data[j] < data[minIndex]) minIndex = j;
        }
        if (minIndex != i)
        {
            (data[i], data[minIndex]) = (data[minIndex], data[i]);
            swaps++;
        }
    }
}

static void InsertionSort(int[] data, out int comparisons, out int shifts)
{
    comparisons = 0;
    shifts = 0;
    for (int i = 1; i < data.Length; i++)
    {
        int current = data[i];
        int j = i - 1;
        while (j >= 0 && data[j] > current)
        {
            comparisons++;
            data[j + 1] = data[j];
            shifts++;
            j--;
        }
        if (j >= 0) comparisons++;
        data[j + 1] = current;
    }
}

static int LinearSearch(int[] data, int key, out int comparisons)
{
    comparisons = 0;
    for (int i = 0; i < data.Length; i++)
    {
        comparisons++;
        if (data[i] == key) return i;
    }
    return -1;
}

static int BinarySearch(int[] sorted, int key, out int comparisons)
{
    comparisons = 0;
    int left = 0, right = sorted.Length - 1;
    while (left <= right)
    {
        int middle = left + (right - left) / 2;
        comparisons++;
        if (sorted[middle] == key) return middle;
        if (sorted[middle] < key) left = middle + 1;
        else right = middle - 1;
    }
    return -1;
}
```

```
  1000        499500          993          251038          251038
```

**Висновки з експерименту.** Коли розмір масиву зростає в 10 разів, кількість
порівнянь обох сортувань зростає приблизно в 100 разів — це і є `O(n²)` у дії.
Сортування вибором завжди робить рівно `n(n-1)/2` порівнянь, але майже не
переставляє елементи; вставками на випадкових даних робить приблизно вдвічі менше
порівнянь, зате багато зсувів. Бінарний пошук виграє в лінійного вже на десяти
елементах, а зі зростанням `n` розрив стає вирішальним.
