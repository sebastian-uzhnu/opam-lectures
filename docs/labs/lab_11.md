# Лабораторна робота №11

## Тема
Робота з текстовими та CSV-файлами. Збереження результатів обчислень

## Мета
Навчитися зберігати результати роботи програми у файлах і читати вихідні дані з файлів, а не лише з клавіатури. Закріпити роботу з рядками й масивами на задачі розбору формату CSV. Набути навичок безпечної роботи з файловою системою: перевірка існування файлу, побудова шляхів, обробка виняткових ситуацій. Зрозуміти, що таке кодування тексту і чому файл, збережений в одному кодуванні, може відкритися нечитабельним у іншому.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор і термінал, система контролю версій Git.

## Теоретичні відомості

### 1. Навіщо програмі файли

Досі всі дані ваших програм жили лише в оперативній пам'яті: після завершення програми вони зникали. **Файл** — іменована послідовність байтів на носії інформації, яка існує незалежно від програми. Саме файли дають програмі те, що називають **перзистентністю** — здатність даних переживати завершення роботи.

Загальна схема взаємодії програми з файлом:

```
        ОПЕРАТИВНА ПАМ'ЯТЬ                        ДИСК
   ┌───────────────────────────┐          ┌──────────────────┐
   │                           │          │                  │
   │   змінні, масиви          │  читання │  data.csv        │
   │   ┌───────────────┐       │◄─────────┤  Прізвище;Бал    │
   │   │ string[] lines│       │          │  Мельник;92      │
   │   └───────────────┘       │          │  Іванчук;74      │
   │           │               │          │                  │
   │           ▼               │          └──────────────────┘
   │   ┌───────────────┐       │
   │   │  обчислення   │       │          ┌──────────────────┐
   │   └───────────────┘       │  запис   │                  │
   │           │               ├─────────►│  report.txt      │
   │           ▼               │          │  Середній: 83.0  │
   │   ┌───────────────┐       │          │                  │
   │   │  результат    │       │          └──────────────────┘
   │   └───────────────┘       │
   │                           │
   └───────────────────────────┘
        зникає після виходу           залишається назавжди
```

Типовий цикл роботи такої програми: **прочитати вхідний файл → розібрати рядки на дані → обчислити → записати результат у новий файл**. Саме його ви реалізуєте в цій роботі.

### 2. Шляхи до файлів

**Шлях** — текстовий опис розташування файлу. Він буває двох видів.

**Абсолютний шлях** починається від кореня файлової системи й однозначно вказує на файл: `C:\Users\Student\data.csv` у Windows, `/home/student/data.csv` у Linux і macOS.

**Відносний шлях** відлічується від **робочої папки програми** — папки, яку операційна система вважає поточною на момент запуску. Для програми, зібраної командою `dotnet run`, робочою папкою є папка проєкту; для зібраного застосунку — зазвичай папка з виконуваним файлом, тобто щось на кшталт `bin/Debug/net8.0`.

```csharp
Console.WriteLine($"Робоча папка: {Directory.GetCurrentDirectory()}");
Console.WriteLine($"Папка програми: {AppContext.BaseDirectory}");
```

```
Вивід:
Робоча папка: /home/student/Lab11
Папка програми: /home/student/Lab11/bin/Debug/net8.0/
```

Через цю різницю відносний шлях `"data.csv"` може несподівано «не знайти» файл. Тому надійніше будувати шлях явно, від відомої папки, і ніколи не склеювати шляхи вручну через `+`: роздільник каталогів у Windows і в Linux різний.

Для роботи зі шляхами є статичний клас `Path`:

| Метод | Призначення | Приклад | Результат |
|---|---|---|---|
| `Path.Combine(a, b)` | коректно склеює частини шляху | `Path.Combine("data", "in.csv")` | `data/in.csv` |
| `Path.GetFileName(p)` | ім'я файлу з розширенням | для `data/in.csv` | `in.csv` |
| `Path.GetFileNameWithoutExtension(p)` | ім'я без розширення | для `data/in.csv` | `in` |
| `Path.GetExtension(p)` | розширення | для `data/in.csv` | `.csv` |
| `Path.GetDirectoryName(p)` | папка, у якій лежить файл | для `data/in.csv` | `data` |
| `Path.GetFullPath(p)` | абсолютний шлях із відносного | для `in.csv` | `/home/student/Lab11/in.csv` |

```csharp
string folder = Directory.GetCurrentDirectory();
string inputPath = Path.Combine(folder, "students.csv");

Console.WriteLine(inputPath);
Console.WriteLine(Path.GetExtension(inputPath));
```

```
Вивід:
/home/student/Lab11/students.csv
.csv
```

Записуючи абсолютний шлях у коді, зручно використовувати дослівний рядок із ЛР10: `@"C:\Дані\звіт.txt"` замість `"C:\\Дані\\звіт.txt"`.

### 3. Клас File: читання й запис одним викликом

Статичний клас `File` (простір імен `System.IO`, який у .NET 8 підключено неявно) виконує типові файлові операції одним рядком коду.

| Метод | Що робить | Повертає |
|---|---|---|
| `File.Exists(path)` | перевіряє, чи файл існує | `bool` |
| `File.ReadAllText(path)` | читає весь файл в один рядок | `string` |
| `File.ReadAllLines(path)` | читає файл у масив рядків | `string[]` |
| `File.WriteAllText(path, text)` | записує рядок, **затираючи** старий вміст | — |
| `File.WriteAllLines(path, lines)` | записує масив рядків, затираючи старий вміст | — |
| `File.AppendAllText(path, text)` | **дописує** текст у кінець файлу | — |
| `File.AppendAllLines(path, lines)` | дописує масив рядків у кінець | — |
| `File.Delete(path)` | видаляє файл | — |
| `File.Copy(src, dst, overwrite)` | копіює файл | — |

Ключова відмінність, яку студенти забувають найчастіше: `WriteAllText` **знищує** попередній вміст файлу без попередження, а `AppendAllText` дописує в кінець. Якщо ви ведете журнал подій, потрібен другий; якщо формуєте звіт наново — перший.

```csharp
string path = Path.Combine(Directory.GetCurrentDirectory(), "log.txt");

File.WriteAllText(path, "Журнал запусків\n");   // створює або затирає
File.AppendAllText(path, "Запуск о 09:15\n");   // дописує
File.AppendAllText(path, "Запуск о 14:40\n");

string[] lines = File.ReadAllLines(path);
Console.WriteLine($"Рядків у файлі: {lines.Length}");
foreach (string line in lines)
{
    Console.WriteLine($"> {line}");
}
```

```
Вивід:
Рядків у файлі: 3
> Журнал запусків
> Запуск о 09:15
> Запуск о 14:40
```

Якщо файлу, який ви записуєте, ще не існує, усі методи `Write` і `Append` створять його. А ось якщо не існує папки, у яку ви пишете, буде помилка — папку створюють окремо викликом `Directory.CreateDirectory(folder)`.

### 4. Потокове читання й запис: StreamReader і StreamWriter

`File.ReadAllLines` завантажує **весь** файл у пам'ять. Для навчальних файлів на сотні рядків це нормально, але для файлу на кілька гігабайтів — ні. Тоді застосовують **потокове** читання: файл читається порціями, рядок за рядком, і в пам'яті одночасно перебуває лише один рядок.

**Потік** (stream) — абстракція послідовного доступу до даних. `StreamReader` читає з файлу текст, `StreamWriter` пише текст у файл.

```csharp
string path = Path.Combine(Directory.GetCurrentDirectory(), "big.txt");

using (var reader = new StreamReader(path))
{
    string? line;
    int number = 0;
    while ((line = reader.ReadLine()) != null)
    {
        number++;
        Console.WriteLine($"{number,3}: {line}");
    }
}
```

Метод `ReadLine()` повертає черговий рядок або `null`, коли файл закінчився — саме тому умова циклу порівнює результат із `null`.

Запис виглядає симетрично:

```csharp
using (var writer = new StreamWriter(path))   // затирає файл
{
    writer.WriteLine("Звіт за жовтень");
    writer.WriteLine(new string('-', 20));
    writer.WriteLine($"Сформовано: {DateTime.Now:dd.MM.yyyy HH:mm}");
}

// другий параметр true — дописування замість затирання
using (var log = new StreamWriter(path, append: true))
{
    log.WriteLine("Додано підсумковий рядок");
}
```

**Навіщо `using`.** Відкритий файл — це обмежений ресурс операційної системи: доки програма його не закрила, інші програми можуть не мати до нього доступу, а записані дані можуть залишатися в буфері й не потрапити на диск. Конструкція `using` гарантує, що метод `Dispose()` (він закриває файл і скидає буфер на диск) буде викликано **обов'язково** — навіть якщо всередині блоку станеться виняток і виконання перерветься.

```
   Без using:                          З using:

   var w = new StreamWriter(p);        using (var w = new StreamWriter(p))
   w.WriteLine("a");                   {
   ThrowSomething();   ◄── виняток         w.WriteLine("a");
   w.Close();          ◄── НЕ виконано     ThrowSomething();  ◄── виняток
                                       }   ◄── Dispose() все одно виконано
   Файл лишився відкритим,
   дані втрачено.                      Файл закрито, дані на диску.
```

Є коротший запис — **using-оголошення** без фігурних дужок. Ресурс звільняється в кінці блоку, у якому оголошено змінну:

```csharp
using var writer = new StreamWriter(outputPath);
writer.WriteLine("Рядок звіту");
// файл закриється автоматично наприкінці методу
```

Практичне правило вибору: файл невеликий і потрібен увесь одразу — `File.ReadAllLines`; файл великий або обробляється рядок за рядком — `StreamReader`. Пишете один готовий текст — `File.WriteAllText`; формуєте звіт поступово в циклі — `StreamWriter`.

### 5. Кодування і проблема «кракозябр»

**Кодування** — правило, за яким символ перетворюється на послідовність байтів у файлі. Файл на диску не зберігає «літери» — лише числа; як ці числа тлумачити, вирішує програма, що відкриває файл.

```
   Символ 'і' у різних кодуваннях:

   UTF-8         →  байти  D1 96        (два байти)
   Windows-1251  →  байт   B3           (один байт)

   Якщо файл записано в UTF-8, а прочитано як Windows-1251,
   два байти D1 96 будуть витлумачені як два окремі символи:

        "Мельник"  →  "ÐœÐµÐ»ÑŒÐ½Ð¸Ðº"
```

Саме цей ефект називають «кракозябрами»: текст читається не тим кодуванням, яким його записано.

**UTF-8** — універсальне кодування Unicode, у якому латиниця займає один байт, а кирилиця — два. Це кодування за замовчуванням у .NET, і саме його слід використовувати завжди, коли немає вимоги іншого. Проблеми виникають, коли CSV-файл створено застарілою програмою в кодуванні Windows-1251.

Кодування можна вказати явно другим параметром:

```csharp
using System.Text;

string path = Path.Combine(Directory.GetCurrentDirectory(), "data.txt");

// явно записуємо в UTF-8
File.WriteAllText(path, "Прізвище: Мельник", Encoding.UTF8);

// явно читаємо в UTF-8
string text = File.ReadAllText(path, Encoding.UTF8);
Console.WriteLine(text);
Console.WriteLine($"Байтів у файлі: {new FileInfo(path).Length}");
```

```
Вивід:
Прізвище: Мельник
Байтів у файлі: 32
```

Якщо кирилиця виводиться в консоль знаками питання, додайте на початок програми рядок `Console.OutputEncoding = Encoding.UTF8;` — це стосується виводу в термінал, а не самого файлу.

### 6. Формат CSV

**CSV** (Comma-Separated Values — значення, розділені комами) — найпростіший текстовий формат таблиці. Його читає будь-який табличний процесор і будь-яка мова програмування.

Правила формату:
- один рядок файлу = один **запис** (рядок таблиці);
- усередині рядка значення розділені **роздільником**: комою, крапкою з комою або табуляцією;
- перший рядок часто є **заголовком** — містить назви стовпців, а не дані;
- порядок і кількість стовпців однакові в усіх рядках.

Приклад вхідного файлу `students.csv`, з яким працює задача з розділу «Приклад виконання»:

```
Прізвище;Група;Математика;Програмування;Фізика
Мельник Олег;ІПЗ-21;88;95;79
Іванчук Дарія;ІПЗ-21;92;90;85
Коваль Богдан;ІПЗ-22;61;74;58
Шевчук Ірина;ІПЗ-21;74;68;81
Гнатюк Сергій;ІПЗ-22;95;98;93
Романюк Анна;ІПЗ-22;55;62;49
```

Схема відповідності файлу й структур у пам'яті:

```
   students.csv                          у пам'яті програми
   ─────────────────────────────         ──────────────────────────────

   Прізвище;Група;Мат;Прог;Фіз   ──►  lines[0]   (заголовок, пропускаємо)
   Мельник Олег;ІПЗ-21;88;95;79  ──►  lines[1] ──Split(';')──► ["Мельник Олег",
   Іванчук Дарія;ІПЗ-21;92;90;85 ──►  lines[2]                   "ІПЗ-21",
   Коваль Богдан;ІПЗ-22;61;74;58 ──►  lines[3]                   "88","95","79"]
   ...                                                                 │
                                                                       ▼
                                              names[i]=cells[0]   int.Parse(cells[2])
```

Чому в українських файлах роздільником частіше є крапка з комою: у багатьох локалізаціях десятковим роздільником є кома (`23,5`), і кома як роздільник стовпців створила б плутанину. У цій роботі використовуйте крапку з комою.

Обмеження навчального підходу: якщо саме значення містить роздільник, у справжньому CSV його беруть у лапки (`"Мельник, Олег";ІПЗ-21`). Розбір лапок значно складніший, тому в цій роботі домовимося, що значення роздільника не містять.

### 7. Розбір і складання рядка CSV

Розбір — це `Split` із ЛР10, складання — `string.Join`:

```csharp
string line = "Коваль Богдан;ІПЗ-22;61;74;58";

string[] cells = line.Split(';');
Console.WriteLine($"Стовпців: {cells.Length}");
Console.WriteLine($"Прізвище: {cells[0]}");

int math = int.Parse(cells[2]);
int prog = int.Parse(cells[3]);
int phys = int.Parse(cells[4]);
double average = (math + prog + phys) / 3.0;

Console.WriteLine($"Середній бал: {average:F2}");

// складаємо новий рядок для файлу-результату
string outLine = string.Join(";", cells[0], cells[1], average.ToString("F2"));
Console.WriteLine(outLine);
```

```
Вивід:
Стовпців: 5
Прізвище: Коваль Богдан
Середній бал: 64.33
Коваль Богдан;ІПЗ-22;64.33
```

Числа з файлу майже завжди доводиться перетворювати з тексту. Дані у файлі можуть бути зіпсовані, тому замість `int.Parse` (кидає виняток) надійніше `int.TryParse` (повертає `false`):

```csharp
string[] raw = ["88", "дев'яносто", "", "75"];
int sum = 0, good = 0;

foreach (string cell in raw)
{
    if (int.TryParse(cell.Trim(), out int value)) { sum += value; good++; }
    else Console.WriteLine($"Пропущено некоректне значення: [{cell}]");
}

Console.WriteLine($"Оброблено {good} значень, сума {sum}");
```

```
Вивід:
Пропущено некоректне значення: [дев'яносто]
Пропущено некоректне значення: []
Оброблено 2 значень, сума 163
```

Для дробових чисел діє `double.TryParse`. Щоб число з крапкою (`23.75`) читалося однаково на будь-якому комп'ютері, незалежно від мовних налаштувань системи, культуру вказують явно: `double.TryParse(cell, NumberStyles.Float, CultureInfo.InvariantCulture, out double value)` — клас `CultureInfo` міститься в просторі імен `System.Globalization`.

### 8. Обробка помилок: try/catch

Файлові операції залежать від зовнішнього світу, і будь-яка з них може не вдатися: файл видалили, диск заповнено, немає прав доступу. Такі ситуації називають **винятковими**, а об'єкт з описом проблеми — **винятком** (exception).

Конструкція `try/catch` дозволяє перехопити виняток і продовжити роботу замість аварійного завершення:

```
   try
   {
       ...код, який може кинути виняток...
   }
   catch (конкретний тип виняткуA ex)   ◄── найточніший тип — першим
   {
       ...реакція на цю ситуацію...
   }
   catch (загальніший тип ex)
   {
       ...реакція на решту...
   }
   finally
   {
       ...виконається в будь-якому разі...
   }
```

Винятки, які трапляються в цій роботі:

| Тип винятку | Причина | Типова реакція |
|---|---|---|
| `FileNotFoundException` | файлу за вказаним шляхом немає | повідомити шлях, створити файл-зразок або завершити роботу |
| `DirectoryNotFoundException` | немає папки зі шляху | створити папку або виправити шлях |
| `UnauthorizedAccessException` | немає прав або це папка, а не файл | повідомити користувача |
| `IOException` | файл зайнято іншою програмою, помилка диска | запропонувати повторити спробу |
| `FormatException` | текст у файлі не є числом | пропустити рядок і полічити його як зіпсований |
| `IndexOutOfRangeException` | у рядку CSV менше стовпців, ніж очікувалося | пропустити рядок |

`FileNotFoundException` і `DirectoryNotFoundException` є окремими випадками `IOException`, тому загальний `catch (IOException)` слід ставити **після** них.

```csharp
string path = Path.Combine(Directory.GetCurrentDirectory(), "input.csv");

try
{
    string[] lines = File.ReadAllLines(path);
    Console.WriteLine($"Прочитано рядків: {lines.Length}");
}
catch (FileNotFoundException)
{
    Console.WriteLine($"Файл не знайдено: {path}");
    Console.WriteLine("Створіть його поряд із програмою або вкажіть інший шлях.");
}
catch (IOException ex)
{
    Console.WriteLine($"Помилка доступу до файлу: {ex.Message}");
}
finally
{
    Console.WriteLine("Спробу читання завершено.");
}
```

```
Вивід (коли файлу немає):
Файл не знайдено: /home/student/Lab11/input.csv
Створіть його поряд із програмою або вкажіть інший шлях.
Спробу читання завершено.
```

Що робити, якщо файлу немає, вирішує логіка задачі. Три розумні варіанти: повідомити й коректно завершити роботу; попросити ввести інший шлях; створити файл із даними-зразком, щоб програму можна було перевірити. Чого робити не можна — мовчки продовжувати роботу так, ніби дані є.

Перевірка `File.Exists(path)` перед читанням — корисна, але **не замінює** `try/catch`: файл може зникнути або виявитися зайнятим у проміжку між перевіркою й читанням. Надійна програма робить і те, і те.

## Приклад виконання

**Умова.** Файл `students.csv` містить заголовок і рядки виду `Прізвище;Група;Математика;Програмування;Фізика`. Потрібно:
1. прочитати файл, обробивши ситуацію його відсутності;
2. для кожного студента обчислити середній бал;
3. знайти загальний середній бал по файлу, найкращого й найгіршого студента, кількість тих, хто має середній бал нижче 60;
4. відсортувати студентів за спаданням середнього балу;
5. записати відсортований список у CSV-файл `sorted.csv`, а текстовий звіт зі статистикою — у файл `report.txt`.

**Аналіз.**

Колекцій студент ще не знає, тому дані зберігаємо в **паралельних масивах**: `names`, `groups`, `averages`. Розмір масивів відомий заздалегідь — це `lines.Length - 1` (усі рядки, крім заголовка). Зіпсовані рядки пропускаємо, тому реальна кількість записів `count` може виявитися меншою за розмір масивів; усі подальші цикли ходять до `count`, а не до `.Length`.

Сортування — за спаданням середнього балу. Беремо бульбашкове сортування з ЛР9, але при обміні **обов'язково переставляємо елементи всіх трьох масивів одночасно**, інакше прізвище перестане відповідати своєму балу.

Читання — через `File.ReadAllLines` (файл навчальний, невеликий). Звіт формуємо через `StreamWriter`, бо пишемо його порядково в циклі; CSV-результат складаємо `string.Join` і пишемо одним викликом `File.WriteAllLines`.

Обробку файлу розбиваємо на методи, як у ЛР9: окремо читання, окремо обчислення, окремо запис.

**Код.**

```csharp
using System.Text;

Console.OutputEncoding = Encoding.UTF8;

string folder = Directory.GetCurrentDirectory();
string inputPath = Path.Combine(folder, "students.csv");
string csvOutPath = Path.Combine(folder, "sorted.csv");
string reportPath = Path.Combine(folder, "report.txt");

string[] lines;

// --- 1. Читання з обробкою помилок ---
try
{
    if (!File.Exists(inputPath))
    {
        Console.WriteLine($"Файл не знайдено: {inputPath}");
        Console.WriteLine("Створюю файл-зразок, щоб програму можна було перевірити.");
        CreateSample(inputPath);
    }

    lines = File.ReadAllLines(inputPath, Encoding.UTF8);
}
catch (IOException ex)
{
    Console.WriteLine($"Не вдалося прочитати файл: {ex.Message}");
    return;
}

if (lines.Length < 2)
{
    Console.WriteLine("У файлі немає жодного запису, лише заголовок.");
    return;
}

// --- 2. Розбір рядків у паралельні масиви ---
int capacity = lines.Length - 1;          // рядок 0 — заголовок
string[] names = new string[capacity];
string[] groups = new string[capacity];
double[] averages = new double[capacity];

int count = 0;      // скільки коректних записів реально прочитано
int broken = 0;     // скільки рядків пропущено

for (int i = 1; i < lines.Length; i++)
{
    string line = lines[i].Trim();
    if (line.Length == 0) continue;       // порожні рядки просто пропускаємо

    string[] cells = line.Split(';');
    if (cells.Length != 5)
    {
        Console.WriteLine($"Рядок {i + 1}: очікувалося 5 стовпців, є {cells.Length}");
        broken++;
        continue;
    }

    if (!int.TryParse(cells[2].Trim(), out int math) ||
        !int.TryParse(cells[3].Trim(), out int prog) ||
        !int.TryParse(cells[4].Trim(), out int phys))
    {
        Console.WriteLine($"Рядок {i + 1}: оцінка не є цілим числом");
        broken++;
        continue;
    }

    names[count] = cells[0].Trim();
    groups[count] = cells[1].Trim();
    averages[count] = (math + prog + phys) / 3.0;
    count++;
}

Console.WriteLine($"Прочитано записів: {count}, пропущено рядків: {broken}");

if (count == 0)
{
    Console.WriteLine("Жодного коректного запису — звіт не формується.");
    return;
}

// --- 3. Статистика ---
double total = 0;
int bestIndex = 0;
int worstIndex = 0;
int failing = 0;

for (int i = 0; i < count; i++)
{
    total += averages[i];
    if (averages[i] > averages[bestIndex]) bestIndex = i;
    if (averages[i] < averages[worstIndex]) worstIndex = i;
    if (averages[i] < 60) failing++;
}

double groupAverage = total / count;

// --- 4. Сортування за спаданням середнього балу (три масиви разом) ---
for (int i = 0; i < count - 1; i++)
{
    for (int j = 0; j < count - 1 - i; j++)
    {
        if (averages[j] < averages[j + 1])
        {
            (averages[j], averages[j + 1]) = (averages[j + 1], averages[j]);
            (names[j], names[j + 1]) = (names[j + 1], names[j]);
            (groups[j], groups[j + 1]) = (groups[j + 1], groups[j]);
        }
    }
}

// --- 5. Запис відсортованого CSV ---
string[] outLines = new string[count + 1];
outLines[0] = "Місце;Прізвище;Група;СереднійБал";
for (int i = 0; i < count; i++)
{
    outLines[i + 1] = string.Join(";",
        i + 1, names[i], groups[i], averages[i].ToString("F2"));
}
File.WriteAllLines(csvOutPath, outLines, Encoding.UTF8);

// --- 6. Запис текстового звіту ---
using (var writer = new StreamWriter(reportPath, false, Encoding.UTF8))
{
    writer.WriteLine("ЗВІТ ПРО УСПІШНІСТЬ");
    writer.WriteLine(new string('=', 46));
    writer.WriteLine($"Джерело даних : {Path.GetFileName(inputPath)}");
    writer.WriteLine($"Сформовано    : {DateTime.Now:dd.MM.yyyy HH:mm}");
    writer.WriteLine($"Записів       : {count} (пропущено {broken})");
    writer.WriteLine();
    writer.WriteLine($"{"Місце",-6}{"Прізвище",-18}{"Група",-10}{"Бал",6}");
    writer.WriteLine(new string('-', 46));

    for (int i = 0; i < count; i++)
    {
        writer.WriteLine($"{i + 1,-6}{names[i],-18}{groups[i],-10}{averages[i],6:F2}");
    }

    writer.WriteLine(new string('-', 46));
    writer.WriteLine($"Середній бал по файлу : {groupAverage:F2}");
    writer.WriteLine($"Найкращий результат   : {names[0]} ({averages[0]:F2})");
    writer.WriteLine($"Найгірший результат   : {names[count - 1]} ({averages[count - 1]:F2})");
    writer.WriteLine($"Середній бал нижче 60 : {failing} студент(ів)");
}

Console.WriteLine($"Записано: {Path.GetFileName(csvOutPath)}, {Path.GetFileName(reportPath)}");
Console.WriteLine($"Середній бал по файлу: {groupAverage:F2}");

// --- Допоміжний метод: створення файлу-зразка ---
static void CreateSample(string path)
{
    string[] sample =
    [
        "Прізвище;Група;Математика;Програмування;Фізика",
        "Мельник Олег;ІПЗ-21;88;95;79",
        "Іванчук Дарія;ІПЗ-21;92;90;85",
        "Коваль Богдан;ІПЗ-22;61;74;58",
        "Шевчук Ірина;ІПЗ-21;74;68;81",
        "Гнатюк Сергій;ІПЗ-22;95;98;93",
        "Романюк Анна;ІПЗ-22;55;62;49"
    ];
    File.WriteAllLines(path, sample, Encoding.UTF8);
}
```


**Що тут варто помітити.** Програма не падає на зіпсованому файлі — вона повідомляє номер проблемного рядка й продовжує роботу. Масиви створено з запасом (`lines.Length - 1`), а фактична кількість записів лічиться окремою змінною `count`: це стандартний прийом, доки немає динамічних колекцій. При обміні під час сортування переставляються **всі три** масиви — якщо забути один, звіт мовчки покаже неправильні прізвища, і помилку буде важко помітити.

## Додаткове завдання (на вищу оцінку)

Доповніть програму **режимом дописування записів**. Після формування звіту програма пропонує меню: додати новий запис, переглянути поточний вміст файлу, сформувати звіт заново, вийти.

Новий запис користувач вводить із клавіатури по полях, програма перевіряє коректність кожного поля (число є числом, рядок не порожній, значення в допустимому діапазоні), складає рядок CSV через `string.Join` і дописує його в кінець вхідного файлу методом `File.AppendAllText` або `StreamWriter` із `append: true` — **не затираючи** наявні дані. Перед дописуванням програма створює резервну копію вхідного файлу викликом `File.Copy` з іменем виду `students_backup.csv`.

У звіті поясніть, чому дописування зроблено саме `Append`-методом, що станеться, якщо помилково використати `WriteAllText`, і навіщо потрібна резервна копія.

## Контрольні питання

1. Чим абсолютний шлях відрізняється від відносного? Чому відносний шлях `"data.csv"` може працювати під час `dotnet run` і не працювати для зібраного застосунку?
2. Навіщо потрібен `Path.Combine`, якщо частини шляху можна склеїти оператором `+`?
3. У чому різниця між `File.ReadAllText` і `File.ReadAllLines`? Коли зручніший кожен із них?
4. Чим `File.WriteAllText` відрізняється від `File.AppendAllText`? Який із них знищить ваш журнал подій при повторному запуску програми?
5. Навіщо потрібна конструкція `using` при роботі зі `StreamWriter`? Що може статися з даними, якщо файл не закрити?
6. Коли слід обирати `StreamReader` замість `File.ReadAllLines`? Наведіть приклад ситуації, у якій `ReadAllLines` неприйнятний.
7. Що таке кодування тексту? Чому той самий файл може відкритися як «кракозябри» і як це виправити?
8. Опишіть формат CSV: що таке запис, роздільник, заголовок. Чому в українських файлах роздільником частіше беруть крапку з комою, а не кому?
9. Чому при читанні чисел із файлу надійніше використовувати `TryParse`, а не `Parse`? Що станеться з програмою в кожному випадку, якщо у файлі буде текст замість числа?
10. У якому порядку слід розташовувати блоки `catch` для `IOException` і `FileNotFoundException` і чому? Що виконає блок `finally`, якщо виняток не буде перехоплено?

## Зміст звіту

1. Титульна сторінка: назва закладу, дисципліна, номер і тема роботи, група, прізвище та ім'я студента, номер варіанта, прізвище викладача.
2. Мета роботи.
3. Умова індивідуального завдання за своїм варіантом із зазначенням структури вхідного CSV-файлу.
4. Вміст підготовленого вхідного файлу (перші 10 рядків, у блоці коду).
5. Короткий аналіз: які масиви створено для зберігання даних, як обробляються зіпсовані рядки, які винятки перехоплюються.
6. Лістинг програми з коментарями українською мовою.
7. Вміст обох згенерованих файлів — CSV-результату й текстового звіту.
8. Таблиця тестування: коректний файл, файл із зіпсованим рядком, відсутній файл, порожній файл — очікуваний і фактичний результат.
9. Відповіді на 3 контрольні питання, номери яких вказує викладач.
10. Висновок: 3–5 речень.
