# Лабораторна робота №17

## Тема
Розробка консольного застосунку засобами ООП (підсумкова робота)

## Мета
Звести напрацювання шести лабораторних робіт у завершений консольний застосунок: додати авторизацію користувачів із зберіганням пароля у вигляді хешу, розмежування доступу за ролями, журнал дій та підсумковий звіт за темою проєкту. Закріпити структуровану обробку виняткових ситуацій і власні класи винятків. Підготувати проєкт до захисту: навести лад у коді, оформити репозиторій і пояснити кожне прийняте рішення.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор і термінал, система контролю версій Git.

## Що було на попередньому кроці

Це шостий, останній крок наскрізного проєкту. Після лабораторної роботи №16 ваш застосунок має такий вигляд.

- Абстрактний базовий клас головної сутності з абстрактним методом і двома-трьома нащадками.
- Реалізовані `IComparable<T>`, власні `IHasId` та `IRepository<T>`, сховище `CsvRepository`, яке читає й пише дані у файл.
- Один метод пошуку з параметром `Predicate<T>` і сортування через `Comparison<T>`.
- Подія `OrderChanged` у сховищі, на яку підписано запис у `log.txt`.
- Меню у вигляді `Dictionary<string, Action>`.
- Програму може запустити будь-хто й зробити будь-що: користувачів у застосунку немає.

## Що додаємо

Останній крок робить застосунок схожим на справжню робочу програму.

1. **Користувачі.** З'являються клас `User`, перелічення `UserRole` і служба `AuthService`: реєстрація, вхід, обмежена кількість спроб.
2. **Паролі зберігаються у вигляді хешу**, а не відкритим текстом, і вводяться без відображення символів на екрані.
3. **Ролі визначають доступні дії.** Гість лише переглядає й шукає, оператор додає й редагує, адміністратор може все, зокрема керувати користувачами. Меню будується під роль, а перед виконанням дії ще раз перевіряється право на неї.
4. **Власний клас винятку** й структурована обробка помилок: жодна недозволена дія й жодне хибне введення не завершує програму аварійно.
5. **Журнал дій користувачів** (хто, коли й що зробив) і **підсумковий звіт** за темою проєкту — той, що вказаний у переліку тем навпроти вашого номера.

Це підсумкова робота семестру: вона оцінюється у **20 балів** і захищається.

## Теоретичні відомості

### 1. Перелічення `enum`

**Перелічення** (`enum`) — тип, значеннями якого є іменований скінченний набір сталих. Роль користувача — класичний випадок: варіантів рівно три, і жодного іншого бути не може.

```csharp
public enum UserRole { Guest, Operator, Administrator }
```

Під кожним іменем стоїть ціле число: `Guest` — 0, `Operator` — 1, `Administrator` — 2. Звідси корисний наслідок: ролі можна **порівнювати** й перевіряти «не нижче за», якщо перелічити їх у порядку зростання прав.

```csharp
UserRole role = UserRole.Operator;

Console.WriteLine(role);                       // Operator
Console.WriteLine((int)role);                  // 1
Console.WriteLine(role >= UserRole.Operator);  // True
Console.WriteLine(role >= UserRole.Administrator);  // False

// Розбір із рядка (наприклад, під час читання з файлу)
if (Enum.TryParse("Administrator", out UserRole parsed))
    Console.WriteLine($"Прочитано роль: {parsed}");
```

**Вивід:**

```
Operator
1
True
False
Прочитано роль: Administrator
```

Чому не рядок `"оператор"` і не число `1`? Бо рядок можна написати з помилкою, а число нічого не пояснює читачеві коду. Перелічення дає перевірку на етапі компіляції: `UserRole.Operatr` не скомпілюється.

### 2. Клас користувача

```csharp
public class User
{
    public string Login { get; }                          // лише для читання
    public string PasswordHash { get; private set; }      // змінюється лише зсередини
    public UserRole Role { get; set; }

    public User(string login, string passwordHash, UserRole role)
    {
        if (string.IsNullOrWhiteSpace(login))
            throw new ArgumentException("Логін не може бути порожнім.");
        Login = login.Trim().ToLowerInvariant();          // логін не залежить від регістру
        PasswordHash = passwordHash;
        Role = role;
    }

    public void ChangePassword(string newHash) => PasswordHash = newHash;
    public override string ToString() => $"{Login} ({Role})";
}
```

Клас зберігає **не пароль**, а `PasswordHash`, і сеттер у нього закритий: змінити хеш можна лише спеціальним методом.

### 3. Чому пароль не можна зберігати у відкритому вигляді

Файл із даними застосунку може потрапити до чужих рук: його скопіюють, надішлють на перевірку, він опиниться в резервній копії або випадково в репозиторії. Якщо там лежить `ivan;qwerty123;Administrator`, зловмисник отримує не лише доступ до вашої програми, а й, найімовірніше, до інших сервісів користувача — люди повторюють паролі.

**Хеш-функція** — перетворення довільних даних у рядок фіксованої довжини, для якого виконуються дві умови: та сама вхідна величина завжди дає той самий результат, а відновити вхідні дані з результату неможливо. Тому програма зберігає хеш, а під час входу хешує введений пароль і **порівнює хеші**.

```
   Реєстрація "qwerty123"            Вхід "qwerty123"
        │ SHA-256                         │ SHA-256
        ▼                                 ▼
   65E84BE33532FB78...  ──порівняння──  65E84BE33532FB78...  ─▶ збіглося: вхід дозволено
        │
        ▼ записано у файл users.csv
```

У .NET хешування доступне у просторі імен `System.Security.Cryptography`:

```csharp
using System.Security.Cryptography;
using System.Text;

public static class PasswordHasher
{
    // Пароль -> шістнадцятковий рядок із 64 символів.
    public static string Hash(string password)
    {
        byte[] bytes = Encoding.UTF8.GetBytes(password);
        byte[] hash = SHA256.HashData(bytes);      // .NET 5+: статичний виклик
        return Convert.ToHexString(hash);
    }

    public static bool Verify(string password, string storedHash) =>
        Hash(password) == storedHash;
}
```

```csharp
Console.WriteLine(PasswordHasher.Hash("qwerty123"));
Console.WriteLine(PasswordHasher.Hash("qwerty124"));   // змінився один символ
```

**Вивід:**

```
65E84BE33532FB784C48129675F9EFF3A682B27168C0EA744B2CF58EE02337C5
1A2F0F5A6E0E3C9C4F1C1E0E8B9D2A4C5E7F8091A2B3C4D5E6F708192A3B4C5D
```

Зміна одного символу пароля змінює хеш повністю — це називають **лавинним ефектом**.

**Чесна примітка.** Так, як показано вище, у справжніх системах паролі **не зберігають**. SHA-256 працює дуже швидко, тому зловмисник, маючи файл із хешами, може перебирати мільярди варіантів за секунду або скористатися готовою таблицею популярних паролів. У реальних системах до пароля додають **сіль** — випадковий рядок, унікальний для кожного користувача, — і застосовують навмисно повільні алгоритми (`PBKDF2`, `bcrypt`, `Argon2`). У .NET для цього є клас `Rfc2898DeriveBytes`. Це тема дисципліни «Захист інформації»; у навчальному проєкті достатньо SHA-256, але ви маєте розуміти й уміти пояснити, чому цього мало.

### 4. Служба автентифікації

**Автентифікація** — перевірка, що користувач той, за кого себе видає (логін і пароль). **Авторизація** — перевірка, що йому дозволено виконати конкретну дію (роль). Плутати їх не варто.

```csharp
public class AuthService
{
    private const int MaxAttempts = 3;
    private readonly List<User> users = new();
    private readonly string path;

    public User? Current { get; private set; }

    public AuthService(string fileName)
    {
        path = Path.Combine(Directory.GetCurrentDirectory(), "data", fileName);
        Load();
    }

    public void Register(string login, string password, UserRole role)
    {
        if (password.Length < 6)
            throw new AuthException("Пароль має містити щонайменше 6 символів.");
        if (FindUser(login) is not null)
            throw new AuthException($"Користувач «{login}» уже існує.");
        users.Add(new User(login, PasswordHasher.Hash(password), role));
        Save();
    }

    // Повертає користувача або зриває власний виняток.
    public User SignIn(string login, string password)
    {
        var user = FindUser(login);
        if (user is null || !PasswordHasher.Verify(password, user.PasswordHash))
            throw new AuthException("Невірний логін або пароль.");
        Current = user;
        return user;
    }
}
```

Повідомлення «Невірний логін **або** пароль» однакове в обох випадках навмисно: інакше програма підказувала б стороннім, які логіни в системі існують.

**Обмеження кількості спроб** захищає від простого перебору паролів:

```csharp
public User? RunLoginDialog()
{
    for (int attempt = 1; attempt <= MaxAttempts; attempt++)
    {
        Console.Write("Логін: ");
        string login = Console.ReadLine() ?? "";
        string password = ReadPassword("Пароль: ");
        try { return SignIn(login, password); }
        catch (AuthException ex)
        { Console.WriteLine($"{ex.Message} Спроба {attempt} з {MaxAttempts}."); }
    }
    return null;          // вичерпано спроби
}
```

### 5. Введення пароля без відображення символів

`Console.ReadLine()` показує все, що набирає користувач. Пароль так вводити не можна. Метод `Console.ReadKey(true)` зчитує одну натиснуту клавішу й **не виводить** її на екран (`true` — саме це й означає).

```csharp
public static string ReadPassword(string prompt)
{
    Console.Write(prompt);
    var builder = new StringBuilder();

    while (true)
    {
        ConsoleKeyInfo key = Console.ReadKey(intercept: true);

        if (key.Key == ConsoleKey.Enter) { Console.WriteLine(); break; }

        if (key.Key == ConsoleKey.Backspace)
        {
            if (builder.Length > 0)
            {
                builder.Remove(builder.Length - 1, 1);
                Console.Write("\b \b");                 // стерти зірочку на екрані
            }
            continue;
        }
        if (char.IsControl(key.KeyChar)) continue;   // Tab, Esc тощо ігноруємо
        builder.Append(key.KeyChar);
        Console.Write('*');
    }
    return builder.ToString();
}
```

**Вивід:**

```
Пароль: ********
```

### 6. Розмежування доступу за ролями

Розмежування роблять **у двох місцях одночасно**, і це не надмірність. **Перше — меню будується під роль**: користувач не бачить пунктів, які йому недоступні, — це зручно й не дратує. **Друге — перевірка безпосередньо перед виконанням дії**: меню є лише способом відображення й захистом бути не може. Якщо колись з'явиться інший спосіб викликати метод (гарячі клавіші, аргументи командного рядка, друга частина програми), перевірка в меню нічого не дасть.

```csharp
// Перевірка права: роль користувача має бути не нижчою за потрібну.
private static void Require(UserRole minimal)
{
    var user = auth.Current;
    if (user is null || user.Role < minimal)
        throw new AccessDeniedException(
            $"Дія потребує ролі «{minimal}», а ваша роль — «{user?.Role}».");
}

private static void RemoveOrder()
{
    Require(UserRole.Administrator);      // перша дія методу — перевірка права
    // ... решта коду видалення
}
```

Порівняння `user.Role < minimal` працює, бо `enum` — це числа, а ми впорядкували ролі за зростанням прав. Якби ролі не були впорядковані (наприклад, «бухгалтер» і «комірник» — різні, але не старші один за одного), довелося б перевіряти належність до переліку дозволених ролей.

### 7. Власний клас винятку й структурована обробка

**Виняток** — об'єкт, що описує позаштатну ситуацію. Власний клас винятку потрібен тоді, коли ви хочете **відрізнити свою** помилку від чужих і обробити її окремо. Оголошується він просто: успадкування від `Exception` і конструктори.

```csharp
public class AuthException : Exception
{
    public AuthException(string message) : base(message) { }
}

public class AccessDeniedException : Exception
{
    public UserRole Required { get; }            // яка роль була потрібна
    public AccessDeniedException(string message, UserRole required = UserRole.Guest)
        : base(message) => Required = required;
}
```

Кидають виняток оператором `throw`, перехоплюють блоками `catch` — від **найконкретнішого** до найзагальнішого, бо перший відповідний блок і спрацює.

```csharp
try { action(); }                                      // виклик пункту меню
catch (AccessDeniedException ex)                       // наш виняток: доступ
    { Console.WriteLine($"Відмовлено: {ex.Message}"); }
catch (AuthException ex)                               // наш виняток: автентифікація
    { Console.WriteLine($"Помилка входу: {ex.Message}"); }
catch (IOException ex)                                 // чужий, але очікуваний
    { Console.WriteLine($"Помилка роботи з файлом: {ex.Message}"); }
catch (Exception ex)                                   // усе інше: програма не має впасти
    { Console.WriteLine($"Несподівана помилка: {ex.Message}"); }
finally
    { Console.WriteLine("— дію завершено —"); }        // виконається в будь-якому разі
```

Один такий блок **навколо виклику пункту меню** робить весь застосунок стійким: що б не сталося всередині дії, програма повернеться в меню, а не завершиться.

### 8. Журнал дій користувачів

Журнал змін із ЛР16 фіксував, **що** сталося; тепер він фіксує ще й **хто** це зробив. Формат рядка — дата й час, логін, роль, дія, опис.

```
2025-09-16 15:04:12  operator1  Operator       Вхід       успішно
2025-09-16 15:05:38  operator1  Operator       Додано     №7 Платний Гнатюк Олег ASUS
2025-09-16 15:06:02  operator1  Operator       Відмовлено Видалення потребує ролі Administrator
```

Журнал ведеться **лише на дописування** (`File.AppendAllText` або `StreamWriter` з `append: true`): журнал, який можна перезаписати, не має сенсу.

### 9. Підсумковий звіт

Звіт — це не «вивести список». Це агрегація: групування за ознакою, підсумки, частки, середні значення, виявлення проблемних записів. Що саме — вказано в переліку тем навпроти вашого номера (стовпець «Підсумковий звіт»).

Технічно звіт будують без LINQ: `Dictionary<ключ, накопичувач>` і один прохід циклом.

```csharp
var totals = new Dictionary<string, decimal>();
foreach (var order in repo.GetAll())
{
    if (!totals.ContainsKey(order.Kind)) totals[order.Kind] = 0;   // перша поява ключа
    totals[order.Kind] += order.GetTotal();
}
```

Звіт має виводитися на екран **і** зберігатися у текстовий файл `data/report.txt` з вирівняними колонками.

## Приклад виконання

**Умова.** Довести демонстраційний проєкт «Облік ноутбуків у сервісному центрі» до стану підсумкової роботи: авторизація, три ролі, журнал дій, звіт «сума до сплати за різновидами ремонту та кількість заявок, що в роботі понад 7 днів». **Аналіз.** Класи предметної області (`RepairOrder` і нащадки), сховище й подія не змінюються. Додаються чотири нові файли: `UserRole.cs` + `User.cs`, `PasswordHasher.cs`, `AuthService.cs`, `Exceptions.cs`; `Program` отримує вхід у систему, побудову меню під роль і звіт.

```
   ЗАПУСК ──▶ ┌────────────────┐  вичерпано 3 спроби  ┌───────────────────┐
              │ RunLoginDialog │─────────────────────▶│ вихід із програми │
              └───────┬────────┘                      └───────────────────┘
                      │ успіх
                      ▼
              ┌──────────────────────┐   Guest: 1,2,3,0
              │ BuildMenu(user.Role) │──▶Operator: + 4,5
              └───────┬──────────────┘   Administrator: + 6,7,8
                      ▼
              ┌──────────────────────┐
              │ цикл меню: try/catch │──▶ Require(роль) ──▶ AccessDeniedException ──▶ журнал
              └──────────────────────┘
```

**Файл `Exceptions.cs`** містить перелічення `UserRole` та обидва класи винятків — `AuthException` і `AccessDeniedException` — дослівно так, як їх наведено в пунктах 1 і 7 теоретичних відомостей.

**Файл `User.cs`** — клас `User` із пункту 2 теоретичних відомостей, доповнений перетворенням у рядок CSV і назад, та статичний клас хешування `PasswordHasher` із пункту 3.

```csharp
public class User
{
    // Login, PasswordHash, Role, конструктор, ChangePassword і ToString() —
    // без змін із пункту 2 теорії. Додано перетворення у рядок файлу й назад:

    public string ToCsv() => string.Join(';', Login, PasswordHash, Role);

    public static User FromCsv(string line)
    {
        string[] p = line.Split(';');
        if (p.Length < 3) throw new FormatException("пошкоджений рядок користувача");
        if (!Enum.TryParse(p[2], out UserRole role))
            throw new FormatException($"невідома роль «{p[2]}»");
        return new User(p[0], p[1], role);
    }
}
```

**Файл `AuthService.cs`**

```csharp
using System.Text;

namespace ServiceCenter;

public class AuthService
{
    // Поля MaxAttempts, users, path, властивість Current, конструктор із
    // Directory.CreateDirectory і викликом Load(), а також методи Register,
    // SignIn, RunLoginDialog і статичний ReadPassword — з пунктів 4 і 5 теорії.

    // GetAll() повертає копію списку користувачів; приватний Find(login)
    // у циклі шукає користувача за логіном, зведеним до нижнього регістру.

    private void Load()
    {
        users.Clear();
        if (!File.Exists(path))
        {
            // Перший запуск: створюємо адміністратора за замовчуванням.
            users.Add(new User("admin", PasswordHasher.Hash("admin123"), UserRole.Administrator));
            Save();
            Console.WriteLine("Створено користувача admin з паролем admin123. Змініть його!");
            return;
        }
        try
        {
            foreach (string line in File.ReadAllLines(path, Encoding.UTF8))
            {
                if (string.IsNullOrWhiteSpace(line)) continue;
                try { users.Add(User.FromCsv(line)); }
                catch (FormatException ex) { Console.WriteLine($"Рядок пропущено: {ex.Message}"); }
            }
        }
        catch (IOException ex)
        { Console.WriteLine($"Не вдалося прочитати файл користувачів: {ex.Message}"); }
```

```csharp
using System.Text;

namespace ServiceCenter;

internal static class Program
{
    private static readonly CsvRepository repo = new CsvRepository("orders.csv");
    private static readonly AuthService auth = new AuthService("users.csv");
    private static readonly Journal journal = new Journal("actions.log");
    private static readonly Dictionary<string, Action> menu = new();
    private static readonly List<string> menuLines = new();
    private static bool running = true;

    private static void Main()
    {
        Console.OutputEncoding = Encoding.UTF8;
        Console.WriteLine("=== Сервісний центр: вхід у систему ===");

        User? user = auth.RunLoginDialog();
        if (user is null)
        {
            Console.WriteLine("Вичерпано кількість спроб. Програму завершено.");
            journal.Write("—", "Вхід", "невдало, вичерпано спроби");
            return;
        }
        journal.Write(user.Login, "Вхід", $"успішно, роль {user.Role}");
        repo.OrderChanged += (sender, e) => journal.Write(user.Login, e.Action, e.Description);
        repo.Load();
        BuildMenu(user.Role);

        while (running)
        {
            Console.WriteLine($"\n=== Заявки ===  користувач: {user}");
            foreach (string line in menuLines) Console.WriteLine(line);
            Console.Write("Ваш вибір: ");
            if (!menu.TryGetValue(Console.ReadLine() ?? "", out Action? action))
            {
                Console.WriteLine("Немає такого пункту меню.");
                continue;
            }

            try { action(); }                       // один try навколо будь-якої дії меню
            catch (AccessDeniedException ex)
            {
                Console.WriteLine($"Відмовлено: {ex.Message}");
                journal.Write(user.Login, "Відмовлено", ex.Message);
            }
            catch (IOException ex)
            { Console.WriteLine($"Помилка роботи з файлом: {ex.Message}"); }
            catch (Exception ex)
            { Console.WriteLine($"Несподівана помилка: {ex.Message}"); }
        }
    }

    // Меню будується під роль: недоступних пунктів користувач не бачить.
    private static void BuildMenu(UserRole role)
    {
        Add("1", "показати всі", () => Show(repo.GetAll()));
        Add("2", "пошук за власником", FindByOwner);
        Add("3", "підсумковий звіт", Report);
        if (role >= UserRole.Operator)
        {
            Add("4", "додати заявку", AddOrder);
            Add("5", "позначити виконаною", CloseOrder);
        }
        if (role >= UserRole.Administrator)
        {
            Add("6", "видалити заявку", RemoveOrder);
            Add("7", "список користувачів", ShowUsers);
            Add("8", "додати користувача", AddUser);
        }
        Add("0", "зберегти й вийти", () => { repo.Save(); running = false; });
    }

    // Пункт меню = дія у словнику + рядок для виводу.
    private static void Add(string key, string title, Action action)
    {
        menu[key] = action;
        menuLines.Add($"{key} — {title}");
    }

    // Друга лінія захисту: перевірка права безпосередньо перед дією.
    private static void Require(UserRole minimal)
    {
        var user = auth.Current;
        if (user is null || user.Role < minimal)
            throw new AccessDeniedException(
                $"дія потребує ролі «{minimal}», а ваша — «{user?.Role}»", minimal);
    }

    private static void RemoveOrder()
    {
        Require(UserRole.Administrator);          // перший рядок кожної дії, що змінює дані
        Console.Write("Номер заявки: ");
        if (int.TryParse(Console.ReadLine(), out int id))
            Console.WriteLine(repo.Remove(id) ? "Заявку видалено." : "Заявку не знайдено.");
    }

    // AddUser так само починається з Require(UserRole.Administrator), читає логін,
    // пароль через AuthService.ReadPassword, роль через Enum.TryParse і викликає
    // auth.Register(...). ShowUsers друкує логін і роль кожного з auth.GetAll().

    // Підсумковий звіт: сума за різновидами і довгі незавершені заявки.
    private static void Report()
    {
        var all = repo.GetAll();
        var totals = new Dictionary<string, decimal>();      // сума за різновидом
        var counts = new Dictionary<string, int>();          // кількість за різновидом
        int overdue = 0;
        decimal grand = 0;
        foreach (var order in all)
        {
            if (!totals.ContainsKey(order.Kind)) { totals[order.Kind] = 0; counts[order.Kind] = 0; }
            totals[order.Kind] += order.GetTotal();
            counts[order.Kind]++;
            grand += order.GetTotal();
            if (!order.IsDone && order.DaysInService > 7) overdue++;
        }

        var text = new StringBuilder();
        text.AppendLine($"ЗВІТ СЕРВІСНОГО ЦЕНТРУ на {DateTime.Now:dd.MM.yyyy HH:mm}");
        text.AppendLine(new string('-', 46));
        text.AppendLine($"{"Різновид",-16}{"Заявок",8}{"Сума, грн",14}{"Частка",8}");
        foreach (var pair in totals)
        {
            decimal share = grand == 0 ? 0 : pair.Value / grand * 100;
            text.AppendLine($"{pair.Key,-16}{counts[pair.Key],8}{pair.Value,14:F2}{share,7:F1}%");
        }
        text.AppendLine(new string('-', 46));
        text.AppendLine($"{"Разом",-16}{all.Count,8}{grand,14:F2}");
        text.AppendLine($"У роботі понад 7 днів: {overdue}");
        Console.Write(text.ToString());
        File.WriteAllText(Path.Combine("data", "report.txt"), text.ToString(), Encoding.UTF8);
        Console.WriteLine("Звіт збережено у data/report.txt");
        journal.Write(auth.Current!.Login, "Звіт", $"сформовано, записів {all.Count}");
    }

    // Методи Show, FindByOwner, AddOrder, CloseOrder — з ЛР15 і ЛР16;
    // у AddOrder і CloseOrder першим рядком додано Require(UserRole.Operator).
}
```

## Вимоги до підсумкового застосунку

Застосунок, який ви захищаєте, має задовольняти **всі** наведені вимоги.

1. Предметна область — ваша тема за номером у списку групи (або погоджена з викладачем).
2. Головна сутність описана класом із **не менш ніж сімома** властивостями, серед яких є рядок, число, дата, логічне значення або `enum` і **обчислювана** властивість. Значення перевіряються в сеттерах.
3. Ієрархія **щонайменше з трьох класів**: абстрактний базовий і два-три нащадки; абстрактний метод перевизначено в кожному нащадкові.
4. Реалізовано **щонайменше один інтерфейс**, окрім стандартних, — власний `IRepository<T>`; крім того, реалізовано `IComparable<T>`.
5. Дані зберігаються у файлі та завантажуються під час запуску. Формат — CSV, кодування UTF-8, числа й дати в інваріантній культурі.
6. Реалізовано повний набір дій: додати, переглянути всі, знайти за умовою, змінити, видалити, сформувати звіт.
7. Пошук виконує **один** метод із параметром `Predicate<T>`; сортування — через `Comparison<T>` або `IComparer<T>`, не менше ніж у двох варіантах.
8. Є подія, на яку підписано ведення журналу.
9. Вхід у програму — за логіном і паролем; пароль зберігається у вигляді хешу й вводиться без відображення символів; кількість спроб обмежена.
10. Ролей **не менше трьох**: адміністратор (усі дії та керування користувачами), оператор (додавання й редагування записів), гість (лише перегляд і пошук). Меню будується під роль, і право перевіряється перед виконанням дії.
11. Спроба виконати недоступну дію коректно відхиляється власним винятком; літера замість числа, порожній рядок, неіснуючий номер запису та відсутній файл не «валять» застосунок.
12. Ведеться журнал дій користувачів із логіном, часом, дією та описом.
13. Формується підсумковий звіт за темою з агрегацією (суми, кількості, частки, середні, проблемні записи), виводиться на екран і зберігається у файл.
14. У програмі **немає LINQ** (`System.Linq`), немає WPF і баз даних.
15. Код розділено на файли (один клас — один файл), імена змістовні, коментарі українською; дані для демонстрації правдоподібні: щонайменше **десять** записів усіх різновидів і **три** користувачі з різними ролями.
16. Проєкт лежить у репозиторії Git з історією **не менш ніж із шести комітів** — по одному на кожну лабораторну, починаючи з дванадцятої. Папки `bin` і `obj` до репозиторію не потрапляють.

## Порядок захисту

Захист відбувається індивідуально, триває 7–10 хвилин і складається з трьох частин.

**Частина перша — демонстрація (3–4 хвилини).** Студент послідовно показує: запуск із порожньою папкою `data` (створення адміністратора); невдалий вхід і вичерпання спроб; вхід гостем — пунктів зміни даних у меню немає; вхід оператором — додавання запису, пошук за двома різними умовами, сортування; спробу виконати дію адміністратора під роллю оператора й повідомлення про відмову; вхід адміністратором — видалення запису, створення користувача; формування звіту й файл `report.txt`; вміст журналу дій; перезапуск програми — дані на місці; вивід `git log --oneline`.

**Частина друга — код (3–4 хвилини).** Викладач відкриває довільний файл проєкту й просить пояснити. Типові питання:

- покажіть абстрактний клас і поясніть, чому він абстрактний саме тут;
- де у вашому проєкті поліморфізм і що станеться, якщо прибрати `override`;
- навіщо потрібен інтерфейс `IRepository`, якщо реалізація одна;
- що передається в метод пошуку й у якому місці ця умова виконується;
- хто збуджує подію, хто на неї підписаний і в якому рядку відбувається підписка;
- у якому порядку розташовані блоки `catch` і чому саме в такому;
- що зберігається у файлі користувачів і чому саме це; що станеться, якщо видалити файл даних або зіпсувати в ньому один рядок;
- покажіть місце, де перевіряється право на дію, і поясніть, чому недостатньо просто не показувати пункт меню, і знайдіть у власному коді місце, яке ви написали б інакше, якби починали спочатку.

**Частина третя — модифікація (1–2 хвилини).** Викладач просить внести невелику зміну просто під час захисту: додати пункт меню, змінити умову пошуку, додати поле у звіт, поміняти порядок сортування. Зміна має скомпілюватися й запрацювати.

Робота **не приймається**, якщо проєкт не збирається, якщо студент не може пояснити код, який здає, або якщо в репозиторії немає власної історії комітів.

## Чек-лист самоперевірки перед захистом

Пройдіть його самостійно напередодні. Кожен пункт — «так» або «ні»; якщо хоч один «ні», на захист іти рано.

**Збірка й запуск**

- [ ] `dotnet build` завершується без помилок і без попереджень.
- [ ] Програма запускається у порожній папці `data`, не падає, і папки `bin` та `obj` не потрапили до репозиторію (перевірено `git status`).

**Функціональність**

- [ ] Працюють усі пункти меню, зокрема під кожною з трьох ролей.
- [ ] Дані зберігаються й підвантажуються; після перезапуску нічого не втрачено. Звіт формується, виводиться на екран і зберігається у файл.
- [ ] Журнал дій накопичується, а не перезаписується.

**Стійкість**

- [ ] Літера замість числа не завершує програму.
- [ ] Порожнє введення в кожному полі опрацьовано.
- [ ] Видалений файл даних не завершує програму.
- [ ] Зіпсований рядок у файлі пропускається з повідомленням, решта читається; спроба недоступної дії дає повідомлення, а не аварійне завершення.

**Безпека доступу**

- [ ] У файлі користувачів немає жодного пароля відкритим текстом.
- [ ] Пароль під час введення не видно на екрані.
- [ ] Кількість спроб входу обмежена.
- [ ] Право на дію перевіряється в самій дії, а не лише в меню.

**Код і репозиторій**

- [ ] Один клас — один файл; немає закоментованого «сміття».
- [ ] Немає жодного `using System.Linq` і жодного виклику `Where`/`Select`/`OrderBy`.
- [ ] Коментарі українською пояснюють «навіщо», а не переказують код.
- [ ] `git log --oneline` показує не менш ніж шість комітів, останній — `Лабораторна 17: авторизація, ролі, підсумковий звіт`.
- [ ] Звіт містить усі розділи, лістинги читабельні, є вивід програми.
- [ ] Ви можете пояснити будь-який рядок власного коду.

## Контрольні питання

1. Що таке перелічення `enum` і чим воно краще за набір рядкових сталих або «магічних» чисел? Чому порядок значень у `UserRole` має значення?
2. Чим автентифікація відрізняється від авторизації? Наведіть із власного проєкту приклад коду для кожної.
3. Що таке хеш-функція і які дві її властивості роблять її придатною для зберігання паролів?
4. Чому програма зберігає хеш пароля, а не сам пароль? Що зможе зробити зловмисник, який отримав файл із хешами, і що — який отримав файл із паролями?
5. Що таке «сіль» і чому SHA-256 без солі вважають недостатнім захистом у справжніх системах? Які алгоритми застосовують замість нього?
6. Як зчитати пароль без відображення символів? Що означає параметр `true` у `Console.ReadKey(true)`?
7. Навіщо перевіряти право на дію, якщо недоступний пункт меню й так не показано? Наведіть сценарій, у якому перевірки лише в меню виявиться замало.
8. Навіщо оголошувати власний клас винятку, якщо є готовий `Exception`? У якому порядку мають стояти блоки `catch`, що станеться, якщо поставити `catch (Exception)` першим, і навіщо обгортати у `try/catch` саме виклик пункту меню?
9. Які принципи ООП ви застосували у своєму проєкті? Покажіть по одному прикладу інкапсуляції, наслідування, поліморфізму й абстракції у власному коді.

## Зміст звіту

1. Титульна сторінка: назва закладу, дисципліна, номер і тема роботи, група, прізвище та ім'я студента, номер і назва теми проєкту, прізвище викладача.
2. Мета роботи й короткий опис предметної області застосунку.
3. Опис структури проєкту: перелік файлів і призначення кожного класу (таблиця).
4. Схема ієрархії класів і схема взаємодії «користувач — меню — сховище — файл» (ASCII-схеми або креслення).
5. Таблиця розподілу прав: дія — гість — оператор — адміністратор.
6. Пояснення механізму зберігання паролів: що саме потрапляє у файл, як перевіряється вхід, чому цього мало для справжньої системи.
7. Лістинги: `UserRole` і класи винятків, `User` із хешуванням, `AuthService`, побудова меню під роль, метод `Require`, метод формування звіту.
8. Вивід програми: невдалий вхід, меню під кожною з трьох ролей, відмова в доступі, підсумковий звіт.
9. Уміст файлів `users.csv` (із хешами), `actions.log` і `report.txt`.
10. Таблиця тестування не менш ніж із десяти рядків: дія — очікуваний результат — фактичний результат.
11. Відповіді на 3 контрольні питання, номери яких вказує викладач, і висновок на 5–7 речень про те, що зроблено за шість кроків проєкту й що ви зробили б інакше.
12. Посилання на репозиторій Git і вивід `git log --oneline` із щонайменше шістьма комітами.

## Критерії оцінювання

Підсумкова робота оцінюється у **20 балів** за наведеною розбивкою. Бали за складову виставляються повністю або частково.

| № | Складова | Макс. | Що саме оцінюється |
|---|---|---|---|
| 1 | Функціональність | 4 | Працюють усі шість дій (додати, переглянути, знайти, змінити, видалити, звіт). Дані зберігаються у файл і підвантажуються. Звіт відповідає темі, містить агрегацію й зберігається у файл. |
| 2 | Об'єктна модель | 3 | Абстрактний базовий клас і два-три нащадки, абстрактний метод перевизначено; властивості з валідацією й обчислювана властивість; реалізовано `IComparable<T>` і власний `IRepository<T>`. |
| 3 | Делегати й події | 2 | Один метод пошуку з `Predicate<T>`, сортування через `Comparison<T>`; подія з передплатником, який веде журнал. |
