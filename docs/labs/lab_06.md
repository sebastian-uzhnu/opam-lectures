# Лабораторна робота №6

## Тема
Програмування циклічних алгоритмів. Оператори for, while, do while

## Мета
Навчитися розпізнавати циклічні алгоритми та програмувати їх трьома видами циклів.
Закріпити прийоми роботи з лічильником і накопичувачем — обчислення суми, добутку,
кількості, найбільшого та найменшого значень. Набути навичок керування ходом циклу
операторами `break` і `continue`, побудови вкладених циклів і обробки введення
до стоп-слова. Навчитися виявляти нескінченні цикли та зсув на одиницю.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Персональний комп'ютер, .NET 8 SDK, будь-яке середовище розробки або текстовий редактор
і термінал, Git.

## Теоретичні відомості

### 1. Навіщо потрібні цикли

Уявіть, що треба вивести таблицю множення на 7 від 1 до 20. Засобами ЛР1–ЛР5 це двадцять
майже однакових рядків `Console.WriteLine`. А якщо меж не 20, а стільки, скільки введе
користувач, — лінійна програма взагалі безсила.

**Цикл** — конструкція алгоритму, яка задає багаторазове виконання однієї групи операторів.
Тіло циклу пишуть **один раз**, а виконується воно стільки разів, скільки потрібно.

Будь-який цикл складається з чотирьох частин, і пропуск будь-якої з них — помилка:

```text
   ┌── 1. ПІДГОТОВКА: початкові значення лічильника й накопичувачів
   │
   ▼
   ╱ 2. УМОВА ╲── хибна ──▶ вихід із циклу
   │ істинна
   ▼
  ┌──────────────────────────────────┐
  │ 3. ТІЛО: корисна робота          │
  │ 4. ЗМІНА: крок до завершення     │
  └──────────────────────────────────┘
   │
   └──────────▶ назад до умови
```

**Ітерація** — одне повне виконання тіла циклу.

### 2. Три види циклів

| Цикл | Коли перевіряється умова | Скільки разів виконається тіло | Коли доречний |
|---|---|---|---|
| `for` | до тіла | нуль або більше | кількість повторень відома наперед |
| `while` | до тіла | нуль або більше | кількість повторень невідома, залежить від умови |
| `do while` | після тіла | один або більше | тіло треба виконати хоча б раз (наприклад, запит даних) |

```text
        for / while                          do while

      │                                    │
      ▼                                    ▼
  ╱ умова ╲── хибна ──▶ вихід         ┌─────────┐
      │ істинна                       │  тіло   │◀──┐
      ▼                               └─────────┘   │
  ┌─────────┐                              │        │
  │  тіло   │────────┐                 ╱ умова ╲────┘ істинна
  └─────────┘        │                     │ хибна
      ▲              │                     ▼
      └──────────────┘                   вихід
```

### 3. Цикл `for`

```csharp
for (ініціалізація; умова; крок)
{
    // тіло
}
```

Приклад: касир формує чек на 5 однакових товарів і нумерує позиції.

```csharp
double itemPrice = 24.50;
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine($"Позиція {i}: сік яблучний — {itemPrice:F2} грн");
}
```

**Вивід:**

```
Позиція 1: сік яблучний — 24,50 грн
Позиція 2: сік яблучний — 24,50 грн
Позиція 3: сік яблучний — 24,50 грн
Позиція 4: сік яблучний — 24,50 грн
Позиція 5: сік яблучний — 24,50 грн
```

Порядок виконання: ініціалізація (один раз) → перевірка умови → тіло → крок → перевірка
умови → тіло → крок → … доки умова не стане хибною.

**Змінна циклу** `i` існує лише всередині циклу: після закритої дужки звертатися до неї
не можна. Якщо значення потрібне після циклу, оголошуйте змінну до нього.

Крок не обов'язково дорівнює одиниці:

```csharp
for (int i = 10; i >= 1; i--)         // зворотний відлік 10, 9, …, 1
for (int i = 0; i <= 100; i += 25)    // 0, 25, 50, 75, 100
for (double x = 0; x <= 1.0; x += 0.5)  // 0; 0,5; 1 — обережно з дробовим кроком
```

Для дробового кроку через похибки `double` краще рахувати цілим лічильником, а значення
обчислювати множенням: `double x = start + i * step;`.

### 4. Цикл `while`

Умову перевіряють **перед** кожною ітерацією, тож тіло може не виконатися жодного разу.

```csharp
// Скільки разів треба скласти аркуш паперу навпіл, щоб товщина перевищила 1 мм?
double thickness = 0.1;               // початкова товщина, мм
int foldCount = 0;

while (thickness <= 1.0)
{
    thickness *= 2;
    foldCount++;
}

Console.WriteLine($"Потрібно згинань: {foldCount}, товщина: {thickness:F2} мм");
```

**Вивід:**

```
Потрібно згинань: 4, товщина: 1,60 мм
```

### 5. Цикл `do while`

Тіло виконується, а вже потім перевіряється умова, тому воно спрацьовує щонайменше
один раз. Крапка з комою після `while (умова)` обов'язкова.

```csharp
int number;
do
{
    Console.Write("Введіть додатне число: ");
    number = int.Parse(Console.ReadLine());
}
while (number <= 0);

Console.WriteLine($"Прийнято: {number}");
```

**Вивід:**

```
Введіть додатне число: -5
Введіть додатне число: 0
Введіть додатне число: 12
Прийнято: 12
```

Це головне застосування `do while`: запит даних, який має відбутися хоча б раз і
повторюватися, доки дані некоректні.

### 6. Лічильник і накопичувач

Це два прийоми, на яких тримається більшість задач із циклами.

**Лічильник** — змінна, яка збільшується на одиницю щоразу, коли трапляється потрібна
подія. Початкове значення — нуль.

**Накопичувач** — змінна, у якій поступово збирається результат. Початкове значення
залежить від дії: для суми — `0`, для добутку — `1` (нуль усе занулив би).

| Задача | Початкове значення | Дія в тілі циклу |
|---|---|---|
| Сума | `int sum = 0;` | `sum += value;` |
| Добуток | `long product = 1;` | `product *= value;` |
| Кількість | `int count = 0;` | `count++;` |
| Найбільше | `int max = int.MinValue;` | `if (value > max) max = value;` |
| Найменше | `int min = int.MaxValue;` | `if (value < min) min = value;` |
| Середнє | `sum` і `count` | після циклу `(double)sum / count` |

Приклад: облік температури за тиждень (значення задано в коді, бо масивів ще немає —
дані надходять по одному).

```csharp
int sum = 0;
int max = int.MinValue;
int min = int.MaxValue;
int warmDays = 0;

for (int day = 1; day <= 7; day++)
{
    Console.Write($"Температура за день {day}: ");
    int t = int.Parse(Console.ReadLine());

    sum += t;                              // накопичувач суми
    if (t > max) { max = t; }              // максимум «на льоту»
    if (t < min) { min = t; }              // мінімум «на льоту»
    if (t >= 20) { warmDays++; }           // лічильник теплих днів
}

Console.WriteLine($"Середня температура: {(double)sum / 7:F1} °C");
Console.WriteLine($"Найтепліше: {max} °C, найхолодніше: {min} °C");
Console.WriteLine($"Теплих днів (від 20 °C): {warmDays}");
```

**Вивід:**

```
Температура за день 1: 18
Температура за день 2: 21
Температура за день 3: 25
Температура за день 4: 24
Температура за день 5: 16
Температура за день 6: 19
Температура за день 7: 22
Середня температура: 20,7 °C
Найтепліше: 25 °C, найхолодніше: 16 °C
Теплих днів (від 20 °C): 3
```

Пошук максимуму «на льоту» — важливий прийом: значення порівнюють одразу під час
надходження, зберігати всю послідовність не потрібно. Початкове значення `int.MinValue`
гарантує, що перше ж число стане максимумом. Якщо всі числа напевно додатні, можна
починати з нуля, але звичка брати `int.MinValue` надійніша.

### 7. Оператори `break` і `continue`

| Оператор | Дія | Типове застосування |
|---|---|---|
| `break` | негайно завершує **весь** цикл | знайшли потрібне — далі шукати немає сенсу |
| `continue` | завершує поточну ітерацію й переходить до наступної | цей елемент пропускаємо, решту обробляємо |

```csharp
// Перший дільник числа, більший за одиницю
int number = 91;
int firstDivisor = 0;

for (int d = 2; d <= number; d++)
{
    if (number % d == 0)
    {
        firstDivisor = d;
        break;                      // далі перевіряти немає сенсу
    }
}

Console.WriteLine($"Найменший дільник числа {number}: {firstDivisor}");

// Сума лише непарних чисел від 1 до 10
int oddSum = 0;
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0) { continue; }   // парні пропускаємо
    oddSum += i;
}
Console.WriteLine($"Сума непарних чисел від 1 до 10: {oddSum}");
```

**Вивід:**

```
Найменший дільник числа 91: 7
Сума непарних чисел від 1 до 10: 25
```

Увага: у циклі `while` оператор `continue` перестрибує решту тіла, зокрема й рядок зі
зміною лічильника. Якщо крок записано в кінці тіла, `continue` створить нескінченний
цикл. У `for` крок виконується завжди, тому там `continue` безпечний.

### 8. Вкладені цикли

Цикл може містити інший цикл. **Зовнішній** цикл задає рядки, **внутрішній** — те, що
міститься в кожному рядку. Внутрішній цикл повністю відпрацьовує на кожній ітерації
зовнішнього: якщо зовнішній робить 3 ітерації, а внутрішній 4, тіло спрацює 12 разів.

```csharp
// Таблиця множення від 2 до 4
for (int i = 2; i <= 4; i++)
{
    for (int j = 1; j <= 5; j++)
    {
        Console.Write($"{i} x {j} = {i * j,-3}  ");
    }
    Console.WriteLine();            // перехід на новий рядок після кожного i
}
```

**Вивід:**

```
2 x 1 = 2    2 x 2 = 4    2 x 3 = 6    2 x 4 = 8    2 x 5 = 10 
3 x 1 = 3    3 x 2 = 6    3 x 3 = 9    3 x 4 = 12   3 x 5 = 15 
4 x 1 = 4    4 x 2 = 8    4 x 3 = 12   4 x 4 = 16   4 x 5 = 20 
```

Вкладеними циклами малюють фігури із символів. Ключ до таких задач — зрозуміти,
як кількість символів у рядку залежить від номера рядка.

```csharp
int height = 5;
for (int row = 1; row <= height; row++)
{
    for (int space = 1; space <= height - row; space++) { Console.Write(" "); }
    for (int star = 1; star <= 2 * row - 1; star++) { Console.Write("*"); }
    Console.WriteLine();
}
```

**Вивід:**

```
    *
   ***
  *****
 *******
*********
```

У рядку з номером `row` пробілів `height - row`, а зірочок `2 * row - 1`. Саме ці
формули й треба виводити на папері перед написанням коду.

`break` у внутрішньому циклі перериває **лише його**, а зовнішній продовжує роботу.

### 9. Нескінченний цикл

**Нескінченний цикл** — цикл, умова якого ніколи не стає хибною. Програма «зависає»,
її доводиться переривати вручну (у терміналі — Ctrl+C).

Три найчастіші причини:

```csharp
int i = 1;
while (i <= 10)
{
    Console.WriteLine(i);       // 1) забули i++
}

while (i != 10) { i += 3; }     // 2) лічильник «перестрибує» значення умови

for (int k = 10; k >= 1; k++)   // 3) крок у протилежний бік від межі
{
    Console.WriteLine(k);
}
```

Правило: після написання циклу вголос перевірте, **яка саме дія наближає умову
до хибності** і чи виконується вона на кожній ітерації. Для умов із лічильником
надійніше писати `<` або `<=`, а не `!=`.

Свідомий нескінченний цикл `while (true)` теж застосовують — але лише разом із `break`
усередині, який гарантовано спрацьовує.

### 10. Цикл із введенням до стоп-слова

Коли наперед невідомо, скільки значень введе користувач, домовляються про **стоп-слово**
або **стоп-значення** — ознаку завершення введення.

```csharp
Console.WriteLine("Уводьте суми чеків. Для завершення введіть 0.");
double total = 0;
int checkCount = 0;

while (true)
{
    Console.Write("Сума чека: ");
    double amount = double.Parse(Console.ReadLine());

    if (amount == 0) { break; }            // стоп-значення

    total += amount;
    checkCount++;
}

Console.WriteLine($"Чеків: {checkCount}, разом: {total:F2} грн");
```

**Вивід:**

```
Уводьте суми чеків. Для завершення введіть 0.
Сума чека: 240,50
Сума чека: 99
Сума чека: 1200
Сума чека: 0
Чеків: 3, разом: 1539,50 грн
```

Стоп-значення має бути таким, яке не може бути справжніми даними: нуль для сум, від'ємне
число для віку, слово «кінець» для тексту.

### 11. Типові помилки

| Помилка | Приклад | Наслідок і виправлення |
|---|---|---|
| Крапка з комою після заголовка | `for (int i = 0; i < 5; i++);` | тіло циклу порожнє, наступний блок виконується один раз. Прибрати `;` |
| Зсув на одиницю | `for (int i = 1; i < 10; i++)` замість `i <= 10` | оброблено на один елемент менше. Перевіряти межі на папері |
| Змінна циклу змінюється в тілі | `for (...) { i++; }` | частину значень пропущено, хід циклу непередбачуваний. Не чіпати `i` в тілі |
| Забута зміна лічильника у `while` | тіло без `i++` | нескінченний цикл. Додати крок |
| Накопичувач усередині циклу | `for (...) { int sum = 0; sum += x; }` | сума щоразу обнулюється. Оголошувати до циклу |
| Добуток починається з нуля | `int p = 0; p *= x;` | результат завжди нуль. Починати з `1` |
| Ділення цілих для середнього | `sum / count` для `int` | дробова частина втрачається. Писати `(double)sum / count` |
| `continue` перед `i++` у `while` | крок у кінці тіла | нескінченний цикл. Змінювати лічильник до `continue` або брати `for` |

Порівняйте два цикли та їх результати:

```csharp
int sumWrong = 0;
for (int i = 1; i < 5; i++) { sumWrong += i; }      // 1+2+3+4
int sumRight = 0;
for (int i = 1; i <= 5; i++) { sumRight += i; }     // 1+2+3+4+5
Console.WriteLine($"i < 5 дає {sumWrong}, i <= 5 дає {sumRight}");
```

**Вивід:**

```
i < 5 дає 10, i <= 5 дає 15
```

## Приклад виконання

**Умова.** Оператор виробничої дільниці вводить масу деталей, виготовлених за зміну
(у грамах, ціле число). Кількість деталей наперед невідома; ознака завершення введення —
число 0. Деталь вважають придатною, якщо її маса в межах від 480 до 520 г включно.
Обчислити: кількість деталей, кількість придатних і бракованих, сумарну та середню масу,
найбільшу й найменшу масу, а також відсоток браку. Якщо не введено жодної деталі —
повідомити про це. Наприкінці вивести шкалу з символів, де кожна зірочка позначає одну
придатну деталь.

**Аналіз.**

1. Кількість повторень невідома → цикл `while (true)` зі стоп-значенням і `break`.
2. Потрібні накопичувачі: `totalMass` (сума), лічильники `partCount`, `goodCount`,
   `badCount`, а також `maxMass` і `minMass` — пошук «на льоту».
3. Ділення на кількість деталей робимо лише тоді, коли деталі були: інакше ділення
   на нуль. Це розгалуження після циклу.
4. Шкала з зірочок — окремий цикл `for` після основного.

**Схема:**

```text
  підготовка: total = 0, count = 0, good = 0, max = int.MinValue, min = int.MaxValue
          │
          ▼
  ┌──▶ введення маси ──▶ ╱ маса == 0? ╲── так ──▶ вихід із циклу
  │                            │ ні
  │       накопичення: total += m; count++; оновлення max, min
  │       ╱ 480 <= m <= 520? ╲── так ──▶ good++   ── ні ──▶ bad++
  └────────────────────────────┘
          │
          ▼
    ╱ count == 0? ╲── так ──▶ «деталей не введено»
          │ ні
          ▼
   обчислення середнього й відсотка браку ──▶ вивід ──▶ шкала (цикл for)
```

**Код:**

```csharp
// Облік деталей, виготовлених за зміну
Console.WriteLine("=== Контроль якості деталей ===");
Console.WriteLine("Уводьте масу деталі в грамах. Для завершення введіть 0.");

const int MinNorm = 480;        // нижня межа норми, г
const int MaxNorm = 520;        // верхня межа норми, г

int totalMass = 0;              // накопичувач сумарної маси
int partCount = 0;              // лічильник усіх деталей
int goodCount = 0;              // лічильник придатних
int badCount = 0;               // лічильник бракованих
int maxMass = int.MinValue;     // найбільша маса «на льоту»
int minMass = int.MaxValue;     // найменша маса «на льоту»

while (true)
{
    Console.Write($"Маса деталі {partCount + 1}: ");
    int mass = int.Parse(Console.ReadLine());

    if (mass == 0) { break; }             // стоп-значення: виходимо з циклу
    if (mass < 0)
    {
        Console.WriteLine("Маса не може бути від'ємною, значення пропущено.");
        continue;                          // ця ітерація далі не виконується
    }

    partCount++;
    totalMass += mass;
    if (mass > maxMass) { maxMass = mass; }
    if (mass < minMass) { minMass = mass; }

    if (mass >= MinNorm && mass <= MaxNorm) { goodCount++; }
    else { badCount++; }
}

Console.WriteLine();
if (partCount == 0)
{
    Console.WriteLine("Жодної деталі не введено, звіт порожній.");
}
else
{
    double averageMass = (double)totalMass / partCount;   // зведення типу обов'язкове
    double badPercent = (double)badCount / partCount * 100;

    Console.WriteLine($"Усього деталей: {partCount}");
    Console.WriteLine($"Придатних: {goodCount}, бракованих: {badCount}");
    Console.WriteLine($"Сумарна маса: {totalMass} г");
    Console.WriteLine($"Середня маса: {averageMass:F1} г");
    Console.WriteLine($"Найбільша: {maxMass} г, найменша: {minMass} г");
    Console.WriteLine($"Відсоток браку: {badPercent:F1} %");

    Console.Write("Придатні деталі: ");
    for (int i = 1; i <= goodCount; i++)
    {
        Console.Write("*");
    }
    Console.WriteLine();
}
```

**Аналіз результату.** У програмі задіяно всі прийоми теми: цикл із невідомою кількістю
ітерацій і стоп-значенням, `break` для виходу, `continue` для пропуску некоректних даних,
два лічильники, накопичувач суми, пошук максимуму й мінімуму «на льоту» та окремий цикл
`for` для побудови шкали. Перевірка `partCount == 0` перед діленням — не формальність:
без неї програма аварійно завершилася б, якби оператор одразу ввів 0.

## Контрольні питання

1. З яких чотирьох частин складається будь-який цикл? Що станеться, якщо пропустити
   частину, яка змінює лічильник?
2. Чим цикл `while` відрізняється від `do while`? Наведіть задачу, у якій правильним
   є лише `do while`.
3. У яких випадках доречніший цикл `for`, а в яких — `while`? Чому кількість ітерацій
   `for` вважають відомою наперед?
4. Що таке накопичувач? Чому для суми його початкове значення нуль, а для добутку —
   одиниця?
5. Поясніть прийом пошуку максимуму «на льоту». Чому початковим значенням беруть
   `int.MinValue`, а не нуль чи перше введене число?
6. Чим `break` відрізняється від `continue`? Що перерве `break`, розміщений у внутрішньому
   з двох вкладених циклів?
7. Скільки разів виконається тіло внутрішнього циклу, якщо зовнішній робить 6 ітерацій,
   а внутрішній — 4? Як це впливає на час виконання програми?
8. Що таке зсув на одиницю? Наведіть приклад циклу, у якому через нього обробляється
   на один елемент менше, ніж потрібно.
9. Назвіть три причини нескінченного циклу. Як перевірити ще на етапі написання коду,
   що цикл завершиться?
10. Що станеться, якщо в циклі `while` розмістити `continue` перед рядком зі збільшенням
    лічильника? Чому в циклі `for` така сама конструкція безпечна?
