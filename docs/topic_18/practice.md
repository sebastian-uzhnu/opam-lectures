# Самоперевірка та домашнє завдання

## Питання для самоперевірки

Питання згруповані за підрозділами теми. Відповідайте своїми словами — якщо
не виходить, поверніться до відповідного підрозділу.

### Поняття делегата та синтаксис

1. Що таке делегат? Поясніть на аналогії з вказівниками на функції в C++
   і скажіть, що саме робить делегат типобезпечним, а вказівник — ні.
2. Що саме описує оголошення `public delegate int MathOperation(int x, int y);`
   — конкретний метод чи форму методу? Назвіть два будь-які методи,
   які підійдуть під цей делегат.
3. Чи можна присвоїти делегату `MathOperation` метод
   `static double Divide(int a, int b)`? Чому ні, і що саме перевіряє
   компілятор у момент присвоєння?
4. Чим делегат відрізняється від звичайного виклику методу? Назвіть дві
   речі, які можна зробити з методом через делегат і не можна без нього.
5. **Що виведе цей код?** Випишіть усі рядки виводу по порядку.

   ```csharp
   MathAction action = Add;
   action += Multiply;
   action += Add;
   action(4, 2);

   Console.WriteLine("---");

   action -= Add;
   action(4, 2);
   ```

   (де `Add` друкує `Add: сума`, а `Multiply` — `Multiply: добуток`;
   зверніть особливу увагу на те, скільки разів `Add` у списку
   і який саме з них прибирає `-=`)

6. **Знайдіть помилку в цьому коді.** Компілятор не приймає другий рядок.
   У чому річ і як це виправити?

   ```csharp
   Notify notifyDelegate = ShowMessage("Привіт");
   notifyDelegate("Привіт, світ!");
   ```

### Вбудовані делегати .NET

7. У чому різниця між `Action` і `Func`? Як за оголошенням
   `Func<string, int, bool>` зрозуміти, скільки в методі параметрів,
   якого вони типу і що метод повертає?
8. Скільки аргументів максимально приймає `Action`? Як записати
   `Action` без жодного параметра?
9. Чим `Predicate<T>` відрізняється від `Func<T, bool>` за можливостями?
   Чому тоді в .NET є обидва? Де історично використовується `Predicate`?
10. **Знайдіть помилку в цьому коді.** Обидва рядки не компілюються.
    Виправте кожен, змінивши **лише тип делегата**, а не саму лямбду.

    ```csharp
    Action<int> square = x => x * x;
    Func<int> addThem = (x, y) => x + y;
    ```

11. **Що виведе цей код?**

    ```csharp
    Predicate<int> isPositive = x => x > 0;
    var numbers = new List<int> { -1, 2, -3, 4, 5 };
    var result = numbers.FindAll(isPositive);
    Console.WriteLine(string.Join(", ", result));
    Console.WriteLine(result.Count);
    ```

### Події

12. Хто такий видавець (publisher), а хто підписник (subscriber)?
    Наведіть приклад із лекції та один власний приклад із життя.
13. Що саме додає ключове слово `event` до звичайного поля-делегата?
    Назвіть два обмеження, і поясніть, від якої біди рятує заборона `=` ззовні.
14. **Знайдіть помилку в цьому коді.** Термостат оголошено правильно,
    але цей фрагмент у `Main` не компілюється. Чому? І навіть якби він
    компілювався — що б сталося з попереднім підписником?

    ```csharp
    thermostat.TemperatureChanged = display.OnTempChanged;
    thermostat.TemperatureChanged += logger.OnTempChanged;
    ```

15. Навіщо у методі `OnTemperatureChanged` стоїть `?.Invoke(this, e)`,
    а не просто `TemperatureChanged(this, e)`? Що станеться без знака
    питання, якщо на подію ніхто не підписався?
16. Чому `SetTemperature` спершу перевіряє `if (_currentTemperature != newTemp)`
    і лише потім генерує подію? Що зміниться, якщо цю перевірку прибрати?
17. Для чого стандартний шаблон радить окремий `protected virtual` метод
    `OnTemperatureChanged`, а не виклик події прямо з `SetTemperature`?

### Лямбда-вирази та анонімні методи

18. Як читається оператор `=>`? У яких випадках дужки навколо параметра
    можна опустити, а в яких — ні?
19. Коли лямбда-вираз потребує фігурних дужок і слова `return`, а коли
    обходиться без них? Перепишіть блочну лямбду `factorial` з лекції
    і поясніть, чому її не можна записати одним виразом.
20. **Що виведе цей код?** Поясніть, що саме порівнює лямбда всередині
    `Sort` і чому порядок вийшов саме таким.

    ```csharp
    List<string> names = new List<string> { "Ivan", "Anna", "Petro", "Bo" };
    names.Sort((s1, s2) => s1.Length.CompareTo(s2.Length));
    Console.WriteLine(string.Join(", ", names));
    ```

## Практичні міні-задачі

Короткі вправи на 5–10 хвилин кожна, для перевірки розуміння прямо
після лекції.

1. **Калькулятор на делегаті.** Оголосіть делегат
   `delegate double Operation(double a, double b);` і чотири методи:
   додавання, віднімання, множення, ділення. Користувач вводить два числа
   й символ операції; у `switch` ви присвоюєте делегату потрібний метод
   і викликаєте його **один раз** наприкінці — а не всередині кожної гілки.

2. **Мультикастовий логер.** Зробіть `Action<string> log`, до якого підписані
   три методи: один друкує повідомлення у верхньому регістрі, другий додає
   попереду час `DateTime.Now.ToShortTimeString()`, третій додає рядок
   із дефісів. Викличте делегат одним рядком і подивіться на вивід.
   Потім відпишіть один метод через `-=` і викличте ще раз.

3. **Три лямбди замість трьох методів.** Перепишіть на `Func` і `Action`
   з лямбдами: метод, що повертає квадрат числа; метод, що перевіряє,
   чи рядок довший за 5 символів; метод, що друкує число в рамці з зірочок.

4. **Фільтр без циклів.** Створіть `List<int>` із двадцяти випадкових чисел
   від 1 до 100. Виведіть окремо: усі парні, усі більші за 50, усі, що
   діляться на 3 і при цьому менші за 30 — щоразу через `FindAll`
   і лямбду. Жодного власного циклу `for` писати не можна.

5. **Сортування на замовлення.** Створіть масив рядків з іменами
   одногрупників і відсортуйте його трьома різними лямбдами: за абеткою,
   за довжиною, за останньою літерою. Кожне сортування — один рядок коду.

6. **Найпростіша подія.** Клас `Counter` із методом `Add()` і подією
   `ReachedTen`, яка спрацьовує рівно один раз — коли лічильник дійшов
   до десяти. Підпишіться на неї лямбдою прямо в `Main` і викличте
   `Add()` п'ятнадцять разів.

### Завдання: «Розумний павербанк»

Ви пишете «мозок» для павербанка. Він сам по собі нічого не вміє, крім
як витрачати заряд, — але має попереджати про це решту пристрою: екран
має потьмяніти, динамік пікнути, а журнал подій — усе записати.
Головна ідея: **павербанк нічого не знає про екран, динамік і журнал**.
Він лише піднімає подію, а хто на неї підписався — його не обходить.

Симулюйте день: у циклі павербанк живить різні пристрої та витрачає заряд,
доки не сяде.

**Вимоги:**

- клас `PowerBank` із властивістю `Level` (заряд у відсотках, від 0 до 100)
  і методом `void Consume(int amount)`, який зменшує заряд і не пускає його
  нижче нуля;
- клас `BatteryEventArgs : EventArgs` із властивостями `Level`
  та `DeviceName` (що саме живили в цей момент);
- дві події: `LowBattery` (заряд уперше опустився нижче 20 відсотків)
  і `Depleted` (заряд дійшов до нуля);
- обидві події оголошені через `event EventHandler<BatteryEventArgs>?`
  і піднімаються через окремі `protected virtual` методи з `?.Invoke`;
- `LowBattery` має спрацювати **рівно один раз** за розряд, а не на кожному
  кроці нижче 20 відсотків — заведіть для цього прапорець;
- щонайменше три підписники: клас `Screen` (метод «переходжу в економрежим»),
  клас `Speaker` (метод «пікаю»), і лямбда прямо в `Main`, яка пише рядок
  у журнал `List<string>`;
- масив пристроїв, які треба живити, і `Func<string, int>` `costOf`, яка
  за назвою пристрою повертає витрату заряду (телефон — 8, навушники — 3,
  ноутбук — 20, решта — 5);
- у циклі перебирайте пристрої по колу й викликайте `Consume`, доки
  заряд більший за нуль;
- наприкінці — вивести журнал подій і через `Predicate<string>`
  відфільтрувати з нього лише рядки з попередженнями.

**Приклад роботи:**

```
=== ПАВЕРБАНК 100% ===

Живлю: телефон (-8)       -> 92%
Живлю: навушники (-3)     -> 89%
Живлю: ноутбук (-20)      -> 69%
Живлю: телефон (-8)       -> 61%
Живлю: навушники (-3)     -> 58%
Живлю: ноутбук (-20)      -> 38%
Живлю: телефон (-8)       -> 30%
Живлю: навушники (-3)     -> 27%
Живлю: ноутбук (-20)      -> 7%
  [Екран]   Заряд 7%. Переходжу в економрежим, яскравість на мінімум.
  [Динамік] Біп-біп! Залишилось 7% (живили ноутбук).
Живлю: телефон (-8)       -> 0%
  [Динамік] Павербанк розряджено повністю.
  [Екран]   Вимикаюсь.

=== ЖУРНАЛ ПОДІЙ (2 записи) ===
12:41 LOW      7% під час живлення пристрою «ноутбук»
12:41 DEPLETED 0% під час живлення пристрою «телефон»

=== ЛИШЕ ПОПЕРЕДЖЕННЯ ===
12:41 LOW      7% під час живлення пристрою «ноутбук»
```

:::tip[Підказка]
Прапорець для одноразового спрацювання найпростіший:
`private bool _lowFired = false;`. Усередині `Consume` після зменшення
заряду перевіряйте `if (!_lowFired && Level < 20)`, піднімайте подію
і одразу ставте `_lowFired = true;`.

`Func` можна оголосити прямо в `Main` лямбдою з блоком і `switch`-виразом:

```csharp
Func<string, int> costOf = device => device switch
{
    "телефон" => 8,
    "навушники" => 3,
    "ноутбук" => 20,
    _ => 5
};
```

Підписка лямбдою на подію виглядає так:
`bank.LowBattery += (sender, e) => journal.Add($"LOW {e.Level}% ...");`
— сигнатура лямбди має точно збігатися з делегатом події,
тобто два параметри.

Фільтр журналу наприкінці — `journal.FindAll(line => line.Contains("LOW"))`,
але оголосіть його окремою змінною типу `Predicate<string>`, щоб побачити
тип явно.
:::

**Додатково (за бажанням, на вищу оцінку):** додайте подію `Charged`
і метод `Charge(int amount)`, який скидає прапорець `_lowFired` назад
у `false`, коли заряд піднявся вище 20 відсотків. Тоді зробіть повний
цикл «розрядився — підзарядили — знову розрядився» і переконайтеся,
що `LowBattery` спрацювала двічі. Заодно відпишіть динамік від події
під час зарядки (`-=`) і поясніть у коментарі, чому підписку варто
знімати, коли підписник більше не потрібен.
