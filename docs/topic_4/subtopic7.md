# Параметри функцій. Передача за значенням

Коли ви викликаєте функцію й передаєте їй змінну, виникає питання, на яке інтуїція
відповідає неправильно: функція отримує **саму змінну** чи **її копію**?

Від відповіді залежить, чи побачить викликач зміни, зроблені всередині функції.
І оскільки в C# відповідь різна для різних типів, саме тут виникає один із
найпоширеніших «незрозумілих» багів.

## Параметри й аргументи

Спочатку домовимося про терміни — їх постійно плутають:

```csharp
void Greet(string name)     // name — ПАРАМЕТР (в оголошенні)
{
    Console.WriteLine($"Привіт, {name}!");
}

Greet("Олена");             // "Олена" — АРГУМЕНТ (при виклику)
```

| Термін | Де живе | Що це |
|--------|---------|-------|
| **Параметр** | В оголошенні функції | Ім'я, під яким функція знає значення |
| **Аргумент** | У місці виклику | Конкретне значення, що передається |

Аргументи зіставляються з параметрами **за позицією**: перший аргумент —
першому параметру, і так далі.

```csharp
void ShowInfo(string name, int age)
{
    Console.WriteLine($"{name}, {age} років");
}

ShowInfo("Іван", 20);      // ✅ name = "Іван", age = 20
ShowInfo(20, "Іван");      // ❌ помилка компіляції: типи не збігаються
```

:::warning[Коли компілятор не врятує]
Якщо типи параметрів однакові, переплутати порядок дуже легко, і компілятор
промовчить:

```csharp
void Divide(int dividend, int divisor) { ... }

Divide(10, 2);   // 5   — правильно
Divide(2, 10);   // 0.2 — теж компілюється, але це вже не те, що ви хотіли
```

Саме від цього рятують **іменовані аргументи**, до яких ми дійдемо
в підрозділі про необов'язкові параметри.
:::

## Передача за значенням

За замовчуванням **усі** параметри в C# передаються **за значенням**: функція
отримує **копію** аргументу.

```csharp
void Increase(int number)
{
    number = number + 100;
    Console.WriteLine($"Усередині функції: {number}");   // 105
}

int x = 5;
Increase(x);
Console.WriteLine($"Після виклику: {x}");                // 5 (!)
```

Змінна `x` не змінилася. Функція працювала з копією, а копія зникла разом
із завершенням функції.

Що відбувається в пам'яті:

```
   Викликач              Функція Increase
  ┌─────────┐           ┌──────────────┐
  │ x = 5   │──копія──► │ number = 5   │
  └─────────┘           │ number = 105 │  ← змінюється лише копія
       ↑                └──────────────┘
   залишається 5
```

:::note
Це те саме, що ви бачили в темі 3 при копіюванні значимих типів:
`int b = a;` створює незалежну копію. Передача аргументу — по суті таке саме
присвоєння, просто неявне.
:::

## Пастка: посилальні типи

А тепер найважливіше. Правило «передається копія» діє **завжди** — але для
посилального типу копіюється **посилання**, а не самі дані.

Обидва посилання вказують на **той самий об'єкт** у купі:

```csharp
void ModifyArray(int[] numbers)
{
    numbers[0] = 999;          // змінюємо об'єкт, на який вказує посилання
}

int[] data = { 1, 2, 3 };
ModifyArray(data);
Console.WriteLine(data[0]);    // 999 (!) — оригінал змінився
```

```
   Викликач                Функція
  ┌──────────┐            ┌──────────┐
  │ data ────┼──копія────►│ numbers  │
  └────┬─────┘  посилання └────┬─────┘
       │                       │
       └────────► [999,2,3] ◄──┘
                 один об'єкт у купі
```

:::warning[Різниця, яку треба засвоїти назавжди]
| Тип аргументу | Що копіюється | Чи побачить викликач зміни |
|---------------|---------------|----------------------------|
| Значимий (`int`, `double`, `bool`, `struct`) | Саме значення | **Ні** |
| Посилальний (масив, клас, `List`) | Посилання | **Так**, якщо змінювати вміст |

Це не два різні правила, а одне: **копіюється завжди те, що лежить у змінній**.
Просто в значимому типі лежать дані, а в посилальному — адреса.
:::

### Присвоєння нового об'єкта зміни не дає

Тонкість, на якій спотикаються навіть досвідчені:

```csharp
void Replace(int[] numbers)
{
    numbers = new int[] { 7, 8, 9 };   // міняємо саму КОПІЮ посилання
}

int[] data = { 1, 2, 3 };
Replace(data);
Console.WriteLine(data[0]);            // 1 — оригінал не змінився!
```

Функція перенаправила **свою копію** посилання на новий масив. Змінна викликача
досі вказує на старий. Щоб замінити сам об'єкт, потрібен модифікатор `ref` —
про нього в наступному підрозділі.

### Особливий випадок: `string`

`string` — посилальний тип, але поводиться як значимий:

```csharp
void ChangeText(string text)
{
    text = text + " змінено";
}

string message = "Привіт";
ChangeText(message);
Console.WriteLine(message);    // Привіт — не змінилося
```

Причина — **незмінність** (immutability) рядків із теми 3: будь-яка операція
створює **новий** рядок, а не змінює наявний. Тому змінити рядок викликача
зсередини функції неможливо в принципі.

## Перевірте себе

Що виведе цей код?

```csharp
struct Point
{
    public int X;
    public int Y;
}

void Move(Point p)
{
    p.X = 100;
}

Point a = new Point();
a.X = 5;
Move(a);
Console.WriteLine(a.X);
```

<details>
<summary>Відповідь</summary>

Виведе **5**.

`Point` оголошено як `struct`, тобто це **значимий** тип. Функція отримала повну
копію структури й змінила поле в копії. Оригінал не постраждав.

Якби `Point` був оголошений як `class`, вивелося б **100**: копіювалося б
посилання, і обидві змінні вказували б на той самий об'єкт.

Одне ключове слово — протилежний результат. Саме тому різницю між значимими
й посилальними типами треба розуміти, а не запам'ятовувати.

</details>

## Чому передача за значенням — це добре

Здається обмеженням, але насправді це захист. Функція, що не може зіпсувати
ваші змінні, значно безпечніша:

```csharp
int price = 100;
decimal total = CalculateTotal(price);   // price гарантовано залишиться 100
```

Ви можете викликати функцію, не читаючи її код і не боячись побічних ефектів.
Саме тому зміна аргументів (через `ref`/`out`) вважається винятком, а не нормою.

:::tip[Хороший стиль]
Функція має **повертати результат**, а не змінювати те, що їй передали:

```csharp
// ❌ Погано: незрозуміло, що функція щось змінює
void AddBonus(ref int salary) { salary += 500; }

// ✅ Добре: очевидно з місця виклику
int AddBonus(int salary) { return salary + 500; }

salary = AddBonus(salary);
```
:::

## Висновок

- **Параметр** — ім'я в оголошенні функції, **аргумент** — значення при виклику;
  зіставляються за позицією.
- За замовчуванням усі параметри передаються **за значенням** — функція отримує
  **копію** аргументу.
- Для **значимих** типів копіюється саме значення, тому зміни всередині функції
  не видно ззовні.
- Для **посилальних** типів копіюється **посилання**, тому зміна **вмісту**
  об'єкта видна ззовні — а присвоєння нового об'єкта вже ні.
- `string` — посилальний тип, але через **незмінність** поводиться як значимий.
- Функції краще **повертати результат**, ніж змінювати передані аргументи.
