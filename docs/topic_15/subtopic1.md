# Властивості та інкапсуляція

У попередньому підрозділі ми зупинилися на незручному компромісі: щоб захистити
дані, довелося сховати поле й написати пару методів `GetAge` / `SetAge`. Захист
з'явився, зручність зникла. Цей підрозділ — про те, як у C# отримати і те, і те.

## Від пари методів до властивості

Ось код, на якому ми зупинилися:

```csharp
class Student
{
    private int age;

    public int GetAge() => age;

    public void SetAge(int value)
    {
        if (value >= 14 && value <= 120)
        {
            age = value;
        }
    }
}
```

```csharp
student.SetAge(student.GetAge() + 1);   // збільшити вік на рік
```

Останній рядок читається жахливо. А тепер той самий клас із **властивістю**:

```csharp
class Student
{
    private int age;

    public int Age
    {
        get { return age; }
        set
        {
            if (value >= 14 && value <= 120)
            {
                age = value;
            }
        }
    }
}
```

```csharp
student.Age = 18;          // викликається set
Console.WriteLine(student.Age);   // викликається get
student.Age++;             // викликається і get, і set
```

**Властивість** (property) — член класу, який зовні виглядає як поле, а всередині
працює як пара методів. Розберемо синтаксис:

- `get` — **аксесор читання**. Виконується щоразу, коли значення властивості
  читають. Має повернути значення.
- `set` — **аксесор запису**. Виконується при присвоєнні. Усередині `set`
  доступне неявне ключове слово **value** — те, що написали праворуч
  від знака рівності.
- `age` — **поле-бекінг** (backing field), справжнє місце зберігання даних.
  Воно приватне, ззовні його не видно.

```
        Зовнішній код                    Усередині класу
   ┌──────────────────────┐        ┌──────────────────────────┐
   │ student.Age = 18;    │───────▶│ set { value = 18         │
   │                      │        │       перевірка          │
   │                      │        │       age = 18 }         │
   │                      │        │                          │
   │ int x = student.Age; │◀───────│ get { return age; }      │
   └──────────────────────┘        └──────────────────────────┘
                                     поле age — приватне,
                                     ззовні недосяжне
```

Тепер спробуємо зламати об'єкт:

```csharp
var student = new Student();
student.Age = 18;
Console.WriteLine($"Вік: {student.Age}");

student.Age = -25;      // set відхилить
Console.WriteLine($"Вік після спроби записати -25: {student.Age}");
```

**Вивід:**

```
Вік: 18
Вік після спроби записати -25: 18
```

Синтаксис такий самий зручний, як у поля, а контроль — як у методу.

:::warning[Обережно]
Мовчки ігнорувати некоректне значення, як у прикладі вище, — не найкраща
стратегія: код, який записав дурницю, навіть не дізнається про це. Часто
правильніше кинути виняток — тоді помилка виявиться одразу і в тому місці,
де вона сталася:

```csharp
set
{
    if (value < 14 || value > 120)
    {
        throw new ArgumentOutOfRangeException(nameof(value),
            $"Вік має бути від 14 до 120, отримано {value}.");
    }
    age = value;
}
```
:::

## Автоматичні властивості

Дуже часто ніякої валідації не потрібно — властивість просто зберігає значення.
Писати заради цього поле-бекінг і два аксесори нудно, тому в C# є скорочення:

```csharp
class Student
{
    public string Name { get; set; } = "";
    public string Group { get; set; } = "";
    public int Course { get; set; }
}
```

Це **автоматична властивість** (auto-property). Компілятор сам створює приховане
поле-бекінг, яке ви навіть не можете назвати на ім'я, і найпростіші `get` та `set`.

Запис `= ""` наприкінці — початкове значення. Для рядкових властивостей це
дуже корисно: без нього властивість буде `null`.

:::tip[Порада]
Починайте з автоматичної властивості. Якщо згодом знадобиться валідація —
додасте поле-бекінг і розгорнете аксесори. Найголовніше, що зовнішній код
при цьому **не зміниться взагалі**: `student.Age = 18` виглядає однаково
для обох варіантів. Саме заради цієї свободи властивості й придумали.
:::

## Різні комбінації доступу

Властивість не зобов'язана мати обидва аксесори або робити їх однаково
доступними.

### Тільки для читання

```csharp
class Student
{
    public string Name { get; }          // задати можна лише в конструкторі

    public Student(string name)
    {
        Name = name;
    }
}
```

Ззовні `student.Name = "Інше"` не скомпілюється. Це аналог `readonly`-поля,
але у формі властивості.

### Приватний `set`

```csharp
class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        if (amount > 0)
        {
            Balance += amount;    // усередині класу писати можна
        }
    }
}
```

Ззовні баланс можна читати, але не змінювати — тільки через `Deposit`.
Це чи не найкорисніша комбінація в реальному коді.

### Властивість `init`

```csharp
class Student
{
    public string Name { get; init; } = "";
    public string RecordBook { get; init; } = "";
}
```

**init** — аксесор, який дозволяє присвоєння лише під час створення об'єкта,
а потім «замикає» властивість назавжди:

```csharp
var student = new Student { Name = "Олена", RecordBook = "ПЗ-21-014" };
// student.Name = "Ігор";   // помилка компіляції
```

Це сучасний спосіб (C# 9+) описати незмінні дані, які задаються один раз
при створенні.

### Обчислювана властивість

Властивість не мусить нічого зберігати — вона може обчислювати значення
на льоту:

```csharp
class Student
{
    public string FirstName { get; set; } = "";
    public string LastName { get; set; } = "";
    public DateTime BirthDate { get; set; }

    public string FullName => $"{FirstName} {LastName}";

    public int Age
    {
        get
        {
            int years = DateTime.Now.Year - BirthDate.Year;
            if (DateTime.Now.DayOfYear < BirthDate.DayOfYear)
            {
                years--;
            }
            return years;
        }
    }
}
```

```csharp
var student = new Student
{
    FirstName = "Олена",
    LastName = "Кравчук",
    BirthDate = new DateTime(2007, 5, 12)
};

Console.WriteLine(student.FullName);
Console.WriteLine($"Вік: {student.Age}");
```

**Вивід:**

```
Олена Кравчук
Вік: 19
```

Запис `public string FullName => …` — це скорочення для властивості з одним
лише `get`. Стрілка `=>` тут називається **expression body** і читається
як «повертає».

Головна перевага обчислюваних властивостей: **немає чого розсинхронізувати**.
Якби `FullName` було звичайним полем, довелося б оновлювати його щоразу
при зміні імені чи прізвища — і рано чи пізно хтось забув би.

:::danger[Часта помилка]
Обчислювана властивість виконує код **щоразу**, коли її читають. Якщо всередині
важкі обчислення або читання файлу, а властивість викликається у циклі —
програма несподівано стане повільною. Правило: властивість має бути дешевою.
Якщо операція довга, зробіть звичайний метод — назва з дужками попереджає,
що там щось відбувається.
:::

## Порівняння: поле, властивість, метод

| Що обрати | Коли | Приклад |
|---|---|---|
| **Приватне поле** | внутрішнє зберігання, зовнішній світ про нього не знає | `private int age;` |
| **Автовластивість** | просте зберігання без перевірок | `public string Name { get; set; }` |
| **Властивість з логікою** | потрібна валідація або обчислення | `Age` з перевіркою діапазону |
| **Метод** | дія, довга операція, кілька параметрів | `Deposit(500)`, `SaveToFile(path)` |
| **Публічне поле** | практично ніколи | — |

Просте правило: **іменник — властивість, дієслово — метод**. `Balance` — це
характеристика, тому властивість. `Deposit` — це дія, тому метод.

## Модифікатори доступу

Тепер розберемо весь набір ключових слів, які керують видимістю. Спершу
потрібно зрозуміти, які взагалі бувають «рівні» видимості:

```
   ┌───────────────────────────────────────────────────────────────┐
   │  ВЕСЬ СВІТ (інші проєкти, які підключили вашу бібліотеку)      │
   │                                                               │
   │   ┌───────────────────────────────────────────────────────┐   │
   │   │  ЗБІРКА (ваш проєкт, один .dll)                        │   │
   │   │                                                       │   │
   │   │   ┌───────────────────────┐   ┌───────────────────┐   │   │
   │   │   │  КЛАС Person          │   │  Клас Program     │   │   │
   │   │   │   private int age;    │   │  (інший клас тієї │   │   │
   │   │   │                       │   │   самої збірки)   │   │   │
   │   │   └───────────┬───────────┘   └───────────────────┘   │   │
   │   │               │ наслідує                              │   │
   │   │   ┌───────────▼───────────┐                           │   │
   │   │   │  КЛАС Student         │  нащадок у тій самій      │   │
   │   │   └───────────────────────┘  збірці                   │   │
   │   └───────────────────────────────────────────────────────┘   │
   │                                                               │
   │        Нащадок в ІНШІЙ збірці (чужий проєкт наслідує Person)   │
   └───────────────────────────────────────────────────────────────┘
```

Модифікатор доступу відповідає на питання: **звідки з цієї схеми видно член класу**.

| Модифікатор | Свій клас | Нащадок у цій збірці | Інший клас цієї збірки | Нащадок в іншій збірці | Будь-хто ззовні |
|---|:---:|:---:|:---:|:---:|:---:|
| `private` | так | ні | ні | ні | ні |
| `protected` | так | так | ні | так | ні |
| `internal` | так | так | так | ні | ні |
| `protected internal` | так | так | так | так | ні |
| `private protected` | так | так | ні | ні | ні |
| `public` | так | так | так | так | так |

Словами:

- **private** — «тільки я сам». Найзакритіший рівень. Це значення
  за замовчуванням для членів класу: якщо модифікатор не написати, буде `private`.
- **protected** — «я і мої нащадки». Використовується, коли базовий клас
  готує щось для похідних, але не для всього світу. Детально — у темі 16.
- **internal** — «уся моя збірка». Клас-помічник, потрібний лише всередині
  вашого проєкту. Для **типів** (самих класів) це значення за замовчуванням.
- **protected internal** — «моя збірка **або** будь-який нащадок». Об'єднання,
  не перетин — доступ ширший за кожен окремо.
- **private protected** — «нащадок, але тільки в моїй збірці». Найрідше
  вживаний варіант, з'явився в C# 7.2.
- **public** — «будь-хто». Це ваш публічний контракт: усе, що ви позначили
  `public`, доведеться підтримувати надалі, бо на це вже може спиратися
  чужий код.

:::note
Найчастіше в реальному коді ви бачитимете лише три з шести: `private` для полів,
`public` для властивостей і методів, `protected` — коли справа дійде
до наслідування. Решта потрібні у великих багатопроєктних рішеннях.
:::

Приклад, де використано кілька рівнів одразу:

```csharp
public class Product
{
    private decimal price;                        // тільки цей клас
    protected string internalCode = "";           // цей клас і нащадки
    internal int WarehouseId { get; set; }        // тільки ця збірка
    public string Name { get; set; } = "";        // усі

    public decimal Price
    {
        get => price;
        set
        {
            if (value < 0)
            {
                throw new ArgumentException("Ціна не може бути від'ємною.");
            }
            price = value;
        }
    }
}
```

:::tip[Порада]
Правило проєктування: **починайте з найзакритішого**. Спершу `private`,
і відкривайте лише те, без чого зовнішній код не обійдеться. Зробити
приватний член публічним легко в будь-який момент. Забрати `public`, на який
уже спираються десять інших файлів, — боляче.
:::

## Інкапсуляція як ідея

Тепер, коли є інструменти, повернімося до самого принципу. Інкапсуляція —
це не «зробити всі поля приватними». Це **об'єкт сам відповідає за коректність
свого стану**.

Порівняйте два підходи до однієї задачі — переказ грошей.

**Без інкапсуляції.** Правила живуть у зовнішньому коді:

```csharp
// клас — просто мішок даних
class Account
{
    public decimal Balance;
}

// а перевірки — де завгодно
if (from.Balance >= amount && amount > 0)
{
    from.Balance -= amount;
    to.Balance += amount;
}
```

Проблема: ці два `if` доведеться повторити в кожному місці програми, де є
переказ. Забули в одному — з'явився від'ємний баланс, і знайти джерело
буде важко.

**З інкапсуляцією.** Правила живуть усередині класу:

```csharp
class Account
{
    public decimal Balance { get; private set; }

    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > Balance)
        {
            return false;
        }
        Balance -= amount;
        return true;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            throw new ArgumentException("Сума має бути додатною.");
        }
        Balance += amount;
    }
}
```

```csharp
if (from.Withdraw(amount))
{
    to.Deposit(amount);
}
else
{
    Console.WriteLine("Недостатньо коштів.");
}
```

Тепер, скільки б місць у програмі не робили переказ, від'ємний баланс
неможливий **фізично**. Не «ми домовилися перевіряти», а неможливий: іншого
шляху змінити `Balance` просто не існує.

**Аналогія з життя.** Автомат із газованою водою. Ви кидаєте монету
і натискаєте кнопку. Ви не можете просто відкрити автомат і взяти напій —
не тому, що це заборонено правилами, а тому, що корпус зачинений. Інкапсуляція
робить некоректну дію не «забороненою», а **неможливою**.

:::info[Цікаво]
Слово «інкапсуляція» походить від латинського *capsula* — «коробочка».
Ідея старіша за ООП: у механіці її називають «чорна скринька». Вам відомі
входи й виходи, а нутрощі — не ваша справа. Саме тому автомобілем можна
керувати, не знаючи, що таке розподільний вал.
:::

## Типові помилки

**Автовластивість замість валідації.** `public int Age { get; set; }` захищає
не більше, ніж публічне поле: записати `-25` можна так само. Якщо потрібне
правило — потрібне поле-бекінг і `set` із перевіркою.

**Порожній `set`.** Аксесор `set { }`, який нічого не робить, — пастка:
присвоєння мовчки зникає, а програміст думає, що значення записалося. Якщо
змінювати не можна, взагалі не пишіть `set` — тоді компілятор чесно
поскаржиться на спробу запису.

**Рекурсія у властивості.** Класична помилка:

```csharp
public int Age
{
    get => Age;          // властивість викликає саму себе — StackOverflowException
    set => Age = value;
}
```
Правильно — звертатися до **поля-бекінга** `age`, а не до властивості `Age`.

**Приватне поле і публічна властивість з однаковою назвою.** C# розрізняє
регістр, тому `age` і `Age` — різні імена, і це працює. А от `Age` і `Age`
не скомпілюється. Тримайтеся угоди: поле `camelCase`, властивість `PascalCase`.
