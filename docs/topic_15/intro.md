# Поля та методи класу

У темі 14 ми оголосили найпростіший клас: кілька публічних полів і все. Цього
достатньо, щоб зрозуміти ідею, але недостатньо, щоб писати справжній код.
Тепер розберемо члени класу докладно — почнемо з полів і методів, а в наступних
підрозділах додамо властивості, конструктори й статичні члени.

## Що взагалі буває всередині класу

**Член класу** (member) — усе, що оголошено між фігурними дужками класу.
Ось повний список того, що ми вивчатимемо в цій темі:

| Член | Що це | Приклад |
|---|---|---|
| **Поле** | змінна, що належить об'єкту | `private int age;` |
| **Метод** | дія, яку об'єкт уміє виконувати | `public void Grow()` |
| **Властивість** | «розумне поле» з контролем доступу | `public int Age` з get/set |
| **Конструктор** | код, що виконується при створенні об'єкта | `public Student(...)` |
| **Константа** | незмінне значення, спільне для всіх | `public const int MaxAge = 120;` |

Порядок оголошення членів компілятору байдужий, але усталена практика така:
спочатку константи й поля, потім конструктори, далі властивості, наприкінці
методи. Коли всі пишуть однаково, чужий код читається швидше.

## Поля

**Поле** (field) — змінна, оголошена безпосередньо в класі. Кожен об'єкт має
власний набір значень своїх полів: у одного студента `age` дорівнює 17,
у іншого — 19, і вони ніяк не заважають одне одному.

```csharp
class Student
{
    private string name;
    private int age;
    private double averageGrade;
}
```

Синтаксис: `модифікатор_доступу тип назва;`. Назви полів пишуть у стилі
**camelCase** — з маленької літери: `name`, `averageGrade`, `birthDate`.

:::note
Деякі команди пишуть приватні поля з підкресленням на початку: `_name`,
`_averageGrade`. Це поширена домовленість, яка допомагає одразу відрізнити
поле від локальної змінної. Обидва варіанти правильні — головне, щоб у межах
одного проєкту стиль був однаковий. У цьому курсі використовуємо просто
`camelCase`.
:::

### Значення за замовчуванням

Якщо поле не ініціалізувати, воно **не** містить сміття, як у деяких інших мовах.
CLR гарантовано заповнює його значенням за замовчуванням:

| Тип поля | Значення за замовчуванням |
|---|---|
| `int`, `long`, `double`, `decimal` | `0` |
| `bool` | `false` |
| `char` | символ з кодом 0 |
| `string` і будь-який клас | `null` |
| структура | усі її поля — своїми значеннями за замовчуванням |

```csharp
class Student
{
    private string name;      // null
    private int age;          // 0
    private bool isActive;    // false
}
```

:::warning Обережно
Поле типу `string` за замовчуванням дорівнює `null`, а не порожньому рядку.
Виклик `name.Length` на такому полі дасть `NullReferenceException`.
Компілятор .NET 8 із увімкненим `Nullable` попередить вас жовтим підкресленням —
не ігноруйте це попередження.
:::

### Ініціалізація поля при оголошенні

Поле можна одразу забезпечити початковим значенням:

```csharp
class Student
{
    private string name = "Невідомо";
    private int age = 17;
    private List<double> grades = new List<double>();
    private string[] subjects = [];        // порожній масив, C# 12
}
```

Цей код виконується **для кожного нового об'єкта** — перед тілом конструктора.
Ініціалізувати колекції прямо при оголошенні — дуже гарна звичка: так поле
ніколи не буде `null`, і ви позбавитеся цілого класу помилок.

### Поля `readonly`

Іноді значення поля має бути задане один раз — при створенні об'єкта — і більше
ніколи не змінюватися. Наприклад, номер залікової книжки або дата реєстрації.
Для цього є модифікатор **readonly**:

```csharp
class Student
{
    private readonly string recordBookNumber;
    private readonly DateTime registeredAt = DateTime.Now;

    public Student(string number)
    {
        recordBookNumber = number;    // тут можна: це конструктор
    }

    public void ChangeNumber(string newNumber)
    {
        // recordBookNumber = newNumber;   // помилка компіляції!
    }
}
```

`readonly`-поле можна присвоїти лише у двох місцях: при оголошенні
або в конструкторі. Будь-яка спроба змінити його пізніше не скомпілюється —
помилку знайдено ще до запуску програми.

### Константи

**Константа** (`const`) — значення, відоме вже на етапі компіляції і однакове
для всієї програми. Її не можна змінити ніде і ніколи:

```csharp
class Student
{
    public const int MinAge = 14;
    public const int MaxAge = 120;
    public const string DefaultGroup = "не зараховано";
}
```

Звертаються до константи **через ім'я класу**, а не через об'єкт:

```csharp
Console.WriteLine(Student.MinAge);     // 14
// student.MinAge — так не можна
```

Це логічно: константа не належить конкретному студентові, вона належить самому
поняттю «студент».

| Ознака | `const` | `readonly` |
|---|---|---|
| Коли задається значення | під час компіляції | при оголошенні або в конструкторі |
| Чи може залежати від даних об'єкта | ні | так |
| Належить | класу | об'єкту (або класу, якщо `static readonly`) |
| Дозволені типи | числа, `bool`, `char`, `string`, `enum` | будь-які |
| Приклад | `const double Pi = 3.14159;` | `readonly DateTime createdAt;` |

:::tip Порада
Побачили в коді «магічне число» — 14, 120, 0.2, 100 — винесіть його в константу
з осмисленою назвою. Через місяць `MinAge` буде зрозумілим, а `14` посеред
умови — ні. І виправляти таке значення доведеться в одному місці, а не в семи.
:::

## Методи екземпляра

**Метод** — дія, яку вміє виконувати об'єкт. Ви вже писали методи в процедурному
стилі; всередині класу вони працюють так само, але з однією принциповою
відмінністю: **метод бачить поля свого об'єкта без жодних параметрів**.

```csharp
class Student
{
    private string name = "";
    private List<double> grades = [];

    public void AddGrade(double grade)
    {
        grades.Add(grade);
    }

    public double GetAverage()
    {
        if (grades.Count == 0)
        {
            return 0;
        }

        double sum = 0;
        foreach (double grade in grades)
        {
            sum += grade;
        }
        return sum / grades.Count;
    }

    public void PrintReport()
    {
        Console.WriteLine($"{name}: оцінок {grades.Count}, середній {GetAverage():F2}");
    }
}
```

Зверніть увагу на три речі:

1. `AddGrade` користується полем `grades`, хоча його не передавали параметром —
   поле «своє», воно завжди під рукою.
2. `PrintReport` викликає інший метод того самого класу — `GetAverage()` —
   просто за назвою.
3. Такі методи називають **методами екземпляра** (instance methods): щоб їх
   викликати, потрібен об'єкт.

Використання:

```csharp
var student = new Student();
student.AddGrade(90);
student.AddGrade(75);
student.AddGrade(84);
student.PrintReport();
```

**Вивід:**

```
: оцінок 3, середній 83,00
```

Ім'я порожнє, бо ми його ніде не задали, — цю проблему розв'яжуть конструктори
у підрозділі 3.

### Кожен об'єкт має власні поля

Це варто побачити наочно:

```csharp
var a = new Student();
var b = new Student();

a.AddGrade(100);
a.AddGrade(90);
b.AddGrade(60);

Console.WriteLine($"a: {a.GetAverage():F1}");
Console.WriteLine($"b: {b.GetAverage():F1}");
```

**Вивід:**

```
a: 95,0
b: 60,0
```

```
        КУПА (heap)
 ┌────────────────────────┐      ┌────────────────────────┐
 │ об'єкт a               │      │ об'єкт b               │
 │  name   = ""           │      │  name   = ""           │
 │  grades = [100, 90]    │      │  grades = [60]         │
 └────────────────────────┘      └────────────────────────┘
      власні дані                     власні дані

 Код методу AddGrade існує в пам'яті в ОДНОМУ примірнику.
 Дані — окремі в кожного об'єкта.
```

Це важливо розуміти: методи не дублюються для кожного об'єкта. Дублюються лише
дані. Коли ви пишете `a.AddGrade(100)`, CLR викликає той самий код, просто
передає йому «на якому об'єкті працювати».

## Ключове слово `this`

**this** — це посилання на **поточний об'єкт**, тобто на той, для якого зараз
викликано метод. Саме через `this` метод і дістається до своїх полів —
просто зазвичай його не пишуть, бо компілятор здогадується сам.

```csharp
public void AddGrade(double grade)
{
    this.grades.Add(grade);   // те саме, що grades.Add(grade)
}
```

Але є ситуація, де `this` **обов'язковий**: коли параметр методу називається
так само, як поле.

```csharp
class Student
{
    private string name = "";
    private int age;

    public void SetData(string name, int age)
    {
        this.name = name;    // поле = параметр
        this.age = age;
    }
}
```

Без `this` рядок `name = name;` присвоїв би параметр самому собі, а поле
залишилося б порожнім. Компілятор навіть попередить про це, але помилку
зробити легко.

:::danger Часта помилка
```csharp
public void SetName(string name)
{
    name = name;      // НІЧОГО не робить: параметр присвоєно сам собі
}
```
Поле класу після такого виклику залишиться порожнім, а програма мовчки
працюватиме неправильно. Правильно — `this.name = name;`.
:::

`this` знадобиться ще в кількох місцях: у ланцюжку конструкторів
(підрозділ 3) і коли об'єкт передає самого себе в інший метод:

```csharp
public void Register(Group group)
{
    group.Add(this);      // передаємо цей самий об'єкт
}
```

## Чому публічні поля — погана ідея

Тепер головне питання цього підрозділу. Повернімося до класу з теми 14:

```csharp
class Student
{
    public string Name;
    public int Age;
    public double AverageGrade;
}
```

Зовні все зручно. А тепер подивіться, що може зробити зовнішній код:

```csharp
var student = new Student();
student.Name = "";               // студент без імені
student.Age = -25;               // від'ємний вік
student.AverageGrade = 3000;     // середній бал 3000 зі 100
student.Age = 999999;

Console.WriteLine($"[{student.Name}], вік {student.Age}, бал {student.AverageGrade}");
```

**Вивід:**

```
[], вік -25, бал 3000
```

Програма не впала. Компілятор не сказав ані слова. Об'єкт спокійно існує
у стані, який фізично неможливий у реальному світі. І поки цей об'єкт кудись
не потрапить — у звіт, у розрахунок стипендії, у файл — ніхто нічого не помітить.

Проблем тут насправді чотири.

**1. Немає перевірки.** Клас не має жодного способу відхилити некоректне
значення. Дані з клавіатури, з файлу, з інтернету потраплять у поле як є.

**2. Помилку неможливо локалізувати.** Уявіть, що в програмі 50 місць, де
пишуть у `Age`. Знайшли від'ємний вік — хто його записав? Доведеться перевіряти
всі 50. Якби запис ішов через один метод, ви поставили б один `if` — і одразу
знайшли б винуватця.

**3. Неможливо змінити реалізацію.** Сьогодні `AverageGrade` — поле. Завтра
виявиться, що середній бал треба **обчислювати** зі списку оцінок, а не зберігати
окремо. Ви змінюєте клас — і ламається весь код, що звертався до поля. Якби
зовнішній світ бачив властивість, ви змінили б лише її нутрощі, а зовнішній
код навіть не помітив би.

**4. Неможливо зробити «читати можна, писати ні».** Поле або повністю відкрите,
або повністю закрите. Проміжного варіанта немає, а він потрібен постійно:
баланс рахунку читати можна всім, а змінювати — лише через операції.

Ось перша спроба це виправити — закрити поле і додати методи:

```csharp
class Student
{
    private int age;

    public void SetAge(int value)
    {
        if (value < 14 || value > 120)
        {
            Console.WriteLine($"Некоректний вік: {value}. Значення не змінено.");
            return;
        }
        age = value;
    }

    public int GetAge()
    {
        return age;
    }
}
```

```csharp
var student = new Student();
student.SetAge(18);
Console.WriteLine(student.GetAge());
student.SetAge(-25);
Console.WriteLine(student.GetAge());
```

**Вивід:**

```
18
Некоректний вік: -25. Значення не змінено.
18
```

Тепер об'єкт себе захищає. Але писати `student.SetAge(18)` замість
`student.Age = 18` незручно, а таких пар «get/set» у справжньому класі буде
десяток. Саме тому в C# є **властивості** — вони дають захист методів
із синтаксисом полів. Про них — наступний підрозділ.

:::info Цікаво
У Java властивостей немає, і програмісти там досі пишуть `getAge()` / `setAge()`
вручну (точніше, генерують середовищем розробки). C# від самого початку
1.0 мав властивості саме тому, що така пара методів — очевидний повторюваний
шаблон, який мова може взяти на себе.
:::

## Типові помилки

**Публічні поля «бо швидше».** Швидше писати — так. Але через місяць
доведеться шукати, хто записав туди дурницю. Тримайте поля `private`,
а назовні виставляйте властивості.

**`name = name;` у методі замість `this.name = name;`.** Тихо не працює,
поле лишається порожнім. Якщо параметр і поле мають однакову назву — `this`
обов'язковий.

**Забути ініціалізувати колекцію.** `private List<double> grades;` без
`= []` дорівнює `null`, і перший же `grades.Add(...)` уронить програму.
Ініціалізуйте колекції прямо при оголошенні.

**Використовувати `const` там, де потрібен `readonly`.** `const` обчислюється
на етапі компіляції, тому в нього не можна покласти `DateTime.Now` або значення
з конструктора. Для цього є `readonly`.
