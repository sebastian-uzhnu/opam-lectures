# Конструктори та статичні члени

Класи, які ми писали досі, мали одну спільну ваду: об'єкт народжувався порожнім.
Спочатку `new Student()`, потім три-чотири рядки присвоєнь — і тільки після цього
об'єкт ставав придатним до використання. А якщо якийсь рядок забути, у програмі
з'явиться напівзаповнений студент.

Цей підрозділ — про те, як зробити так, щоб об'єкт **не міг** народитися
некоректним, і про членів, які належать не об'єкту, а класу в цілому.

## Проблема: об'єкт-напівфабрикат

```csharp
var student = new Student();
student.Name = "Олена Кравчук";
student.Group = "ПЗ-21";
// забули задати RecordBook — і ніхто про це не дізнається
```

Такий об'єкт існує у стані, у якому існувати не повинен. Компілятор не допоможе:
з його погляду все чудово. Розв'язання — **конструктор**.

## Конструктор за замовчуванням

**Конструктор** — спеціальний метод, який виконується автоматично при створенні
об'єкта. Його завдання — привести новий об'єкт у коректний стан.

Ознаки конструктора:

- називається **точно так само**, як клас;
- **не має типу, що повертається** — навіть `void` не пишуть;
- викликається лише через `new`.

Ви вже писали `new Student()` — отже, конструктор існував. Просто його створив
компілятор. Це **конструктор за замовчуванням** (default constructor): без
параметрів, з порожнім тілом, він лише заповнює поля значеннями за замовчуванням.

```csharp
class Student
{
    public string Name = "";
    // компілятор неявно додає:
    // public Student() { }
}
```

### Він зникає, щойно ви написали свій

Це важлива деталь, на якій спотикаються всі:

```csharp
class Student
{
    public string Name;

    public Student(string name)      // ми написали свій конструктор
    {
        Name = name;
    }
}
```

```csharp
var a = new Student("Олена");     // працює
var b = new Student();            // ПОМИЛКА КОМПІЛЯЦІЇ
```

**Помилка:**

```
CS7036: There is no argument given that corresponds to the required
parameter 'name' of 'Student.Student(string)'
```

Логіка компілятора така: конструктор за замовчуванням він додає лише тоді,
коли ви не оголосили **жодного** свого. Щойно з'явився ваш — компілятор
вважає, що ви самі знаєте, як має створюватися об'єкт, і не втручається.

Якщо порожній конструктор усе ж потрібен, напишіть його явно:

```csharp
public Student() { }
public Student(string name) { Name = name; }
```

:::danger Часта помилка
Додали конструктор з параметрами — і раптом перестав компілюватися код
в іншому файлі, де було `new Student()`. Це не поломка, це саме та поведінка.
Або передайте аргументи, або допишіть порожній конструктор.
:::

## Власний конструктор

Тепер по-справжньому:

```csharp
class Student
{
    public string Name { get; }
    public string Group { get; set; }
    public string RecordBook { get; }
    private double averageGrade;

    public Student(string name, string group, string recordBook)
    {
        if (string.IsNullOrWhiteSpace(name))
        {
            throw new ArgumentException("Ім'я не може бути порожнім.", nameof(name));
        }

        Name = name;
        Group = group;
        RecordBook = recordBook;
        averageGrade = 0;
    }
}
```

```csharp
var student = new Student("Олена Кравчук", "ПЗ-21", "ПЗ-21-014");
Console.WriteLine($"{student.Name}, група {student.Group}");
// Вивід: Олена Кравчук, група ПЗ-21
```

Що ми виграли:

1. Створити студента без імені **неможливо** — компілятор вимагатиме аргумент.
2. Створити студента з **порожнім** іменем теж неможливо — конструктор
   кине виняток.
3. Властивості `Name` і `RecordBook` не мають `set`, тож після створення
   їх не змінити.

Об'єкт із моменту народження коректний і лишається коректним. Це і є мета.

:::tip Порада
Правило проєктування: у параметрах конструктора має бути все, **без чого об'єкт
не має сенсу**. Ім'я студента — обов'язкове. Список оцінок — ні, він на початку
порожній. Не тягніть у конструктор те, що можна задати пізніше, — інакше
отримаєте конструктор на дванадцять параметрів.
:::

## Перевантаження конструкторів

**Перевантаження** — кілька методів з однаковою назвою, але різними наборами
параметрів. Для конструкторів це працює так само і дозволяє створювати об'єкт
кількома зручними способами:

```csharp
class Rectangle
{
    public double Width { get; }
    public double Height { get; }

    public Rectangle()                              // одиничний
    {
        Width = 1;
        Height = 1;
    }

    public Rectangle(double side)                   // квадрат
    {
        Width = side;
        Height = side;
    }

    public Rectangle(double width, double height)   // прямокутник
    {
        Width = width;
        Height = height;
    }

    public double Area => Width * Height;
}
```

```csharp
Console.WriteLine($"{new Rectangle().Area}  {new Rectangle(5).Area}  {new Rectangle(3, 4).Area}");
// Вивід: 1  25  12
```

Компілятор обирає потрібний конструктор за кількістю й типами аргументів.
Головна вимога: набори параметрів мають відрізнятися — два конструктори
з однаковими типами параметрів не скомпілюються.

### Ланцюжок конструкторів

У прикладі вище присвоєння `Width` і `Height` повторюється тричі. Це погано:
додасте валідацію — доведеться додавати її в три місця. C# дозволяє одному
конструктору **викликати інший** через `: this(...)`:

```csharp
class Rectangle
{
    public double Width { get; }
    public double Height { get; }

    public Rectangle() : this(1, 1) { }

    public Rectangle(double side) : this(side, side) { }

    public Rectangle(double width, double height)     // головний конструктор
    {
        if (width <= 0 || height <= 0)
        {
            throw new ArgumentException("Сторони мають бути додатними.");
        }
        Width = width;
        Height = height;
    }

    public double Area => Width * Height;
}
```

Порядок виконання:

```
   new Rectangle(5)
         │
         │  : this(side, side)
         ▼
   Rectangle(5, 5)        ◀── головний конструктор: валідація + присвоєння
         │
         ▼
   тіло Rectangle(double side)   (тут порожнє)
         │
         ▼
   об'єкт готовий
```

Зверніть увагу: спершу відпрацьовує **той конструктор, який викликали через
`this`**, і лише потім — тіло початкового. Валідація тепер написана один раз.

:::tip Порада
Шаблон, до якого варто прагнути: один «головний» конструктор із повним набором
параметрів робить усю роботу, а решта — короткі перенаправлення на нього
через `: this(...)`. Так уся логіка створення живе в одному місці.
:::

## Ініціалізатор об'єкта

Іноді конструктор з параметрами зайвий — властивостей багато, і всі необов'язкові.
Для таких випадків є **ініціалізатор об'єкта**:

```csharp
class Settings
{
    public string Theme { get; set; } = "light";
    public int FontSize { get; set; } = 14;
    public bool ShowLineNumbers { get; set; } = true;
    public string Language { get; set; } = "uk";
}
```

```csharp
var settings = new Settings
{
    Theme = "dark",
    FontSize = 16
};

Console.WriteLine($"{settings.Theme}, {settings.FontSize}pt, мова {settings.Language}");
// Вивід: dark, 16pt, мова uk
```

Синтаксис `new Settings` із фігурними дужками — це не конструктор. Спершу
викликається звичайний конструктор без параметрів, а потім по черзі
присвоюються перелічені властивості. Тобто це просто короткий запис
кількох рядків присвоєння.

| Що обрати | Коли |
|---|---|
| **Конструктор з параметрами** | значення обов'язкові, потрібна валідація, є незмінні властивості |
| **Ініціалізатор об'єкта** | багато необов'язкових налаштувань із розумними значеннями за замовчуванням |
| **Обидва разом** | обов'язкове — у конструктор, решта — в ініціалізатор |

Останній варіант виглядає так:

```csharp
var student = new Student("Олена Кравчук", "ПЗ-21", "ПЗ-21-014")
{
    Phone = "+380671234567",
    Email = "olena@example.com"
};
```

:::note
Ініціалізатор чудово поєднується з `init`-властивостями з попереднього
підрозділу: властивість можна задати в ініціалізаторі, а потім вона
стає незмінною назавжди.
:::

## Статичні поля й методи

Досі кожен член класу належав об'єкту. Але буває інформація, яка стосується
**класу в цілому**, а не окремого екземпляра. Наприклад: скільки всього
студентів створено в програмі.

**Статичний** член (`static`) існує в **одному примірнику на весь клас**,
незалежно від того, скільки об'єктів створено — нуль чи мільйон.

### Класичний приклад: лічильник об'єктів

```csharp
class Student
{
    private static int totalCount = 0;      // один на весь клас

    public string Name { get; }
    public int Id { get; }                  // свій у кожного об'єкта

    public Student(string name)
    {
        Name = name;
        totalCount++;                       // збільшуємо спільний лічильник
        Id = totalCount;                    // запам'ятовуємо свій номер
    }

    public static int TotalCount => totalCount;
}
```

```csharp
var a = new Student("Олена");
var b = new Student("Ігор");
var c = new Student("Софія");

Console.WriteLine($"{a.Name} має номер {a.Id}");
Console.WriteLine($"{c.Name} має номер {c.Id}");
Console.WriteLine($"Усього створено студентів: {Student.TotalCount}");
```

**Вивід:**

```
Олена має номер 1
Софія має номер 3
Усього створено студентів: 3
```

Зверніть увагу на звертання: `Student.TotalCount` — **через ім'я класу**,
а не через об'єкт. Спроба написати `a.TotalCount` не скомпілюється, і це
логічно: загальна кількість не належить Олені.

Ось як це виглядає в пам'яті:

```
   Область статичних даних            КУПА (heap)
   ┌────────────────────┐     ┌──────────────┐ ┌──────────────┐
   │ Student.totalCount │     │ об'єкт a     │ │ об'єкт b     │
   │        = 3         │     │  Name="Олена"│ │  Name="Ігор" │
   └────────────────────┘     │  Id = 1      │ │  Id = 2      │
      один на весь клас       └──────────────┘ └──────────────┘
                                  ┌──────────────┐
                                  │ об'єкт c     │
                                  │  Name="Софія"│
                                  │  Id = 3      │
                                  └──────────────┘
                                 у кожного свої дані
```

### Статичні методи

**Статичний метод** не має доступу до полів об'єкта — бо не має самого об'єкта.
Він працює тільки з тим, що йому передали, і зі статичними членами класу.

```csharp
class MathHelper
{
    public static double Average(params double[] values)
    {
        if (values.Length == 0)
        {
            return 0;
        }

        double sum = 0;
        foreach (double value in values)
        {
            sum += value;
        }
        return sum / values.Length;
    }
}
```

```csharp
Console.WriteLine(MathHelper.Average(90, 75, 84));   // 83
```

Ви користувалися статичними методами весь курс, навіть не помічаючи:
`Math.Sqrt(16)`, `Console.WriteLine(...)`, `int.Parse("42")`,
`File.ReadAllText(path)`, `Array.Sort(arr)`. Ніде не було `new Math()` —
бо ці методи статичні.

:::danger Часта помилка
```csharp
class Student
{
    private string name = "";

    public static void Print()
    {
        Console.WriteLine(name);   // помилка компіляції
    }
}
```
**Помилка:** an object reference is required for the non-static field `name`.

Статичний метод питає: «ім'я **якого** студента вивести?» Об'єкта немає,
відповіді немає. Або зробіть метод нестатичним, або передайте об'єкт
параметром: `public static void Print(Student student)`.
:::

## Статичний конструктор

**Статичний конструктор** виконується **один раз** — перед першим використанням
класу. Його призначення — підготувати статичні дані.

```csharp
class Config
{
    public static readonly string AppName;
    public static readonly DateTime StartedAt;

    static Config()          // без модифікатора доступу і без параметрів
    {
        AppName = "Журнал успішності";
        StartedAt = DateTime.Now;
        Console.WriteLine("Статичний конструктор виконано");
    }
}
```

```csharp
Console.WriteLine("Початок програми");
Console.WriteLine(Config.AppName);
Console.WriteLine(Config.AppName);
```

**Вивід:**

```
Початок програми
Статичний конструктор виконано
Журнал успішності
Журнал успішності
```

Повідомлення з'явилося лише один раз — і не на початку програми, а саме тоді,
коли до класу вперше звернулися.

## Статичний клас

Якщо **всі** члени класу статичні, клас можна позначити як `static`:

```csharp
static class StringHelper
{
    public static string Capitalize(string text)
    {
        if (string.IsNullOrEmpty(text))
        {
            return text;
        }
        return char.ToUpper(text[0]) + text.Substring(1).ToLower();
    }

    public static string Shorten(string text, int maxLength)
    {
        return text.Length <= maxLength ? text : text[..maxLength] + "…";
    }
}
```

```csharp
Console.WriteLine(StringHelper.Capitalize("оЛЕНА"));          // Олена
Console.WriteLine(StringHelper.Shorten("Основи програмування", 10));  // Основи про…
```

Статичний клас не можна створити через `new` — компілятор цього не дозволить.
Це просто контейнер для набору функцій. Так влаштовані `Math`, `File`,
`Console`, `Convert`.

## Коли `static` доречний, а коли — ні

| Ситуація | Доречно? | Чому |
|---|---|---|
| Утиліта без стану: `Math.Abs`, конвертери, форматувальники | так | результат залежить лише від аргументів |
| Константи й налаштування, що не змінюються | так | одне значення на всю програму |
| Лічильник створених об'єктів, статистика по класу | так | стосується класу, а не екземпляра |
| Змінні дані «щоб зручно було звідусіль дістати» | ні | це глобальна змінна з іншою назвою |
| Поточний користувач, поточне з'єднання, «головне вікно» | ні | у програмі їх може стати кілька |

:::warning Обережно
`static` спокусливий: не треба нічого створювати й передавати — написав
`Data.Students` і працюй. Але статичне змінюване поле — це **глобальна змінна**,
з усіма її бідами: змінити її може будь-хто звідки завгодно, і коли значення
виявиться неправильним, ви шукатимете винуватця по всій програмі. Плюс такий
код майже неможливо тестувати. Якщо `static` зберігає дані, які змінюються, —
зупиніться і подумайте ще раз.
:::

## Коротко про `record`

Часто клас потрібен лише як «пакунок даних»: кілька властивостей, конструктор
і `ToString()`. Писати це вручну — багато рутини. У C# 9 з'явився **record**:

```csharp
record Track(string Title, string Artist, int Seconds);
```

Один рядок. Компілятор сам згенерував:

- властивості `Title`, `Artist`, `Seconds` тільки для читання;
- конструктор із трьома параметрами;
- осмислений `ToString()`;
- порівняння **за значеннями**, а не за посиланнями;
- метод `with` для створення зміненої копії.

```csharp
var track = new Track("Обійми", "Океан Ельзи", 252);
Console.WriteLine(track);

var same = new Track("Обійми", "Океан Ельзи", 252);
Console.WriteLine(track == same);

var longer = track with { Seconds = 300 };
Console.WriteLine(longer);
```

**Вивід:**

```
Track { Title = Обійми, Artist = Океан Ельзи, Seconds = 252 }
True
Track { Title = Обійми, Artist = Океан Ельзи, Seconds = 300 }
```

Порівняйте з класом: `track == same` для звичайного класу дало б `False`,
бо це **два різні об'єкти**, хоч і з однаковими даними. Record порівнює вміст.

| Що обрати | Коли |
|---|---|
| `class` | є поведінка, стан змінюється, важлива ідентичність об'єкта |
| `record` | незмінний пакунок даних: DTO, координата, рядок звіту, налаштування |

:::info Цікаво
`record` — не окремий вид типу, а звичайний клас, для якого компілятор
дописав купу коду. Ви можете подивитися згенерований результат на сайті
sharplab.io — там видно, що з одного рядка `record Track(...)` виходить
близько сімдесяти рядків звичайного C#.
:::

У цьому курсі ми пишемо класи вручну — важливо розуміти, що саме `record`
робить за вас. Але знайте, що в сучасному коді він трапляється постійно.

## Типові помилки

**Забути, що конструктор за замовчуванням зникає.** Написали свій конструктор
з параметрами — `new Student()` більше не працює. Якщо потрібні обидва варіанти,
оголосіть порожній конструктор явно.

**Дублювати логіку в кількох конструкторах.** Замість копіювання присвоєнь
використовуйте ланцюжок `: this(...)` і одну «головну» точку створення.

**Звертатися до нестатичного поля зі статичного методу.** Компілятор не пропустить.
Статичний метод не має об'єкта, отже, не має і його полів.

**Робити `static` усе підряд «щоб було зручно».** Змінюваний статичний стан —
це глобальна змінна. Використовуйте `static` для утиліт і констант, а не
для зберігання даних програми.

**Вважати, що ініціалізатор об'єкта — це конструктор.** Ні: спершу спрацьовує
конструктор без параметрів, а лише потім присвоюються властивості. Якщо
конструктора без параметрів немає, ініціалізатор без аргументів не скомпілюється.
