# Біт, байт і представлення даних

Перш ніж говорити про типи даних, треба розібратися, у чому взагалі комп'ютер зберігає
числа. Без цього таблиця типів із діапазонами на кшталт «від −32 768 до 32 767»
виглядає набором випадкових чисел, які доводиться зубрити. Насправді ці числа
виводяться за півхвилини.

## Біт

**Біт** (від англ. *binary digit* — двійкова цифра) — найменша одиниця інформації.
Біт має рівно два стани: `0` або `1`.

Причина такого вибору фізична. Усередині процесора стан зберігається напругою:
є напруга — `1`, немає — `0`. Розрізнити два стани надійно легко. Розрізнити десять
рівнів напруги (щоб зберігати десяткову цифру) — важко, бо завади зіпсують результат.
Саме тому вся обчислювальна техніка двійкова.

Один біт дає 2 варіанти. Два біти — 4 комбінації (`00`, `01`, `10`, `11`).
Три біти — 8. Закономірність:

> **N бітів дають 2^N різних комбінацій.**

| Бітів | Комбінацій (2^N) | Що можна закодувати |
|-------|------------------|---------------------|
| 1 | 2 | Так / ні |
| 2 | 4 | Пора року |
| 3 | 8 | День тижня (з запасом) |
| 4 | 16 | Одна шістнадцяткова цифра |
| 8 | 256 | Символ ASCII, відтінок кольору |
| 16 | 65 536 | Символ Unicode |
| 32 | 4 294 967 296 | Ціле число `int` |

## Байт

**Байт** — група з **8 бітів**. Байт — найменша одиниця, яку процесор адресує в пам'яті:
звернутися до окремого біта напряму не можна, тільки до байта цілком.

Один байт має 2⁸ = **256** можливих значень: від `0` до `255`, якщо без знака.

### Похідні одиниці

| Одиниця | Скільки байтів | Приблизно |
|---------|----------------|-----------|
| 1 кілобайт (КБ) | 1024 | Сторінка тексту |
| 1 мегабайт (МБ) | 1024 КБ ≈ 1 млн | Фотографія |
| 1 гігабайт (ГБ) | 1024 МБ ≈ 1 млрд | Фільм |
| 1 терабайт (ТБ) | 1024 ГБ | Жорсткий диск |

:::note[Чому 1024, а не 1000]
Бо 1024 = 2¹⁰ — «кругле» число у двійковій системі. Через це виробники дисків
і операційні системи рахують по-різному: диск «на 1 ТБ» у Windows показується
як ~931 ГБ. Диск не обманув — це та сама кількість байтів, порахована з основою 1024
замість 1000.
:::

## Звідки беруться діапазони типів

Тепер найголовніше. Візьмемо тип, що займає `N` бітів.

**Без знака** (тільки додатні): всі 2^N комбінацій ідуть на значення від `0`
до `2^N − 1`.

> `byte` — 8 бітів → від **0** до **255** (тобто 2⁸ − 1).

**Зі знаком** (додатні й від'ємні): один біт витрачається на знак, значення
діляться навпіл:

> від **−2^(N−1)** до **2^(N−1) − 1**

Перевіримо на типі `short` (16 бітів):

- −2¹⁵ = −32 768
- 2¹⁵ − 1 = 32 767

Саме ці числа й стоять у таблицях типів. Їх не треба запам'ятовувати — достатньо
знати розрядність і формулу.

:::tip[Чому додатних на одиницю менше]
Бо нуль теж займає одну комбінацію, і його віднесли до «додатної» половини.
Тому діапазон несиметричний: `−128…127`, а не `−128…128`.
:::

### Перевірка в коді

У C# межі кожного типу доступні як константи — їх не треба пам'ятати:

```csharp
Console.WriteLine(byte.MinValue);    // 0
Console.WriteLine(byte.MaxValue);    // 255

Console.WriteLine(short.MinValue);   // -32768
Console.WriteLine(short.MaxValue);   // 32767

Console.WriteLine(int.MinValue);     // -2147483648
Console.WriteLine(int.MaxValue);     // 2147483647
```

## Що буває, коли значення не вміщається

Спробуємо покласти в `byte` число, більше за 255:

```csharp
byte b = 300;   // ❌ помилка компіляції: константа не вміщається в byte
```

Компілятор помітив це одразу, бо число відоме заздалегідь. Але якщо значення
обчислюється під час виконання, перевірки не буде:

```csharp
byte b = 250;
b = (byte)(b + 10);          // очікуємо 260
Console.WriteLine(b);        // насправді виведе 4
```

Результат `260` не вміщається у 8 бітів. Старший біт просто відкидається, і
залишається `260 − 256 = 4`. Це називають **переповненням** (overflow), і саме
воно стоїть за багатьма historично відомими збоями — від «зникнення» рекордів
в іграх до аварії ракети Ariane 5.

:::warning
Переповнення — логічна помилка з минулої теми у чистому вигляді: програма не падає,
нічого не повідомляє, а результат неправильний. Детально способи захисту
(`checked`, `unchecked`) розглянемо в темі 3.
:::

## Як кодуються не тільки числа

Будь-які дані в пам'яті — це байти. Різниця лише в **домовленості**, як їх тлумачити:

| Дані | Як кодуються |
|------|--------------|
| Ціле число | Двійкове представлення значення |
| Символ | Номер символу в таблиці Unicode (`'A'` → 65) |
| Текст | Послідовність номерів символів |
| Колір | Три байти: червоний, зелений, синій (0–255 кожен) |
| Зображення | Масив кольорів пікселів |
| Звук | Числові значення амплітуди через рівні проміжки часу |

Один і той самий байт `01000001` — це число `65`, символ `'A'` або відтінок сірого,
залежно від того, яким типом ми його оголосили. **Тип даних — це і є та домовленість,
як тлумачити байти.**

```csharp
char symbol = 'A';
int code = symbol;           // неявне перетворення символу в його код

Console.WriteLine(code);     // 65
Console.WriteLine((char)66); // B — той самий байт, інше тлумачення
```

## Висновок

- **Біт** — 0 або 1; **байт** — 8 бітів, найменша адресована одиниця пам'яті.
- `N` бітів дають **2^N** комбінацій — звідси всі діапазони типів.
- Без знака: `0 … 2^N − 1`. Зі знаком: `−2^(N−1) … 2^(N−1) − 1`.
- Межі типів не треба вчити напам'ять — є константи `int.MaxValue`, `byte.MinValue` тощо.
- **Переповнення** виникає, коли результат не вміщається в тип; програма при цьому
  не падає, а тихо видає неправильне число.
- Тип даних — це домовленість про те, як тлумачити байти в пам'яті.
