# Структура програми

Коли ви створите в Visual Studio новий консольний проєкт, у файлі `Program.cs`
побачите один рядок. Коли відкриєте будь-який підручник — побачите одинадцять.
Обидва варіанти правильні, і зараз розберемо, звідки береться різниця.

## Класична структура

Історично програма на C# складалася з чотирьох вкладених рівнів:

```csharp
using System;                             // 1. підключення просторів імен

namespace HelloApp                        // 2. простір імен
{
    class Program                         // 3. клас
    {
        static void Main(string[] args)   // 4. метод Main — точка входу
        {
            Console.WriteLine("Привіт!"); // 5. тіло програми
        }
    }
}
```

Розберемо кожен рівень окремо.

### 1. Директива `using`

**Простір імен** (namespace) — це «прізвище» для класів. Клас `Console` насправді
має повне ім'я `System.Console`. Директива `using System;` дозволяє писати просто
`Console`, не вказуючи щоразу повний шлях.

```csharp
// Без using — повне ім'я щоразу
System.Console.WriteLine("Привіт!");

// З using System; — коротко
Console.WriteLine("Привіт!");
```

Навіщо взагалі простори імен? Щоб уникнути **конфлікту імен**. У великій програмі
цілком може бути два різні класи `Timer` — один для таймера в інтерфейсі, інший
для вимірювання часу. Повні імена `System.Windows.Forms.Timer` і `System.Timers.Timer`
розрізняють їх однозначно.

| Простір імен | Що містить |
|--------------|------------|
| `System` | Базові типи, `Console`, `Math`, `String` |
| `System.Collections.Generic` | Списки, словники — тема 10 |
| `System.IO` | Робота з файлами — тема 13 |
| `System.Linq` | Запити до колекцій — тема 12 |

:::note[Неявні using]
У сучасних проєктах (.NET 6+) рядок `using System;` зазвичай відсутній, але `Console`
все одно працює. Це функція **implicit usings**: компілятор сам підключає найпоширеніші
простори імен. Побачити їх перелік можна у файлі `obj/Debug/.../GlobalUsings.g.cs`.
:::

### 2. Простір імен програми

```csharp
namespace HelloApp
{
    // весь код проєкту
}
```

Зазвичай його ім'я збігається з назвою проєкту. Сучасний C# дозволяє скоротити запис —
**file-scoped namespace**, без дужок і зайвого рівня вкладеності:

```csharp
namespace HelloApp;      // крапка з комою замість блока

class Program
{
    // ...
}
```

### 3. Клас

**Клас** — основний будівельний блок C#. У класичній структурі будь-який код має
лежати всередині класу: у C# не буває «вільних» функцій, як у C чи Python.

```csharp
class Program
{
    // поля, методи, властивості
}
```

Детально класи розглянемо в темі 6. Поки що `class Program` — просто обов'язкова
обгортка.

### 4. Метод `Main` — точка входу

```csharp
static void Main(string[] args)
{
    // код
}
```

Коли операційна система запускає програму, вона має знати, з якого рядка починати.
Цим рядком є **`Main`** — і саме тому до нього стільки вимог:

| Частина | Що означає |
|---------|------------|
| `static` | Метод належить класу, а не об'єкту — його можна викликати, не створюючи об'єкт |
| `void` | Метод нічого не повертає (може повертати `int` — код завершення) |
| `Main` | Ім'я з великої літери — саме його шукає середовище виконання |
| `string[] args` | Аргументи командного рядка (може бути відсутнім) |

:::info[Що таке args]
Якщо запустити програму з консолі командою `MyApp.exe Олена 20`, то в масиві `args`
опиниться `["Олена", "20"]`. Так програмі передають параметри без діалогу
з користувачем — саме так працюють усі консольні утиліти.
:::

Точка входу в програмі має бути **рівно одна**. Два методи `Main` у різних класах —
помилка компіляції, бо середовище не знає, з якого починати.

## Сучасна структура: top-level statements

З C# 9 (2020) усю обгортку можна не писати:

```csharp
Console.WriteLine("Привіт!");
```

Це називається **top-level statements** — інструкції верхнього рівня. Компілятор
сам генерує клас і метод `Main`, а ваш код ставить усередину. Тобто обгортка
нікуди не поділася — просто її тепер пише компілятор.

Обмеження: такий файл у проєкті може бути **тільки один** — інакше знову виникне
питання, де точка входу.

```csharp
// Program.cs — сучасний стиль
Console.Write("Як вас звати? ");
string name = Console.ReadLine();

Console.WriteLine($"Вітаю, {name}!");
```

:::tip[Який стиль використовувати]
У навчальних консольних задачах — сучасний, менше шуму навколо суті.
Класичну структуру треба **вміти читати**, бо в неї ви впираєтеся щоразу, коли
відкриваєте чужий код або старіший приклад з інтернету.

Коли в темі 4 дійдемо до власних методів, обгортка з класом повернеться —
методи мають десь жити.
:::

## Інструкції та блоки

**Інструкція** (statement) — одна завершена дія, що закінчується `;`.

```csharp
int a = 5;                    // оголошення зі значенням
a = a + 1;                    // присвоєння
Console.WriteLine(a);         // виклик методу
```

**Блок** — група інструкцій у фігурних дужках, що сприймається як одне ціле.

```csharp
if (a > 0)
{
    Console.WriteLine("Додатне");
    a = 0;
}
```

## Повний приклад із поясненням

Програма, що питає ім'я і рік народження та виводить вік:

```csharp
// Просимо ввести ім'я
Console.Write("Ваше ім'я: ");
string name = Console.ReadLine();

// Просимо рік народження і перетворюємо текст на число
Console.Write("Рік народження: ");
int birthYear = int.Parse(Console.ReadLine());

// Обчислюємо вік
int currentYear = DateTime.Now.Year;
int age = currentYear - birthYear;

// Виводимо результат
Console.WriteLine($"{name}, вам приблизно {age} років.");
```

Що тут нового:

- **`Console.Write`** проти **`Console.WriteLine`** — перший не переводить курсор
  на новий рядок, тому запрошення і відповідь користувача стоять в одному рядку;
- **`Console.ReadLine()`** читає рядок із клавіатури й **завжди повертає `string`**,
  навіть якщо користувач увів число;
- **`int.Parse(...)`** перетворює текст на число. Без нього `"2005" - 5` не має сенсу;
- **`$"..."`** — інтерпольований рядок: вирази у фігурних дужках підставляються
  у текст. Зручніше за склеювання через `+`;
- **`DateTime.Now.Year`** — поточний рік із системного годинника.

:::warning
`int.Parse` впаде з помилкою, якщо користувач введе не число. Поки що просто
не вводьте текст там, де очікується число; надійний спосіб (`int.TryParse`)
розберемо в темі 3.
:::

## Порядок виконання

Інструкції виконуються **згори вниз, одна за одною** — це те саме слідування
з попередньої теми. Порядок не можна порушувати довільно:

```csharp
Console.WriteLine(sum);     // ❌ помилка: sum ще не існує
int sum = 2 + 2;
```

Змінну треба спочатку оголосити, і лише потім використовувати.

## Висновок

- Класична структура програми має чотири рівні: `using` → `namespace` → `class` → `Main`.
- **`Main`** — точка входу, з неї починається виконання; вона має бути рівно одна
  і бути `static`.
- **Простори імен** запобігають конфліктам імен; `using` дозволяє не писати
  повне ім'я класу щоразу.
- **Top-level statements** (C# 9+) дозволяють не писати обгортку — компілятор
  генерує її сам; такий файл у проєкті може бути один.
- Інструкція завершується `;`, блок обмежується `{ }`, виконання йде згори вниз.
- `Console.ReadLine()` завжди повертає **рядок** — для числа потрібне перетворення
  через `int.Parse`.
