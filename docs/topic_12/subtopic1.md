# Текстові файли: читання і запис

## Два рівні API

У .NET є два способи працювати з текстовим файлом, і вибір між ними — перше,
що треба зрозуміти в цій темі.

**Простий спосіб** — статичні методи класу `File`. Один рядок коду: «прочитай
мені весь файл» або «запиши цей текст».

**Потоковий спосіб** — класи `StreamReader` і `StreamWriter`. Файл читається
або пишеться порціями, рядок за рядком, і в пам'яті ніколи не лежить більше,
ніж один рядок.

Різниця не в тому, який «правильніший». Різниця у **пам'яті**.

## Простий спосіб: методи класу File

```csharp
string path = "notes.txt";

// ЗАПИС: створює файл або ПЕРЕЗАПИСУЄ наявний
File.WriteAllText(path, "Перший рядок\nДругий рядок");

// ДОПИС у кінець
File.AppendAllText(path, "\nТретій рядок");

// ЧИТАННЯ всього файлу одним рядком
string content = File.ReadAllText(path);
Console.WriteLine(content);

Console.WriteLine("---");

// ЧИТАННЯ по рядках у масив
string[] lines = File.ReadAllLines(path);
Console.WriteLine($"Рядків у файлі: {lines.Length}");
for (int i = 0; i < lines.Length; i++)
{
    Console.WriteLine($"{i + 1}: {lines[i]}");
}
```

**Вивід:**

```
Перший рядок
Другий рядок
Третій рядок
---
Рядків у файлі: 3
1: Перший рядок
2: Другий рядок
3: Третій рядок
```

Повний набір методів:

| Метод | Що робить |
| --- | --- |
| `File.ReadAllText(path)` | читає весь файл в один рядок |
| `File.ReadAllLines(path)` | читає файл у масив рядків |
| `File.WriteAllText(path, text)` | записує рядок, **перезаписуючи** файл |
| `File.WriteAllLines(path, array)` | записує масив рядків, кожен з нового рядка |
| `File.AppendAllText(path, text)` | дописує в кінець |
| `File.AppendAllLines(path, array)` | дописує масив рядків у кінець |
| `File.ReadAllBytes(path)` | читає файл у масив байтів |
| `File.WriteAllBytes(path, bytes)` | записує масив байтів |

Особливо зручний `WriteAllLines` із масивом:

```csharp
string[] students = ["Олена", "Тарас", "Марія", "Богдан"];
File.WriteAllLines("group.txt", students);

// і назад
string[] loaded = File.ReadAllLines("group.txt");
Console.WriteLine($"Завантажено {loaded.Length} студентів: {string.Join(", ", loaded)}");
```

**Вивід:**

```
Завантажено 4 студентів: Олена, Тарас, Марія, Богдан
```

:::danger Часта помилка
`WriteAllText` і `WriteAllLines` **знищують** старий вміст файлу без жодного
попередження. Якщо ви хотіли додати рядок у журнал, а написали
`WriteAllText` — журналу більше немає. Дописування — це `AppendAllText`
і `AppendAllLines`.
:::

:::tip Порада
Усі ці методи створюють файл, якщо його немає, і створюють його порожнім,
якщо він є. Але **папку** вони не створюють: якщо шлях веде в неіснуючу
папку, буде `DirectoryNotFoundException`. Тому перед записом корисно
викликати `Directory.CreateDirectory(Path.GetDirectoryName(path)!)`.
:::

## Потік як труба

Тепер про другий спосіб. Щоб зрозуміти, навіщо він, треба уявити, що таке
потік.

**Потік** (англ. *stream*) — це абстракція «послідовність даних, яку читають
або пишуть по шматочку». Думайте про нього як про трубу між вашою програмою
і диском.

```
        ЗАПИС (StreamWriter)

  Програма                    Буфер у пам'яті              Файл на диску
  ┌──────────┐   WriteLine   ┌─────────────────┐  Flush   ┌───────────────┐
  │ "Олена"  │──────────────▶│ Олена\nТарас\n  │─────────▶│  group.txt    │
  │ "Тарас"  │──────────────▶│                 │          │               │
  └──────────┘               └─────────────────┘          └───────────────┘
                              накопичує, поки             реально пишеться
                              не набереться порція        рідко, великими
                                                          порціями


        ЧИТАННЯ (StreamReader)

  Файл на диску              Буфер у пам'яті             Програма
  ┌───────────────┐         ┌─────────────────┐  ReadLine ┌──────────┐
  │  group.txt    │────────▶│ Олена\nТарас\n  │──────────▶│ "Олена"  │
  │  (1 ГБ)       │         │  (4 КБ за раз)  │──────────▶│ "Тарас"  │
  └───────────────┘         └─────────────────┘           └──────────┘
                             у пам'яті лише              обробляємо
                             маленький шматок            по одному рядку
```

Ключова ідея: **у пам'яті ніколи не лежить весь файл**. Це і є та перевага,
заради якої існують потоки.

`File.ReadAllText` для файлу на 2 ГБ спробує створити рядок на 2 ГБ у пам'яті
і майже напевно впаде з `OutOfMemoryException`. `StreamReader` прочитає той
самий файл, використавши кілька кілобайтів.

:::info Цікаво
Насправді `File.ReadAllText` усередині теж використовує `StreamReader` —
просто читає до кінця і повертає все одразу. Тобто «простий спосіб» — це
обгортка над «потоковим». Метод `File.ReadAllLines` так само робить цикл
`ReadLine` у масив.
:::

## StreamWriter: запис

```csharp
string path = "journal.txt";

using (StreamWriter writer = new StreamWriter(path, append: false))
{
    writer.WriteLine("=== Журнал відвідування ===");
    writer.WriteLine($"Дата: {DateTime.Now:dd.MM.yyyy}");
    writer.WriteLine();
    writer.WriteLine("Олена — присутня");
    writer.Write("Тарас — ");        // Write не переходить на новий рядок
    writer.WriteLine("відсутній");
}   // ← тут файл закривається і дані гарантовано потрапляють на диск

Console.WriteLine(File.ReadAllText(path));
```

**Вивід:**

```
=== Журнал відвідування ===
Дата: 14.09.2026

Олена — присутня
Тарас — відсутній
```

Другий аргумент конструктора вирішує долю старого вмісту:

| Аргумент | Що робить |
| --- | --- |
| `append: false` (за замовчуванням) | перезаписує файл з нуля |
| `append: true` | дописує в кінець наявного |

Методи `StreamWriter`:

| Метод | Що робить |
| --- | --- |
| `Write(значення)` | пише без переходу на новий рядок |
| `WriteLine(значення)` | пише і переходить на новий рядок |
| `WriteLine()` | просто порожній рядок |
| `Flush()` | негайно скидає буфер на диск |
| `Dispose()` / `Close()` | скидає буфер і закриває файл |

:::tip Порада
`Write` і `WriteLine` приймають не лише рядки, а й числа, `bool`, `DateTime`
і будь-що інше — вони самі викликають `ToString()`. І інтерполяція тут
працює так само, як у `Console.WriteLine`:

```csharp
writer.WriteLine($"{name,-15} {score,5:F2}");
```
:::

## StreamReader: читання

```csharp
using (StreamReader reader = new StreamReader("journal.txt"))
{
    string? line;
    int number = 0;

    while ((line = reader.ReadLine()) != null)
    {
        number++;
        Console.WriteLine($"{number,3}: {line}");
    }
}
```

**Вивід:**

```
  1: === Журнал відвідування ===
  2: Дата: 14.09.2026
  3: 
  4: Олена — присутня
  5: Тарас — відсутній
```

### Розбираємо цей while

Рядок `while ((line = reader.ReadLine()) != null)` виглядає загадково,
але це класика, яку варто прочитати уважно — ви бачитимете її постійно.

```
while (   (line = reader.ReadLine())   !=   null   )
           └──────────┬──────────┘
                      │
      1. викликаємо ReadLine() — читаємо наступний рядок
      2. присвоюємо результат змінній line
      3. вираз присвоєння САМ повертає це значення
      4. порівнюємо його з null
      5. якщо не null — заходимо в тіло циклу
```

`ReadLine()` повертає `null`, коли рядки скінчились. Це **єдина** ознака
кінця файлу — не порожній рядок (`""` — це нормальний порожній рядок
у файлі), а саме `null`.

Ті самі три кроки можна написати довше й зрозуміліше:

```csharp
using StreamReader reader = new StreamReader("journal.txt");

while (true)
{
    string? line = reader.ReadLine();
    if (line == null) break;

    Console.WriteLine(line);
}
```

Або через властивість `EndOfStream`:

```csharp
using StreamReader reader = new StreamReader("journal.txt");

while (!reader.EndOfStream)
{
    string line = reader.ReadLine()!;
    Console.WriteLine(line);
}
```

Усі три варіанти рівноцінні. Перший — найкоротший і найпоширеніший,
третій — найзрозуміліший для початківця.

:::danger Часта помилка
Не плутайте «порожній рядок» і «кінець файлу»:

```csharp
while (line != "")   // ← НЕПРАВИЛЬНО: цикл обірветься на першому
{                    //   порожньому рядку всередині файлу
    ...
}
```

Умова — тільки `!= null`.
:::

Інші методи `StreamReader`:

| Метод | Що робить |
| --- | --- |
| `ReadLine()` | читає один рядок; `null` у кінці файлу |
| `ReadToEnd()` | читає весь залишок в один рядок |
| `Read()` | читає **один символ**; `-1` у кінці |
| `Peek()` | «підглядає» наступний символ, не читаючи його |
| `EndOfStream` | властивість: чи досягли кінця |

## using: чому без нього не можна

Це найважливіший практичний момент підрозділу.

Коли ви відкриваєте файл на запис, операційна система **блокує** його:
жодна інша програма (і навіть ваша власна) не зможе його відкрити,
доки ви не закриєте.

Подивіться, що станеться без `using`:

```csharp
StreamWriter writer = new StreamWriter("data.txt");
writer.WriteLine("Дуже важливі дані");

// забули writer.Close();

string text = File.ReadAllText("data.txt");   // ← вибух
Console.WriteLine(text);
```

**Вивід:**

```
Unhandled exception. System.IO.IOException: The process cannot access the file
'C:\Projects\Demo\bin\Debug\net8.0\data.txt' because it is being used by
another process.
```

«Інший процес» — це ви самі. Файл досі відкритий на запис.

І це ще не все. Дані, які ви записали, можуть узагалі **не потрапити на диск**:
`StreamWriter` накопичує їх у буфері й скидає порціями. Якщо файл не закрити,
останній шматок так і залишиться в пам'яті, а програма завершиться — і його
не буде.

З `using` обидві проблеми зникають:

```csharp
using (StreamWriter writer = new StreamWriter("data.txt"))
{
    writer.WriteLine("Дуже важливі дані");
}   // ← Dispose(): буфер скинуто, файл закрито

string text = File.ReadAllText("data.txt");   // працює
Console.WriteLine(text);
```

**Вивід:**

```
Дуже важливі дані
```

`using` розгортається компілятором у `try/finally` — той самий, що ми
розбирали в темі про винятки:

```csharp
StreamWriter writer = new StreamWriter("data.txt");
try
{
    writer.WriteLine("Дуже важливі дані");
}
finally
{
    writer.Dispose();     // виконається навіть при винятку
}
```

Саме тому `using` надійніший за ручний `Close()`: якщо всередині блоку
станеться виняток, `Close()` пропуститься, а `Dispose()` — ні.

### using-оголошення

З C# 8 є коротша форма без зайвих дужок:

```csharp
using StreamWriter writer = new StreamWriter("data.txt");

writer.WriteLine("Рядок 1");
writer.WriteLine("Рядок 2");

// Dispose() викличеться в кінці блоку, у якому оголошено writer
```

| Форма | Коли зручніша |
| --- | --- |
| `using (...) { ... }` | треба, щоб файл закрився **раніше** кінця методу; кілька файлів по черзі |
| `using ... ;` | файл потрібен до кінця методу; менше вкладеності |

:::warning Обережно
Класична пастка з `using`-оголошенням: ви пишете у файл, а потім у тому ж
методі хочете його прочитати. Файл ще не закритий — буде `IOException`.
У такому випадку потрібна форма з дужками, щоб явно обмежити час життя:

```csharp
using (StreamWriter w = new StreamWriter("a.txt"))
{
    w.WriteLine("текст");
}   // ← тут закрився

string s = File.ReadAllText("a.txt");   // тепер можна
```
:::

:::note
Прості методи `File.WriteAllText` і `File.ReadAllText` не потребують `using`:
вони відкривають і закривають файл усередині себе. Це ще одна причина, чому
для маленьких файлів вони зручніші.
:::

## Кодування: звідки беруться кракозябри

Файл на диску — це послідовність **байтів**. Байт — це число від 0 до 255.
Літера — це не число. Отже, потрібна таблиця відповідності: який байт
(чи група байтів) яку літеру означає. Ця таблиця називається **кодуванням**.

Проблема в тому, що кодувань багато:

| Кодування | Скільки байтів на символ | Кирилиця |
| --- | --- | --- |
| ASCII | 1 | ❌ немає взагалі |
| Windows-1251 | 1 | ✅ є (стара українська/російська кодова сторінка) |
| KOI8-U | 1 | ✅ є (зовсім стара) |
| UTF-8 | 1 для латиниці, 2 для кирилиці, 3–4 для решти | ✅ є |
| UTF-16 | 2 або 4 | ✅ є (внутрішній формат рядків у .NET) |

Якщо файл записали в одному кодуванні, а читають в іншому, байти
інтерпретуються за чужою таблицею — і замість «Привіт» з'являється
«Ïðèâ³ò» або «������». Це і є **кракозябри**.

```
Записали "Привіт" у UTF-8:
байти:  D0 9F D1 80 D0 B8 D0 B2 D1 96 D1 82

Читаємо ті самі байти як Windows-1251:
D0 → Р     9F → Ÿ     D1 → С     80 → €    ...
результат: "РЯС€РёРІС–С‚"
```

### Добра новина

У **.NET 8 кодування за замовчуванням — UTF-8** для всіх файлових операцій.
Якщо і пишете, і читаєте своєю ж програмою — проблем не буде взагалі.

Явно вказати кодування можна так:

```csharp
using System.Text;

// Запис у UTF-8 (це і так за замовчуванням)
File.WriteAllText("ua.txt", "Привіт, світе!", Encoding.UTF8);

using (StreamWriter w = new StreamWriter("ua2.txt", false, Encoding.UTF8))
{
    w.WriteLine("Привіт з потоку");
}

// Читання зі старого файлу у Windows-1251
Encoding win1251 = Encoding.GetEncoding(1251);
string oldText = File.ReadAllText("old.txt", win1251);
```

:::warning Обережно
Кодування Windows-1251 у .NET 8 «з коробки» не зареєстроване — ви отримаєте
`NotSupportedException`. Щоб воно запрацювало, треба один раз на початку
програми написати:

```csharp
using System.Text;
Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
```

Це знадобиться, лише якщо ви відкриваєте старі файли, створені у Windows
до 2010-х. Для нових завжди беріть UTF-8.
:::

### Кракозябри у консолі, а не у файлі

Буває, що файл записаний правильно, а в консолі все одно каша. Тоді проблема
не у файлі, а у виводі. Лікується одним рядком на початку програми:

```csharp
using System.Text;
Console.OutputEncoding = Encoding.UTF8;
```

:::info Цікаво
UTF-8 придумали Кен Томпсон і Роб Пайк 1992 року, начебто на серветці
в закусочній. Геніальність рішення в тому, що перші 128 символів у ньому
збігаються з ASCII: старі англомовні програми читають UTF-8-файли без змін,
а всі інші мови світу дописані «зверху» за допомогою послідовностей
із двох-чотирьох байтів. Сьогодні понад 98% сторінок в інтернеті —
у UTF-8.
:::

## Читання великого файлу порядково

Задача, заради якої існують потоки. Уявіть лог-файл на 500 МБ, у якому треба
порахувати рядки зі словом `ERROR`.

**Неправильно:**

```csharp
string all = File.ReadAllText("server.log");   // 500 МБ у пам'ять!
```

**Правильно:**

```csharp
string path = "server.log";
int errorCount = 0;
int totalLines = 0;

using (StreamReader reader = new StreamReader(path))
{
    string? line;
    while ((line = reader.ReadLine()) != null)
    {
        totalLines++;
        if (line.Contains("ERROR"))
        {
            errorCount++;
            if (errorCount <= 5)
            {
                Console.WriteLine($"  рядок {totalLines}: {line}");
            }
        }
    }
}

Console.WriteLine($"Оброблено рядків: {totalLines}");
Console.WriteLine($"Знайдено помилок: {errorCount}");
```

**Вивід:**

```
  рядок 42: 2026-09-14 08:11:03 ERROR Не вдалося підключитися до бази
  рядок 118: 2026-09-14 08:15:47 ERROR Таймаут запиту
  рядок 903: 2026-09-14 09:02:12 ERROR Файл конфігурації пошкоджено
Оброблено рядків: 2 481 337
Знайдено помилок: 3
```

Два з половиною мільйони рядків — і в пам'яті ніколи не було більше одного.

## Коли який спосіб

| Ситуація | `File.*` | `StreamReader` / `StreamWriter` |
| --- | --- | --- |
| Файл маленький (до кількох МБ) | ✅ простіше | можна, але зайве |
| Файл великий (сотні МБ, ГБ) | ❌ `OutOfMemoryException` | ✅ єдиний варіант |
| Треба весь текст одразу як рядок | ✅ `ReadAllText` | доведеться `ReadToEnd` |
| Треба обробляти по рядку і не тримати все | ❌ | ✅ |
| Багато дописувань у циклі | ❌ повільно: файл відкривається щоразу | ✅ один раз відкрили — пишемо |
| Один короткий запис | ✅ один рядок коду | зайва церемонія |
| Потрібне `using` | ❌ не потрібне | ✅ обов'язкове |
| Читабельність навчального коду | ✅ | трохи більше рядків |

Про «багато дописувань» варто сказати окремо. Ось як **не треба**:

```csharp
// ПОГАНО: 10 000 разів відкриваємо і закриваємо файл
for (int i = 0; i < 10_000; i++)
{
    File.AppendAllText("log.txt", $"Рядок {i}\n");
}
```

```csharp
// ДОБРЕ: відкрили один раз
using (StreamWriter writer = new StreamWriter("log.txt", append: true))
{
    for (int i = 0; i < 10_000; i++)
    {
        writer.WriteLine($"Рядок {i}");
    }
}
```

Другий варіант швидший у десятки разів. Це найпоказовіший випадок, коли
потоки виграють не через пам'ять, а через швидкість.

## Обробка помилок при читанні

Файлові операції — класичний випадок, коли `try/catch` обов'язковий:
причини збоїв від вас не залежать.

```csharp
string path = "settings.txt";

try
{
    using StreamReader reader = new StreamReader(path);
    string? line;
    while ((line = reader.ReadLine()) != null)
    {
        Console.WriteLine(line);
    }
}
catch (FileNotFoundException)
{
    Console.WriteLine($"Файл {Path.GetFullPath(path)} не знайдено.");
}
catch (DirectoryNotFoundException)
{
    Console.WriteLine("Папка, вказана у шляху, не існує.");
}
catch (UnauthorizedAccessException)
{
    Console.WriteLine("Немає прав доступу до файлу.");
}
catch (IOException ex)
{
    Console.WriteLine($"Помилка вводу-виводу: {ex.Message}");
}
```

Зверніть увагу на порядок: `FileNotFoundException` і
`DirectoryNotFoundException` — нащадки `IOException`, тому загальний
`catch (IOException)` стоїть **останнім**. Якби він був першим, конкретні
блоки ніколи б не спрацювали (компілятор би на це поскаржився).

Докладна таблиця файлових винятків — у наступному підрозділі.

## Асинхронні варіанти: коротко наперед

У сучасному .NET майже кожен файловий метод має двійника з суфіксом `Async`:
`File.ReadAllTextAsync`, `File.WriteAllLinesAsync`, `reader.ReadLineAsync`.
Вони потрібні там, де програма не має «завмирати» під час звернення до диска
чи мережі — у застосунках з інтерфейсом, у веб-серверах, у мобільних
програмах. Виглядає це так:

```csharp
string content = await File.ReadAllTextAsync("big.txt");
```

Ключове слово `await` каже: «поки диск працює, звільни потік для інших справ,
а коли дані будуть готові — продовж звідси». Асинхронне програмування —
велика окрема тема з власними правилами, і ми до неї повернемось.
У консольних навчальних програмах синхронних методів цілком достатньо.

## Типові помилки

**1. Забути `using` і отримати `IOException`.**
Найчастіша помилка теми. Файл лишається заблокованим, дані — в буфері.
Правило просте: побачили `new StreamReader` або `new StreamWriter` —
попереду має бути `using`.

**2. Використати `WriteAllText` замість `AppendAllText`.**
Журнал відвідування, у якому щоразу один рядок, — класичний симптом.

**3. Обірвати цикл читання за порожнім рядком.**

```csharp
while ((line = reader.ReadLine()) != "")   // неправильно
while ((line = reader.ReadLine()) != null) // правильно
```

**4. Прочитати `ReadAllLines` і забути, що масив може бути порожнім.**

```csharp
string[] lines = File.ReadAllLines("empty.txt");
Console.WriteLine(lines[0]);   // IndexOutOfRangeException
```

Завжди перевіряйте `lines.Length` перед зверненням до елементів.

**5. Читати файл двічі підряд одним і тим самим `StreamReader`.**
Після `ReadToEnd()` потік стоїть у кінці, і повторний виклик поверне
порожній рядок. Щоб прочитати ще раз — створіть новий `StreamReader`.
