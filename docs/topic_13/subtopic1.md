# Dictionary\<K, V\> та HashSet\<T\>

## Задача, з якої почнемо

Треба порахувати, скільки разів кожне слово зустрічається у тексті.
Спробуймо зробити це тим, що вже вміємо — двома списками:

```csharp
string[] words = ["кіт", "пес", "кіт", "їжак", "кіт", "пес"];

List<string> uniqueWords = [];
List<int> counts = [];

foreach (string word in words)
{
    int index = uniqueWords.IndexOf(word); // шукаємо перебором!

    if (index == -1)
    {
        uniqueWords.Add(word);
        counts.Add(1);
    }
    else counts[index]++;
}

for (int i = 0; i < uniqueWords.Count; i++)
    Console.WriteLine($"{uniqueWords[i]}: {counts[i]}");
```

**Вивід:**

```
кіт: 3
пес: 2
їжак: 1
```

Працює. Але тут дві проблеми:

1. **Два паралельні списки треба тримати синхронними.** Забули `counts.Add(1)` —
   і все поїхало. Це класичне джерело помилок.
2. **`IndexOf` перебирає весь список щоразу.** Для тексту з 50 000 унікальних слів
   кожне нове слово вимагає до 50 000 порівнянь.

Потрібна структура, де можна сказати «дай мені значення за цим ключем» — і отримати
його одразу.

## Dictionary: масив із будь-якими ключами

**Словник** (`Dictionary<TKey, TValue>`) — колекція пар «ключ — значення»,
де ключ унікальний і за ним миттєво знаходиться значення.

Найпростіша аналогія — це масив, у якого замість номерів комірок може бути
будь-що: рядки, числа, дати.

```
Масив: індекси тільки цілі, підряд   Словник: ключі які завгодно
┌───┬───┬───┬───┐                    ┌────────┬─────┐
│ 0 │ 1 │ 2 │ 3 │  ← індекс          │ "кіт"  │  3  │
├───┼───┼───┼───┤                    │ "пес"  │  2  │
│ 7 │ 4 │ 9 │ 1 │  ← значення        │ "їжак" │  1  │
└───┴───┴───┴───┘                    └────────┴─────┘
                                       ключ  значення
```

### Створення і базові операції

```csharp
Dictionary<string, int> ages = new();   // ключ — рядок, значення — ціле

Dictionary<string, int> population = new()   // одразу з даними
{
    ["Київ"] = 2952000,
    ["Львів"] = 717000,
    ["Одеса"] = 993000
};

ages["Олена"] = 19;      // індексатор: додає або перезаписує
ages.Add("Тарас", 20);   // Add: кидає виняток, якщо ключ уже є

Console.WriteLine(ages["Олена"]);            // читання
ages["Олена"] = 20;                          // зміна
Console.WriteLine(ages.ContainsKey("Тарас")); // перевірка наявності
ages.Remove("Тарас");                        // видалення

Console.WriteLine($"Записів у словнику: {ages.Count}");
```

**Вивід:**

```
19
True
Записів у словнику: 1
```

:::warning[Обережно]
`Add` і індексатор поводяться по-різному, якщо ключ **уже існує**:

- `dict.Add("Олена", 19)` — кидає `ArgumentException`.
- `dict["Олена"] = 19` — просто перезаписує старе значення.

Якщо ви хочете «додати або оновити» — беріть індексатор. Якщо дублікат ключа
означає помилку в даних — беріть `Add`, хай програма про це скаже.
:::

### Три способи прочитати значення

Це місце, де студенти помиляються найчастіше.

**Спосіб 1: індексатор напряму — небезпечний**

```csharp
int age = ages["Богдан"]; // ← KeyNotFoundException, програма падає
```

:::danger[Часта помилка]
Звернення до неіснуючого ключа через індексатор кидає `KeyNotFoundException`.
Це не `null` і не нуль — це аварійне завершення програми.
:::

**Спосіб 2: ContainsKey, потім індексатор — працює, але подвійна робота**

```csharp
if (ages.ContainsKey("Богдан"))
    Console.WriteLine(ages["Богдан"]);
else
    Console.WriteLine("Такого немає");
```

Безпечно, але словник тут шукає ключ **двічі**: один раз у `ContainsKey`,
другий — в індексаторі.

**Спосіб 3: TryGetValue — правильний**

```csharp
if (ages.TryGetValue("Богдан", out int age))
    Console.WriteLine($"Вік: {age}");
else
    Console.WriteLine("Такого немає");
```

`TryGetValue` за **один** пошук робить дві речі: повертає `true`/`false`
і, якщо знайшов, кладе значення у змінну `age` через `out`.
Якщо не знайшов — у `age` буде значення за замовчуванням (`0` для чисел,
`null` для рядків).

| Спосіб | Коли використовувати | Коли не варто |
| --- | --- | --- |
| `dict[key]` | ви **впевнені**, що ключ є | коли ключа може не бути — впаде |
| `ContainsKey` + `dict[key]` | коли значення не потрібне, лише факт наявності | як спосіб «безпечно прочитати» — подвійний пошук |
| `TryGetValue` | завжди, коли треба **прочитати** можливо-відсутній ключ | коли значення взагалі не цікавить |
| `GetValueOrDefault(key)` | потрібне значення або нуль/`null`, без гілок | коли треба розрізнити «немає» і «є, але 0» |

:::tip[Порада]
Просте правило: **`TryGetValue` — за замовчуванням**. Він безпечний
і швидший за зв'язку `ContainsKey` плюс індексатор.
:::

Ще один зручний варіант — `GetValueOrDefault`:

```csharp
int bohdanAge = ages.GetValueOrDefault("Богдан");    // 0, якщо немає
int olenaAge = ages.GetValueOrDefault("Олена", -1);  // -1, якщо немає
Console.WriteLine($"{bohdanAge}, {olenaAge}");       // 0, 19
```

### Перебір словника: KeyValuePair

Коли ви пишете `foreach` по словнику, кожен елемент — це **пара**
типу `KeyValuePair<TKey, TValue>` з властивостями `Key` і `Value`.

```csharp
foreach (KeyValuePair<string, int> city in population)
{
    Console.WriteLine($"{city.Key}: {city.Value} мешканців");
}
```

Той самий цикл коротше — через `var` і **деконструкцію** пари на дві змінні:

```csharp
foreach (var (name, people) in population)
    Console.WriteLine($"{name}: {people} мешканців");
```

**Вивід:**

```
Київ: 2952000 мешканців
Львів: 717000 мешканців
Одеса: 993000 мешканців
```

Окремо можна перебирати тільки ключі або тільки значення:

```csharp
foreach (string city in population.Keys) Console.WriteLine(city);

int total = 0;
foreach (int people in population.Values) total += people;
Console.WriteLine($"Разом: {total}");
```

:::warning[Обережно]
Порядок перебору словника **не гарантований**: він не збігається ні з порядком
додавання, ні з алфавітним. Якщо порядок важливий — сортуйте ключі окремо або
візьміть `SortedDictionary<TKey, TValue>` (тримає ключі впорядкованими, але
пошук у ньому трохи повільніший).
:::

## HashSet: множина унікальних значень

**Множина** (`HashSet<T>`) зберігає значення без повторів і без гарантованого
порядку — це словник, у якого є лише ключі й немає значень.

```csharp
HashSet<string> genres = new();

genres.Add("рок");              // true — додалося
genres.Add("поп");              // true
bool added = genres.Add("рок"); // false — уже є, нічого не сталося

Console.WriteLine($"Спроба додати дубль: {added}");
Console.WriteLine($"Жанрів: {genres.Count}");
Console.WriteLine($"Є джаз? {genres.Contains("джаз")}");

genres.Remove("поп");
Console.WriteLine(string.Join(", ", genres));
```

**Вивід:**

```
Спроба додати дубль: False
Жанрів: 2
Є джаз? False
рок
```

`Add` повертає `bool` — і це часто дуже зручно:

```csharp
string[] logins = ["ira", "petro", "ira", "olha", "petro"];
HashSet<string> seen = new();

foreach (string login in logins)
{
    if (!seen.Add(login)) Console.WriteLine($"Дублікат логіна: {login}");
}
```

**Вивід:**

```
Дублікат логіна: ira
Дублікат логіна: petro
```

### Прибрати дублікати з List

```csharp
List<int> numbers = [3, 7, 3, 1, 7, 7, 9];
HashSet<int> unique = new(numbers);   // дублікати відсіялись самі
List<int> result = new(unique);
result.Sort();

Console.WriteLine(string.Join(", ", result)); // 1, 3, 7, 9
```

### Операції над множинами

Це те, чого немає в жодній іншій колекції: `HashSet` уміє математичні операції
над множинами. Усі вони змінюють **той набір, у якого викликані**.

```csharp
HashSet<string> mathGroup = ["Олена", "Тарас", "Ірина", "Петро"];
HashSet<string> sportGroup = ["Тарас", "Петро", "Богдан"];

HashSet<string> union = new(mathGroup);      // об'єднання: хто ходить хоч кудись
union.UnionWith(sportGroup);
Console.WriteLine($"Разом: {string.Join(", ", union)}");

HashSet<string> both = new(mathGroup);       // перетин: хто і туди, і туди
both.IntersectWith(sportGroup);
Console.WriteLine($"На обох: {string.Join(", ", both)}");

HashSet<string> onlyMath = new(mathGroup);   // різниця: тільки математика
onlyMath.ExceptWith(sportGroup);
Console.WriteLine($"Лише математика: {string.Join(", ", onlyMath)}");

HashSet<string> onlyOne = new(mathGroup);    // симетрична різниця
onlyOne.SymmetricExceptWith(sportGroup);
Console.WriteLine($"Лише в одній: {string.Join(", ", onlyOne)}");
```

**Вивід:**

```
Разом: Олена, Тарас, Ірина, Петро, Богдан
На обох: Тарас, Петро
Лише математика: Олена, Ірина
Лише в одній: Олена, Ірина, Богдан
```

```
   mathGroup                sportGroup
 ┌─────────────┐         ┌─────────────┐
 │  Олена      │         │             │
 │  Ірина      │ Тарас   │   Богдан    │
 │             │ Петро   │             │
 └─────────────┘         └─────────────┘
   ExceptWith    IntersectWith   (решта)
        └────────── UnionWith ─────────┘
```

:::note
Ці методи **змінюють** набір, у якого викликані. Тому ми щоразу робили копію
через `new HashSet<string>(mathGroup)`: без копії `mathGroup` зіпсується
і наступна операція дасть неправильний результат.
:::

Є ще методи-перевірки, які нічого не змінюють і повертають `bool`: `IsSubsetOf`
(«чи я всередині іншого»), `IsSupersetOf` і `Overlaps` («чи є спільні елементи»).

## Чому пошук тут швидкий: хешування «на пальцях»

Головне питання підрозділу: **чому `List.Contains` повільний, а
`HashSet.Contains` і `Dictionary.ContainsKey` — швидкі?**

### Як шукає List

Ніяк особливо — просто перебирає:

```
Шукаємо "їжак" у списку з 6 елементів:
┌──────┬──────┬───────┬──────┬───────┬───────┐
│ кіт  │ пес  │ лис   │ вовк │ їжак  │ борсук│
└──────┴──────┴───────┴──────┴───────┴───────┘
   1      2      3       4      5 ✓
                                 знайшли на 5-му кроці
```

У середньому — половина списку. Це **O(n)**: удвічі більший список — удвічі
довший пошук. У списку зі 100 000 елементів це 50 000 порівнянь рядків.

### Як шукає HashSet і Dictionary

Тут працює **хешування**. Ідея така:

1. Для кожного значення обчислюється **хеш-код** — ціле число, отримане
   з вмісту об'єкта за спеціальною формулою (метод `GetHashCode()`).
   Однакові значення завжди дають однаковий хеш.
2. Усередині колекції є масив **кошиків** (buckets). Номер кошика — це залишок
   від ділення хеша на кількість кошиків. Туди значення й кладуть.

Тепер, щоб знайти елемент, не треба нікого перебирати: обчислюємо хеш,
одразу знаємо номер кошика — і дивимось тільки в нього.

```
Кладемо "кіт": GetHashCode() = 91726351 → 91726351 % 8 = 7 → кошик 7
Кладемо "пес": GetHashCode() = 45810022 → 45810022 % 8 = 6 → кошик 6
Кладемо "лис": GetHashCode() = 33110918 → 33110918 % 8 = 6 → кошик 6 (зайнятий!)

  кошики
 ┌───┬──────────────────────────────┐
 │ 0 │ (порожньо)                   │
 │ 1 │ (порожньо)                   │
 │ 2 │ (порожньо)                   │
 │ 3 │ (порожньо)                   │
 │ 4 │ (порожньо)                   │
 │ 5 │ (порожньо)                   │
 │ 6 │ "пес" -> "лис"  ← колізія    │
 │ 7 │ "кіт"                        │
 └───┴──────────────────────────────┘

Пошук "кіт":  хеш → кошик 7 → там одразу "кіт".  1 перевірка.
Пошук "лис":  хеш → кошик 6 → перевіряємо "пес", потім "лис". 2 перевірки.
Пошук "тхір": хеш → кошик 3 → порожньо → елемента немає. 0 перевірок.
```

Ключове: **кількість перевірок не залежить від розміру колекції**. Хоч 10
елементів, хоч 10 мільйонів — ви дивитесь в один кошик, у якому зазвичай
один-два елементи. Це і називається **O(1)** — константний час. Ситуація, коли
два різних значення потрапляють в один кошик, називається **колізією**: колізії
неминучі, але їх мало, бо колекція збільшує кількість кошиків, коли стає тісно.

| Операція | `List<T>` | `Dictionary` / `HashSet` |
| --- | --- | --- |
| Пошук значення | O(n) — перебір | O(1) — по хешу |
| Додавання в кінець | O(1) у середньому | O(1) у середньому |
| Видалення за значенням | O(n) | O(1) |
| Доступ за індексом | O(1) | ❌ немає індексів |
| Збереження порядку | ✅ так | ❌ ні |
| Пам'ять | економно | більше (кошики з запасом) |

:::info[Цікаво]
За швидкість треба платити. `Dictionary` займає помітно більше пам'яті, ніж
`List` з тими самими даними: він тримає масив кошиків із запасом плюс службові
поля для кожного запису. Це класичний компроміс «пам'ять в обмін на швидкість»,
і у більшості задач він вигідний.
:::

:::warning[Обережно]
Хешування працює тільки якщо `GetHashCode()` для ваших значень поводиться
правильно. Для `int`, `string`, `double`, `DateTime`, `record` і кортежів усе
працює з коробки. Для власного класу доведеться подбати про `Equals`
і `GetHashCode` самостійно — це тема наступних розділів курсу.
:::

## Практичний приклад: частота слів у тексті

Повернімось до задачі з початку — тепер із словником.

```csharp
string text = """
    Кіт спить. Кіт їсть. Пес біжить.
    Кіт і пес дружать. Пес спить.
    """;

// розбиваємо на слова, прибираючи розділові знаки
char[] separators = [' ', '.', ',', '!', '?', ';', ':', '\n', '\r'];
string[] words = text.ToLower()
                     .Split(separators, StringSplitOptions.RemoveEmptyEntries);

Dictionary<string, int> frequency = new();

// якщо слово вже є — беремо його лічильник, інакше 0; додаємо одиницю
foreach (string word in words)
    frequency[word] = frequency.GetValueOrDefault(word) + 1;

// сортуємо ключі за спаданням частоти
List<string> sortedWords = new(frequency.Keys);
sortedWords.Sort((a, b) => frequency[b].CompareTo(frequency[a]));

Console.WriteLine($"Унікальних слів: {frequency.Count}");
Console.WriteLine("Найчастіші:");

for (int i = 0; i < 5 && i < sortedWords.Count; i++)
    Console.WriteLine($"  {sortedWords[i],-10} {frequency[sortedWords[i]]}");
```

**Вивід:**

```
Унікальних слів: 7
Найчастіші:
  кіт        3
  пес        3
  спить      2
  їсть       1
  біжить     1
```

Розберемо два неочевидні місця.

**Рядок з лічильником** — `frequency[word] = frequency.GetValueOrDefault(word) + 1;`
Якщо слова ще немає, `GetValueOrDefault` поверне `0`, і в словник запишеться `1`.
Якщо є — поверне поточне значення, і запишеться на одиницю більше.
Один рядок замість `if`/`else` з початку підрозділу.

**Сортування за значенням** — `sortedWords.Sort((a, b) => frequency[b].CompareTo(frequency[a]));`
Тут ми передаємо в `Sort` правило порівняння: «порівняй два слова за їхніми
частотами». Оскільки `b` стоїть першим — сортування виходить за спаданням.

:::tip[Порада]
Словник із лічильниками — один із найкорисніших шаблонів у програмуванні.
Підрахунок голосів, статистика символів, скільки товарів кожної категорії,
скільки помилок кожного типу в лозі — усе це той самий
`dict[key] = dict.GetValueOrDefault(key) + 1`.
:::

## Типові помилки

**1. Читати неіснуючий ключ через індексатор.**
`int x = scores["Богдан"];` кидає `KeyNotFoundException`.
Правильно: `if (scores.TryGetValue("Богдан", out int x))`.

**2. Використовувати `Add` там, де можливе повторення ключа.**
`frequency.Add(word, 1)` у циклі впаде на другому «кіт».
Правильно — індексатор: `frequency[word] = ...`.

**3. Розраховувати на порядок у `Dictionary` чи `HashSet`.**
Порядок не гарантований і може відрізнятися між запусками. Потрібен порядок —
сортуйте явно або беріть `List`.

**4. Забувати про копію перед `UnionWith` / `IntersectWith`.**
Вони змінюють вихідний набір. Потрібен оригінал — спершу `new HashSet<T>(original)`.

**5. Класти в `HashSet` те, що потім треба дістати за номером.**
У множині немає індексів: `set[0]` не скомпілюється — для цього є `List`.
