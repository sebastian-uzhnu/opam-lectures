# Queue\<T\>, Stack\<T\> та вибір структури даних

## Дві задачі, у яких важливий порядок

`List` дає доступ за номером, `Dictionary` — за ключем. Але є задачі, де ні номер,
ні ключ не потрібні, а важливо інше: **у якому порядку елементи виходитимуть
із колекції**.

- У сервісному центрі є заявки. Обслуговувати треба в порядку надходження:
  хто перший здав ноутбук, того першим і полагодять.
- У браузері ви натиснули «Назад». Куди він поверне? На сторінку, де ви були
  **останньою** перед поточною.

Це два протилежні правила, і під кожне в .NET є своя колекція.

## Queue\<T\> — черга, FIFO

**Черга** (`Queue<T>`) працює за принципом **FIFO** — *First In, First Out*,
«перший прийшов — перший вийшов». Точно як черга в магазині: додаємо в кінець,
забираємо з початку.

```
              ┌─────┬─────┬─────┬─────┐
  Dequeue ◀───│  A  │  B  │  C  │  D  │◀─── Enqueue
   (голова)   └─────┴─────┴─────┴─────┘     (хвіст)
                 ▲                    ▲
              виходить             заходить
              найперший             новий
```

### Методи черги

```csharp
Queue<string> tickets = new();
tickets.Enqueue("Заявка #1: не вмикається ноутбук");
tickets.Enqueue("Заявка #2: тріснув екран");
tickets.Enqueue("Заявка #3: не працює клавіатура");

Console.WriteLine($"У черзі заявок: {tickets.Count}");
Console.WriteLine($"Наступна на черзі: {tickets.Peek()}");
Console.WriteLine($"Після Peek у черзі: {tickets.Count}");

string current = tickets.Dequeue();
Console.WriteLine($"Взяли в роботу: {current}");
Console.WriteLine($"Залишилось: {tickets.Count}");
```

**Вивід:**

```
У черзі заявок: 3
Наступна на черзі: Заявка #1: не вмикається ноутбук
Після Peek у черзі: 3
Взяли в роботу: Заявка #1: не вмикається ноутбук
Залишилось: 2
```

| Метод | Що робить | Змінює чергу |
| --- | --- | --- |
| `Enqueue(item)` | додає в **кінець** | ✅ так |
| `Dequeue()` | забирає з **початку** і повертає | ✅ так |
| `Peek()` | показує початок, **не забираючи** | ❌ ні |
| `TryDequeue(out item)` | забирає, якщо є; повертає `bool` | ✅ так |
| `TryPeek(out item)` | підглядає, якщо є | ❌ ні |
| `Count` | скільки елементів | ❌ ні |
| `Contains(item)` | чи є такий елемент | ❌ ні (але O(n)) |
| `Clear()` | очищає | ✅ так |

:::danger[Часта помилка]
`Dequeue()` і `Peek()` на **порожній** черзі кидають `InvalidOperationException`.
Завжди перевіряйте `Count` або використовуйте `TryDequeue`:

```csharp
while (tickets.TryDequeue(out string? ticket))
{
    Console.WriteLine($"Обробляємо: {ticket}");
}
```

Цей цикл сам зупиниться, коли черга спорожніє.
:::

### Живий приклад: обробка заявок

```csharp
Queue<string> requests = new();
requests.Enqueue("Іван — заміна батареї");
requests.Enqueue("Марія — чистка від пилу");
requests.Enqueue("Олег — встановлення Windows");

int number = 1;
while (requests.Count > 0)
{
    Console.WriteLine($"[{number++}] Виконуємо: {requests.Dequeue()}");
    Console.WriteLine($"    Ще в черзі: {requests.Count}");
}

Console.WriteLine("Усі заявки оброблено.");
```

**Вивід:**

```
[1] Виконуємо: Іван — заміна батареї
    Ще в черзі: 2
[2] Виконуємо: Марія — чистка від пилу
    Ще в черзі: 1
[3] Виконуємо: Олег — встановлення Windows
    Ще в черзі: 0
Усі заявки оброблено.
```

:::warning[Обережно]
Не пишіть `for (int i = 0; i < queue.Count; i++) queue.Dequeue();`.
`Count` зменшується на кожній ітерації, а `i` росте — цикл обробить лише
половину черги. Правильно — `while (queue.Count > 0)` або `while (TryDequeue(...))`.
:::

Черга також перебирається через `foreach` — від голови до хвоста і **без**
видалення елементів: після циклу черга залишиться такою самою, як була.

## Stack\<T\> — стек, LIFO

**Стек** (`Stack<T>`) працює за принципом **LIFO** — *Last In, First Out*,
«останній прийшов — перший вийшов». Аналогія — стопка тарілок: кладете зверху
і берете теж зверху.

```
        Push ─┐   ┌─ Pop
              ▼   ▲
            ┌───────┐  ← вершина (top)
            │   D   │
            ├───────┤
            │   C   │
            ├───────┤
            │   B   │
            ├───────┤
            │   A   │  ← дно, покладене найпершим
            └───────┘
```

### Методи стека

```csharp
Stack<string> history = new();
history.Push("google.com");
history.Push("wikipedia.org");
history.Push("github.com");

Console.WriteLine($"Зараз дивимось: {history.Peek()}");

string back = history.Pop();
Console.WriteLine($"Пішли назад із: {back}");
Console.WriteLine($"Тепер тут: {history.Peek()}");
Console.WriteLine($"В історії сторінок: {history.Count}");
```

**Вивід:**

```
Зараз дивимось: github.com
Пішли назад із: github.com
Тепер тут: wikipedia.org
В історії сторінок: 2
```

| Метод | Що робить | Змінює стек |
| --- | --- | --- |
| `Push(item)` | кладе **на вершину** | ✅ так |
| `Pop()` | знімає з вершини і повертає | ✅ так |
| `Peek()` | показує вершину, не знімаючи | ❌ ні |
| `TryPop(out item)` | знімає, якщо є | ✅ так |
| `TryPeek(out item)` | підглядає, якщо є | ❌ ні |
| `Count` | скільки елементів | ❌ ні |
| `Clear()` | очищає | ✅ так |

:::note
`foreach` по стеку йде **від вершини до дна** — тобто у зворотному порядку
додавання. Це логічно: саме в такому порядку елементи звідти виходили б.
:::

### Живий приклад: кнопка «Назад» у браузері

```csharp
Stack<string> backStack = new();
string currentPage = "home";

void GoTo(string page)
{
    backStack.Push(currentPage); // поточну сторінку — в історію
    currentPage = page;
    Console.WriteLine($"Перейшли на: {currentPage}");
}

void GoBack()
{
    if (backStack.TryPop(out string? previous))
    {
        currentPage = previous;
        Console.WriteLine($"Назад на: {currentPage}");
    }
    else Console.WriteLine("Назад нікуди — це перша сторінка.");
}

GoTo("catalog");
GoTo("product/42");
GoTo("checkout");
GoBack();
GoBack();
GoBack();
GoBack();
```

**Вивід:**

```
Перейшли на: catalog
Перейшли на: product/42
Перейшли на: checkout
Назад на: product/42
Назад на: catalog
Назад на: home
Назад нікуди — це перша сторінка.
```

Зверніть увагу, наскільки природно стек лягає на задачу: ніякої логіки
«знайти попередній елемент» писати не довелося.

:::info[Цікаво]
Стек — не просто зручна колекція, це фундамент роботи будь-якої програми.
Коли метод `A` викликає `B`, а `B` викликає `C`, адреси повернення складаються
у **стек викликів**. Тому й помилка називається `StackOverflowException`
(нескінченна рекурсія переповнює цей стек), і тому в повідомленнях про помилку ви бачите
«stack trace» — це буквально вміст стека викликів.
:::

## Класична задача: перевірка правильності дужок

Це «візитівка» стека. Задача: перевірити, чи правильно розставлені дужки
у виразі. Правильно означає, що кожна відкрита дужка закривається
дужкою того самого типу і в правильному порядку.

Правильно: `(a + b) * [c - d]`
Неправильно: `(a + b]` або `([a + b)]` або `((a + b)`

**Ідея:** йдемо по рядку зліва направо.

- Побачили відкриваючу дужку — кладемо її у стек.
- Побачили закриваючу — знімаємо верхню зі стека і перевіряємо, чи вона парна.
- У кінці стек має бути порожній.

```
Вираз:  ( a + [ b ] )

крок 1: '('  → Push       стек: ( 
крок 2: 'a'  → пропускаємо стек: (
крок 3: '+'  → пропускаємо стек: (
крок 4: '['  → Push       стек: ( [
крок 5: 'b'  → пропускаємо стек: ( [
крок 6: ']'  → Pop = '['  пара? так    стек: (
крок 7: ')'  → Pop = '('  пара? так    стек: порожній
кінець: стек порожній → вираз правильний
```

### Повний код

```csharp
bool IsBalanced(string expression)
{
    Stack<char> brackets = new();

    foreach (char symbol in expression)
    {
        // відкриваючі дужки просто складаємо у стек
        if (symbol is '(' or '[' or '{')
        {
            brackets.Push(symbol);
        }
        // закриваючі — перевіряємо пару
        else if (symbol is ')' or ']' or '}')
        {
            // закриваюча є, а стек порожній — зайва закриваюча
            if (brackets.Count == 0) return false;

            bool matches = (brackets.Pop(), symbol) switch
            {
                ('(', ')') or ('[', ']') or ('{', '}') => true,
                _ => false
            };

            if (!matches) return false;
        }
        // усі інші символи нас не цікавлять
    }

    // якщо щось лишилось у стеку — є незакриті дужки
    return brackets.Count == 0;
}

string[] tests =
[
    "(a + b) * [c - d]",
    "{ if (x > 0) { y = [1, 2]; } }",
    "(a + b]",
    "([a + b)]",
    "((a + b)",
    "a + b)"
];

foreach (string test in tests)
{
    string verdict = IsBalanced(test) ? "правильно" : "ПОМИЛКА";
    Console.WriteLine($"{test,-32} → {verdict}");
}
```

**Вивід:**

```
(a + b) * [c - d]                → правильно
{ if (x > 0) { y = [1, 2]; } }   → правильно
(a + b]                          → ПОМИЛКА
([a + b)]                        → ПОМИЛКА
((a + b)                         → ПОМИЛКА
a + b)                           → ПОМИЛКА
```

У коді використано дві сучасні конструкції C#: **зіставлення зі зразком**
`symbol is '(' or '[' or '{'` замість трьох порівнянь через `||`, і `switch`-вираз
по кортежу — компактна таблиця відповідностей замість купи `if`
(прочерк `_` означає «будь-яка інша комбінація»).

:::tip[Порада]
Саме цей алгоритм працює у вашому редакторі коду, коли він підсвічує парну дужку
і сварить на незакриту. Тепер ви знаєте, як він влаштований — і що це двадцять
рядків, а не магія.
:::

## Чому не зробити те саме списком

Технічно можна: `List` уміє `Add` і `RemoveAt`. Але подивіться на різницю.

```csharp
Stack<char> stack = new();          // стеком
stack.Push('(');
char top = stack.Pop();

List<char> list = new();            // списком «як стеком»
list.Add('(');
char last = list[^1];
list.RemoveAt(list.Count - 1);
```

Різниця не лише в довжині. Головне — **читабельність наміру**. Побачивши
`Stack<char>`, ви одразу знаєте: тут LIFO. Побачивши `List<char>` — доводиться
читати весь код, щоб зрозуміти, як його використовують.

А для черги різниця ще й у швидкості: `list.RemoveAt(0)` зсуває **всі** елементи
вліво — O(n). `Queue.Dequeue()` — O(1), бо всередині черга влаштована як
кільцевий буфер із двома вказівниками.

```
List.RemoveAt(0):  ┌───┬───┬───┬───┐
                   │ A │ B │ C │ D │
                   └───┴───┴───┴───┘
                     ✗ ◀── ◀── ◀──   зсув усіх елементів

Queue.Dequeue():   ┌───┬───┬───┬───┐
                   │ A │ B │ C │ D │
                   └───┴───┴───┴───┘
                     ▲   ▲
                   head→head        просто зсунули вказівник
```

:::warning[Обережно]
Найповільніша операція зі списком — `RemoveAt(0)` або `Insert(0, item)` у циклі:
кожен виклик зсуває весь «хвіст». Якщо вам треба постійно працювати з початком
колекції — це майже завжди означає, що потрібна `Queue`.
:::

## Як обрати структуру даних

Це головна таблиця теми. Повертайтесь до неї, коли не знаєте, що взяти.

| Структура | Швидкий доступ за індексом | Швидкий пошук значення | Зберігає порядок | Гарантує унікальність | Типова задача |
| --- | --- | --- | --- | --- | --- |
| `T[]` (масив) | ✅ O(1) | ❌ O(n) | ✅ порядок додавання | ❌ | фіксований набір: дні тижня, матриця |
| `List<T>` | ✅ O(1) | ❌ O(n) | ✅ порядок додавання | ❌ | список товарів, треків, оцінок |
| `Dictionary<K,V>` | ❌ немає індексів | ✅ O(1) за ключем | ❌ | ✅ за ключем | «код товару → ціна», лічильники |
| `HashSet<T>` | ❌ немає індексів | ✅ O(1) | ❌ | ✅ | список унікальних тегів, «хто вже голосував» |
| `Queue<T>` | ❌ | ❌ O(n) | ✅ FIFO | ❌ | заявки, черга друку, розсилка |
| `Stack<T>` | ❌ | ❌ O(n) | ✅ LIFO | ❌ | «Назад», скасування дії, дужки |
| `SortedDictionary<K,V>` | ❌ | ✅ O(log n) | ✅ за ключем | ✅ за ключем | рейтинг, звіт, впорядкований довідник |

### Питання, які варто собі поставити

1. **Чи потрібен доступ за номером?** Так — `List` або масив.
2. **Чи буде часто пошук «а чи є таке значення»?** Так — `HashSet`.
3. **Чи є пари «щось у щось»?** Так — `Dictionary`.
4. **Чи мають дублікати бути неможливими?** Так — `HashSet` або ключі словника.
5. **Чи важливий порядок обробки?** Перший прийшов — `Queue`. Останній — `Stack`.
6. **Нічого з переліченого?** Беріть `List` — універсальний вибір за замовчуванням.

:::tip[Порада]
У реальній програмі структури часто комбінують. Наприклад, у грі:
`List` — усі гравці; `Dictionary` «нікнейм → рахунок» — швидкий пошук рахунку;
`HashSet` — хто вже зробив хід у цьому раунді; `Queue` — черговість ходів.
Кожна структура закриває свою частину задачі.
:::

## Комбінований приклад: симулятор кав'ярні

```csharp
Queue<string> orders = new();               // черга замовлень
Dictionary<string, int> drinkStats = new(); // напій → скільки замовили
HashSet<string> regulars = new();           // унікальні постійні клієнти
Stack<string> cancelled = new();            // останні скасовані — для відновлення

void PlaceOrder(string customer, string drink)
{
    orders.Enqueue($"{customer}|{drink}");
    drinkStats[drink] = drinkStats.GetValueOrDefault(drink) + 1;
    regulars.Add(customer);
}

PlaceOrder("Оля", "лате");
PlaceOrder("Тарас", "еспресо");
PlaceOrder("Оля", "лате");
PlaceOrder("Ігор", "капучино");

// баріста готує по черзі
while (orders.TryDequeue(out string? order))
{
    string[] parts = order.Split('|');
    Console.WriteLine($"Готово: {parts[1]} для {parts[0]}");
}

Console.WriteLine($"\nУнікальних клієнтів: {regulars.Count}");
Console.WriteLine("Статистика напоїв:");

foreach (var (drink, count) in drinkStats)
    Console.WriteLine($"  {drink,-10} {count}");
```

**Вивід:**

```
Готово: лате для Оля
Готово: еспресо для Тарас
Готово: лате для Оля
Готово: капучино для Ігор

Унікальних клієнтів: 3
Статистика напоїв:
  лате       2
  еспресо    1
  капучино   1
```

## Типові помилки

**1. `Dequeue` або `Pop` на порожній колекції.**

```csharp
Queue<int> q = new();
int x = q.Dequeue(); // ← InvalidOperationException
```

Правильно: `if (q.Count > 0)` або `q.TryDequeue(out int x)`.

**2. Цикл `for` по `Count` із одночасним видаленням.**

```csharp
for (int i = 0; i < queue.Count; i++) queue.Dequeue(); // обробить половину
```

Правильно: `while (queue.Count > 0)`.

**3. Плутати `Peek` і `Pop`.**
`Peek` — «подивитися», колекція не змінюється. `Pop` / `Dequeue` — «взяти»,
елемент зникає. Цикл `while (stack.Count > 0) Console.WriteLine(stack.Peek());`
працюватиме вічно.

**4. Використовувати `List` як чергу через `RemoveAt(0)`.**
Працює, але повільно й нечитабельно. Для FIFO є `Queue`.

**5. Плутати напрямок `foreach` по стеку.**
Він іде від вершини до дна, тобто у зворотному порядку додавання.

## Що далі

Усі колекції записуються з кутовими дужками: `List<int>`,
`Dictionary<string, int>`, `Queue<string>`. Це не синтаксична прикраса —
це механізм **узагальнених типів**, який ми розберемо в останньому підрозділі
теми. Заодно побачимо, як писати власні узагальнені методи й типи.
