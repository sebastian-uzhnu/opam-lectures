# Узагальнені типи (generics)

## Звідки взялися кутові дужки

Через усю тему нас супроводжував один і той самий запис: `List<int>`,
`Dictionary<string, int>`, `Queue<string>`, `HashSet<char>`. Настав час
розібратися, що це таке.

**Узагальнений тип** (*generic*) — це тип або метод, який написаний один раз,
але працює з будь-яким типом даних, який ви йому вкажете. Те, що в дужках —
**аргумент типу**: конкретний тип, який підставляється замість заглушки.

```csharp
List<int> numbers = [];      // список цілих
List<string> names = [];     // список рядків
List<DateTime> dates = [];   // список дат
```

Автори .NET не писали три різних класи. Вони написали **один** клас `List<T>`,
де `T` — це «тип, який вкажуть при використанні». Щоб зрозуміти, наскільки це
важливо, треба побачити, як жили без generics.

## Життя до generics: колекція object

У найпершій версії C# (2002 рік) узагальнених типів не було. Був клас
`ArrayList` — динамічний список, який зберігав елементи типу `object`.

Чому `object`? Бо в C# **усі типи успадковані від `object`**. Отже, змінна типу
`object` може зберігати що завгодно: число, рядок, дату, масив.

```csharp
// так писали до 2005 року
System.Collections.ArrayList list = new();

list.Add(42);
list.Add("привіт");
list.Add(3.14);
list.Add(DateTime.Now);
```

Компілюється. Працює. І це джерело трьох великих проблем.

### Проблема 1: помилки виявляються лише під час виконання

```csharp
System.Collections.ArrayList numbers = new();
numbers.Add(10);
numbers.Add(20);
numbers.Add("тридцять"); // ← ой. Компілятор мовчить!

int sum = 0;
foreach (object item in numbers) sum += (int)item;  // ← тут програма впаде
```

**Вивід:**

```
Unhandled exception. System.InvalidCastException:
Unable to cast object of type 'System.String' to type 'System.Int32'.
```

Компілятор не заперечував: у `ArrayList` можна класти будь-що, а зворотне
приведення `(int)item` синтаксично коректне. Помилку знайде тільки користувач,
коли програма впаде. Може, через півроку після релізу.

З `List<int>` цього неможливо навіть написати:

```csharp
List<int> numbers = [];
numbers.Add(10);
numbers.Add("тридцять");
// ← Compile error CS1503: cannot convert from 'string' to 'int'
```

Червона хвиляста лінія у Visual Studio **до запуску**. Це і є головна перевага
generics: **помилки типів ловляться на етапі компіляції, а не в продакшені**.

### Проблема 2: постійні приведення типів

Із `ArrayList` кожне читання елемента вимагає ручного приведення, із
`List<string>` — ні:

```csharp
System.Collections.ArrayList old = new();
old.Add("Олена");
string a = (string)old[0];              // приведення обов'язкове
int lenA = ((string)old[0]).Length;     // а тут ще й дужки

List<string> names = ["Олена"];
string b = names[0];                    // без приведень
int lenB = names[0].Length;             // IntelliSense підказує методи рядка
```

І, до речі, IntelliSense працює: після `names[0].` редактор покаже методи рядка.
З `ArrayList` він показав би методи `object` — тобто майже нічого.

### Проблема 3: боксинг

Це найменш очевидна, але важлива річ.

**Боксинг** (*boxing*) — це «загортання» значення простого типу (`int`, `double`,
`bool`, `char`, структури) в об'єкт у купі, щоб його можна було зберігати
як `object`.

```
Без боксингу: List<int>              З боксингом: ArrayList
                                     
Масив у купі                         Масив посилань у купі
┌────┬────┬────┐                     ┌────┬────┬────┐
│ 10 │ 20 │ 30 │                     │ ●  │ ●  │ ●  │
└────┴────┴────┘                     └─┬──┴─┬──┴─┬──┘
значення лежать                        │    │    │
безпосередньо                          ▼    ▼    ▼
                                     ┌────┐┌────┐┌────┐
                                     │ 10 ││ 20 ││ 30 │  ← окремі об'єкти
                                     └────┘└────┘└────┘     у купі
```

Кожне число перетворюється на окремий об'єкт у купі. Це:

- витрачає пам'ять (об'єкт у купі важить набагато більше за 4 байти числа);
- навантажує збирач сміття;
- сповільнює роботу — кожне читання вимагає **розпакування** (*unboxing*).

`List<int>` зберігає числа безпосередньо у внутрішньому масиві. Ніякого
боксингу, ніякого сміття.

:::info[Цікаво]
Generics з'явилися в C# 2.0 у 2005 році і були настільки важливими, що заради них
змінили саму віртуальну машину .NET (CLR). У Java, наприклад, generics зроблені
через *type erasure* — типи стираються під час компіляції, і `List` цілих чисел
там усе одно зберігає загорнуті об'єкти. У .NET generics справжні: для `List<int>`
під час виконання створюється окремий машинний код, який працює саме з `int`.
Тому .NET-generics не тільки зручніші, а й швидші.
:::

### Порівняння

| | `ArrayList` (без generics) | `List<T>` (з generics) |
| --- | --- | --- |
| Перевірка типів | ❌ під час виконання | ✅ під час компіляції |
| Приведення при читанні | потрібне завжди | не потрібне |
| Боксинг чисел | ✅ так, на кожен елемент | ❌ немає |
| Підказки IntelliSense | тільки методи `object` | повні методи типу |
| Швидкість | повільніше | швидше |
| Коли використовувати | ніколи в новому коді | завжди |

:::warning[Обережно]
`ArrayList` і `Hashtable` (це «словник до generics») досі існують у .NET заради
сумісності зі старим кодом. У навчальних матеріалах в інтернеті вони
трапляються — часто в статтях 2008 року, які видаються за актуальні.

**У новому коді їх не використовують.** Якщо ви бачите `ArrayList` — це або дуже
старий код, або поганий приклад. Заміна: `ArrayList` → `List<T>`,
`Hashtable` → `Dictionary<TKey, TValue>`.
:::

## Узагальнені методи

Generics — це не тільки колекції. Ви можете писати власні узагальнені методи.

### Задача

Треба метод, який повертає більше з двох значень. Для цілих:

```csharp
int Max(int a, int b) => a > b ? a : b;
```

А тепер такий самий для `double`. І для `decimal`. І для рядків (за алфавітом).
І для дат. Чотири однакові методи, які відрізняються лише типом.

```csharp
// так робити не треба — це копіпаст
double Max(double a, double b) => a > b ? a : b;
decimal Max(decimal a, decimal b) => a > b ? a : b;
// а для string оператор > взагалі не працює
```

### Розв'язок: параметр типу

```csharp
T Max<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) > 0 ? a : b;
}

Console.WriteLine(Max(10, 25));                  // int
Console.WriteLine(Max(3.7, 2.1));                // double
Console.WriteLine(Max("яблуко", "банан"));       // string, за алфавітом
Console.WriteLine(Max(new DateTime(2024, 1, 1),
                      new DateTime(2026, 5, 9))); // DateTime
```

**Вивід:**

```
25
3,7
яблуко
09.05.2026 0:00:00
```

Розберемо запис по частинах:

```
T Max<T>(T a, T b) where T : IComparable<T>
▲     ▲   ▲    ▲         ▲
│     │   │    │         └─ обмеження: T має вміти порівнюватись
│     │   └────┴─── параметри того самого типу T
│     └─ оголошення параметра типу
└─ метод повертає значення типу T
```

Зверніть увагу: при виклику ми **не пишемо** `Max<int>(10, 25)`. Компілятор сам
здогадується, що `T` — це `int`, бо саме такі аргументи ми передали.
Це називається **виведення типу**. Явно вказати теж можна, якщо потрібно:

```csharp
Console.WriteLine(Max<double>(10, 25)); // 25 як double
```

### Ще два приклади

```csharp
void Swap<T>(ref T first, ref T second)   // обмеження не потрібні:
{                                         // щоб перекласти значення зі змінної
    T temp = first;                       // у змінну, про тип знати нічого не треба
    first = second;
    second = temp;
}

void PrintAll<T>(List<T> items, string title)
{
    Console.WriteLine($"=== {title} ({items.Count}) ===");
    foreach (T item in items) Console.WriteLine($"  {item}");
}

int x = 1, y = 2;
Swap(ref x, ref y);
Console.WriteLine($"{x} {y}");

PrintAll([1, 2, 3], "Числа");
PrintAll(["кіт", "пес"], "Тварини");
```

**Вивід:**

```
2 1
=== Числа (3) ===
  1
  2
  3
=== Тварини (2) ===
  кіт
  пес
```

## Обмеження (constraints)

Слово `where` у прикладі з `Max` — це **обмеження типу**. Воно каже компілятору:
«сюди можна підставляти не будь-що, а лише типи, які задовольняють умову».

Навіщо це потрібно? Без обмеження компілятор нічого не знає про `T` і не дозволить
робити з ним нічого, крім найпростішого:

```csharp
T Max<T>(T a, T b)
{
    return a > b ? a : b;  // ← Compile error CS0019:
                           // Operator '>' cannot be applied to operands of type 'T' and 'T'
}
```

Компілятор має рацію: а раптом `T` — це `Queue<int>`? Як порівнювати дві черги
знаком «більше»? Обмеження `where T : IComparable<T>` гарантує, що у типу
є метод `CompareTo` — і тоді ним можна користуватись.

### Основні види обмежень

| Обмеження | Що вимагає від `T` | Приклад типу, який підходить |
| --- | --- | --- |
| `where T : struct` | значимий тип (число, `bool`, `char`, структура) | `int`, `double`, `DateTime` |
| `where T : class` | посилальний тип | `string`, масив, будь-який клас |
| `where T : new()` | має публічний конструктор без параметрів | більшість класів |
| `where T : IComparable<T>` | вміє порівнюватися з собою | `int`, `string`, `DateTime` |
| `where T : SomeType` | цей тип або нащадок | ваша ієрархія типів |
| `where T : notnull` | не може бути `null` | будь-який ненульовий тип |

Кілька обмежень пишуться через кому:

```csharp
T CreateAndCompare<T>(T other) where T : IComparable<T>, new()
{
    T fresh = new T();                 // дозволено завдяки new()
    return fresh.CompareTo(other) > 0  // дозволено завдяки IComparable
        ? fresh : other;
}
```

### Обмеження struct: працюємо тільки з числами

```csharp
double Average<T>(List<T> numbers) where T : struct, IConvertible
{
    if (numbers.Count == 0) return 0;

    double sum = 0;
    foreach (T item in numbers) sum += Convert.ToDouble(item);
    return sum / numbers.Count;
}

Console.WriteLine(Average([1, 2, 3, 4]));   // 2,5   — int
Console.WriteLine(Average([1.5, 2.5]));     // 2     — double
// Average(["а", "б"]) — не скомпілюється, string не struct
```

:::tip[Порада]
Не додавайте обмеження «про всяк випадок». Правило просте: **обмеження додається
тоді, коли без нього код не компілюється**. Кожне зайве обмеження звужує коло
типів, з якими ваш метод зможе працювати.
:::

## Власний узагальнений тип

Тепер напишемо власний узагальнений тип. Почнемо з найпростішого — «коробки»,
яка зберігає одне значення будь-якого типу.

```csharp
class Box<T>
{
    private T? content;
    public bool IsEmpty => content is null;

    public void Put(T item)
    {
        content = item;
        Console.WriteLine($"Поклали: {item}");
    }

    public T? Take()
    {
        T? item = content;
        content = default;   // default(T): 0 для чисел, null для посилань
        return item;
    }
}
```

Використання:

```csharp
Box<string> giftBox = new();
Console.WriteLine($"Порожня? {giftBox.IsEmpty}");

giftBox.Put("шоколадка");
Console.WriteLine($"Дістали: {giftBox.Take()}");
Console.WriteLine($"Порожня? {giftBox.IsEmpty}");

Box<int> numberBox = new();
numberBox.Put(42);
Console.WriteLine($"Дістали число: {numberBox.Take()}");
```

**Вивід:**

```
Порожня? True
Поклали: шоколадка
Дістали: шоколадка
Порожня? True
Поклали: 42
Дістали число: 42
```

Один тип — і він працює і з рядками, і з числами, і з чим завгодно.
Без generics довелося б писати `StringBox`, `IntBox`, `DateBox`.

:::note
Слово `default` без вказаного типу означає «значення за замовчуванням для `T`»:
`0` для чисел, `false` для `bool`, `null` для рядків і класів. Це потрібно саме
в узагальненому коді, де ви не знаєте, який саме тип буде.
:::

### Два параметри типу: Pair

Параметрів типу може бути кілька. Класичний приклад — пара значень різних типів.

```csharp
class Pair<TFirst, TSecond>
{
    public TFirst First { get; set; }
    public TSecond Second { get; set; }

    public Pair(TFirst first, TSecond second)
    {
        First = first;
        Second = second;
    }

    public override string ToString() => $"({First}, {Second})";

    public Pair<TSecond, TFirst> Swap() => new(Second, First);
}
```

```csharp
Pair<string, int> score = new("Оля", 95);
Console.WriteLine(score);
Console.WriteLine($"Ім'я: {score.First}, бали: {score.Second}");
Console.WriteLine(score.Swap());   // Pair<int, string>

List<Pair<string, double>> prices = [new("кава", 45.0), new("чай", 30.0)];

foreach (var item in prices)
    Console.WriteLine($"{item.First} — {item.Second} грн");
```

**Вивід:**

```
(Оля, 95)
Ім'я: Оля, бали: 95
(95, Оля)
кава — 45 грн
чай — 30 грн
```

Зверніть увагу на `List<Pair<string, double>>` — узагальнені типи вкладаються
один в одного. `Dictionary<string, List<int>>` теж цілком нормальний тип:
словник, у якому значення — це списки.

:::info[Цікаво]
У .NET уже є готова пара — **кортеж** (*tuple*). Замість власного `Pair`
частіше пишуть просто `(string Name, int Score) player = ("Оля", 95);`
або `List<(string Name, double Price)> menu = [("кава", 45.0)];`.
Кортеж — це той самий узагальнений тип `ValueTuple<T1, T2>` з гарним синтаксисом.
Але корисно розуміти, що всередині нього.
:::

### Іменування параметрів типу

Домовленість, якої дотримуються всі .NET-розробники: `T` — коли параметр один
і його роль очевидна (`List<T>`, `Box<T>`); `TKey`, `TValue`, `TFirst` — коли
параметрів кілька, тоді ім'я починається з `T` і пояснює роль
(`Dictionary<TKey, TValue>`). Не називайте параметр типу просто `X` або `Type`.

## Що дають generics: підсумок

1. **Безпека типів на етапі компіляції.** Помилка ловиться у редакторі,
   а не в користувача.
2. **Немає приведень типів.** Код чистіший, IntelliSense працює.
3. **Немає боксингу.** Швидше і економніше з пам'яттю.
4. **Один код замість копіпасту.** Написали `Max<T>` один раз — працює
   з усіма типами, які вміють порівнюватись.

Саме тому вся сучасна бібліотека .NET побудована на generics: колекції, `Task<T>`,
`Nullable<T>` (той самий `int?`), `IEnumerable<T>` — усе це узагальнені типи.

## Типові помилки

**1. Використовувати `ArrayList` або `Hashtable` у новому коді.**
Правильно: `List<T>` і `Dictionary<TKey, TValue>`.

**2. Використовувати `List<object>` замість узагальненого типу.**
`List<object> mixed = [1, "текст", 3.14];` — це generics лише формально:
перевірок типів немає, боксинг є. Якщо ви пишете `List<object>` — майже завжди
це означає, що структура даних продумана погано.

**3. Забути обмеження і намагатися порівнювати `T`.**
`T Max<T>(T a, T b) => a > b ? a : b;` не скомпілюється (CS0019).
Правильно: додати `where T : IComparable<T>` і використати `CompareTo`.

**4. Писати `new T()` без обмеження `where T : new()`.**
Компілятор не знає, чи є у `T` конструктор без параметрів. Або додайте `new()`,
або використайте `default`.

**5. Писати `Max<int>(10, 25)` там, де тип виводиться сам.**
Не помилка, але зайвий шум. Пишіть `Max(10, 25)` — компілятор розбереться.

## Підсумок теми

Ви пройшли шлях від масиву фіксованого розміру до повного набору колекцій .NET:

- `List<T>` — коли важливий порядок і доступ за індексом;
- `Dictionary<TKey, TValue>` — коли є пари «ключ — значення» і потрібен
  миттєвий пошук;
- `HashSet<T>` — коли потрібна унікальність і операції над множинами;
- `Queue<T>` і `Stack<T>` — коли важливий порядок обробки, FIFO чи LIFO;
- **generics** — механізм, який робить усе це типобезпечним і швидким,
  і яким ви тепер можете користуватись у власному коді.

Наступна тема курсу — об'єктно-орієнтоване програмування. Там ви навчитеся
створювати власні типи, і колекції одразу стануть у пригоді: `List` ваших
власних об'єктів — це найчастіша конструкція в реальних програмах.
