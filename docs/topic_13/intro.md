# Від масивів до колекцій. List\<T\>

## Проблема, з якої все почалося

Ви вже вмієте працювати з масивами. Масив — чудова річ: швидкий, простий, займає
рівно стільки пам'яті, скільки потрібно. Але у нього є одна властивість, яка
псує життя майже в кожній реальній задачі:

> **Розмір масиву задається один раз при створенні і більше ніколи не змінюється.**

Уявіть просту задачу: програма зчитує імена студентів, які прийшли на пару.
Скільки їх буде? Ви не знаєте — може десять, може двадцять п'ять, може троє.
А розмір треба вказати одразу: `new string[???]`.

Є два поганих варіанти:

1. **Взяти «з запасом»** — `new string[1000]`. Тоді 995 комірок стоять порожні,
   а якщо прийде 1001 студент — програма впаде.
2. **Перевиділяти масив вручну** щоразу, коли місце закінчилось. Це працює,
   але подивіться, скільки коду це коштує.

### Як виглядає «додати елемент» у масив вручну

```csharp
string[] students = new string[0]; // порожній масив
string name = "Олена";

// 1. створюємо новий масив на одну комірку більший
string[] bigger = new string[students.Length + 1];

// 2. копіюємо всі старі елементи
for (int i = 0; i < students.Length; i++)
{
    bigger[i] = students[i];
}

// 3. кладемо новий елемент у кінець
bigger[students.Length] = name;

// 4. підміняємо посилання
students = bigger;
```

Десять рядків, щоб зробити те, що логічно звучить як «додай ім'я в список» —
і це лише **один** елемент. Уявіть цей блок усередині циклу читання з клавіатури.
У .NET є трохи коротший варіант через `Array.Resize`:

```csharp
string[] students = [];             // collection expression, C# 12

void AddStudent(ref string[] arr, string name)
{
    Array.Resize(ref arr, arr.Length + 1); // створює НОВИЙ масив і копіює все
    arr[^1] = name;                        // ^1 — останній елемент
}

AddStudent(ref students, "Олена");
AddStudent(ref students, "Тарас");
Console.WriteLine(string.Join(", ", students));
```

**Вивід:**

```
Олена, Тарас
```

Коротше — але не швидше. `Array.Resize` не «розтягує» масив: він створює новий
і копіює туди всі елементи. Додати 1000 імен = 1000 копіювань цілих масивів.

:::info Цікаво
Чому масив не може «дорости»? Бо він лежить у пам'яті одним суцільним шматком.
Одразу за ним може лежати щось інше — рядок, інший масив, чиїсь дані. Дописати
комірку «збоку» неможливо, треба знайти нове вільне місце потрібного розміру
і перенести туди все. Саме це `Array.Resize` і робить.
:::

### А видалити елемент?

Ще гірше. У масиві немає «дірок»: якщо ви приберете елемент з середини,
всі наступні треба зсунути вліво.

```csharp
int[] numbers = [10, 20, 30, 40, 50];
int indexToRemove = 2; // хочемо прибрати 30

int[] result = new int[numbers.Length - 1];
for (int i = 0, j = 0; i < numbers.Length; i++)
{
    if (i == indexToRemove) continue; // пропускаємо
    result[j++] = numbers[i];
}

Console.WriteLine(string.Join(", ", result)); // 10, 20, 40, 50
```

Два лічильники, `continue`, окремий масив — і все це заради однієї операції,
яку хочеться написати одним словом.

:::tip Порада
Якщо ви ловите себе на тому, що пишете цикл копіювання масиву — це майже завжди
сигнал, що потрібна колекція, а не масив.
:::

## Колекції: готові структури даних

**Колекція** — це тип із простору імен `System.Collections.Generic`, який зберігає
набір елементів і сам піклується про пам'ять: виділяє її, збільшує, звільняє.
Ви просто кажете «додай», «прибери», «знайди».

Основні колекції .NET, які ми розберемо у цій темі:

| Колекція | Що зберігає | Головна перевага |
| --- | --- | --- |
| `List<T>` | впорядкований список | динамічний розмір + доступ за індексом |
| `Dictionary<TKey, TValue>` | пари «ключ — значення» | миттєвий пошук за ключем |
| `HashSet<T>` | множину унікальних значень | автоматична унікальність |
| `Queue<T>` | чергу (FIFO) | «хто перший прийшов, того першим обслужили» |
| `Stack<T>` | стек (LIFO) | «останній прийшов — першим вийшов» |

Запис `List<T>` читається як «список чого-небудь». Буква `T` — це **параметр типу**:
місце, куди ви підставите конкретний тип. `List<int>` — список цілих,
`List<string>` — список рядків. Про те, як цей механізм влаштований усередині,
буде окремий підрозділ про generics.

:::note
Простір імен `System.Collections.Generic` у .NET 8 підключається автоматично
завдяки *implicit usings* — писати `using System.Collections.Generic;` вручну
не треба. Якщо у старому проєкті колекції «не знаходяться» — допишіть цей рядок угорі.
:::

## List\<T\> — динамічний масив

`List<T>` — найчастіше вживана колекція в C#. Всередині це той самий масив,
але з розумною логікою розширення, схованою від вас.

### Створення

```csharp
List<string> students = new List<string>();  // порожній список
List<string> teachers = new();               // коротше: тип зрозумілий зліва
List<int> scores = [90, 75, 88, 100];        // collection expression, C# 12
List<int> big = new(capacity: 1000);         // з місцем наперед (оптимізація)
```

### Основні операції

```csharp
List<string> playlist = ["Океан Ельзи — Обійми", "Wellboy — Kalyna"];

playlist.Add("KAZKA — Плакала");                 // у кінець
playlist.Insert(0, "ДахаБраха — Шо з-під дуба"); // на позицію 0

Console.WriteLine($"Треків: {playlist.Count}");
Console.WriteLine($"Перший: {playlist[0]}");
Console.WriteLine($"Останній: {playlist[^1]}");

playlist.Remove("Wellboy — Kalyna"); // за значенням
playlist.RemoveAt(0);                // за індексом

bool hasKazka = playlist.Contains("KAZKA — Плакала");
int position = playlist.IndexOf("KAZKA — Плакала");
Console.WriteLine($"KAZKA у плейлисті: {hasKazka}, позиція: {position}");
Console.WriteLine($"Залишилось треків: {playlist.Count}");
```

**Вивід:**

```
Треків: 4
Перший: ДахаБраха — Шо з-під дуба
Останній: KAZKA — Плакала
KAZKA у плейлисті: True, позиція: 1
Залишилось треків: 2
```

### Довідник методів List\<T\>

| Метод / властивість | Що робить | Примітка |
| --- | --- | --- |
| `Add(item)` | додає в кінець | найшвидша операція |
| `AddRange(collection)` | додає одразу багато | замість циклу з `Add` |
| `Insert(index, item)` | вставляє на позицію | повільніше: зсуває «хвіст» |
| `Clear()` | видаляє все | `Count` стає 0 |
| `Remove(item)` | видаляє **перше** входження | повертає `bool` — чи знайшлося |
| `RemoveAt(index)` | видаляє за індексом | кидає виняток, якщо індекс поза межами |
| `RemoveAll(predicate)` | видаляє всі, що підходять | безпечний спосіб «почистити» список |
| `Contains(item)` | чи є такий елемент | перебирає список — O(n) |
| `IndexOf(item)` | позиція або `-1` | теж перебирає |
| `Count` | скільки елементів **зараз** | те, що вам зазвичай потрібно |
| `Capacity` | скільки поміститься **без розширення** | внутрішня кухня |
| `Sort()` | сортує на місці | для чисел і рядків працює одразу |
| `Reverse()` | перевертає порядок | на місці, нічого не повертає |
| `ToArray()` | робить звичайний масив | копія, не посилання |

### Count і Capacity — це різні речі

```csharp
List<int> numbers = new();
Console.WriteLine($"Count={numbers.Count}, Capacity={numbers.Capacity}");

for (int i = 1; i <= 9; i++)
{
    numbers.Add(i);
    Console.WriteLine($"Додали {i}: Count={numbers.Count}, Capacity={numbers.Capacity}");
}
```

**Вивід:**

```
Count=0, Capacity=0
Додали 1: Count=1, Capacity=4
Додали 2: Count=2, Capacity=4
...
Додали 4: Count=4, Capacity=4
Додали 5: Count=5, Capacity=8
...
Додали 8: Count=8, Capacity=8
Додали 9: Count=9, Capacity=16
```

- **Count** — скільки елементів ви реально поклали.
- **Capacity** — скільки комірок вже виділено у внутрішньому масиві.

Коли `Count` дорівнює `Capacity` і ви додаєте ще один елемент, `List<T>`
**подвоює** внутрішній масив.

### Як List росте: ASCII-схема

```
Capacity = 4, Count = 4  (місця більше немає)
┌────┬────┬────┬────┐
│ 1  │ 2  │ 3  │ 4  │
└────┴────┴────┴────┘

  Add(5)  →  виділяємо новий масив удвічі більший
             і копіюємо в нього старі елементи

┌────┬────┬────┬────┬────┬────┬────┬────┐
│ 1  │ 2  │ 3  │ 4  │ 5  │    │    │    │
└────┴────┴────┴────┴────┴────┴────┴────┘
  └──── скопійовано ────┘  ↑    └── вільно ──┘
                        новий
Capacity = 8, Count = 5

  Add(6..8) — просто заповнюємо вільні комірки, копіювання НЕ потрібне

  Add(9)  →  знову подвоєння: Capacity = 16
```

Копіювання відбувається рідко (при 4, 8, 16, 32, 64 елементах), тому в середньому
`Add` коштує «майже нічого». Це і є та розумна логіка, яку ви писали б руками.

:::tip Порада
Якщо ви наперед знаєте приблизну кількість елементів — передайте її в конструктор:
`new List<int>(10000)`. Це прибере всі проміжні копіювання. На маленьких списках
різниці не помітите, на великих — помітите добре.
:::

### Сортування і перетворення

```csharp
List<int> scores = [75, 92, 60, 88, 100];

scores.Sort();                       // за зростанням, на місці
Console.WriteLine(string.Join(" ", scores));

scores.Reverse();                    // перевернули
Console.WriteLine(string.Join(" ", scores));

int[] asArray = scores.ToArray();          // список → масив
List<int> backToList = new(asArray);       // масив → список
List<int> alsoList = [.. asArray];         // те саме, spread-елемент C# 12

Console.WriteLine($"У масиві {asArray.Length}, у списку {backToList.Count}");
```

**Вивід:**

```
60 75 88 92 100
100 92 88 75 60
У масиві 5, у списку 5
```

:::info Цікаво
`List<T>.Sort()` використовує **інтроспективне сортування** (introsort) — гібрид
швидкого сортування, пірамідального і сортування вставками. Він автоматично
перемикається між алгоритмами залежно від даних, щоб уникнути найгіршого випадку
QuickSort. Ви вивчали ці алгоритми окремо — тут вони вже реалізовані й
відлагоджені за вас.
:::

## foreach: правильний спосіб перебору

Перебирати список циклом `for` можна — `for (int i = 0; i < playlist.Count; i++)`.
Але якщо індекс вам не потрібен, `foreach` читається краще і не дає помилитися
з межами:

```csharp
foreach (string track in playlist)   // або: foreach (var track in playlist)
{
    Console.WriteLine($"- {track}");
}
```

`foreach` працює з будь-якою колекцією: `List`, `Dictionary`, `HashSet`, `Queue`,
`Stack`, масивом і навіть рядком (по символах). Це універсальний інструмент,
і далі у темі ми користуватимемось саме ним.

### Чому всередині foreach не можна змінювати колекцію

Спробуємо видалити з плейлиста всі треки, коротші за 10 символів:

```csharp
List<string> playlist = ["Kalyna", "Обійми", "Плакала", "Шо з-під дуба"];

foreach (var track in playlist)
{
    if (track.Length < 10)
    {
        playlist.Remove(track); // ← ось тут все зламається
    }
}
```

**Вивід:**

```
Unhandled exception. System.InvalidOperationException:
Collection was modified; enumeration operation may not execute.
```

:::danger Часта помилка
**Змінювати колекцію (Add, Remove, Insert, Clear) під час `foreach` по ній —
заборонено.** Програма впаде з `InvalidOperationException`.
:::

**Чому так?** `foreach` не бігає по індексах — він просить у колекції
«перелічувач» (енумератор), який пам'ятає, де саме зупинився. Якщо колекція
під час перебору змінилась, ця позиція втрачає сенс: елементи зсунулись, і
перелічувач або пропустить елемент, або прочитає той самий двічі. Замість того,
щоб мовчки видати неправильний результат, .NET одразу кидає виняток.

```
foreach бачить це:              а після Remove стало це:
┌──────┬──────┬──────┬──────┐   ┌──────┬──────┬──────┐
│  A   │  B   │  C   │  D   │   │  A   │  C   │  D   │
└──────┴──────┴──────┴──────┘   └──────┴──────┴──────┘
           ▲ позиція = 1                    ▲ позиція = 1
           читаємо B                   тут уже D, а C пропущено
```

### Три правильні способи

**1. Цикл `for` у зворотному напрямку** — індекси елементів, які ще не оброблені,
не зсуваються:

```csharp
for (int i = playlist.Count - 1; i >= 0; i--)
{
    if (playlist[i].Length < 10)
    {
        playlist.RemoveAt(i);
    }
}
```

**2. Метод `RemoveAll`** — найкоротший і найзрозуміліший варіант:

```csharp
playlist.RemoveAll(track => track.Length < 10);
```

Запис `track => track.Length < 10` — це **лямбда-вираз**: маленька безіменна
функція «взяти track і сказати, чи він коротший за 10». `RemoveAll` викликає її
для кожного елемента і викидає ті, для яких вона повернула `true`.

**3. Зібрати «список на видалення», потім видалити:**

```csharp
List<string> toRemove = new();
foreach (var track in playlist)
{
    if (track.Length < 10) toRemove.Add(track);
}
foreach (var track in toRemove)
{
    playlist.Remove(track); // перебираємо toRemove, змінюємо playlist — це можна
}
```

Тут другий цикл перебирає **інший** список, тому конфлікту немає.

## Практичний приклад: журнал оцінок

```csharp
List<int> grades = [];

Console.WriteLine("Вводьте оцінки (порожній рядок — завершити):");

while (true)
{
    string? input = Console.ReadLine();
    if (string.IsNullOrWhiteSpace(input)) break;

    if (int.TryParse(input, out int grade) && grade is >= 1 and <= 12)
        grades.Add(grade);
    else
        Console.WriteLine("Оцінка має бути числом від 1 до 12.");
}

if (grades.Count == 0)
{
    Console.WriteLine("Оцінок немає.");
    return;
}

grades.Sort();

int sum = 0;
foreach (int g in grades) sum += g;

Console.WriteLine($"Оцінок: {grades.Count}");
Console.WriteLine($"Найнижча: {grades[0]}, найвища: {grades[^1]}");
Console.WriteLine($"Середня: {(double)sum / grades.Count:F2}");
Console.WriteLine($"Відсортовані: {string.Join(", ", grades)}");
```

**Вивід** (для введення 8, 12, 5, 10, 12):

```
Оцінок: 5
Найнижча: 5, найвища: 12
Середня: 9,40
Відсортовані: 5, 8, 10, 12, 12
```

Зверніть увагу: ми ні разу не думали про розмір, не рахували, скільки буде оцінок,
не копіювали масиви. Саме заради цього колекції й існують.

## Коли масив, а коли List

| Ситуація | Масив | `List<T>` |
| --- | --- | --- |
| Кількість елементів відома і не змінюється | ✅ так | можна, але зайве |
| Кількість наперед невідома | ❌ біль | ✅ саме те |
| Треба часто додавати або видаляти | ❌ | ✅ |
| Потрібен доступ за індексом | ✅ | ✅ так само швидко |
| Матриця, таблиця `[,]` | ✅ | ❌ немає прямого аналога |
| Максимальна економія пам'яті | ✅ | трохи більше через запас Capacity |
| Робота з байтами файлу, буфер | ✅ | рідко |

Коротке правило: **за замовчуванням беріть `List<T>`**, а масив — коли розмір
жорстко фіксований або цього вимагає API (наприклад, `File.ReadAllLines`
повертає саме масив).

## Типові помилки

**1. Плутати `Count` і `Capacity`.**

```csharp
List<int> list = new(100);
Console.WriteLine(list.Count);    // 0 — елементів немає!
// list[0] → ArgumentOutOfRangeException
```

`new List<int>(100)` не створює 100 елементів, а лише резервує місце.
Перебирати треба до `Count`, а не до `Capacity`.

**2. Забути, що `Remove` видаляє лише перше входження.**

```csharp
List<int> nums = [5, 3, 5, 5];
nums.Remove(5);
Console.WriteLine(string.Join(",", nums)); // 3,5,5 — а не «3»
```

Щоб прибрати всі входження — `nums.RemoveAll(n => n == 5);`.

**3. Змінювати колекцію всередині `foreach`.**
Розібрали вище: `InvalidOperationException`. Використовуйте `RemoveAll`
або зворотний `for`.

**4. Використовувати `Length` замість `Count`.**
У масиву — `Length`, у колекції — `Count`. У рядка — теж `Length`.
Компілятор одразу підкреслить помилку, але звикнути варто.

## Що далі

`List<T>` чудово підходить, коли важливий **порядок** і доступ **за номером**.
Але спробуйте знайти в списку з 100 000 імен конкретне ім'я — доведеться
перебрати всі. У наступному підрозділі розберемо `Dictionary<TKey, TValue>`
і `HashSet<T>`, які роблять пошук майже миттєвим.
