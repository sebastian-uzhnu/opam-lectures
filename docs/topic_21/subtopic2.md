# Панелі компонування

Ми вміємо описувати елементи. Лишилося найважче й найважливіше: розкласти
їх по вікну так, щоб інтерфейс виглядав охайно і не розсипався, коли
користувач потягне вікно за кут.

## Чому координати — погана ідея

Найочевидніший спосіб розмістити кнопку — сказати, де саме вона стоїть:
«від лівого краю 20, від верхнього 100, ширина 120, висота 30». Так робили
десятиліттями, і на перший погляд це найпростіше.

Проблема виявляється за п'ять хвилин. Ось вікно, зроблене на координатах:

```
  Вікно 400×250, як його задумав розробник

  ┌─ Розрахунок ─────────────────────── ─ □ ✕ ┐
  │                                             │
  │  Сума:  ┌─────────────────────┐             │
  │         └─────────────────────┘             │
  │                                             │
  │  Відсоток: ┌──────────────────┐             │
  │            └──────────────────┘             │
  │                                             │
  │              ┌────────────────┐             │
  │              │   Порахувати   │             │
  │              └────────────────┘             │
  └─────────────────────────────────────────────┘

  Те саме вікно, розтягнуте користувачем до 700×250

  ┌─ Розрахунок ───────────────────────────────────────── ─ □ ✕ ┐
  │                                                               │
  │  Сума:  ┌─────────────────────┐                               │
  │         └─────────────────────┘        ← поля не виросли,     │
  │                                          праворуч порожньо     │
  │  Відсоток: ┌──────────────────┐                               │
  │            └──────────────────┘                               │
  │                                                               │
  │              ┌────────────────┐        ← кнопка лишилася      │
  │              │   Порахувати   │          в лівому кутку        │
  │              └────────────────┘                               │
  └───────────────────────────────────────────────────────────────┘
```

Це ще м'який випадок. Гірше буває, коли вікно **зменшують**: елементи
не зменшуються, а просто зникають за краєм. Або коли користувач вмикає
масштаб 125 %, шрифти стають більшими, текст у кнопці більше не вміщається —
а кнопка не знає, що їй треба підрости. Або коли текст перекладають
українською: замість `Save` там `Зберегти`, і воно не влазить.

Ідея WPF інша:

> **Ви не задаєте, де стоїть елемент. Ви задаєте правило, за яким
> його розташовують. Розміри рахує платформа.**

Замість «кнопка в точці (150, 180)» ви кажете «кнопка притиснута до
правого краю нижньої смуги, з відступом 10». І тоді, куди б не потягнув
користувач, правило виконується.

Правила задають **панелі компонування** (layout panels) — спеціальні
елементи-контейнери, єдина робота яких — розкласти своїх дітей. Панель
сама нічого не малює: її не видно, видно лише результат її роботи.

:::info[Цікаво]
Як саме панель розкладає дітей? У два проходи. Спершу **Measure**: панель
питає кожну дитину «скільки місця тобі треба, якщо доступно ось стільки?»
Дитина, якщо вона сама панель, питає те саме своїх дітей — і так до низу
дерева. Потім **Arrange**: панель роздає дітям реальні прямокутники,
виходячи з їхніх побажань і власних правил. Саме тому в WPF вміст керує
розміром: кнопка стає такою, щоб уміщався текст, а не навпаки.
:::

## StackPanel: усе в одну лінію

Найпростіша панель. Складає дітей один за одним — за замовчуванням згори
вниз, а якщо вказати `Orientation="Horizontal"` — зліва направо.

```
  Orientation="Vertical"             Orientation="Horizontal"
  (за замовчуванням)

  ┌───────────────────────┐          ┌────────────────────────────┐
  │ ┌───────────────────┐ │          │ ┌────┐┌──────┐┌─────────┐  │
  │ │  елемент 1        │ │          │ │ 1  ││  2   ││    3    │  │
  │ └───────────────────┘ │          │ └────┘└──────┘└─────────┘  │
  │ ┌───────────────────┐ │          │                            │
  │ │  елемент 2        │ │          │  висота — за найвищим,     │
  │ └───────────────────┘ │          │  ширина кожного — своя     │
  │ ┌───────────────────┐ │          │                            │
  │ │  елемент 3        │ │          └────────────────────────────┘
  │ └───────────────────┘ │
  │                       │
  │   решта простору      │
  │   залишається порожньою│
  └───────────────────────┘
```

Головне правило `StackPanel`: **уздовж напрямку складання елемент отримує
рівно стільки місця, скільки йому треба, а поперек — усе доступне**.
У вертикальній панелі кнопка буде заввишки під свій текст, але завширшки
на всю панель.

```xml
<Window x:Class="LayoutDemo.StackWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="StackPanel" Height="260" Width="320">

    <StackPanel Margin="16">
        <TextBlock Text="Оберіть спосіб доставки" FontSize="16"
                   Margin="0,0,0,10"/>
        <RadioButton Content="Самовивіз" Margin="0,4"/>
        <RadioButton Content="Кур'єр" Margin="0,4" IsChecked="True"/>
        <RadioButton Content="Поштомат" Margin="0,4"/>
        <Button Content="Продовжити" Margin="0,16,0,0" Padding="8"/>
    </StackPanel>
</Window>
```

**Коли обирати:** список елементів, які йдуть один за одним і не мусять
ділити між собою простір. Панель інструментів, група перемикачів,
вертикальна форма з кількох полів.

**Коли не обирати:** коли треба, щоб елементи розтягувалися на весь доступний
простір або вирівнювалися в колонки. `StackPanel` навмисно цього не вміє.

:::warning[Обережно]
`StackPanel` не обмежує себе розміром вікна. Якщо дітей багато, останні
просто виїдуть за нижній край і будуть невидимі — без жодної помилки
і без смуги прокручування. Якщо вміст може не поміститися, загорніть
панель у `ScrollViewer`:

```xml
<ScrollViewer VerticalScrollBarVisibility="Auto">
    <StackPanel>
        <!-- багато елементів -->
    </StackPanel>
</ScrollViewer>
```
:::

## WrapPanel: із переносом на новий рядок

Те саме, що `StackPanel`, але коли елементи не вміщаються в рядок, панель
переносить їх на наступний. Так поводяться слова в текстовому редакторі
й плитки в галереї зображень.

```
  Вікно широке                    Те саме вікно вужче

  ┌──────────────────────────┐    ┌────────────────┐
  │ ┌────┐┌────┐┌────┐┌────┐ │    │ ┌────┐┌────┐   │
  │ │ A  ││ B  ││ C  ││ D  │ │    │ │ A  ││ B  │   │
  │ └────┘└────┘└────┘└────┘ │    │ └────┘└────┘   │
  │ ┌────┐                   │    │ ┌────┐┌────┐   │
  │ │ E  │                   │    │ │ C  ││ D  │   │
  │ └────┘                   │    │ └────┘└────┘   │
  └──────────────────────────┘    │ ┌────┐         │
                                  │ │ E  │         │
                                  │ └────┘         │
                                  └────────────────┘
```

```xml
<Window x:Class="LayoutDemo.WrapWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="WrapPanel" Height="220" Width="380">

    <WrapPanel Margin="12" ItemHeight="40" ItemWidth="90">
        <Button Content="7"/>
        <Button Content="8"/>
        <Button Content="9"/>
        <Button Content="4"/>
        <Button Content="5"/>
        <Button Content="6"/>
        <Button Content="1"/>
        <Button Content="2"/>
        <Button Content="3"/>
    </WrapPanel>
</Window>
```

Властивості `ItemWidth` і `ItemHeight` змушують усі елементи бути однакового
розміру — зручно для плиток. Якщо їх не вказати, кожен елемент отримає
свій природний розмір.

**Коли обирати:** набір однорідних елементів, кількість яких заздалегідь
невідома і яким байдуже, у якому рядку опинитися. Теги, плитки, панель
кнопок форматування.

**Коли не обирати:** коли позиція елемента має значення. Форму на `WrapPanel`
будувати не можна — поля перескакуватимуть рядками при зміні розміру вікна.

## DockPanel: притиснути до країв

`DockPanel` роздає дітям краї. Кожна дитина каже, до якого краю вона
притискається — через приєднану властивість `DockPanel.Dock` зі значенням
`Left`, `Top`, `Right` або `Bottom`. Останній елемент за замовчуванням
займає всю серединку.

```
  ┌─────────────────────────────────────────┐
  │            Dock="Top"                   │
  ├──────────┬────────────────────┬─────────┤
  │          │                    │         │
  │  Dock=   │   останній         │  Dock=  │
  │  "Left"  │   елемент          │ "Right" │
  │          │   (заповнює        │         │
  │          │    залишок)        │         │
  ├──────────┴────────────────────┴─────────┤
  │           Dock="Bottom"                 │
  └─────────────────────────────────────────┘
```

Важлива деталь: **порядок має значення**. Панель обробляє дітей по черзі,
і кожна наступна отримує те, що лишилося після попередніх. Якщо спершу
йде `Left`, а потім `Top` — верхня смуга не дійде до лівого краю.

```xml
<Window x:Class="LayoutDemo.DockWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="DockPanel" Height="300" Width="460">

    <DockPanel>

        <Border DockPanel.Dock="Top" Background="#FF2D4059" Height="40">
            <TextBlock Text="Мій застосунок" Foreground="White"
                       FontSize="16" VerticalAlignment="Center"
                       Margin="12,0,0,0"/>
        </Border>

        <Border DockPanel.Dock="Bottom" Background="#FFEEEEEE" Height="26">
            <TextBlock Text="Готово" Margin="8,0,0,0"
                       VerticalAlignment="Center"/>
        </Border>

        <Border DockPanel.Dock="Left" Background="#FFF4F4F4" Width="120">
            <StackPanel Margin="8">
                <Button Content="Головна" Margin="0,4"/>
                <Button Content="Звіти" Margin="0,4"/>
                <Button Content="Налаштування" Margin="0,4"/>
            </StackPanel>
        </Border>

        <!-- Останній елемент без Dock заповнює те, що лишилось -->
        <TextBlock Text="Робоча область"
                   HorizontalAlignment="Center"
                   VerticalAlignment="Center"
                   FontSize="18" Foreground="Gray"/>

    </DockPanel>
</Window>
```

**Коли обирати:** класична структура вікна — шапка згори, рядок стану знизу,
навігація збоку, вміст посередині. Це саме той випадок, для якого `DockPanel`
створений.

**Коли не обирати:** усередині робочої області, де потрібна сітка полів.

:::tip[Порада]
Властивість `LastChildFill` за замовчуванням `True` — саме тому останній
елемент заповнює середину. Якщо вам потрібно, щоб усі діти були притиснуті
до країв і нічого не розтягувалося, поставте `LastChildFill="False"`
і задайте `Dock` кожному.
:::

## Canvas: єдине місце, де є координати

`Canvas` — та сама модель абсолютних координат, від якої ми відмовилися
на початку підрозділу. Дитині задають `Canvas.Left` і `Canvas.Top` —
відстані від лівого й верхнього краю полотна.

```
  Canvas
  ┌───────────────────────────────────────┐
  │  ▲                                    │
  │  │ Canvas.Top="30"                    │
  │  ▼    ┌──────────────┐                │
  │◀─────▶│   Елемент    │                │
  │Left=  └──────────────┘                │
  │ "40"                                  │
  │                                       │
  │  при зміні розміру вікна елемент      │
  │  лишається там, де був                │
  └───────────────────────────────────────┘
```

```xml
<Window x:Class="LayoutDemo.CanvasWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="Canvas" Height="240" Width="320">

    <Canvas Background="White">
        <Ellipse Canvas.Left="40" Canvas.Top="40"
                 Width="80" Height="80" Fill="#FF6FAF6F"/>
        <Rectangle Canvas.Left="120" Canvas.Top="70"
                   Width="120" Height="60" Fill="#FF4A7EBB"/>
        <TextBlock Canvas.Left="40" Canvas.Top="150"
                   Text="Довільне розташування" FontSize="14"/>
    </Canvas>
</Window>
```

**Коли обирати:** графіка, схеми, ігрове поле, діаграми — усе, де розташування
задається обчисленнями, а не логікою інтерфейсу. У темі про двовимірну
графіку `Canvas` стане основним інструментом.

**Коли не обирати:** для звичайних елементів керування. Ніколи. Саме про
цю панель ідеться в застереженні на початку підрозділу.

:::danger[Часта помилка]
Новачок, побачивши `Canvas`, полегшено видихає: «нарешті, як я звик».
І будує на ньому форму з полями й кнопками. Результат: вікно не масштабується,
на іншому масштабі шрифтів усе наповзає одне на одне, додати поле в середину
форми означає пересунути руками двадцять елементів. Якщо ви ловите себе
на тому, що підбираєте координати на око, — ви обрали не ту панель.
:::

## Grid: головна панель

`Grid` — сітка з рядків і стовпців. Це найпотужніша й найуживаніша панель
у WPF; більшість реальних вікон побудовані саме на ній. Недарма шаблон
Visual Studio створює у вікні порожній `Grid`.

Робота з `Grid` складається з двох кроків: **оголосити рядки й стовпці**,
а потім **розставити елементи по комірках**.

```xml
<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
        <RowDefinition Height="40"/>
    </Grid.RowDefinitions>

    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="120"/>
        <ColumnDefinition Width="*"/>
    </Grid.ColumnDefinitions>

    <TextBlock Grid.Row="0" Grid.Column="0" Text="Назва:"/>
    <TextBox   Grid.Row="0" Grid.Column="1"/>
</Grid>
```

```
              Column 0          Column 1
              Width="120"       Width="*"
           ◀──────────────▶ ◀────────────────────▶
          ┌───────────────┬──────────────────────┐
 Row 0    │ [0,0]         │ [0,1]                │  Height="Auto"
 Auto     │ Назва:        │ [текстове поле     ] │  (за вмістом)
          ├───────────────┼──────────────────────┤
          │ [1,0]         │ [1,1]                │
 Row 1    │               │                      │  Height="*"
 *        │               │                      │  (увесь залишок)
          │               │                      │
          ├───────────────┼──────────────────────┤
 Row 2    │ [2,0]         │ [2,1]                │  Height="40"
 40       │               │                      │  (рівно 40)
          └───────────────┴──────────────────────┘
```

**Нумерація починається з нуля.** Якщо в елемента не вказані `Grid.Row`
і `Grid.Column`, він потрапляє в комірку [0, 0].

### Три види розмірів

Це найважливіша таблиця всієї теми.

| Запис | Назва | Як рахується | Коли використовувати |
|---|---|---|---|
| `Height="Auto"` | автоматичний | рівно стільки, скільки треба вмісту | заголовки, підписи, рядки з кнопками — усе, що має свою природну висоту |
| `Height="*"` | зірковий (пропорційний) | увесь простір, що лишився після `Auto` і фіксованих | робоча область, список, велике поле — те, що має розтягуватись |
| `Height="2*"` | зірковий із вагою | вдвічі більше, ніж сусідній `*` | коли залишок треба поділити в певній пропорції |
| `Height="120"` | фіксований | рівно 120 одиниць, завжди | рідко: смуга сталої висоти, іконка |

Зіркові розміри працюють так: платформа спершу віддає місце фіксованим
рядкам і рядкам `Auto`, а потім увесь **залишок** ділить між зірковими
пропорційно їхнім вагам.

```
  Три стовпці: Width="*"  Width="2*"  Width="*"
  Загальна ширина 400. Сума ваг = 1 + 2 + 1 = 4.
  Одна частка = 400 / 4 = 100.

  ┌──────────┬─────────────────────┬──────────┐
  │   100    │        200          │   100    │
  │    *     │        2*           │    *     │
  └──────────┴─────────────────────┴──────────┘

  Користувач розтягнув вікно до 800:

  ┌────────────────────┬───────────────────────────────────┬────────────────────┐
  │        200         │              400                  │        200         │
  └────────────────────┴───────────────────────────────────┴────────────────────┘
      пропорція збереглася
```

:::tip[Порада]
Проста схема, з якої варто починати майже будь-яке вікно:

```xml
<Grid.RowDefinitions>
    <RowDefinition Height="Auto"/>   <!-- шапка -->
    <RowDefinition Height="*"/>      <!-- вміст -->
    <RowDefinition Height="Auto"/>   <!-- кнопки внизу -->
</Grid.RowDefinitions>
```

Шапка й кнопки займають рівно скільки треба, а весь приріст вікна дістається
середині. Це виглядає правильно за будь-якого розміру.
:::

### Об'єднання комірок

Елемент може займати кілька комірок поспіль — через приєднані властивості
`Grid.RowSpan` (скільки рядків) і `Grid.ColumnSpan` (скільки стовпців).

```
  ┌────────────┬────────────┬────────────┐
  │  Заголовок, ColumnSpan="3"           │
  ├────────────┼────────────┼────────────┤
  │            │            │            │
  │  Row       │   [1,1]    │   [1,2]    │
  │  Span      ├────────────┼────────────┤
  │  ="2"      │            │            │
  │            │   [2,1]    │   [2,2]    │
  └────────────┴────────────┴────────────┘
```

```xml
<Grid Margin="12">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>
    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="*"/>
        <ColumnDefinition Width="*"/>
        <ColumnDefinition Width="*"/>
    </Grid.ColumnDefinitions>

    <TextBlock Grid.Row="0" Grid.Column="0" Grid.ColumnSpan="3"
               Text="Панель керування" FontSize="18"
               HorizontalAlignment="Center" Margin="0,0,0,10"/>

    <Border Grid.Row="1" Grid.Column="0" Grid.RowSpan="2"
            Background="#FFF0F4F8" Margin="2">
        <TextBlock Text="Бічна колонка" Margin="6"/>
    </Border>

    <Border Grid.Row="1" Grid.Column="1" Background="#FFE8F0E8" Margin="2"/>
    <Border Grid.Row="1" Grid.Column="2" Background="#FFE8F0E8" Margin="2"/>
    <Border Grid.Row="2" Grid.Column="1" Background="#FFF8F0E8" Margin="2"/>
    <Border Grid.Row="2" Grid.Column="2" Background="#FFF8F0E8" Margin="2"/>
</Grid>
```

### Вкладені сітки

Не намагайтеся втиснути складне вікно в одну велику сітку з дев'ятьма
рядками — читати таку розмітку неможливо. Правильний підхід: зовнішня
сітка ділить вікно на великі зони, а всередині кожної зони — своя маленька
сітка або панель.

```xml
<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>

    <!-- Зона 1: шапка -->
    <TextBlock Grid.Row="0" Text="Замовлення" FontSize="20" Margin="12"/>

    <!-- Зона 2: усередині власна сітка з двох стовпців -->
    <Grid Grid.Row="1" Margin="12">
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="2*"/>
            <ColumnDefinition Width="*"/>
        </Grid.ColumnDefinitions>

        <Border Grid.Column="0" Background="#FFF6F6F6" Margin="0,0,6,0"/>
        <StackPanel Grid.Column="1">
            <Button Content="Додати" Margin="0,0,0,6"/>
            <Button Content="Видалити"/>
        </StackPanel>
    </Grid>
</Grid>
```

Правило: **одна сітка — одне рішення про компонування**. Так само, як один
клас робить одну роботу.

:::warning[Обережно]
Якщо ви забули оголосити `RowDefinitions`, сітка вважає, що в неї один рядок
і один стовпець. Усі елементи опиняться в комірці [0, 0] — тобто один поверх
одного. Помилки не буде, і це збиває з пантелику: у вікні видно тільки
останній елемент, решта під ним. Побачили «зник увесь інтерфейс, крім
однієї кнопки» — перевіряйте визначення рядків.
:::

## Margin і Padding

Дві властивості, які плутають усі й завжди. Різниця в тому, **з якого боку
межі елемента** лежить порожнє місце.

- **`Margin`** — зовнішній відступ. Порожнє місце **навколо** елемента,
  між ним і сусідами. Належить елементу, впливає на його розташування.
- **`Padding`** — внутрішнє поле. Порожнє місце **всередині** елемента,
  між його рамкою і вмістом. Впливає на розмір самого елемента.

```
        Margin (зовні)
  ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  │                              │
  │   ╔══════════════════════╗   │  ← межа елемента (Border/Button)
  │   ║      Padding         ║   │
  │   ║   ┌──────────────┐   ║   │
  │   ║   │    Вміст     │   ║   │
  │   ║   │   (текст)    │   ║   │
  │   ║   └──────────────┘   ║   │
  │   ║                      ║   │
  │   ╚══════════════════════╝   │
  │                              │
  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

Практичний висновок: щоб кнопка була більшою й текст не тулився до рамки —
`Padding`. Щоб кнопка не злипалася із сусідньою — `Margin`.

Обидві властивості мають тип `Thickness` і приймають три форми запису:

| Запис | Значення |
|---|---|
| `Margin="10"` | по 10 з усіх чотирьох боків |
| `Margin="20,10"` | 20 ліворуч і праворуч, 10 згори й знизу |
| `Margin="5,10,15,20"` | ліворуч 5, згори 10, праворуч 15, знизу 20 |

Порядок у повній формі — **ліво, верх, право, низ**, за годинниковою
стрілкою від лівого краю. Його доведеться запам'ятати.

:::tip[Порада]
Типовий прийом: у вертикальній `StackPanel` задавайте всім елементам
`Margin="0,0,0,8"` — відступ тільки знизу. Тоді між елементами буде рівно
8 одиниць, а не 16, як вийшло б при відступі з обох боків. І не забудьте
`Margin` самій панелі, щоб вміст не тулився до рамки вікна.
:::

## Вирівнювання та розміри

Коли комірка (або панель) дає елементу більше місця, ніж йому треба,
постає питання: де саме в цьому місці елемент стане? Відповідають
властивості вирівнювання.

**`HorizontalAlignment`**: `Left`, `Center`, `Right`, `Stretch`.
**`VerticalAlignment`**: `Top`, `Center`, `Bottom`, `Stretch`.

```
   Комірка сітки 200×80, кнопка з текстом "Ok"

   HorizontalAlignment="Stretch"     HorizontalAlignment="Right"
   VerticalAlignment="Stretch"       VerticalAlignment="Center"
   (за замовчуванням)

   ┌────────────────────────┐        ┌────────────────────────┐
   │┌──────────────────────┐│        │                        │
   ││                      ││        │                ┌──────┐│
   ││          Ok          ││        │                │  Ok  ││
   ││                      ││        │                └──────┘│
   │└──────────────────────┘│        │                        │
   └────────────────────────┘        └────────────────────────┘
```

За замовчуванням у більшості елементів стоїть `Stretch` — елемент розтягується
на всю доступну область. Це головна причина подиву «чому моя кнопка на пів
вікна». Лікується або вирівнюванням, або зверненням до правильної панелі.

Тепер про розміри. Є дві родини властивостей, і різниця між ними принципова.

| Властивість | Що робить | Наслідок |
|---|---|---|
| `Width`, `Height` | жорстко фіксує розмір | елемент не реагує на зміну вікна; текст може не поміститися |
| `MinWidth`, `MinHeight` | нижня межа | елемент розтягується, але не стискається менше межі |
| `MaxWidth`, `MaxHeight` | верхня межа | елемент розтягується, але лише до межі |

`Width` і `Height` у вікні варто ставити якомога рідше. Найкорисніша пара —
`MinWidth` плюс `MaxWidth`: поле введення розтягується разом із вікном,
але не звужується до нечитабельного і не розповзається на весь монітор.

```xml
<TextBox MinWidth="120" MaxWidth="400"
         HorizontalAlignment="Stretch"
         Margin="0,0,0,8"/>
```

:::danger[Часта помилка]
Задати кнопці `Height="30"` і не подумати про масштабування шрифтів.
На комп'ютері з масштабом 150 % системний шрифт стане більшим, а кнопка
залишиться заввишки 30 — і текст у ній обріжеться. Замість `Height` ставте
`Padding`: кнопка сама виросте під свій вміст.
:::

## Порівняння всіх п'яти панелей

| Панель | Принцип | Скільки дітей | Реагує на зміну розміру | Типове застосування | Коли не варто |
|---|---|---|---|---|---|
| `StackPanel` | один за одним у лінію | багато | частково: поперек розтягує, уздовж ні | групи перемикачів, стовпчик кнопок, проста форма | коли вміст може не поміститися |
| `WrapPanel` | у лінію з переносом | багато | так, переносить елементи | плитки, теги, панелі інструментів | форми та будь-що з фіксованою структурою |
| `DockPanel` | притиснути до країв | багато | так, серединка тягнеться | каркас вікна: шапка, статус, бічна панель | сітка полів усередині робочої області |
| `Canvas` | абсолютні координати | багато | ні, зовсім | графіка, схеми, ігрове поле, анімація | звичайні елементи керування |
| `Grid` | рядки й стовпці | багато | так, через зіркові розміри | практично будь-яке вікно | коли достатньо простого стовпчика |

Практична порада на кожен день: **починайте з `Grid`**. Якщо виявилося, що
рядки й стовпці не потрібні, а елементи просто йдуть один за одним —
замініть на `StackPanel`. Це швидше й надійніше, ніж іти зворотним шляхом.

## Типові помилки

**Забули `Grid.RowDefinitions`, але розставили `Grid.Row`.** Усі елементи
складаються в одну комірку один поверх одного. Помилки не буде — буде дивне
вікно.

**Поставили всім рядкам `Height="Auto"`.** Сітка займе рівно стільки, скільки
треба вмісту, і при розтягуванні вікна вміст лишиться вгорі, а низ буде
порожнім. Хоча б один рядок має бути зірковим.

**Будують форму на `Canvas`.** Вікно перестає масштабуватися. Для форм —
`Grid`.

**Плутають `Margin` і `Padding`.** «Текст тулиться до рамки кнопки» —
це `Padding`. «Кнопки злиплися між собою» — це `Margin`.

**Ставлять `Width` і `Height` кожному елементу.** Інтерфейс перестає
адаптуватися й ламається на іншому масштабі шрифтів. Фіксовані розміри —
виняток, а не правило.

**Використовують один `Grid` на все вікно з десятком рядків.** Розмітку
неможливо читати й змінювати. Діліть на вкладені сітки за зонами.
