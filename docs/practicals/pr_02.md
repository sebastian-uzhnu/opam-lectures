# Практичне заняття №2

## Тема
Трасування алгоритмів. Складання алгоритмів розв'язування задач

## Мета
Навчитися перевіряти правильність алгоритму вручну, до запуску програми, за допомогою
таблиці трасування. Закріпити етапи розв'язування задачі на комп'ютері. Набути навичок
добору тестових наборів даних і виявлення помилок у чужому алгоритмі.

## Тривалість
2 академічні години.

## Обладнання
Зошит у клітинку, олівець, гумка, лінійка, ручка двох кольорів (другий колір — для
позначення змін у таблиці). Калькулятор не потрібен: усі обчислення в задачах
виконуються усно або в стовпчик. Персональний комп'ютер — лише наприкінці заняття,
для звіряння однієї таблиці за вказівкою викладача.

## Теоретичні відомості

### 1. Що таке трасування і навіщо воно

**Трасування алгоритму** — це покрокове виконання алгоритму людиною з письмовою фіксацією
значень усіх величин після кожного кроку.

Найпоширеніша помилка початківця звучить так: «напишу програму, запущу — і подивлюся».
Так робити не варто з двох причин.

По-перше, запуск показує лише **кінцевий** результат. Якщо він неправильний, ви знаєте,
що помилка десь є, але не знаєте, де саме. Трасування показує **всі проміжні** значення,
тому місце розходження задуму й запису видно одразу.

По-друге, помилка може не проявитися на тих даних, які ви ввели навмання. Програма
видасть правдоподібне число, ви її здасте — а на захисті введуть нуль або від'ємне
значення, і все розсиплеться.

Трасування також потрібне тоді, коли комп'ютера немає під рукою: на контрольній,
на іспиті, під час обговорення задачі біля дошки. Вміння «виконати» алгоритм у голові
й на папері — базова професійна навичка, а не навчальна формальність.

Окремо зазначимо: у середовищі розробки є **покрокове налагодження** — режим, у якому
програма виконується по одному оператору, а значення змінних показує вікно локальних
змінних. Це той самий процес, тільки машина веде таблицю замість вас. Але щоб розуміти,
що показує налагоджувач, треба спершу навчитися вести таблицю власноруч.

### 2. Таблиця трасування

**Таблиця трасування** — таблиця, у якій рядки відповідають крокам виконання алгоритму,
а стовпці — величинам і умовам.

Стандартний набір стовпців:

| Стовпець | Що містить |
|---|---|
| Крок | Порядковий номер дії (1, 2, 3 …) |
| Дія / номер блока | Що виконується: номер блока схеми або короткий запис оператора |
| Змінні | По одному стовпцю на кожну змінну алгоритму |
| Умова | Текст умови та її значення: `істина` / `хиба` |
| Вивід | Що з'явилося на екрані на цьому кроці |

Правила ведення таблиці:

1. Стовпці змінних виписують **до** початку трасування, переглянувши весь алгоритм.
   Інакше посеред роботи доведеться домальовувати стовпець.
2. Якщо змінна ще не набула значення, у клітинці ставлять прочерк `—`, а не нуль.
   Нуль — це значення; прочерк — його відсутність.
3. Якщо на кроці змінна не змінилася, клітинку **не переписують**: залишають порожньою
   або ставлять крапку. Переписування всіх значень щоразу перетворює таблицю на кашу,
   у якій не видно, що саме змінилося.
4. Значення умови записують словом, а не знаком питання. Саме тут найчастіше й ховається
   помилка.
5. Рядок виводу заповнюють тільки тоді, коли виконується блок виведення.

### 3. Трасування лінійного алгоритму

Лінійний алгоритм трасується найпростіше: кроків стільки ж, скільки блоків, повернень
назад немає.

Алгоритм: обчислити периметр і площу прямокутника.

```text
1. Ввести a, b            (a = 6, b = 4)
2. p ← 2 * (a + b)
3. s ← a * b
4. Вивести p, s
```

| Крок | Дія | a | b | p | s | Вивід |
|---|---|---|---|---|---|---|
| 1 | Ввести a, b | 6 | 4 | — | — | |
| 2 | p ← 2*(a+b) | | | 20 | — | |
| 3 | s ← a*b | | | | 24 | |
| 4 | Вивести p, s | | | | | `20 24` |

Порожні клітинки в рядках 2–4 означають «значення не змінилося». Одразу видно, що `a`
і `b` за весь алгоритм не змінюються — це вхідні дані.

### 4. Трасування розгалуженого алгоритму

Додається стовпець умови. Головне правило: у таблицю потрапляють **лише ті** блоки, які
насправді виконалися. Гілка, що не спрацювала, у таблиці не з'являється зовсім.

Алгоритм: визначити більше з двох чисел.

```text
1. Ввести a, b
2. Якщо a > b, то перейти до 3, інакше до 4
3. max ← a; перейти до 5
4. max ← b
5. Вивести max
```

Трасування для `a = 3`, `b = 9`:

| Крок | Дія | a | b | Умова `a > b` | max | Вивід |
|---|---|---|---|---|---|---|
| 1 | Ввести a, b | 3 | 9 | | — | |
| 2 | Перевірка | | | хиба | | |
| 3 | max ← b | | | | 9 | |
| 4 | Вивести max | | | | | `9` |

Блок `max ← a` у таблиці відсутній — він не виконувався. Якщо студент вписує обидві
гілки, він трасує не алгоритм, а свої уявлення про нього.

Щоб перевірити розгалужений алгоритм повністю, потрібно **стільки таблиць, скільки
є різних шляхів** через схему. Для однієї перевірки — дві таблиці; для вкладеної
перевірки з трьох гілок — три.

### 5. Трасування циклічного алгоритму

Тут таблиця стає найдовшою, і тут же найбільше помилок. Кожен прохід циклу дає кілька
рядків: перевірка умови, тіло, зміна керівної змінної. Останній рядок — перевірка,
що дала хибу й вивела з циклу; його обов'язково записують, інакше незрозуміло, чому
цикл завершився.

Алгоритм: обчислити суму чисел від 1 до n.

```text
1. Ввести n
2. s ← 0
3. i ← 1
4. Поки i <= n виконувати кроки 5–6
5.    s ← s + i
6.    i ← i + 1
7. Вивести s
```

Трасування для `n = 4`:

| Крок | Дія | n | s | i | Умова `i <= n` | Вивід |
|---|---|---|---|---|---|---|
| 1 | Ввести n | 4 | — | — | | |
| 2 | s ← 0 | | 0 | | | |
| 3 | i ← 1 | | | 1 | | |
| 4 | Перевірка | | | | істина (1 ≤ 4) | |
| 5 | s ← s + i | | 1 | | | |
| 6 | i ← i + 1 | | | 2 | | |
| 7 | Перевірка | | | | істина (2 ≤ 4) | |
| 8 | s ← s + i | | 3 | | | |
| 9 | i ← i + 1 | | | 3 | | |
| 10 | Перевірка | | | | істина (3 ≤ 4) | |
| 11 | s ← s + i | | 6 | | | |
| 12 | i ← i + 1 | | | 4 | | |
| 13 | Перевірка | | | | істина (4 ≤ 4) | |
| 14 | s ← s + i | | 10 | | | |
| 15 | i ← i + 1 | | | 5 | | |
| 16 | Перевірка | | | | хиба (5 ≤ 4) | |
| 17 | Вивести s | | | | | `10` |

Зверніть увагу на кроки 13–16. Саме на межі виникають дві класичні помилки: цикл
виконується на один раз менше (якщо замість `<=` написати `<`) або на один раз більше
(якщо `i` збільшити не в тому місці). У таблиці це видно без запуску програми.

Якщо циклів багато проходів, дозволяється трасувати не всі: записати перші два-три,
поставити рядок із трьома крапками та обов'язково — останні два проходи й вихід.
Середину пропускати можна лише тоді, коли ви впевнені, що в ній нічого не змінюється
якісно.

### 6. Етапи розв'язування задачі на комп'ютері

Трасування — це не окрема вправа, а частина загального порядку роботи.

```text
 ┌──────────────────┐   Що маємо, що треба знайти,
 │ 1. Постановка    │   які є обмеження на дані
 └────────┬─────────┘
 ┌────────▼─────────┐   Формули, залежності, спрощення;
 │ 2. Модель        │   що враховуємо, чим нехтуємо
 └────────┬─────────┘
 ┌────────▼─────────┐   Блок-схема або псевдокод;
 │ 3. Алгоритм      │   перевірка ТРАСУВАННЯМ
 └────────┬─────────┘
 ┌────────▼─────────┐   Запис алгоритму мовою програмування
 │ 4. Кодування     │
 └────────┬─────────┘
 ┌────────▼─────────┐   Перевірка на наборах даних;
 │ 5. Тестування    │   виправлення помилок
 └────────┬─────────┘
 ┌────────▼─────────┐   Зміни за новими вимогами,
 │ 6. Супровід      │   виправлення виявленого згодом
 └──────────────────┘
```

| Етап | Головне питання | Типовий результат |
|---|---|---|
| Постановка задачі | Що дано і що треба отримати? | Перелік вхідних і вихідних даних, обмеження |
| Побудова моделі | Як пов'язані величини? | Формули, співвідношення, припущення |
| Розробка алгоритму | У якому порядку діяти? | Блок-схема, перевірена трасуванням |
| Кодування | Як це записати мовою? | Текст програми |
| Тестування | Чи працює правильно? | Таблиця тестів, виправлений код |
| Супровід | Що робити далі? | Зміни, доповнення, документація |

Вартість помилки зростає з кожним етапом. Помилка, помічена на етапі алгоритму, коштує
гумки й п'яти хвилин. Та сама помилка, помічена після здачі, коштує переписування
частини програми. Тому трасування роблять **до** кодування, а не замість налагодження.

### 7. Як добирати тестові дані

Перевіряти програму випадковими числами — марна праця. Набори добирають свідомо,
щонайменше трьох видів.

| Вид набору | Що перевіряє | Приклад для задачі «знижка при сумі понад 1000» |
|---|---|---|
| **Нормальні** (типові) | Основну логіку на звичайних даних | 500 (без знижки), 2000 (зі знижкою) |
| **Граничні** | Поведінку на межах діапазонів і умов | 999, 1000, 1001 |
| **Некоректні** | Реакцію на дані, яких не мало бути | −50, 0, текст замість числа |

Граничні набори найцінніші: більшість помилок живе саме на межі. Для кожної умови
з числом перевіряйте три значення — трохи менше за межу, рівно межу, трохи більше.

Для циклів окремо перевіряють:

- «нуль повторень» — чи коректно працює алгоритм, коли цикл не виконався жодного разу;
- «одне повторення» — найкоротший реальний прохід;
- «багато повторень» — звичайна робота.

Для масивів і послідовностей додають ще два випадки: усі елементи однакові та елементи
розташовані у зворотному порядку.

Записуйте набори в таблицю **до** перевірки, разом з очікуваним результатом, обчисленим
вручну. Якщо спершу запустити програму, а потім вирішувати, чи правильна відповідь,
мозок охоче погодиться з будь-яким числом на екрані.

### 8. Інваріант циклу простими словами

**Інваріант циклу** — твердження про змінні, яке істинне перед кожним проходом циклу
і залишається істинним після нього.

Звучить складно, але ідея побутова. Уявіть, що ви складаєте гроші в гаманець і рахуєте.
Твердження «у гаманці лежить рівно стільки, скільки я вже перерахував» істинне на початку
(0 грошей, 0 перераховано) і залишається істинним після кожної купюри. Коли купюри
закінчилися, з цього твердження випливає результат: у гаманці — уся сума.

Для алгоритму суми чисел від 1 до n інваріант формулюється так:

**Інваріант:** перед кожною перевіркою умови `s` дорівнює сумі всіх чисел від 1
до `i − 1`.

Перевірте за таблицею з розділу 5: перед кроком 4 `i = 1`, `s = 0` — сума чисел від 1
до 0 порожня, тобто 0; істина. Перед кроком 13 `i = 4`, `s = 6` — сума 1+2+3 = 6;
істина. Коли цикл завершився, `i = 5`, отже `s` — сума від 1 до 4, тобто 10. Саме те,
що потрібно.

Навіщо це на практиці: якщо ви сформулювали інваріант і він десь порушується, ви точно
знаєте номер кроку, де алгоритм зламався. Це найшвидший спосіб знайти помилку в циклі,
не переглядаючи всю таблицю.

## Приклад виконання

### Умова

Наведено алгоритм. Заповнити таблицю трасування для `n = 4` і визначити, що він
обчислює. Дібрати тестові набори й перевірити алгоритм на граничному випадку.

```text
1. Ввести n
2. f ← 1
3. k ← 2
4. Поки k <= n виконувати кроки 5–6
5.    f ← f * k
6.    k ← k + 1
7. Вивести f
```

### Крок 1. Підготовка таблиці

Переглядаємо алгоритм і виписуємо всі величини: `n`, `f`, `k`. Умова одна: `k <= n`.
Отже, стовпці: Крок, Дія, n, f, k, Умова, Вивід.

### Крок 2. Заповнення таблиці для n = 4

| Крок | Дія | n | f | k | Умова `k <= n` | Вивід |
|---|---|---|---|---|---|---|
| 1 | Ввести n | 4 | — | — | | |
| 2 | f ← 1 | | 1 | | | |
| 3 | k ← 2 | | | 2 | | |
| 4 | Перевірка | | | | істина (2 ≤ 4) | |
| 5 | f ← f * k | | 2 | | | |
| 6 | k ← k + 1 | | | 3 | | |
| 7 | Перевірка | | | | істина (3 ≤ 4) | |
| 8 | f ← f * k | | 6 | | | |
| 9 | k ← k + 1 | | | 4 | | |
| 10 | Перевірка | | | | істина (4 ≤ 4) | |
| 11 | f ← f * k | | 24 | | | |
| 12 | k ← k + 1 | | | 5 | | |
| 13 | Перевірка | | | | хиба (5 ≤ 4) | |
| 14 | Вивести f | | | | | `24` |

### Крок 3. Висновок про призначення алгоритму

Результат 24 для n = 4. Перевіримо здогад: 1·2·3·4 = 24. Алгоритм обчислює **факторіал**
числа `n` — добуток усіх натуральних чисел від 1 до `n`.

Чому `f` починається з 1, а не з 0: `f` — накопичувач добутку. Якби на початку стояв
нуль, усі множення дали б нуль. Накопичувач суми починають з 0, накопичувач добутку —
з 1. Це загальне правило, а не особливість цієї задачі.

Чому `k` починається з 2, а не з 1: множення на одиницю нічого не змінює, тому перший
прохід просто пропущено. Якби `k` починалося з 1, результат був би тим самим, лише
кроків на два більше.

### Крок 4. Інваріант

**Інваріант:** перед кожною перевіркою умови `f` дорівнює добутку всіх чисел від 1
до `k − 1`.

Перевірка за таблицею: крок 7 — `k = 3`, `f = 2` = 1·2; крок 10 — `k = 4`, `f = 6` =
1·2·3; крок 13 — `k = 5`, `f = 24` = 1·2·3·4. Інваріант виконується скрізь, отже алгоритм
правильний не лише для `n = 4`.

### Крок 5. Добір тестових наборів

| № | `n` | Вид набору | Що перевіряє | Очікуваний `f` |
|---|---|---|---|---|
| 1 | 4 | нормальний | звичайну роботу циклу | 24 |
| 2 | 1 | граничний | «нуль повторень»: умова `2 <= 1` хибна одразу | 1 |
| 3 | 2 | граничний | «одне повторення» | 2 |
| 4 | 0 | некоректний | факторіал нуля за означенням 1 | 1 |
| 5 | −3 | некоректний | факторіал від'ємного не визначений | алгоритм видасть 1, хоча мав би повідомити про помилку |

### Крок 6. Трасування граничного випадку n = 1

| Крок | Дія | n | f | k | Умова `k <= n` | Вивід |
|---|---|---|---|---|---|---|
| 1 | Ввести n | 1 | — | — | | |
| 2 | f ← 1 | | 1 | | | |
| 3 | k ← 2 | | | 2 | | |
| 4 | Перевірка | | | | хиба (2 ≤ 1) | |
| 5 | Вивести f | | | | | `1` |

Цикл не виконався жодного разу — і це правильна поведінка: 1! = 1. Саме заради таких
випадків потрібен цикл із **передумовою**. Якби тут стояв цикл із післяумовою, тіло
виконалося б один раз, `f` стало б 2, і відповідь була б хибною.

### Крок 7. Виявлений недолік і його виправлення

Набір 5 показує справжню ваду алгоритму: для від'ємного `n` він мовчки видає 1 замість
повідомлення про помилку. Порушено властивість **результативності**: якщо розв'язку
немає, алгоритм має про це сказати.

Виправлення: перед кроком 2 додати перевірку.

```text
1.  Ввести n
1а. Якщо n < 0, то вивести «Факторіал не визначений» і перейти до кінця
2.  f ← 1
...
```

Це і є головна користь трасування: помилку знайдено на папері, до написання жодного
рядка коду.

Наведений нижче фрагмент подано **лише для порівняння** зі схемою — писати програму
на цьому занятті не потрібно:

```csharp
// f — накопичувач добутку, тому початкове значення 1, а не 0
long f = 1;
for (int k = 2; k <= n; k++)
{
    f *= k;
}
```

## Завдання для аудиторної роботи

**Задача 6 (від умови до алгоритму).** Магазин працює з 9:00 до 21:00. Складіть алгоритм,

## Контрольні питання

1. Що таке трасування алгоритму? Назвіть три ситуації, у яких воно потрібне.
2. З яких стовпців складається таблиця трасування? Що записують у стовпці умови?
3. Чому в таблиці не переписують значення змінних, які не змінилися?
4. Чим прочерк у клітинці відрізняється від нуля?
5. Скільки таблиць трасування потрібно, щоб повністю перевірити алгоритм із одним
   розгалуженням? А з двома вкладеними?
6. Чому в таблиці трасування циклу обов'язково записують останню перевірку умови,
   яка дала хибу?
7. Перелічіть етапи розв'язування задачі на комп'ютері. На якому з них виконують
   трасування і чому не пізніше?
8. Які три види тестових наборів ви знаєте? Наведіть по одному прикладу для задачі
   «обчислити середній бал за трьома оцінками».
9. Чому граничні набори даних цінніші за випадкові? Наведіть помилку, яку виявляє
   лише граничний набір.
10. Що таке інваріант циклу? Сформулюйте інваріант для алгоритму обчислення суми
    елементів послідовності та поясніть, чому накопичувач суми починають з нуля,
    а накопичувач добутку — з одиниці.
