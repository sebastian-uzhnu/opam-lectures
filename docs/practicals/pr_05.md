# Практичне заняття №5

## Тема
Алгоритми обробки одновимірних та двовимірних масивів

## Мета
Навчитися подавати набір однотипних даних масивом і описувати обробку масиву словесною
схемою та блок-схемою до написання коду. Закріпити типові алгоритми: накопичення суми,
пошук екстремуму разом з індексом, підрахунок за умовою, реверс, циклічний зсув, вставка
й видалення елемента. Набути навичок запису умов відбору елементів заданої області
матриці та визначення меж внутрішнього циклу при обході трикутних областей.
Підготуватися до лабораторних робіт №7 і №8.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Зошит у клітинку, олівець, лінійка. Роздруковані бланки таблиць трасування та порожні
сітки матриць 5 × 5 (видає викладач). Персональний комп'ютер із .NET 8 SDK — лише для
перевірки окремих відповідей наприкінці заняття.

## Теоретичні відомості

### 1. Масив як структура даних

**Масив** — іменований набір елементів одного типу, розміщених у пам'яті підряд, доступ
до кожного з яких здійснюється за **індексом** — цілим номером елемента.

До масиву звертаються, коли дані треба зберегти **всі одночасно**: щоб відсортувати,
порівняти кожне з кожним, вивести у зворотному порядку. Якщо досить обробити кожне
значення один раз і забути, масив не потрібен — вистачить циклу з накопичувачами.

```text
   індекси:      0     1     2     3     4     5     6
               ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
   temp[ ]     │ -3  │  0  │  5  │ 12  │  8  │  1  │ -7  │
               └─────┴─────┴─────┴─────┴─────┴─────┴─────┘
                  ▲                                   ▲
              перший temp[0]            останній temp[temp.Length - 1]
   Розмір (temp.Length) = 7      Індекси: від 0 до 6
```

| Поняття | Позначення | Значення для схеми вище |
|---|---|---|
| Розмір масиву | `arr.Length` | 7 |
| Індекс першого / останнього елемента | 0 і `arr.Length - 1` | 0 і 6 |
| Елемент за індексом 3 | `arr[3]` | 12 |
| Допустимі індекси | від 0 до `arr.Length - 1` | 0…6 |

Нумерація **з нуля** — не примха мови: індекс означає «на скільки елементів відступити
від початку», і для першого відступ нульовий. Звідси правило: у циклі пишуть
`i < arr.Length`, а не `i <= arr.Length`. Звернення `arr[7]` для масиву із семи елементів
дає помилку виходу за межі — програма аварійно завершиться.

Розмір масиву **фіксований**: вставка й видалення завжди означають зсув решти елементів.

### 2. Типові алгоритми обробки одновимірного масиву

У словесних схемах нижче `n` позначає `arr.Length`.

**Сума й середнє арифметичне**

```text
 1. sum = 0
 2. для i від 0 до n-1: sum = sum + arr[i]
 3. якщо n > 0, то average = sum / n, інакше масив порожній — середнього немає
```

Ділити треба в дійсному типі: для цілих `sum` і `n` результат буде цілим і 7/2 дасть 3.

**Пошук максимуму та його індексу**

```text
 1. max = arr[0]; maxIndex = 0
 2. для i від 1 до n-1:
 2.1.   якщо arr[i] > max, то max = arr[i]; maxIndex = i
 3. результат: max, maxIndex
```

Цикл починається з індексу 1: нульовий елемент уже взято за рекорд. Строга нерівність
залишає **перший** із однакових максимумів, `>=` залишила б останній.

**Підрахунок і сума елементів за умовою**

```text
 1. count = 0; sum = 0
 2. для i від 0 до n-1:
 2.1.   якщо arr[i] задовольняє умову: count = count + 1; sum = sum + arr[i]
 3. якщо count > 0, середнє серед відібраних = sum / count
```

**Реверс — переставляння елементів у зворотному порядку**

```text
 1. для i від 0 до n/2 - 1:
 1.1.   обміняти arr[i] та arr[n-1-i] через допоміжну змінну

   до:    │ 10 │ 20 │ 30 │ 40 │ 50 │   обміни: (0,4) (1,3)
   після: │ 50 │ 40 │ 30 │ 20 │ 10 │   середній елемент 30 лишається на місці
```

Цикл іде лише до середини. Якщо довести його до `n-1`, кожна пара обміняється двічі
й масив повернеться у вихідний стан — класична помилка.

**Циклічний зсув уліво на одну позицію**

```text
 1. first = arr[0]                     (запам'ятати те, що буде втрачено)
 2. для i від 0 до n-2: arr[i] = arr[i+1]
 3. arr[n-1] = first

   до:    │ 10 │ 20 │ 30 │ 40 │ 50 │
                ↙    ↙    ↙    ↙   ↺
   після: │ 20 │ 30 │ 40 │ 50 │ 10 │
```

Для зсуву **вправо** цикл іде у зворотному напрямку: від `n-1` до 1, `arr[i] = arr[i-1]`.
Якщо піти в той самий бік, перший скопійований елемент затре всі наступні — масив
заповниться одним значенням.

**Вставка на позицію `pos` і видалення з позиції `pos`**

```text
 ВСТАВКА                                      ВИДАЛЕННЯ
 1. якщо місця немає — вставити не можна      1. для i від pos до count-2:
 2. для i від count-1 до pos: arr[i+1]=arr[i]      arr[i] = arr[i+1]
 3. arr[pos] = нове значення                  2. count = count - 1
 4. count = count + 1
```

Оскільки розмір масиву незмінний, поряд ведуть змінну `count` — скільки комірок реально
зайнято; решта зберігає старі значення й до уваги не береться.

| Алгоритм | Напрямок | Межі | Ціна помилки |
|---|---|---|---|
| Сума, підрахунок | уперед | 0 … `n-1` | пропуск елемента |
| Максимум з індексом | уперед | 1 … `n-1` | хибний індекс |
| Реверс | уперед | 0 … `n/2 - 1` | подвійний обмін |
| Зсув уліво / вставка | уперед / назад | 0 … `n-2` / `n-1` … `pos` | затирання сусідів |
| Зсув управо | назад | `n-1` … 1 | затирання всього масиву |
| Видалення | уперед | `pos` … `count-2` | дублювання останнього |

### 3. Двовимірний масив

**Двовимірний масив (матриця)** — таблиця, у якій кожен елемент задано **двома**
індексами: номером рядка `i` та номером стовпця `j`. Запис — `matrix[i, j]`.

```text
                  j = 0    j = 1    j = 2    j = 3
               ┌────────┬────────┬────────┬────────┐
      i = 0    │ [0,0]  │ [0,1]  │ [0,2]  │ [0,3]  │
               ├────────┼────────┼────────┼────────┤
      i = 1    │ [1,0]  │ [1,1]  │ [1,2]  │ [1,3]  │
               ├────────┼────────┼────────┼────────┤
      i = 2    │ [2,0]  │ [2,1]  │ [2,2]  │ [2,3]  │
               └────────┴────────┴────────┴────────┘
      Перший індекс — РЯДОК (вниз), другий — СТОВПЕЦЬ (вправо)
```

| Величина | Як отримати | Для схеми вище |
|---|---|---|
| Кількість рядків | `matrix.GetLength(0)` | 3 |
| Кількість стовпців | `matrix.GetLength(1)` | 4 |
| Усього елементів / останній елемент | добуток розмірів; `matrix[рядків-1, стовпців-1]` | 12; `matrix[2, 3]` |

Порядок індексів переплутати легко, а наслідок непомітний: для квадратної матриці
програма не впаде, а просто оброблятиме не те.

### 4. Порядок обходу матриці

```text
   Обхід ПО РЯДКАХ                    Обхід ПО СТОВПЦЯХ
   зовнішній i, внутрішній j          зовнішній j, внутрішній i
   ──────────────▶                    │  │  │  │
   ──────────────▶                    │  │  │  │
   ──────────────▶                    ▼  ▼  ▼  ▼
   [0,0][0,1][0,2][0,3]               [0,0][1,0][2,0]
   [1,0][1,1][1,2][1,3]               [0,1][1,1][2,1]
   [2,0][2,1][2,2][2,3]               [0,2][1,2][2,2]  …
```

| Що потрібно | Який цикл зовнішній | Накопичувач обнуляють |
|---|---|---|
| Сума кожного рядка | `i` — рядки | на початку тіла зовнішнього циклу |
| Сума кожного стовпця | `j` — стовпці | на початку тіла зовнішнього циклу |
| Сума або максимум усієї матриці | будь-який | до обох циклів |
| Номер рядка з найбільшою сумою | `i` — рядки | рекорд — до циклів, сума — у тілі |

Правило те саме, що й на занятті №4: накопичувач «рядкового» підсумку живе всередині
зовнішнього циклу, накопичувач загального підсумку — зовні обох.

### 5. Діагоналі квадратної матриці

Квадратна матриця має `n` рядків і `n` стовпців. Дві діагоналі задаються умовами:

```text
        n = 4      ГОЛОВНА: i == j          ПОБІЧНА: i + j == n - 1
        j:  0   1   2   3                    j:  0   1   2   3
     i=0  ┌─G─┬───┬───┬───┐               i=0  ┌───┬───┬───┬─P─┐
     i=1  ├───┼─G─┼───┼───┤               i=1  ├───┼───┼─P─┼───┤
     i=2  ├───┼───┼─G─┼───┤               i=2  ├───┼─P─┼───┼───┤
     i=3  └───┴───┴───┴─G─┘               i=3  └─P─┴───┴───┴───┘
        [0,0][1,1][2,2][3,3]                 [0,3][1,2][2,1][3,0]
```

Для обходу діагоналі досить одного циклу: `matrix[i, i]` для головної та
`matrix[i, n-1-i]` для побічної — `n` елементів замість `n²`.

| Область | Умова для елемента `[i, j]` |
|---|---|
| Головна діагональ | `i == j` |
| Побічна діагональ | `i + j == n - 1` |
| Вище головної діагоналі | `i < j` |
| Нижче головної діагоналі | `i > j` |
| Вище побічної діагоналі | `i + j < n - 1` |
| Нижче побічної діагоналі | `i + j > n - 1` |
| Перетин діагоналей (при непарному `n`) | `i == j` і `i + j == n - 1` |

### 6. Обхід трикутних областей

Записати умову — половина справи. Перебирати всю матрицю з перевіркою умови можна,
але межі внутрішнього циклу краще задати так, щоб він одразу відвідував лише потрібні
комірки.

```text
    Вище головної діагоналі (i < j)        Нижче головної діагоналі (i > j)
      j: 0  1  2  3                          j: 0  1  2  3
   i=0  ·  ■  ■  ■                        i=0  ·  ·  ·  ·
   i=1  ·  ·  ■  ■                        i=1  ■  ·  ·  ·
   i=2  ·  ·  ·  ■                        i=2  ■  ■  ·  ·
   i=3  ·  ·  ·  ·                        i=3  ■  ■  ■  ·
   внутрішній j: від i+1 до n-1            внутрішній j: від 0 до i-1
```

| Область | Зовнішній цикл | Внутрішній цикл | Кількість елементів (`n` = 4) |
|---|---|---|---|
| Уся матриця | `i` = 0…`n-1` | `j` = 0…`n-1` | 16 |
| Вище головної | `i` = 0…`n-1` | `j` = `i+1`…`n-1` | 6 |
| Нижче головної | `i` = 0…`n-1` | `j` = 0…`i-1` | 6 |
| Вище головної разом із діагоналлю | `i` = 0…`n-1` | `j` = `i`…`n-1` | 10 |
| Вище побічної | `i` = 0…`n-1` | `j` = 0…`n-2-i` | 6 |

Кількість елементів трикутної області без діагоналі — `n · (n - 1) / 2`, разом
із діагоналлю — `n · (n + 1) / 2`. Перевірте: при `n` = 4 це 6 і 10.

### 7. Транспонування

**Транспонування** — перетворення матриці, при якому рядки стають стовпцями:
елемент `[i, j]` займає місце елемента `[j, i]`.

```text
      A (3 × 2)                 A транспонована (2 × 3)
    ┌────┬────┐               ┌────┬────┬────┐
    │  1 │  2 │               │  1 │  3 │  5 │
    ├────┼────┤      ──▶      ├────┼────┼────┤
    │  3 │  4 │               │  2 │  4 │  6 │
    ├────┼────┤               └────┴────┴────┘
    │  5 │  6 │
    └────┴────┘
```

Для прямокутної матриці транспонована має інший розмір, тому потрібен новий масив.
Квадратну транспонують «на місці», обмінюючи `[i, j]` з `[j, i]`, але **лише для елементів
нижче головної діагоналі**: інакше кожна пара обміняється двічі й матриця повернеться
до початкового вигляду — та сама помилка, що й подвійний обмін у реверсі.

### 8. Типові помилки

| Помилка | Прояв | Як помітити на папері |
|---|---|---|
| `i <= arr.Length` | аварійне завершення на останній ітерації | підставити `n` = 3 і виписати індекси |
| Переплутані `i` та `j` | обробляються не ті елементи | звірити зі схемою індексації |
| `GetLength(0)` замість `GetLength(1)` | для квадратної матриці непомітно | перевірити на прямокутній 2 × 5 |
| Обмін без допоміжної змінної | обидва елементи стають однаковими | протрасувати присвоєння |
| Реверс до кінця масиву або зсув управо вперед по циклу | масив не змінився або заповнений одним значенням | трасувати перші три кроки |
| Накопичувач рядка оголошено до циклів | «рядкові» суми зростають наростаючим підсумком | звірити з ручним підрахунком |

## Приклад виконання

**Умова.** Сервісний центр веде журнал: 4 майстри, 4 робочі дні; у комірці `[i, j]`
записано кількість відремонтованих пристроїв майстром `i` у день `j`. Скласти алгоритм,
який визначає: денну норму кожного майстра (суму по рядку), суму елементів **вище**
головної діагоналі, а також позицію (рядок і стовпець) найбільшого значення матриці.

Дані для перевірки:

```text
        j:   0    1    2    3
     i=0 │   3 │  5 │  2 │  7 │     сума рядка 0 = 17
     i=1 │   4 │  1 │  6 │  3 │     сума рядка 1 = 14
     i=2 │   8 │  2 │  5 │  1 │     сума рядка 2 = 16
     i=3 │   2 │  9 │  4 │  6 │     сума рядка 3 = 21
```

**Крок 1. Аналіз.** Три підзадачі мають різні області обходу, і це визначає структуру
алгоритму.

| Підзадача | Область | Скільки елементів |
|---|---|---|
| Сума кожного рядка та максимум із позицією | усі, по рядках | 16 |
| Сума вище головної діагоналі | `i < j` | 6 |

Перша й третя підзадачі обходять ту саму область, тому їх виконують за **один** прохід.
Друга має власні межі внутрішнього циклу, тому її виносять в окремий цикл — так не треба
перевіряти `i < j` для кожного елемента.

**Крок 2. Де оголошувати змінні.**

| Змінна | Місце оголошення | Причина |
|---|---|---|
| `rowSum` | на початку тіла зовнішнього циклу | своя для кожного рядка |
| `max`, `maxRow`, `maxCol` | до обох циклів | рекорд один на всю матрицю |

**Крок 3. Словесний алгоритм.**

```text
 1. max = matrix[0,0]; maxRow = 0; maxCol = 0
 2. для i від 0 до n-1:
 2.1.   rowSum = 0
 2.2.   для j від 0 до n-1:
 2.2.1.     rowSum = rowSum + matrix[i,j]
 2.2.2.     якщо matrix[i,j] > max, то max = matrix[i,j]; maxRow = i; maxCol = j
 2.3.   вивести номер рядка i та rowSum
 3. upperSum = 0
 4. для i від 0 до n-2:
 4.1.   для j від i+1 до n-1:
 4.1.1.     upperSum = upperSum + matrix[i,j]
 5. вивести upperSum, max, maxRow, maxCol
```

Зверніть увагу на пункт 4: зовнішній цикл іде лише до `n-2`. Для останнього рядка область
`i < j` порожня, і внутрішній цикл усе одно не виконався б — але межа `n-2` точніша.

**Крок 4. Блок-схема першого блоку.**

```text
        ┌─────────────┐
        │   Початок   │
        └──────┬──────┘
               ▼
   ┌──────────────────────────────┐
   │ max = matrix[0,0]            │
   │ maxRow = 0, maxCol = 0, i = 0│
   └──────────────┬───────────────┘
                  ▼
          ╱ i < n ╲──── ні ───▶ до блоку 2 (сума вище діагоналі)
               │ так
               ▼
      ┌──────────────────┐
      │ rowSum = 0, j = 0│
      └────────┬─────────┘
               ▼
          ╱ j < n ╲── ні ──▶ ┌───────────────────────────────────┐
               │ так         │ вивести i, rowSum ; i = i + 1     │
               ▼             └────────┬──────────────────────────┘
   ┌────────────────────────┐         └──▶ назад до ╱ i < n ╲
   │ rowSum += matrix[i,j]  │
   └───────────┬────────────┘
               ▼
       ╱ matrix[i,j] > max ╲── ні ──┐
               │ так                │
               ▼                    │
   ┌──────────────────────────────┐ │
   │ max = matrix[i,j]            │ │
   │ maxRow = i ; maxCol = j      │ │
   └───────────┬──────────────────┘ │
               ▼◀───────────────────┘
        ┌────────────┐
        │ j = j + 1  │──▶ назад до ╱ j < n ╲
        └────────────┘
```

**Крок 5. Трасування першого блоку (рядки 0 і 1).**

| i | j | `matrix[i,j]` | rowSum | max | maxRow | maxCol |
|---|---|---|---|---|---|---|
| вхід | — | — | — | 3 | 0 | 0 |
| 0 | 0 | 3 | 3 | 3 | 0 | 0 |
| 0 | 1 | 5 | 8 | 5 | 0 | 1 |
| 0 | 2 | 2 | 10 | 5 | 0 | 1 |
| 0 | 3 | 7 | 17 | 7 | 0 | 3 |
| 1 | 0 | 4 | 4 | 7 | 0 | 3 |
| 1 | 1 | 1 | 5 | 7 | 0 | 3 |
| 1 | 2 | 6 | 11 | 7 | 0 | 3 |
| 1 | 3 | 3 | 14 | 7 | 0 | 3 |

У рядку `i` = 1, `j` = 0 колонка `rowSum` дорівнює 4, а не 21: перед внутрішнім циклом
накопичувач обнулено. Якби `rowSum` оголосили до зовнішнього циклу, там стояло б 21 —
найчастіша помилка у вкладених циклах.

**Крок 6. Другий блок — сума вище головної діагоналі.**

| i | Значення `j` | Оброблені елементи | Додано | upperSum |
|---|---|---|---|---|
| 0 | 1, 2, 3 | `[0,1]`=5, `[0,2]`=2, `[0,3]`=7 | 14 | 14 |
| 1 | 2, 3 | `[1,2]`=6, `[1,3]`=3 | 9 | 23 |
| 2 | 3 | `[2,3]`=1 | 1 | 24 |

Разом оброблено 3 + 2 + 1 = 6 елементів — збігається з формулою `n · (n - 1) / 2`
при `n` = 4.

**Крок 7. Відповідь і перевірка.** Суми рядків: 17, 14, 16, 21. Сума вище головної
діагоналі — 24. Максимум 9 у позиції `[3, 1]`. Контроль: сума всіх елементів 68 дорівнює
сумі рядкових сум.
