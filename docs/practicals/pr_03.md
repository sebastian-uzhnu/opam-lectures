# Практичне заняття №3

## Тема
Логічні вирази і таблиці істинності. Задачі на розгалуження

## Мета
Навчитися будувати таблиці істинності для логічних виразів і користуватися ними для
перевірки та спрощення умов. Закріпити логічні операції мови C# та їхній пріоритет.
Набути навичок перекладу словесної умови в логічний вираз і пошуку помилок у наведених
умовах. Заняття готує до лабораторної роботи №5, де ці умови буде запрограмовано.

## Тривалість
2 академічні години.

## Обладнання
Зошит у клітинку, олівець, гумка, лінійка, ручка. Персональний комп'ютер потрібен лише
наприкінці заняття — для звіряння однієї з таблиць істинності за вказівкою викладача.
Готових програм не пишуть; наведені фрагменти коду призначені для аналізу.

## Теоретичні відомості

### 1. Логічні величини і тип `bool`

**Логічна величина** — величина, що може мати лише два значення: істина або хиба.
У математичній логіці їх позначають 1 і 0, у C# — `true` і `false`.

**Тип `bool`** — тип даних, множина значень якого складається рівно з двох елементів:
`true` і `false`. Саме значення цього типу очікує будь-яка умова розгалуження.

Логічне значення — таке саме значення, як число: його можна зберегти у змінній,
передати, вивести на екран.

```csharp
int temperature = 12;
bool isCold = temperature < 15;   // isCold отримує значення true
```

Це важливо зрозуміти одразу: `temperature < 15` — не «питання», а **вираз**, що має
значення. Тому складну умову будують із простіших частин так само, як арифметичний вираз.

### 2. Операції порівняння

**Операція порівняння** — операція, що приймає два значення й повертає `bool`.

| Операція | Читається | Приклад | Значення |
|---|---|---|---|
| `==` | дорівнює | `5 == 5` | `true` |
| `!=` | не дорівнює | `5 != 3` | `true` |
| `>` | більше | `2 > 7` | `false` |
| `<` | менше | `2 < 7` | `true` |
| `>=` | більше або дорівнює | `7 >= 7` | `true` |
| `<=` | менше або дорівнює | `8 <= 7` | `false` |

Операції `>`, `<`, `>=`, `<=` застосовні лише до впорядкованих величин: чисел, символів,
дат. Порівнювати ними логічні значення чи рядки не можна.

### 3. Логічні операції та таблиці істинності

**Таблиця істинності** — таблиця, у якій перелічено всі можливі набори значень операндів
і зазначено результат операції для кожного набору.

Кількість рядків визначається кількістю змінних: для однієї змінної — 2 рядки, для двох —
4, для трьох — 8, для `n` змінних — 2 в степені `n`. Набори виписують у сталому порядку
(спершу всі `false`, далі — як двійкові числа за зростанням), інакше легко пропустити рядок.

#### Заперечення (НЕ, `!`)

Змінює значення на протилежне.

| A | `!A` |
|---|---|
| false | true |
| true | false |

#### Кон'юнкція (І, `&&`), диз'юнкція (АБО, `\|\|`), виключне АБО (`^`)

- `A && B` — істина лише тоді, коли істинні **обидва** операнди;
- `A || B` — істина тоді, коли істинний **хоч один** операнд;
- `A ^ B` — істина тоді, коли операнди **різні**.

| A | B | `A && B` | `A \|\| B` | `A ^ B` |
|---|---|---|---|---|
| false | false | false | false | false |
| false | true | false | true | true |
| true | false | false | true | true |
| true | true | true | true | false |

Життєві аналогії. Кон'юнкція: «щоб вийти з дому, треба мати ключі І гроші» — немає
чогось одного, не виходимо. Диз'юнкція: «знижка діє для студентів АБО для пенсіонерів» —
людина, яка є і студентом, і пенсіонером, знижку теж отримає; у цьому відмінність від
побутового «або … або». Виключне АБО якраз відповідає побутовому «або … або»:
«замовлення оплачено або готівкою, або карткою» — обидва способи одночасно неможливі.
Корисна рівність: `A ^ B` істинне тоді й лише тоді, коли `A != B`.

### 4. Пріоритет операцій

У виразі без дужок операції виконуються в такому порядку (згори — найвищий пріоритет):

```text
   1. !                  заперечення
   2. *  /  %            множення, ділення, остача
   3. +  -               додавання, віднімання
   4. <  >  <=  >=       порівняння за порядком
   5. ==  !=             порівняння на рівність
   6. &   ^   |          І, виключне АБО, АБО без скорочення
   7. &&                 І зі скороченням
   8. ||                 АБО зі скороченням
```

Практичні наслідки:

- арифметика виконується **раніше** за порівняння, тому `a + b > c` означає `(a+b) > c`;
- `&&` виконується **раніше** за `||`, тому `a || b && c` означає `a || (b && c)`;
- заперечення діє лише на найближчий операнд: `!a && b` означає `(!a) && b`, а не
  `!(a && b)`.

Остання пара — джерело регулярних помилок. Правило для практики: **ставте дужки скрізь,
де змішуєте `&&` і `||`**. Зайві дужки не сповільнюють програму, але економлять годину
пошуку помилки.

### 5. Скорочене обчислення

Операції `&&` і `||` обчислюють другий операнд **не завжди**.

| Вираз | Коли другий операнд не обчислюється | Чому так можна |
|---|---|---|
| `A && B` | якщо `A` дорівнює `false` | результат уже `false` за будь-якого `B` |
| `A \|\| B` | якщо `A` дорівнює `true` | результат уже `true` за будь-якого `B` |

Це зветься **скороченим обчисленням** (обчисленням за короткою схемою). Операції `&`
та `|` роблять те саме, але обчислюють обидва операнди завжди.

Скорочене обчислення — не оптимізація, а засіб захисту. Класичний приклад:

```csharp
if (count != 0 && sum / count > 10) { }   // безпечно: за count = 0 ділення не буде
if (sum / count > 10 && count != 0) { }   // помилка: ділення виконається до перевірки
```

У першому рядку за нульового `count` перший операнд хибний, другий не обчислюється,
ділення не відбувається. У другому — програма аварійно завершиться. Правило, яке варто запам'ятати: **перевірку-запобіжник ставлять першою**.

### 6. Закони де Моргана

Заперечення складеної умови часто записують неправильно. Закони де Моргана дають
механічне правило.

| Закон | Запис у C# | Словами |
|---|---|---|
| Перший | `!(A && B)` дорівнює `!A \|\| !B` | «Неправда, що обидва» = «хоча б один не» |
| Другий | `!(A \|\| B)` дорівнює `!A && !B` | «Неправда, що хоч один» = «жоден не» |

Правило перетворення: заперечити кожен операнд, а операцію замінити на протилежну
(`&&` на `||` і навпаки).

Перевіримо перший закон таблицею істинності — саме так доводять такі рівності.

| A | B | `A && B` | `!(A && B)` | `!A` | `!B` | `!A \|\| !B` |
|---|---|---|---|---|---|---|
| false | false | false | true | true | true | true |
| false | true | false | true | true | false | true |
| true | false | false | true | false | true | true |
| true | true | true | false | false | false | false |

Четвертий і сьомий стовпці збігаються рядок у рядок, отже вирази рівносильні.

Приклад практичного застосування. Умова допуску до заліку: «студент відвідав понад 70 %
занять **і** має понад 60 балів». Умова недопуску — заперечення:

```text
Було:     attendance > 70 && score > 60
Не так:   attendance <= 70 && score <= 60      ← ПОМИЛКА: замінено лише порівняння
Правильно: attendance <= 70 || score <= 60
```

Помилка типова: порівняння заперечують, а замінити `&&` на `||` забувають. Через це
недопущеними виявляються лише ті, у кого погано і з відвідуванням, і з балами.

### 7. Запис словесної умови логічним виразом

Головна навичка заняття. Порядок дій: виділити прості твердження, визначити, як вони
пов'язані сполучниками «і», «або», «не», записати вираз і перевірити його на межах.

#### Належність проміжку

| Словесна умова | Логічний вираз |
|---|---|
| `x` належить проміжку від 0 до 10 включно | `x >= 0 && x <= 10` |
| `x` належить проміжку від 0 до 10 без кінців | `x > 0 && x < 10` |
| `x` **не** належить проміжку від 0 до 10 | `x < 0 \|\| x > 10` |
| `x` належить одному з двох проміжків | `(x >= 0 && x <= 10) \|\| (x >= 20 && x <= 30)` |

Зверніть увагу на третій рядок: заперечення проміжку — це `||`, а не `&&` (прямий
наслідок закону де Моргана). Жодне число не може бути одночасно меншим за 0 і більшим
за 10, тому варіант з `&&` завжди хибний.

#### Чому не можна писати `0 < x < 10`

У математиці подвійна нерівність — звичний запис, але в C# він не компілюється. Причина
в тому, що порівняння обчислюються зліва направо і повертають `bool`:

```text
   0 < x < 10
   └──┬───┘
      │ обчислюється першим, дає true або false
      ▼
   (true) < 10      ←  порівняти логічне значення з числом неможливо
```

Компілятор C# відкидає такий вираз із помилкою: операція `<` не визначена для операндів
типів `bool` і `int`. Правильний запис — два порівняння, з'єднані операцією `&&`:

```csharp
if (x > 0 && x < 10) { }
```

#### Високосний рік

Словесне правило: рік високосний, якщо він кратний 4, але не кратний 100, або якщо він
кратний 400.

Розберемо на частини:

| Просте твердження | Вираз |
|---|---|
| рік кратний 4 | `year % 4 == 0` |
| рік кратний 100 | `year % 100 == 0` |
| рік кратний 400 | `year % 400 == 0` |

Складаємо:

```csharp
bool isLeap = (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
```

Дужки тут обов'язкові за змістом, хоча формально `&&` і так виконується раніше за `||`.
Перевірка: 2024 — високосний (кратний 4, не кратний 100); 1900 — ні (кратний 100,
не кратний 400); 2000 — високосний (кратний 400); 2023 — ні.

#### Точка всередині фігури

| Фігура | Умова | Вираз |
|---|---|---|
| Прямокутник зі сторонами, паралельними осям, від (x1, y1) до (x2, y2) | точка між сторонами по обох осях | `x >= x1 && x <= x2 && y >= y1 && y <= y2` |
| Коло радіуса `r` із центром у початку координат | відстань до центра не більша за радіус | `x * x + y * y <= r * r` |
| Кільце між радіусами `r1` і `r2` | відстань між двома радіусами | `x*x + y*y >= r1*r1 && x*x + y*y <= r2*r2` |
| Перша чверть координатної площини | обидві координати додатні | `x > 0 && y > 0` |

Умову для кола записують **без** квадратного кореня: піднесення до квадрата обох частин
нерівності зберігає її для невід'ємних величин, а дробових обчислень стає менше.

### 8. Типові помилки

| Помилка | Що виходить насправді | Як правильно |
|---|---|---|
| `if (x = 5)` замість `if (x == 5)` | присвоєння замість порівняння; у C# не компілюється, бо результат має тип `int`, а не `bool` | `if (x == 5)` |
| `if (0 < x < 10)` | спроба порівняти `bool` із числом; не компілюється | `if (x > 0 && x < 10)` |
| `if (a == 0.3)` для дробових | дробові зберігаються наближено, `0.1 + 0.2` не дорівнює `0.3` | порівнювати за модулем різниці: `Math.Abs(a - 0.3) < 1e-9` |
| `!(a > b)` замість `a <= b`, `!(a > 0 && b > 0)` замість `a <= 0 \|\| b <= 0` | працює правильно, але приховує зміст умови | прибрати зайве заперечення або розкрити за законом де Моргана |
| `if (isReady == true)` | зайве порівняння: `isReady` уже має тип `bool` | `if (isReady)`, а для заперечення — `if (!isReady)` |
| `a \|\| b && c` без дужок | обчислюється як `a \|\| (b && c)` | розставити дужки за задумом |
| `if (x > 0);` — крапка з комою | тіло розгалуження порожнє, наступний блок виконується завжди | прибрати крапку з комою |
| `day == 6 \|\| 7` | `7` — не логічне значення, вираз не компілюється | `day == 6 \|\| day == 7` |

Про дробові — докладніше. Числа типу `double` зберігаються у двійковій системі, і дріб
`0,1` у ній нескінченний, як `1/3` у десятковій. Через це:

```csharp
Console.WriteLine(0.1 + 0.2 == 0.3);       // False
Console.WriteLine(0.1 + 0.2);              // 0,30000000000000004
```

Тому дробові на рівність порівнюють через допустиму похибку, а для грошей використовують
тип `decimal`, у якому такої проблеми немає.

## Приклад виконання

### Умова

Дано логічний вираз `!(A && B) || C`.

1. Побудувати таблицю істинності.
2. Спростити вираз, використавши закон де Моргана; довести рівносильність таблицею.
3. Записати логічним виразом словесну умову: «пасажир має право на пільговий квиток,
   якщо він студент і вік від 14 до 25 років включно, або якщо він має посвідчення особи
   з інвалідністю».
4. Побудувати блок-схему розгалуження за цією умовою.

### Крок 1. Таблиця істинності для `!(A && B) || C`

Змінних три, отже рядків 8. Набори виписуємо в сталому порядку, як двійкові числа
від 000 до 111. Проміжні стовпці додаємо за порядком виконання операцій: спершу `A && B`,
потім заперечення, потім диз'юнкція з `C`. Одразу будуємо в цій же таблиці стовпці
спрощеного виразу з кроку 2 — так рівносильність видно без другої таблиці.

| № | A | B | C | `A && B` | `!(A && B)` | `!(A && B) \|\| C` | `!A` | `!B` | `!A \|\| !B \|\| C` |
|---|---|---|---|---|---|---|---|---|---|
| 1 | false | false | false | false | true | true | true | true | true |
| 2 | false | false | true | false | true | true | true | true | true |
| 3 | false | true | false | false | true | true | true | false | true |
| 4 | false | true | true | false | true | true | true | false | true |
| 5 | true | false | false | false | true | true | false | true | true |
| 6 | true | false | true | false | true | true | false | true | true |
| 7 | true | true | false | true | false | false | false | false | false |
| 8 | true | true | true | true | false | true | false | false | true |

Висновок із таблиці: вираз хибний лише в одному випадку з восьми — коли `A` та `B`
істинні, а `C` хибне.

### Крок 2. Спрощення

За першим законом де Моргана `!(A && B)` дорівнює `!A || !B`. Підставляємо:

```text
   !(A && B) || C   =   !A || !B || C
```

У таблиці з кроку 1 сьомий і десятий стовпці збігаються в усіх восьми рядках, отже
вирази рівносильні. Спрощений запис не потребує дужок і читається як «хоча б одне
з трьох: не A, не B, C».

### Крок 3. Запис словесної умови

Виділяємо прості твердження й позначаємо їх змінними:

| Твердження | Змінна | Вираз |
|---|---|---|
| пасажир — студент | `isStudent` | `isStudent` |
| вік не менший за 14 | — | `age >= 14` |
| вік не більший за 25 | — | `age <= 25` |
| має посвідчення особи з інвалідністю | `hasDisabilityId` | `hasDisabilityId` |

Аналізуємо сполучники. «Студент **і** вік від 14 до 25» — це кон'юнкція трьох умов.
«**Або** має посвідчення» — диз'юнкція з першою групою. Вік «від 14 до 25 включно» —
це два порівняння з `>=` і `<=`, бо слово «включно» означає нестрогі знаки.

```csharp
bool hasBenefit = (isStudent && age >= 14 && age <= 25) || hasDisabilityId;
```

Дужки навколо першої групи ставимо обов'язково. Формально `&&` має вищий пріоритет,
і вираз працював би й без них, але дужки роблять структуру умови видимою з першого
погляду.

Перевіряємо на межах — саме там ховаються помилки:

| Набір | `isStudent` | `age` | `hasDisabilityId` | Результат | Правильно? |
|---|---|---|---|---|---|
| студент 20 років | true | 20 | false | true | так, звичайний випадок |
| студент 13 років | true | 13 | false | false | так, не досяг межі |
| студент 14 років | true | 14 | false | true | так, межа входить |
| студент 26 років | true | 26 | false | false | так, вийшов за межу |
| не студент, 40 років, посвідчення | false | 40 | true | true | так, друга гілка умови |
| не студент, 20 років | false | 20 | false | false | так, підстав немає |

### Крок 4. Блок-схема

```text
                  ╭───────────╮
                 (   Початок   )
                  ╰─────┬─────╯
        ┌───────────────▼────────────────┐
       ╱ Ввести isStudent, age,         ╱
      ╱            hasDisabilityId     ╱
     └───────────────┬────────────────┘
                   ╱─▼─╲
                 ╱       ╲
       ні      ╱ (isStudent ╲      так
     ┌───────╱   && age>=14   ╲───────┐
     │       ╲   && age<=25)  ╱       │
     │         ╲ || hasDis. ╱         │
     │           ╲   Id   ╱           │
     │             ╲    ╱             │
┌────▼──────────────┐       ┌─────────▼────────────┐
│ price ← fullPrice │       │ price ←              │
└────┬──────────────┘       │   fullPrice * 0.5    │
     │                      └─────────┬────────────┘
     └──────────┬─────────────────────┘
        ┌───────▼──────────┐
       ╱  Вивести price   ╱
      └───────┬──────────┘
          ╭───▼───────╮
         (    Кінець   )
          ╰───────────╯
```

У ромбі записано весь складений вираз цілком — розбивати його на кілька ромбів тут
не потрібно, бо гілки дій усе одно лише дві. Обидві стрілки з ромба підписані, гілки
сходяться перед блоком виведення.

### Крок 5. Заперечення умови

Окремо запишемо умову «пільги немає» і розкриємо заперечення за другим законом
де Моргана, а потім за першим:

```text
   !((isStudent && age >= 14 && age <= 25) || hasDisabilityId)
   = !(група) && !hasDisabilityId
   = (!isStudent || age < 14 || age > 25) && !hasDisabilityId
```

Читається зрозуміло: «не має посвідчення, і при цьому або не студент, або вік поза
проміжком». Перевірити результат можна за таблицею з кроку 3: у всіх рядках, де
результат був `false`, нова умова має дати `true`.

## Контрольні питання

1. Що таке логічна величина і скільки значень має тип `bool`? Чому умова розгалуження
   не може мати іншого типу?
2. Що таке таблиця істинності? Скільки рядків вона має для виразу з чотирма змінними
   і чому саме стільки?
3. Чим операція `||` відрізняється від `^`? Наведіть життєву умову для кожної.
4. Який пріоритет у операцій `!`, `&&` та `||`? Як обчислиться вираз `a || b && c`
   без дужок?
5. Що таке скорочене обчислення? Наведіть умову, у якій зміна порядку операндів
   навколо `&&` призводить до аварійного завершення програми.
6. Сформулюйте обидва закони де Моргана. Як за ними заперечити умову
   «`x` більше за 0 і менше за 100»?
7. Чому в C# не можна писати `0 < x < 10`? Що саме не влаштовує компілятор?
8. Як записати умову «`x` не належить проміжку від 3 до 7»? Чому тут потрібна операція
   `||`, а не `&&`?
9. Чому дробові числа не можна порівнювати операцією `==`? Як перевірити їх рівність
   правильно і який тип обирають для грошових сум?
10. Що станеться, якщо після `if (x > 0)` поставити крапку з комою? Чому компілятор
    не повідомляє про помилку і як таку помилку виявити без запуску програми?
