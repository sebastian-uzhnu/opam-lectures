# Практичне заняття №4

## Тема
Розв'язування задач із застосуванням циклів. Вкладені цикли

## Мета
Навчитися розпізнавати циклічний характер задачі за її умовою та обирати придатний вид
циклу до того, як почато написання коду. Закріпити вміння визначати параметри циклу —
початкове значення, умову продовження й крок — та обчислювати кількість повторень тіла
без запуску програми. Набути навичок трасування вкладених циклів за таблицею станів
і виявлення типових помилок у чужому фрагменті коду. Підготуватися до лабораторної
роботи №6, де ці самі алгоритми будуть запрограмовані.

## Тривалість
2 академічні години.

## Обладнання та програмне забезпечення
Зошит у клітинку, олівець, лінійка, калькулятор. Роздруковані бланки таблиць трасування
(видає викладач). Персональний комп'ютер із .NET 8 SDK потрібен лише на завершальному
етапі заняття — для перевірки однієї-двох відповідей; основну роботу виконують на папері
й біля дошки.

## Теоретичні відомості

### 1. Чому алгоритм складають до програми

Помилка в циклі коштує дорожче за помилку в лінійній програмі: цикл або «з'їдає» зайвий
елемент, або не доходить до останнього, або не завершується взагалі. Усі три випадки видно
ще на папері, якщо перед кодом відповісти на чотири питання.

| Питання | Що дає відповідь |
|---|---|
| Що саме повторюється? | тіло циклу |
| Скільки разів це треба повторити? | вид циклу і його умова |
| Що змінюється від повторення до повторення? | лічильник, крок |
| Що має накопичитися до кінця? | накопичувач і його початкове значення |

**Трасування** — покрокове ручне виконання алгоритму з фіксацією значень усіх змінних
у таблиці. Це основний інструмент заняття: таблиця показує помилку там,
де читання коду її не помічає.

### 2. Три види циклів і як обрати потрібний

Головний критерій вибору один: **чи відома кількість повторень наперед**, тобто до входу
в цикл.

| Формулювання в умові задачі | Кількість повторень | Який цикл | Чому |
|---|---|---|---|
| «для кожного з 12 місяців» | відома, стала | `for` | межі задано в умові |
| «для перших `n` клієнтів», `n` вводить користувач | відома на момент входу | `for` | `n` уже прочитано, далі не змінюється |
| «від 100 до 200 з кроком 5» | обчислюється за формулою | `for` | арифметична послідовність |
| «доки залишок більший за нуль» | невідома | `while` | залежить від даних |
| «вводити, доки не введуть 0» | невідома | `while` або `do while` | зупиняє стоп-значення |
| «повторювати меню, доки користувач не обере вихід» | невідома, але хоча б один раз | `do while` | меню треба показати бодай раз |
| «ділити число на 10, доки воно не стане нулем» | невідома | `while` | залежить від величини числа |

Практичне правило: якщо ви можете **до** циклу написати на папері число повторень —
беріть `for`; якщо ні — `while`; якщо ні, але тіло потрібне хоча б раз — `do while`.

```text
        Скільки разів повторювати?
                  │
     ┌────────────┴────────────┐
 відомо наперед            невідомо
     │                         │
   for              ┌──────────┴──────────┐
            тіло потрібне            тіло може не
            хоча б раз          виконатися жодного разу
                 │                       │
             do while                  while
```

### 3. Параметри циклу: початкове значення, умова, крок

Будь-який цикл із лічильником задано трьома параметрами. Помилка в кожному з них дає
свій характерний дефект.

| Параметр | Що задає | Типова помилка | Наслідок |
|---|---|---|---|
| Початкове значення | з чого починається лічильник | почали з 1 замість 0 | пропущено перший елемент |
| Умова продовження | доки цикл працює | `i < n` замість `i <= n` | оброблено на один менше |
| Крок | як змінюється лічильник | крок не змінює лічильник | нескінченний цикл |

Кількість повторень циклу з цілим лічильником, що зростає від `a` до `b` з кроком `k`:

```text
   N = (b - a) / k + 1        (цілочислове ділення, за умови b >= a)
   якщо b < a  →  N = 0       (для зростаючого лічильника цикл не виконається жодного разу)
```

| Заголовок циклу | a | b | k | N |
|---|---|---|---|---|
| `for (int i = 1; i <= 10; i++)` | 1 | 10 | 1 | 10 |
| `for (int i = 0; i < 10; i++)` | 0 | 9 | 1 | 10 |
| `for (int i = 0; i <= 10; i++)` | 0 | 10 | 1 | 11 |
| `for (int i = 10; i <= 100; i += 10)` | 10 | 100 | 10 | 10 |
| `for (int i = 5; i <= 5; i++)` | 5 | 5 | 1 | 1 |
| `for (int i = 5; i < 5; i++)` | — | — | 1 | 0 |
| `for (int i = 10; i >= 1; i--)` | 10 | 1 | −1 | 10 |

Цикл, що не виконується жодного разу, — не помилка, а межовий випадок, який передбачають.

### 4. Лічильник і накопичувач

**Лічильник** — змінна, що рахує повторення або підходящі об'єкти.
**Накопичувач** — змінна, у якій поступово збирається результат.

Початкове значення накопичувача — **нейтральний елемент** тієї операції, яку виконують
у тілі: для додавання це 0, для множення — 1.

| Що обчислюємо | Початкове значення | Дія в тілі циклу | Після циклу |
|---|---|---|---|
| Сума | `sum = 0` | `sum = sum + x` | готова |
| Добуток | `product = 1` | `product = product * x` | готовий |
| Кількість за умовою | `count = 0` | якщо умова істинна, `count = count + 1` | готова |
| Середнє арифметичне | `sum = 0`, `count = 0` | накопичити обидва | `sum / count`, якщо `count` не нуль |
| Максимум | `max` = перше значення | якщо `x > max`, то `max = x` | готовий |
| Мінімум | `min` = перше значення | якщо `x < min`, то `min = x` | готовий |
| Індекс максимуму | `maxIndex` = індекс першого | оновлювати разом із `max` | готовий |

Пошук екстремуму **«на льоту»** означає, що значення не зберігаються: кожне нове
порівнюють із поточним рекордсменом і, якщо треба, замінюють його. Так працює
метеостанція, яка тримає не весь архів, а лише поточний рекорд.

Початковим значенням для максимуму беруть **перше реальне значення**, а не нуль: якщо всі
дані від'ємні (температури взимку), нуль так і залишиться «максимумом» і відповідь буде
хибною. Варіант із `int.MinValue` теж правильний, але перше значення надійніше — воно
гарантовано належить до набору даних.

### 5. Цикл із введенням до стоп-значення

**Стоп-значення** (сторожове значення) — умовне значення, яке не є коректними даними
й слугує сигналом завершення введення: 0 для кількості товарів, порожній рядок, −1
для оцінок.

```text
   ┌─────────────────────────────┐
   │ підготовка: sum = 0, cnt = 0│
   └──────────────┬──────────────┘
                  ▼
        ┌──────────────────┐
        │   прочитати x    │◀────────────┐
        └────────┬─────────┘             │
                 ▼                       │
          ╱ x == стоп? ╲── так ──▶ вихід із циклу
                 │ ні                    │
                 ▼                       │
        ┌──────────────────┐             │
        │    обробити x    │─────────────┘
        └──────────────────┘
```

Ключове в цій схемі — **порядок**: стоп-значення перевіряють **до** обробки, інакше воно
потрапить у суму. Оскільки перше читання має відбутися до першої перевірки, таку схему
природно кладуть або на `do while`, або на `while` з читанням усередині тіла.

Обов'язковий межовий випадок: стоп-значення введено **першим**. Тоді `count` = 0
і обчислювати середнє не можна — буде ділення на нуль.

### 6. Вкладені цикли

**Вкладений цикл** — цикл, розміщений у тілі іншого циклу. Зовнішній керує «рядками»,
внутрішній — «стовпцями» кожного рядка.

```text
 for (зовнішній i = 1 .. 3)
 ┌─────────────────────────────────────────────────┐
 │  for (внутрішній j = 1 .. 4)                    │
 │  ┌───────────────────────────────────────────┐  │
 │  │  тіло                                     │  │
 │  └───────────────────────────────────────────┘  │
 │  ← внутрішній цикл повністю відпрацьовує тут   │
 └─────────────────────────────────────────────────┘
        ← і так для кожного значення i

 Порядок пар (i, j):
 (1,1)(1,2)(1,3)(1,4) (2,1)(2,2)(2,3)(2,4) (3,1)(3,2)(3,3)(3,4)
  └──── i = 1 ────┘    └──── i = 2 ────┘    └──── i = 3 ────┘
```

Внутрішній лічильник змінюється швидше — як хвилинна стрілка відносно годинної.

| Зовнішній цикл | Внутрішній цикл | Скільки разів виконається тіло внутрішнього |
|---|---|---|
| 3 ітерації | 4 ітерації | 3 · 4 = 12 |
| `n` ітерацій | `m` ітерацій | `n · m` |
| `n` ітерацій | `n` ітерацій | `n²` |
| 5 ітерацій | залежить від `i`: від 1 до `i` | 1+2+3+4+5 = 15 |
| 4 ітерації | 0 ітерацій (умова хибна одразу) | 0 |

Останні два рядки найважливіші. Якщо межа внутрішнього циклу залежить від лічильника
зовнішнього, кількість повторень уже не є простим добутком, а дорівнює сумі
1 + 2 + … + `n`, тобто `n · (n + 1) / 2`. Такі цикли дають «трикутні» схеми виведення.

```text
  i = 1 : *
  i = 2 : * *
  i = 3 : * *
  i = 4 : * * * *      (для внутрішнього j = 1 .. i)
```

Змінна зовнішнього циклу видима у внутрішньому — саме тому межу внутрішнього задають
через `i`. Навпаки не працює: змінна внутрішнього циклу після його завершення не існує.

### 7. Заміна одного виду циклу іншим

Будь-який `for` можна записати через `while`, і навпаки. Це потрібно не заради вправи,
а щоб розуміти: вид циклу — питання читабельності, а не можливостей.

```csharp
for (int i = 1; i <= 5; i++) { total = total + i; }        // варіант А

int i = 1;                                                 // варіант Б
while (i <= 5) { total = total + i; i++; }                 // крок перенесено в тіло
```

Різниця в одному: у варіанті Б змінна `i` живе після циклу, і забути `i++` дуже легко.
Тому для лічильника з відомими межами обирають `for`, а `while` лишають для умов,
що залежать від даних.

Заміна `while` на `do while` **не завжди можлива**: `do while` виконає тіло хоча б раз,
а `while` може не виконати жодного. Якщо межовий випадок «нуль ітерацій» реальний,
замінювати не можна.

### 8. Типові помилки

| Помилка | Як виглядає | Як виявити на папері |
|---|---|---|
| Зсув на одиницю | `i < n` там, де треба `i <= n` | підставити `n = 3` і виписати значення `i` |
| Нескінченний цикл | крок не змінює умову | перевірити, чи наближається лічильник до межі |
| Накопичувач добутку = 0 | `product = 0` | результат завжди нуль |
| Лічильник змінюється двічі | і в кроці `for`, і в тілі | значення «перестрибують» через одне |
| Крапка з комою після заголовка | `for (...);` | тіло виконається один раз після циклу |
| Тіло без дужок | тільки перший рядок належить циклу | другий рядок виконається один раз |
| Оголошення накопичувача в тілі | обнуляється щоітерації | результат дорівнює останньому значенню |

Кожну з цих помилок шукають однаково: підставляють найменші дані (`n` = 1 або `n` = 3)
і виписують значення змінних по ітераціях. Практика цього заняття — саме така перевірка.

## Приклад виконання

**Умова.** Кав'ярня працює 3 дні поспіль, щодня фіксується виторг за 4 робочі зміни.
Потрібно скласти алгоритм, який для кожного дня обчислює денний виторг, а за всі дні —
загальний виторг і найкращу зміну (її номер дня та номер зміни). Дані вводяться
послідовно, зміна за зміною.

**Крок 1. Аналіз умови.**

| Питання | Відповідь |
|---|---|
| Що повторюється? | введення й обробка виторгу однієї зміни |
| Скільки разів? | 3 · 4 = 12, відомо наперед |
| Що змінюється? | номер дня `d` (1…3) і номер зміни `s` (1…4) |
| Що накопичується? | денна сума `daySum`, загальна сума `total`, рекорд `best` |

Кількість повторень відома наперед, тому обидва цикли — `for`. Зовнішній перебирає дні,
внутрішній — зміни всередині дня.

**Крок 2. Де оголошувати накопичувачі.** Це головне місце помилок у вкладених циклах.

| Змінна | Де ініціалізується | Чому |
|---|---|---|
| `total` | до зовнішнього циклу | накопичується за всі дні |
| `best`, `bestDay`, `bestShift` | до зовнішнього циклу | рекорд шукаємо серед усіх змін |
| `daySum` | на початку тіла зовнішнього циклу | для кожного дня рахунок починається спочатку |

Якщо `daySum` оголосити до зовнішнього циклу, вона накопичить виторг за всі дні й
«денний підсумок» другого дня виявиться сумою двох днів. Якщо `total` оголосити всередині
зовнішнього циклу — вона щодня обнулятиметься й у кінці дорівнюватиме виторгу
останнього дня.

**Крок 3. Словесний алгоритм.**

```text
 1. total = 0; best = -1; bestDay = 0; bestShift = 0
 2. для d від 1 до 3 повторювати:
 2.1.   daySum = 0
 2.2.   для s від 1 до 4 повторювати:
 2.2.1.     прочитати x — виторг зміни s дня d
 2.2.2.     daySum = daySum + x
 2.2.3.     якщо x > best, то best = x; bestDay = d; bestShift = s
 2.3.   вивести d і daySum
 2.4.   total = total + daySum
 3. вивести total, best, bestDay, bestShift
```

**Крок 4. Блок-схема.**

```text
        ┌─────────────┐
        │   Початок   │
        └──────┬──────┘
               ▼
  ┌──────────────────────────────┐
  │ total = 0, best = -1         │
  │ bestDay = 0, bestShift = 0   │
  └──────────────┬───────────────┘
                 ▼
          ┌────────────┐
          │   d = 1    │◀──────────────────────────────────┐
          └──────┬─────┘                                   │
                 ▼                                         │
            ╱ d <= 3 ╲──── ні ───▶ вивести total, best,    │
                 │ так              bestDay, bestShift     │
                 ▼                       │                 │
        ┌──────────────┐                 ▼                 │
        │  daySum = 0  │             ┌───────┐             │
        └──────┬───────┘             │ Кінець│             │
               ▼                     └───────┘             │
          ┌────────────┐                                   │
          │   s = 1    │◀──────────────────────┐           │
          └──────┬─────┘                       │           │
                 ▼                             │           │
            ╱ s <= 4 ╲── ні ──▶ ┌──────────────────────┐   │
                 │ так          │ вивести d, daySum    │   │
                 ▼              │ total += daySum; d++ │───┘
          ╱ ввести x ╱          └──────────────────────┘
                 ▼                             │
     ┌──────────────────────┐                  │
     │ daySum = daySum + x  │                  │
     └──────────┬───────────┘                  │
                ▼                              │
           ╱ x > best ╲── ні ──┐               │
                │ так          │               │
                ▼              │               │
  ┌──────────────────────────┐ │               │
  │ best = x; bestDay = d;   │ │               │
  │ bestShift = s            │ │               │
  └─────────────┬────────────┘ │               │
                ▼◀─────────────┘               │
           ┌────────┐                          │
           │  s++   │──────────────────────────┘
           └────────┘
```

| 11 | 3 | 3 | 2400 | 5300 | 11600 | 2400 | 2 | 3 |
| 12 | 3 | 4 | 1000 | 6300 | 11600 | 2400 | 2 | 3 |
| кінець дня 3 | 3 | — | — | 6300 | 17900 | 2400 | 2 | 3 |

**Крок 6. Перевірка й висновки.**

1. Тіло внутрішнього циклу виконалося 12 разів — збігається з очікуваними 3 · 4.
2. `total` = 5400 + 6200 + 6300 = 17900 — збігається з рядком таблиці.
3. Виторг 2400 трапився двічі: день 2, зміна 3 і день 3, зміна 3. Умова `x > best`
   (строго більше) залишає **перший** рекорд, `x >= best` залишила б останній. Обраний
   варіант обов'язково фіксують у звіті.
4. Межовий випадок: якщо всі виторги нульові, `best` = 0, `bestDay` = 1, `bestShift` = 1,
   бо початкове значення `best` було −1. Якби взяли `best = 0`, жодна зміна не стала б
   рекордною й номери лишилися б нульовими — типова помилка.

## Завдання для аудиторної роботи

**Завдання 1. Вибір виду циклу.**
Для кожної умови вкажіть придатний вид циклу, його початкове значення, умову й крок,
а також кількість повторень (або поясніть, чому вона невідома наперед).

| № | Умова задачі |

| б | Вводити оцінки студентів, доки не введено −1 |

**Завдання 2. Кількість повторень і результат.**
Не запускаючи програми, визначте кількість повторень тіла та кінцеве значення змінної
`result` для кожного фрагмента. Відповідь обґрунтуйте формулою з розділу 3.

```csharp
// A
int result = 0;
for (int i = 3; i <= 27; i += 3) result = result + i;

// Б
int result = 1;
for (int i = 5; i > 0; i--) result = result * 2;

// В
int result = 0;
for (int i = 0; i < 4; i++)
    for (int j = 0; j < 3; j++)
        result++;

// Г
int result = 0;
for (int i = 1; i <= 5; i++)
    for (int j = 1; j <= i; j++)
        result = result + j;
```

**Завдання 3. Трасування вкладених циклів.**
Заповніть таблицю трасування для фрагмента нижче: стовпці `i`, `j`, `s` і рядок виведення.
Скільки всього рядків буде виведено? Скільки разів виконається операція додавання?

```csharp
int s = 0;
for (int i = 1; i <= 4; i++)
{
    for (int j = i; j <= 4; j++)
    {
        s = s + i * j;
    }
    Console.WriteLine($"i = {i}, s = {s}");
}
```

**Завдання 4. Пошук помилки.**
У кожному фрагменті рівно одна помилка з розділу 8. Назвіть її, поясніть наслідок
(конкретним прикладом даних) і запишіть виправлений заголовок або рядок.

```csharp
// A — добуток чисел від 1 до n
int product = 0;
for (int i = 1; i <= n; i++) product = product * i;

// Б — сума перших n натуральних чисел
int sum = 0;
int i = 1;
while (i <= n)
{
    sum = sum + i;
}

// В — вивести всі елементи від 1 до n
for (int i = 1; i < n; i++) Console.WriteLine(i);

// Г — середня температура за тиждень
for (int day = 1; day <= 7; day++)
{
    double sum = 0;
    sum = sum + ReadTemperature(day);
}

// Д — таблиця множення 3 на 3
for (int i = 1; i <= 3; i++)
    for (int j = 1; j <= 3; j++);
        Console.WriteLine($"{i} * {j} = {i * j}");
```

**Завдання 5. Блок-схема алгоритму з накопичувачами.**
Складіть блок-схему алгоритму: вводяться добові витрати пального автомобілем (у літрах)

й найбільшу добову витрату разом із номером дня. Передбачте випадок, коли стоп-значення
введено першим. Початкові значення всіх накопичувачів запишіть таблицею.

**Завдання 6. Табулювання функції.**
**Табулювання** — обчислення значень функції в точках, розміщених з однаковим кроком
на заданому відрізку. Розробіть алгоритм і блок-схему табулювання функції
`y = 2x² − 5x + 3` на відрізку від `a` до `b` з кроком `h` (значення вводить користувач).
Алгоритм має також визначити найбільше й найменше значення `y` на цьому відрізку.

Додатково відповідьте письмово:
1. Чому лічильник циклу краще зробити цілим, а `x` обчислювати як `a + i * h`,
   а не додавати `h` до `x` щоітерації?
2. Скільки точок буде оброблено при `a` = 0, `b` = 2, `h` = 0,5? Запишіть формулу.
3. Що станеться, якщо користувач введе `h` = 0 або від'ємний `h`? Яку перевірку
   треба додати до циклу?

**Завдання 3.** Для кожної пари циклів визначте, чи є вони еквівалентними, тобто чи дають

результати розійдуться.

| № | Варіант А | Варіант Б |
