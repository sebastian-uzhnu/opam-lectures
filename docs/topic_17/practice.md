# Самоперевірка та домашнє завдання

## Питання для самоперевірки

Питання згруповані за підрозділами теми. Відповідайте своїми словами — якщо
не виходить, поверніться до відповідного підрозділу.

### Вступ

1. Яку саме задачу розв'язують абстрактні класи та інтерфейси? Сформулюйте
   одним реченням, що означає «описати загальну поведінку, залишивши
   конкретну реалізацію похідним класам».

### Абстрактні класи

2. Що головне відрізняє абстрактний клас від звичайного? Що станеться,
   якщо написати `Animal a = new Animal();` — це помилка компіляції
   чи виняток під час виконання?
3. Чи може абстрактний клас містити звичайні, вже реалізовані методи
   та властивості? Наведіть приклад `Vehicle` з лекції й поясніть, навіщо
   `Start()` реалізовано, а `Move()` — ні.
4. Чим абстрактний метод відрізняється від віртуального? Чи можна
   не перевизначити віртуальний метод у нащадку? А абстрактний?
5. Чому абстрактний метод не має тіла, а лише крапку з комою після
   сигнатури? Що така сигнатура каже майбутньому нащадку?
6. **Знайдіть помилку в цьому коді.** Проєкт не компілюється. Яке саме
   повідомлення видасть компілятор і як це виправити двома різними способами?

   ```csharp
   abstract class Animal
   {
       public abstract void MakeSound();
   }

   class Dog : Animal
   {
       public void Bark()
       {
           Console.WriteLine("Woof!");
       }
   }
   ```

7. **Що виведе цей код?** Змінна оголошена як `Animal`, а об'єкт — `Dog`.
   Який метод буде викликано і чому саме він?

   ```csharp
   Animal a = new Dog();
   Animal b = new Cat();
   a.MakeSound();
   b.MakeSound();
   ```

### Інтерфейси

8. Як оголошується інтерфейс і чому їхні назви за традицією починаються
   з великої літери `I`? Чи змусить компілятор дотримуватися цієї традиції?
9. Чи можна оголосити в інтерфейсі поле? А властивість? Поясніть різницю
   на прикладі `IWorker` з лекції: що насправді означає рядок
   `string Position { get; }` для класу, який реалізує цей інтерфейс.
10. Скільки інтерфейсів може реалізувати один клас? Скільки класів може
    успадкувати? Наведіть приклад `PrinterScanner` і поясніть, чому
    такого результату не досягти лише наслідуванням.
11. **Знайдіть помилку в цьому коді.** Компілятор скаржиться, що `Bird`
    не реалізує член інтерфейсу, хоча метод `Fly` очевидно є. У чому річ?

    ```csharp
    interface IFlyable
    {
        void Fly();
    }

    class Bird : IFlyable
    {
        void Fly()
        {
            Console.WriteLine("Bird is flying");
        }
    }
    ```

12. У рядку `class Circle : Shape, IDrawable` — що тут базовий клас,
    а що інтерфейс? Чи можна поміняти їх місцями? Чому в `Circle`
    метод `Area()` написаний з `override`, а `Draw()` — без нього?

### Відмінності між абстрактними класами та інтерфейсами

13. Відтворіть з пам'яті таблицю відмінностей за чотирма критеріями:
    реалізація методів, поля, множинне наслідування, конструктори.
    А тепер застосуйте її. Вам треба описати «усі документи мають номер
    і дату створення, і кожен вміє надрукувати себе по-своєму». І окремо —
    «усе, що вміє надрукувати себе, незалежно від того, документ це
    чи фотографія». Який інструмент підходить у першому випадку,
    а який у другому? Сформулюйте правило вибору одним реченням.

### Інтерфейси та SOLID

14. Принцип єдиної відповідальності: чому клас `Report`, який і генерує
    звіт, і зберігає його у файл, вважається поганим? Скільки причин
    для зміни він має?
15. Принцип відкритості/закритості: подивіться на перший варіант
    `AreaCalculator` із драбинкою `if (shape is Rectangle r)`. Скільки
    місць у коді доведеться змінити, щоб додати трикутник? А в другому
    варіанті з `IShape`? Де саме зникла драбинка перевірок?
16. Принцип підстановки Лісков: чому `Ostrich`, яка успадковує `Bird`
    і кидає `NotImplementedException` у методі `Fly()`, порушує контракт?
    Як цю ієрархію переробили в лекції і чому новий варіант чесніший?
17. Принципи розділення інтерфейсу та інверсії залежностей: у прикладі
    з `Switch` до рефакторингу вимикач сам створював `LightBulb`. Що
    змінилося після введення `ISwitchable` і де тепер створюється
    конкретний пристрій? Що це дає, коли завтра з'явиться вентилятор?

### Стандартні інтерфейси .NET

18. Що має повертати метод `CompareTo`, щоб об'єкт вважався «меншим»,
    «рівним» чи «більшим»? Як за допомогою `IComparable` відсортувати
    студентів не за зростанням, а за спаданням оцінки — не змінюючи
    виклику `Array.Sort`?
19. **Знайдіть помилку в цьому коді.** Студентів сортують за оцінкою,
    але результат виходить дивним — усі 100-бальники опиняються десь
    посередині. Що не так із `CompareTo`?

    ```csharp
    class Student : IComparable<Student>
    {
        public string Name { get; set; }
        public int Grade { get; set; }

        public int CompareTo(Student other)
        {
            return Name.CompareTo(other.Name);
        }
    }
    ```

20. Для чого призначені `IDisposable`, `IEnumerable`, `IEquatable`
    та `ICloneable`? Назвіть по одному реченню на кожен. Який із них
    дозволяє писати `foreach` по власному класу, а який робить
    `MemberwiseClone()` доречним?

## Практичні міні-задачі

Короткі вправи на 5–10 хвилин кожна, для перевірки розуміння прямо
після лекції.

1. **Спроба створити абстрактне.** Оголосіть `abstract class Shape`
   з абстрактним методом `Area()`, спробуйте написати `new Shape()`
   і прочитайте повідомлення компілятора. Випишіть його дослівно —
   саме це повідомлення ви побачите ще не раз.

2. **Дві фігури без жодного `if`.** Додайте до `Shape` класи `Square`
   і `Triangle`, покладіть три різні фігури в масив `Shape[]` і порахуйте
   сумарну площу одним циклом. У циклі не має бути жодної перевірки типу.

3. **Один клас — два контракти.** Створіть інтерфейси `IPrintable`
   і `IScannable`, реалізуйте обидва в класі `MultiFunctionPrinter`.
   Потім створіть змінну типу `IPrintable`, покладіть у неї цей об'єкт
   і спробуйте викликати `Scan()`. Поясніть, чому не виходить.

4. **Сортування своїм правилом.** Зробіть клас `Song` з полями `Title`
   і `DurationSeconds`, реалізуйте `IComparable<Song>` так, щоб сортування
   йшло від найдовшої пісні до найкоротшої, і перевірте через `Array.Sort`.

5. **Рефакторинг за ISP.** Дано інтерфейс `IEmployee` з методами `Work()`,
   `Eat()`, `TakeVacation()` і `WriteCode()`. Клас `Robot` мусить його
   реалізувати, але вміє лише працювати й писати код. Розділіть інтерфейс
   так, щоб `Robot` не був змушений писати порожні методи.

6. **Полювання на порушення Лісков.** Дано клас `Rectangle` із методами
   `SetWidth` і `SetHeight` та нащадок `Square`, у якому обидва методи
   змінюють одразу обидві сторони. Напишіть метод, який приймає `Rectangle`,
   встановлює ширину 5 і висоту 4 і перевіряє, що площа дорівнює 20.
   Передайте туди `Square` і поясніть результат.

### Завдання: «Кошик інтернет-магазину»

Ви пишете кошик для маленького онлайн-магазину. У кошику лежать
геть різні речі: книжка, йогурт, навушники. Спільного в них лише те,
що в кожної є назва й ціна. А от знижки поводяться по-різному: на книжки
діє акція «мінус 10 відсотків», йогурт в останній день придатності віддають
за півціни, а на техніку виробник забороняє знижки взагалі — жодної.

Головне, що має показати ваша програма: кошик **не знає**, який саме
товар у ньому лежить. Він просто питає «а ти зі знижкою?» — і хто вміє
відповісти, той відповідає.

**Вимоги:**

- абстрактний клас `Product` із властивостями `Name` і `Price` (тип `decimal`),
  реалізованим методом `string FormatPrice(decimal value)` (повертає рядок
  виду `320,00 грн`) і абстрактним методом `string Describe()`;
- `Product` реалізує `IComparable<Product>` — порівняння за ціною
  від дешевшого до дорожчого;
- інтерфейс `IDiscountable` із властивістю `string DiscountLabel { get; }`
  і методом `decimal GetDiscountedPrice()`;
- три нащадки `Product`:
  - `Book` (автор, кількість сторінок) — реалізує `IDiscountable`, знижка 10 відсотків;
  - `Food` (дата придатності) — реалізує `IDiscountable`, знижка 50 відсотків,
    якщо сьогодні останній день придатності, інакше 0;
  - `Gadget` (гарантія в місяцях) — `IDiscountable` **не реалізує**;
- кожен нащадок по-своєму перевизначає `Describe()`;
- у `Main` — масив `Product[]` щонайменше з п'яти товарів різних типів;
- вивести кошик через `Describe()`, потім відсортувати `Array.Sort`
  і вивести ще раз;
- пройти кошик і для кожного товару порахувати кінцеву ціну: якщо товар
  реалізує `IDiscountable` (перевірка через `is IDiscountable d`) — знижену,
  інакше — звичайну;
- наприкінці — сума без знижок, сума до сплати й скільки вдалося зекономити.

**Приклад роботи:**

```
=== КОШИК (5 товарів) ===
[Книга]   Кобзар, Т. Шевченко, 384 с. — 320,00 грн
[Гаджет]  Навушники JBL, гарантія 24 міс. — 1890,00 грн
[Продукт] Йогурт полуничний, до 14.09.2026 — 42,00 грн
[Книга]   Чистий код, Р. Мартін, 464 с. — 750,00 грн
[Гаджет]  Павербанк 20000, гарантія 12 міс. — 890,00 грн

=== ВІДСОРТОВАНО ЗА ЦІНОЮ ===
42,00 грн     Йогурт полуничний
320,00 грн    Кобзар
750,00 грн    Чистий код
890,00 грн    Павербанк 20000
1890,00 грн   Навушники JBL

=== ЗНИЖКИ ===
Йогурт полуничний   42,00 грн -> 21,00 грн   (останній день, -50%)
Кобзар              320,00 грн -> 288,00 грн (акція на книги, -10%)
Чистий код          750,00 грн -> 675,00 грн (акція на книги, -10%)
Павербанк 20000     890,00 грн                (знижки не передбачені)
Навушники JBL       1890,00 грн               (знижки не передбачені)

Без знижок:   3892,00 грн
До сплати:    3764,00 грн
Зекономлено:  128,00 грн
```

:::tip Підказка
Для грошей беріть `decimal`, а не `double`: `decimal price = 320m;`
(літера `m` наприкінці обов'язкова). Формат `$"{value:F2} грн"` дасть
рівно два знаки після коми.

Знижка в 10 відсотків рахується як `Price * 0.9m`, у 50 — як `Price * 0.5m`.
Ділити на 100 і множити не треба.

`CompareTo` пишеться одним рядком:
`return Price.CompareTo(other.Price);`

Перевірка на інтерфейс робиться так само, як на клас, і одразу дає
готову змінну:

```csharp
if (product is IDiscountable discountable)
{
    decimal finalPrice = discountable.GetDiscountedPrice();
    Console.WriteLine(discountable.DiscountLabel);
}
```

`Gadget` існує в завданні саме для того, щоб показати: не всі нащадки
одного абстрактного класу мають однакові можливості. Не спокушайтеся
реалізувати в ньому `IDiscountable` з поверненням звичайної ціни —
це той самий обман, що й `Ostrich` з методом `Fly()`, який кидає виняток.

Щоб `Food` знала про «сьогодні», порівняйте `ExpiryDate.Date`
з `DateTime.Today`.
:::

**Додатково (за бажанням, на вищу оцінку):** додайте інтерфейс `IShippable`
із властивістю `double WeightKg` і методом `decimal GetShippingCost()`
(книги й гаджети важать і коштують доставки, а йогурт видають лише
самовивозом, тож `IShippable` не реалізує). Порахуйте окремим блоком
вартість доставки й додайте її до підсумку. Зверніть увагу: жоден клас
при цьому не змінив свого базового класу — ви лише додали ще один контракт,
і саме в цьому перевага інтерфейсів перед наслідуванням.
