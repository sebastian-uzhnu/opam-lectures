# Алгоритми сортування

**Сортування** — це перевпорядкування елементів масиву так, щоб вони йшли за
певним правилом: за зростанням, за спаданням, за алфавітом, за датою. Це, мабуть,
найдослідженіша задача в усій інформатиці: придумано десятки алгоритмів, і кожен
має свій характер.

Виникає розумне питання: навіщо це вчити, якщо в .NET є `Array.Sort`, який усе
зробить за нас одним рядком? Бо ці п'ять алгоритмів — найкоротший шлях зрозуміти,
**чому один код швидший за інший**: вони розв'язують ту саму задачу і дають той самий
результат, але відрізняються за швидкістю в тисячі разів. До того ж `Array.Sort`
усередині — це теж алгоритм сортування, і не знаючи, як він влаштований, ви не
зрозумієте його обмежень. Нарешті, прийоми звідси — вкладені цикли, обмін елементів,
зсув частини масиву, «розділяй і володарюй» — потрібні й у задачах, де сортування немає.

## Обмін двох елементів

Операція, яка є в кожному алгоритмі нижче, — **обмін (swap)** двох елементів місцями.
Наївна спроба не працює:

```csharp
// ТАК НЕ ПРАЦЮЄ
arr[i] = arr[j];
arr[j] = arr[i];   // arr[i] уже змінився! Обидва елементи стали однаковими
```

Після першого рядка старе значення `arr[i]` втрачено назавжди. Тому потрібна
тимчасова змінна — або кортеж, у якому права частина обчислюється **повністю**
до присвоювання:

```csharp
int temp = arr[i];      // класичний спосіб
arr[i] = arr[j];
arr[j] = temp;

(arr[i], arr[j]) = (arr[j], arr[i]);   // сучасний спосіб, те саме одним рядком
```

Обидва варіанти правильні, і далі в коді трапляються обидва.

## Сортування бульбашкою

**Сортування бульбашкою (bubble sort)** — найпростіший для розуміння алгоритм.
Ідея: проходимо масивом і порівнюємо кожну пару **сусідніх** елементів. Якщо вони
стоять неправильно — міняємо місцями. За один такий прохід найбільший елемент
гарантовано «спливає» в кінець масиву, як бульбашка повітря спливає на поверхню води.
Звідси й назва.

### Як це виглядає покроково

Масив `[5, 1, 4, 2, 8]`. Символ `^^` позначає пару, яку зараз порівнюємо:

```
ПРОХІД 1
  [5, 1, 4, 2, 8]   5 > 1  міняємо
   ^^ ^^
  [1, 5, 4, 2, 8]   5 > 4  міняємо
      ^^ ^^
  [1, 4, 5, 2, 8]   5 > 2  міняємо
         ^^ ^^
  [1, 4, 2, 5, 8]   5 < 8  залишаємо
            ^^ ^^
  [1, 4, 2, 5 | 8]  8 "сплило" в кінець, далі його не чіпаємо

ПРОХІД 2
  [1, 4, 2, 5 | 8]  1 < 4 залишаємо, 4 > 2 міняємо, 4 < 5 залишаємо
  [1, 2, 4 | 5, 8]  5 теж на місці

ПРОХІД 3
  [1, 2, 4 | 5, 8]  1 < 2, 2 < 4 -> жодного обміну!
                    масив уже відсортований, можна виходити
```

Зверніть увагу на дві речі. Перша: після кожного проходу «хвіст» масиву справа
вже відсортований, і туди більше не треба заглядати. Друга: у проході 3 не сталося
**жодного** обміну — це надійна ознака, що масив повністю відсортований.

### Реалізація з оптимізацією раннього виходу

```csharp
void BubbleSort(int[] arr)
{
    int n = arr.Length;

    for (int i = 0; i < n - 1; i++)
    {
        bool swapped = false;   // чи був хоч один обмін на цьому проході

        // n - i - 1: хвіст із i елементів уже відсортований
        for (int j = 0; j < n - i - 1; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;

                swapped = true;
            }
        }

        if (!swapped)
        {
            break;   // масив уже відсортований — далі працювати немає сенсу
        }
    }
}
```

Прапорець `swapped` — це і є **оптимізація раннього виходу**. Без неї алгоритм
завжди робить рівно `n - 1` проходів, навіть на вже відсортованому масиві: приблизно
`n²/2` порівнянь замість `n - 1` з прапорцем.

:::tip[Порада]
Вираз `n - i - 1` у внутрішньому циклі — не «магія»: після проходу номер `i` рівно `i`
найбільших елементів уже стоять на місцях у кінці масиву. Напишете `j < n - 1` —
масив відсортується правильно, але порівнянь буде приблизно вдвічі більше.
:::

:::info[Цікаво]
Сортування бульбашкою — улюблений приклад підручників і водночас алгоритм, який
майже ніде не застосовують на практиці. Дональд Кнут, автор класичної праці
«Мистецтво програмування», написав про нього так: «Здається, єдине, що можна
сказати на користь сортування бульбашкою, — це його приваблива назва».
:::

## Сортування вибором

**Сортування вибором (selection sort)** працює так, як людина сортувала б стопку
карток: знайти найменшу картку в усій стопці, покласти її першою; знайти найменшу
серед решти, покласти другою; і так далі.

### Як це виглядає покроково

Масив `[29, 10, 14, 37, 13]`. Вертикальна риска відділяє відсортовану частину:

```
Крок 1:  [29, 10, 14, 37, 13]   мінімум = 10 (індекс 1), міняємо з arr[0]
              ^^
         [10 | 29, 14, 37, 13]

Крок 2:  [10 | 29, 14, 37, 13]  мінімум = 13 (індекс 4), міняємо з arr[1]
                         ^^
         [10, 13 | 14, 37, 29]

Крок 3:  [10, 13 | 14, 37, 29]  мінімум = 14 — уже на місці, обміну немає
                   ^^
         [10, 13, 14 | 37, 29]

Крок 4:  [10, 13, 14 | 37, 29]  мінімум = 29 (індекс 4), міняємо з arr[3]
                           ^^
         [10, 13, 14, 29 | 37]

Останній елемент опиняється на місці автоматично — сортувати нічого.
```

### Реалізація

```csharp
void SelectionSort(int[] arr)
{
    int n = arr.Length;

    for (int i = 0; i < n - 1; i++)
    {
        int minIndex = i;

        // шукаємо мінімум у невідсортованій частині
        for (int j = i + 1; j < n; j++)
        {
            if (arr[j] < arr[minIndex])
            {
                minIndex = j;
            }
        }

        // ставимо знайдений мінімум на позицію i
        if (minIndex != i)
        {
            (arr[i], arr[minIndex]) = (arr[minIndex], arr[i]);
        }
    }
}
```

Головна особливість цього алгоритму — **кількість обмінів**: їх завжди не більше
`n - 1`, як би масив не був перемішаний. Порівнянь при цьому багато (приблизно `n²/2`),
але обмінів — мінімум серед усіх простих алгоритмів. Це не дрібниця: порівняти два
числа дешево, а от переставляти великі структури даних (запис про студента з десятком
полів) дорого — і тоді сортування вибором раптом стає розумним вибором.

:::note
Перевірка `if (minIndex != i)` перед обміном не обов'язкова — обмін елемента
із самим собою нічого не псує. Але вона економить три присвоювання у випадку,
коли елемент уже стоїть правильно.
:::

## Сортування вставками

**Сортування вставками (insertion sort)** — це те, як більшість людей сортує карти
в руці. Ліва частина руки вже впорядкована; берете наступну карту і **вставляєте**
її на потрібне місце серед уже впорядкованих, розсуваючи їх.

Ключова відмінність від попередніх алгоритмів: тут ми не міняємо елементи парами,
а **зсуваємо** блок елементів праворуч, звільняючи місце.

### Як це виглядає покроково

Масив `[7, 3, 9, 2]`:

```
Початок: перший елемент сам по собі вже "відсортований"
  [7 | 3, 9, 2]

Крок 1: key = 3
  [7 | 3, 9, 2]    7 більше за 3 -> зсуваємо 7 праворуч
  [_, 7 | 9, 2]    місце на позиції 0 звільнилося
  [3, 7 | 9, 2]    вставляємо 3

Крок 2: key = 9
  [3, 7 | 9, 2]    7 менше за 9 -> зсувати нічого, 9 залишається
  [3, 7, 9 | 2]

Крок 3: key = 2
  [3, 7, 9 | 2]    2 менше за 9 -> зсуваємо 9
  [3, 7, _, 9]     2 менше за 7 -> зсуваємо 7
  [3, _, 7, 9]     2 менше за 3 -> зсуваємо 3
  [_, 3, 7, 9]     дійшли до початку масиву
  [2, 3, 7, 9]     вставляємо 2
```

### Реалізація

```csharp
void InsertionSort(int[] arr)
{
    for (int i = 1; i < arr.Length; i++)
    {
        int key = arr[i];        // елемент, який вставляємо
        int j = i - 1;

        // зсуваємо праворуч усі елементи, більші за key
        while (j >= 0 && arr[j] > key)
        {
            arr[j + 1] = arr[j];
            j--;
        }

        arr[j + 1] = key;        // місце звільнилося — вставляємо
    }
}
```

Два важливі моменти.

**Цикл починається з `i = 1`, а не з нуля.** Масив з одного елемента вже відсортований,
тому перший елемент є початковою «відсортованою частиною».

**Порядок умов у `while` критичний.** Написано `j >= 0 && arr[j] > key`, і саме в такому
порядку. Оператор `&&` обчислює праву частину тільки якщо ліва істинна — це називається
**коротке замикання**. Якщо переставити умови місцями, то на останній ітерації програма
спробує прочитати `arr[-1]` і впаде.

:::danger[Часта помилка]
Записати умову як `arr[j] > key && j >= 0`. Компілятор не заперечить, тести на
«хороших» даних пройдуть, а на масиві, де мінімальний елемент опиниться в кінці,
програма впаде з `IndexOutOfRangeException`. Пам'ятайте: у `&&` перевірка меж
завжди йде **першою**.
:::

### Чому вставки — найкращий із простих алгоритмів

Сортування вставками **швидке на майже відсортованих даних**: якщо масив уже
впорядкований, внутрішній `while` жодного разу не виконається, і весь алгоритм
зробить лише `n - 1` порівнянь. Саме тому вставки — не просто навчальний приклад:
реальні бібліотечні сортування (зокрема в .NET) перемикаються на них, коли підмасив
стає малим — на 10–16 елементах вони швидші за будь-який «розумний» алгоритм,
бо не витрачають часу на рекурсію.

## Швидке сортування

**Швидке сортування (quick sort)** побудоване на стратегії **«розділяй і володарюй»**:
велику задачу розбиваємо на менші однотипні, розв'язуємо їх, а результати об'єднуємо.

1. Обираємо один елемент масиву — **опорний (pivot)**.
2. Переставляємо елементи так, щоб зліва від опорного опинилися всі менші за нього,
   а справа — всі більші. Ця операція називається **розділенням (partition)**;
   після неї опорний елемент **уже стоїть на своєму остаточному місці**.
3. Повторюємо те саме окремо для лівої частини й окремо для правої.

Ключове тут — пункт 2. Ми не сортуємо масив цілком, ми правильно ставимо **один**
елемент, а решту роботи перекладаємо на два менші виклики того самого алгоритму.

### Схема розділення

Масив `[7, 2, 9, 4, 5]`, за опорний беремо останній елемент — 5:

```
  [7, 2, 9, 4 | 5]   pivot = 5
  проходимо зліва направо, менші за pivot переносимо на початок:

  7 менше 5? ні    пропускаємо
  2 менше 5? так   [2, 7, 9, 4 | 5]
  9 менше 5? ні    пропускаємо
  4 менше 5? так   [2, 4, 9, 7 | 5]

  ставимо pivot одразу після менших:
  [2, 4, 5, 7, 9]
         ^ позиція 2 — це ОСТАТОЧНЕ місце опорного елемента

  далі рекурсивно сортуємо [2, 4] і [7, 9]
```

### Схема рекурсії

```
              [7, 2, 9, 4, 5]  pivot = 5
                      |
          +-----------+-----------+
       [2, 4]                  [7, 9]
     pivot = 4                pivot = 9
          |                       |
      +---+---+               +---+---+
    [2]      []             [7]      []
```

Глибина цього дерева — приблизно `log₂ n`, а на кожному рівні виконується
приблизно `n` порівнянь. Звідси й береться оцінка `n log n`, про яку мова
в наступному підрозділі.

### Реалізація

```csharp
void QuickSort(int[] arr, int low, int high)
{
    if (low < high)
    {
        int pivotIndex = Partition(arr, low, high);

        QuickSort(arr, low, pivotIndex - 1);    // ліва частина
        QuickSort(arr, pivotIndex + 1, high);   // права частина
    }
}

int Partition(int[] arr, int low, int high)
{
    int pivot = arr[high];   // за опорний беремо останній елемент
    int i = low - 1;         // межа зони "менших за pivot"

    for (int j = low; j < high; j++)
    {
        if (arr[j] < pivot)
        {
            i++;
            (arr[i], arr[j]) = (arr[j], arr[i]);
        }
    }

    // ставимо pivot одразу після зони менших
    (arr[i + 1], arr[high]) = (arr[high], arr[i + 1]);

    return i + 1;   // остаточна позиція опорного елемента
}

// зручна обгортка
void QuickSort(int[] arr) => QuickSort(arr, 0, arr.Length - 1);
```

:::warning[Обережно]
Швидке сортування має неприємну властивість: якщо опорний елемент щоразу
виявляється найменшим або найбільшим, розділення дає частини розміром 0 і `n - 1`,
рекурсія стає глибиною `n`, і алгоритм деградує до `n²`. З вибором «останній елемент
як опорний» це трапляється саме на **вже відсортованому** масиві — тобто на найзручніших
на вигляд даних. Реальні реалізації обирають опорний елемент хитріше: медіану з трьох
або випадковий елемент.
:::

## Сортування злиттям

**Сортування злиттям (merge sort)** — теж «розділяй і володарюй», але з іншого боку.
Швидке сортування спочатку робить складну роботу (розділення), а потім рекурсію;
сортування злиттям навпаки — ділить масив рівно навпіл, не дивлячись на значення,
а вся робота відбувається на етапі **злиття** двох уже відсортованих половин.
Злиття просте: дивимося на перші елементи обох половин, беремо менший, зсуваємось
у тій половині, звідки взяли, повторюємо.

```
  ліва:  [3, 7]        права: [2, 9]

  3 vs 2  -> беремо 2        результат: [2]
  3 vs 9  -> беремо 3        результат: [2, 3]
  7 vs 9  -> беремо 7        результат: [2, 3, 7]
  ліва порожня -> дописуємо  результат: [2, 3, 7, 9]
```

```csharp
void MergeSort(int[] arr)
{
    if (arr.Length < 2) return;   // масив із 0 або 1 елемента вже відсортований

    int mid = arr.Length / 2;
    int[] left = new int[mid];
    int[] right = new int[arr.Length - mid];

    Array.Copy(arr, 0, left, 0, mid);
    Array.Copy(arr, mid, right, 0, arr.Length - mid);

    MergeSort(left);
    MergeSort(right);

    Merge(arr, left, right);
}

void Merge(int[] arr, int[] left, int[] right)
{
    int i = 0, j = 0, k = 0;

    while (i < left.Length && j < right.Length)
    {
        // "менше або дорівнює" — саме це робить сортування стійким
        if (left[i] <= right[j])
        {
            arr[k++] = left[i++];
        }
        else
        {
            arr[k++] = right[j++];
        }
    }

    // одна з половин вичерпалася — решту другої просто дописуємо
    while (i < left.Length)  arr[k++] = left[i++];
    while (j < right.Length) arr[k++] = right[j++];
}
```

Сортування злиттям завжди працює за `n log n` — навіть у найгіршому випадку, на відміну
від швидкого. Плата за надійність — **додаткова пам'ять** розміром із весь масив.

## Перевіримо всі алгоритми разом

```csharp
int[] source = [64, 25, 12, 22, 11, 90, 34];

void Print(string name, int[] arr)
    => Console.WriteLine($"{name,-12}: {string.Join(", ", arr)}");

int[] a = (int[])source.Clone();   BubbleSort(a);      Print("Бульбашка", a);
int[] b = (int[])source.Clone();   SelectionSort(b);   Print("Вибором", b);
int[] c = (int[])source.Clone();   InsertionSort(c);   Print("Вставками", c);
int[] d = (int[])source.Clone();   QuickSort(d);       Print("Швидке", d);
int[] e = (int[])source.Clone();   MergeSort(e);       Print("Злиттям", e);
```

Вивід:

```
Бульбашка   : 11, 12, 22, 25, 34, 64, 90
Вибором     : 11, 12, 22, 25, 34, 64, 90
Вставками   : 11, 12, 22, 25, 34, 64, 90
Швидке      : 11, 12, 22, 25, 34, 64, 90
Злиттям     : 11, 12, 22, 25, 34, 64, 90
```

Результат однаковий — і це головна думка. П'ять різних способів мислення, а відповідь
одна. Різниця не в тому, **що** вони роблять, а в тому, **скільки роботи** для цього
витрачають — саме це ми виміряємо в наступному підрозділі.

:::tip[Порада]
Виклик `(int[])source.Clone()` створює **копію** масиву. Просте присвоювання
`int[] a = source;` копії не створює — обидві змінні вказуватимуть на той самий масив,
і четверте сортування отримало б уже відсортовані кимось раніше дані.
:::

## Порівняльна таблиця

| Алгоритм | Ідея одним реченням | Сильна сторона | Слабка сторона |
|---|---|---|---|
| Бульбашкою | міняємо сусідів місцями | найпростіший код | найповільніший на практиці |
| Вибором | шукаємо мінімум і ставимо на місце | мінімум обмінів | завжди повні `n²/2` порівнянь |
| Вставками | вставляємо елемент у відсортовану частину | блискавичний на майже відсортованих даних | багато зсувів на випадкових даних |
| Швидке | розділяємо навколо опорного | найшвидше на практиці | деградує до `n²` на невдалих даних |
| Злиттям | ділимо навпіл і зливаємо | стабільно `n log n` завжди | потребує додаткової пам'яті |

## Типові помилки

- **Обмін без тимчасової змінної.** `arr[i] = arr[j]; arr[j] = arr[i];` — обидва елементи
  стають однаковими. Потрібен `temp` або кортеж `(arr[i], arr[j]) = (arr[j], arr[i]);`.
- **Неправильна межа внутрішнього циклу в бульбашці.** `j < n` замість `j < n - i - 1`:
  на останній ітерації звернення до `arr[j + 1]` виходить за межі масиву.
- **Перевірка меж після звернення до елемента у вставках.** `while (arr[j] > key && j >= 0)`
  замість `while (j >= 0 && arr[j] > key)` — падіння на елементі, який має стати першим.
- **Забути, що сортування змінює вихідний масив.** Усі реалізації тут сортують **на місці**
  й нічого не повертають. Потрібен оригінал — робіть копію до сортування.
- **У швидкому сортуванні рекурсія з тими самими межами.** `QuickSort(arr, low, pivotIndex)`
  замість `pivotIndex - 1` — нескінченна рекурсія і `StackOverflowException`.
