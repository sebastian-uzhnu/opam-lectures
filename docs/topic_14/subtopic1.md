# Клас та об'єкт

Досі ви писали програми в **процедурному** стилі: дані окремо (змінні, масиви,
списки), дії окремо (методи). Це чудово працює, поки програма маленька. Цей
підрозділ починається з моменту, коли такий підхід ламається — і саме з цього
місця починається об'єктно-орієнтоване програмування.

## Проблема: облік студентів на паралельних масивах

Уявімо звичайне завдання: програма обліку студентів групи. Для кожного студента
треба зберігати ім'я, середній бал і групу. Знаннями, які у вас є зараз, ви
напишете щось таке:

```csharp
string[] names = ["Олена Кравчук", "Ігор Мельник", "Софія Бондаренко"];
double[] grades = [92.5, 78.0, 85.5];
string[] groups = ["ПЗ-21", "ПЗ-21", "ПЗ-22"];

for (int i = 0; i < names.Length; i++)
{
    Console.WriteLine($"{names[i]} | {groups[i]} | {grades[i]}");
}
```

**Вивід:**

```
Олена Кравчук | ПЗ-21 | 92,5
Ігор Мельник | ПЗ-21 | 78
Софія Бондаренко | ПЗ-22 | 85,5
```

Працює. Такий підхід називається **паралельними масивами**: три окремі масиви,
де елементи з однаковим індексом описують один об'єкт реального світу.

І поки програма складається з двадцяти рядків, усе гаразд. Проблеми починаються
далі.

### Проблема 1. Розсинхронізація

Треба видалити студента з індексом 1. Ви пишете код видалення… і забуваєте
про один масив:

```csharp
// Видаляємо Ігоря — акуратно оновлюємо два масиви з трьох
names = ["Олена Кравчук", "Софія Бондаренко"];
grades = [92.5, 85.5];
// groups забули!  Там і досі три елементи: ПЗ-21, ПЗ-21, ПЗ-22
```

Тепер `names[1]` — це Софія, а `groups[1]` — усе ще «ПЗ-21». Софія раптово
змінила групу. Компілятор мовчить: з його погляду це три ідеально коректні масиви.
Помилку виявить викладач, який отримає неправильний список.

:::danger[Часта помилка]
Паралельні масиви не мають жодного захисту від розсинхронізації. Компілятор
не знає, що `names[i]` і `grades[i]` — це «одна людина». Для нього це просто
два незалежні масиви. Кожна операція вставки, видалення чи сортування
має вручну повторитися для **всіх** масивів — і рано чи пізно один загубиться.
:::

### Проблема 2. Сортування

Відсортуйте студентів за балом. З одним масивом це один рядок:

```csharp
Array.Sort(grades);   // тепер grades = [78.0, 85.5, 92.5]
```

Але імена лишилися на місці! Тепер Олена має 78 балів, а Ігор — 92,5.
Щоб зробити правильно, треба сортувати три масиви одночасно за ключем одного
з них — це вже помітно нетривіальний код, який ви писатимете вручну щоразу.

### Проблема 3. Передавання в метод

Напишіть метод, який виводить одного студента:

```csharp
void PrintStudent(string name, double grade, string group)
{
    Console.WriteLine($"{name} | {group} | {grade}");
}
```

Три параметри для однієї сутності. Додали дату народження — чотири. Додали
телефон, email, номер залікової — сім параметрів, і при виклику дуже легко
переплутати місцями два рядки поспіль. Компілятор і тут промовчить: `string`
і `string` для нього однакові.

### Проблема 4. Зростання

Тепер уявіть, що студентів треба зберігати ще й у списках груп, обчислювати
середній бал по групі, шукати за прізвищем. Кожна нова можливість означає
ще один паралельний масив і ще одне місце, де все може розсинхронізуватися.

**Висновок:** дані, які логічно є одним цілим, треба зберігати як одне ціле.
Саме для цього існує клас.

## Клас — це креслення, об'єкт — це будинок

**Клас** — це опис того, з чого складається сутність і що вона вміє робити.
Клас — не дані. Клас — це креслення, шаблон, тип.

**Об'єкт** (або **екземпляр**, instance) — конкретна річ, створена за цим кресленням.
Об'єкт має дані.

Аналогія, яку варто запам'ятати:

```
   КЛАС (креслення)                   ОБ'ЄКТИ (будинки за кресленням)

   ┌──────────────────┐               ┌──────────────┐  ┌──────────────┐
   │  План будинку    │               │ вул. Січова  │  │ вул. Лесі 12 │
   │  ─────────────   │  ────────▶    │ 4 кімнати    │  │ 4 кімнати    │
   │  • кількість     │   збудували    │ синій дах    │  │ червоний дах │
   │    кімнат        │   3 будинки    └──────────────┘  └──────────────┘
   │  • колір даху    │                ┌──────────────┐
   │  • площа         │                │ вул. Миру 7  │
   └──────────────────┘                │ 4 кімнати    │
                                       │ зелений дах  │
     Креслення одне.                   └──────────────┘
     Будинків — скільки завгодно.
     У кожного власні значення.
```

Креслення саме по собі жити не можна. Будинок — можна. Так само: у класі
`Student` не зберігається жодне ім'я — імена зберігаються в об'єктах.

Ще приклади того самого:

| Клас | Об'єкти |
|---|---|
| `Student` | Олена Кравчук, Ігор Мельник, Софія Бондаренко |
| Форма для випікання кексів | конкретні три кекси на столі |
| Анкета на вступ (порожній бланк) | заповнені анкети конкретних абітурієнтів |
| `Track` (пісня у плеєрі) | «Океан Ельзи — Обійми», «Kalush — Стефанія» |

## Оголошення класу

Синтаксис мінімального класу:

```csharp
class Student
{
    public string Name;
    public double Grade;
    public string Group;
}
```

Розберімо:

- `class` — ключове слово, після нього назва класу. Назви класів у C# пишуть
  з великої літери у стилі **PascalCase**: `Student`, `BankAccount`, `MenuItem`.
- У фігурних дужках — **члени класу** (members). Поки що це три **поля**:
  змінні, які належать об'єкту.
- `public` — **модифікатор доступу**: означає «видно ззовні класу». Детально
  про модифікатори — у темі 15.

:::warning[Обережно]
Публічні поля, як тут, — так робити **не варто** в реальному коді. Ми свідомо
починаємо з найпростішого варіанта, щоб не вантажити одразу все. У темі 15
ви побачите, чому це погано, і замініте поля на властивості.
:::

Де писати клас? Найзручніше — окремий файл `Student.cs` у тому самому проєкті.
Один клас — один файл із такою самою назвою: це не вимога компілятора,
а загальноприйнята практика, і Visual Studio робить так за замовчуванням.

## Створення об'єкта: оператор `new`

Клас оголосили — тепер створимо об'єкт:

```csharp
Student first = new Student();
first.Name = "Олена Кравчук";
first.Grade = 92.5;
first.Group = "ПЗ-21";

Console.WriteLine($"{first.Name} з групи {first.Group}, бал {first.Grade}");
```

**Вивід:**

```
Олена Кравчук з групи ПЗ-21, бал 92,5
```

Що тут відбувається:

- `new Student()` — оператор **new** просить CLR виділити пам'ять під новий
  об'єкт класу `Student` і повертає посилання на нього.
- `Student first = …` — змінна `first` типу `Student` зберігає це посилання.
- `first.Name` — **крапка** — це оператор доступу до члена. Читається як
  «поле `Name` об'єкта `first`».

Скорочені форми запису, які ви бачитимете часто:

```csharp
var second = new Student();          // тип виводиться автоматично
Student third = new();               // target-typed new, C# 9+
```

Обидва рядки роблять те саме. `var` зручний, коли тип очевидний із правої частини.

Створимо трьох студентів і покладемо їх у список:

```csharp
var s1 = new Student();
s1.Name = "Олена Кравчук";
s1.Grade = 92.5;
s1.Group = "ПЗ-21";

var s2 = new Student();
s2.Name = "Ігор Мельник";
s2.Grade = 78.0;
s2.Group = "ПЗ-21";

var s3 = new Student();
s3.Name = "Софія Бондаренко";
s3.Grade = 85.5;
s3.Group = "ПЗ-22";

var students = new List<Student> { s1, s2, s3 };

foreach (var student in students)
{
    Console.WriteLine($"{student.Name} | {student.Group} | {student.Grade}");
}
```

**Вивід:**

```
Олена Кравчук | ПЗ-21 | 92,5
Ігор Мельник | ПЗ-21 | 78
Софія Бондаренко | ПЗ-22 | 85,5
```

Порівняйте з версією на паралельних масивах. Тепер:

- видалити студента — `students.Remove(s2)`, один виклик, нічого не розсинхронізується;
- відсортувати за балом — `students.OrderBy(s => s.Grade)`, і імена їдуть разом
  зі своїми балами;
- передати в метод — один параметр `Student student` замість трьох.

```csharp
void PrintStudent(Student student)
{
    Console.WriteLine($"{student.Name} | {student.Group} | {student.Grade}");
}
```

Ось це і є головна вигода класу: **дані, які належать одне одному, тепер
фізично разом**.

:::tip[Порада]
Гарний спосіб зрозуміти, чи потрібен клас: якщо у вас є кілька змінних,
які ви завжди передаєте разом і завжди змінюєте разом, — це майже напевно
один об'єкт, який ще не оголошено класом.
:::

## Як об'єкт живе в пам'яті

Це ключова схема теми. Клас у C# — **посилальний тип** (reference type).
Це означає, що змінна не містить сам об'єкт: вона містить **посилання** (адресу)
на об'єкт, який лежить у **купі** (heap).

```csharp
Student a = new Student();
a.Name = "Олена";
```

```
        СТЕК                              КУПА (heap)
   ┌──────────────────┐            ┌───────────────────────────┐
   │ a  ──────────────┼───────────▶│  об'єкт Student           │
   │  (посилання)     │            │  Name  = "Олена"          │
   └──────────────────┘            │  Grade = 92.5             │
                                   │  Group = "ПЗ-21"          │
                                   └───────────────────────────┘
```

- **Стек** — швидка невелика ділянка пам'яті для локальних змінних методу.
  Живе рівно стільки, скільки виконується метод.
- **Купа** — велика ділянка, де живуть об'єкти. Об'єкт живе доти, доки на нього
  є хоч одне посилання; далі його прибирає збирач сміття.

### Два посилання на один об'єкт

А тепер найважливіший наслідок. Що виведе цей код?

```csharp
Student a = new Student();
a.Name = "Олена";

Student b = a;        // копіюємо ПОСИЛАННЯ, не об'єкт
b.Name = "Ігор";

Console.WriteLine(a.Name);
```

**Вивід:**

```
Ігор
```

Змінили `b`, а змінилося й `a`. Бо об'єкт **один**, а посилань на нього — два:

```
        СТЕК                              КУПА (heap)
   ┌──────────────────┐            ┌───────────────────────────┐
   │ a  ──────────────┼───────────▶│  об'єкт Student           │
   │                  │      ┌────▶│  Name = "Ігор"            │
   │ b  ──────────────┼──────┘     └───────────────────────────┘
   └──────────────────┘
```

Рядок `Student b = a;` не створює нового об'єкта. Він створює другу табличку
з тією самою адресою. Щоб отримати справді окремий об'єкт, треба явно викликати
`new` ще раз:

```csharp
Student a = new Student();
a.Name = "Олена";

Student b = new Student();   // окремий об'єкт
b.Name = a.Name;             // скопіювали значення поля вручну
b.Name = "Ігор";

Console.WriteLine(a.Name);   // Олена
Console.WriteLine(b.Name);   // Ігор
```

:::danger[Часта помилка]
`b = a` для класів **не копіює об'єкт**. Це найпоширеніша помилка новачків в ООП:
студент «копіює» об'єкт, змінює копію і не розуміє, чому змінився оригінал.
Запам'ятайте: присвоєння копіює посилання, а не те, на що воно вказує.
:::

## `null` і `NullReferenceException`

Змінна-посилання може не вказувати ні на що. Таке «нікуди» позначається
ключовим словом **null**.

```csharp
Student student = null;      // посилання є, об'єкта немає
Console.WriteLine(student.Name);   // тут програма впаде
```

**Вивід:**

```
Unhandled exception. System.NullReferenceException: Object reference not set
to an instance of an object.
```

**NullReferenceException** — виняток «звернення за посиланням, якого немає».
Це найпопулярніша помилка виконання в C# за всю історію мови. Пояснення
просте: ви попросили «дай мені поле `Name` того об'єкта», а об'єкта немає.

Звідки береться `null`:

```csharp
Student[] group = new Student[3];   // масив із трьох посилань — усі null!
Console.WriteLine(group[0].Name);   // NullReferenceException

// Правильно: створити самі об'єкти
for (int i = 0; i < group.Length; i++)
{
    group[i] = new Student();
}
```

Створення масиву об'єктів створює лише масив **порожніх посилань**. Об'єктів
там ще немає — їх треба створити окремо.

Як захищатися:

```csharp
Student? found = FindStudent("Олена");   // метод може нічого не знайти

if (found != null)
{
    Console.WriteLine(found.Name);
}

// або компактно — оператор ?. (null-conditional)
Console.WriteLine(found?.Name ?? "не знайдено");
```

- `Student?` зі знаком питання — **nullable reference type**: явна позначка
  «тут може бути null». Компілятор у .NET 8 попереджає, якщо ви звертаєтеся
  до такої змінної без перевірки.
- `found?.Name` — якщо `found` дорівнює null, увесь вираз дає null і виклику
  не буде (замість падіння).
- `?? "не знайдено"` — оператор об'єднання з null: «якщо ліворуч null, візьми
  те, що праворуч».

:::tip[Порада]
Побачили `NullReferenceException` — не шукайте помилку в тому рядку, де впало.
Шукайте місце, де змінну **не** ініціалізували. Виняток лише повідомляє,
де ви скористалися порожнечею, а не де вона з'явилася.
:::

## Клас і структура: посилальний тип проти значеннєвого

C# має два способи оголосити власний тип: `class` і `struct`. Синтаксис майже
однаковий — досить замінити одне ключове слово. Різниця не в синтаксисі,
а в тому, як тип поводиться в пам'яті. **Структура** — **значеннєвий тип**
(value type): змінна містить самі дані, а не посилання на них. Ви вже працювали
зі значеннєвими типами весь курс: `int`, `double`, `bool`, `char`, `DateTime` —
усе це структури.

### Наочна різниця при копіюванні

Оголосимо два майже однакові типи:

```csharp
struct PointStruct
{
    public int X;
    public int Y;
}

class PointClass
{
    public int X;
    public int Y;
}
```

```csharp
// СТРУКТУРА
var s1 = new PointStruct();
s1.X = 10;
var s2 = s1;      // копіюються ЗНАЧЕННЯ
s2.X = 99;
Console.WriteLine($"Структура: s1.X = {s1.X}, s2.X = {s2.X}");

// КЛАС
var c1 = new PointClass();
c1.X = 10;
var c2 = c1;      // копіюється ПОСИЛАННЯ
c2.X = 99;
Console.WriteLine($"Клас:      c1.X = {c1.X}, c2.X = {c2.X}");
```

**Вивід:**

```
Структура: s1.X = 10, s2.X = 99
Клас:      c1.X = 99, c2.X = 99
```

Один і той самий код дає різний результат. Ось схема, чому:

```
СТРУКТУРА (значеннєвий тип)         КЛАС (посилальний тип)

      СТЕК                                СТЕК            КУПА
 ┌──────────────┐                   ┌──────────────┐   ┌──────────┐
 │ s1: X=10 Y=0 │  ◀── дані тут     │ c1 ──────────┼──▶│ X=99 Y=0 │
 ├──────────────┤                   ├──────────────┤   └──────────┘
 │ s2: X=99 Y=0 │  ◀── окремі дані  │ c2 ──────────┼────────┘
 └──────────────┘                   └──────────────┘
                                      обидва вказують на один об'єкт
```

### Ще одна різниця: null

Структура не може бути `null` — там завжди є дані. Тому `NullReferenceException`
для структур неможливий:

```csharp
PointStruct p = new PointStruct();   // X = 0, Y = 0 — уже коректний об'єкт
PointClass? c = null;                // так можна
```

### Порівняльна таблиця

| Ознака | `class` | `struct` |
|---|---|---|
| Категорія | посилальний тип | значеннєвий тип |
| Де зберігаються дані | у купі | зазвичай на стеку або всередині власника |
| Що копіює присвоєння | посилання | усі дані |
| Може бути `null` | так | ні (лише як `int?`) |
| Наслідування від інших типів | так | ні |
| Значення за замовчуванням | `null` | усі поля нулями |
| Типовий розмір | будь-який | маленький, до ~16 байтів |
| Приклади з BCL | `string`, `List`, `Exception` | `int`, `double`, `DateTime`, `Guid` |

### Коли обирати `struct`

Правило практичне і просте: **за замовчуванням пишіть `class`**. Структуру
обирайте, коли одночасно виконуються всі умови:

- тип маленький (кілька числових полів);
- він логічно є одним значенням, як число: точка, колір, гроші, координата;
- він не змінюється після створення (immutable);
- таких значень буде дуже багато, і кожне зайве виділення пам'яті в купі
  було б помітним.

Приклади вдалих структур: `Point`, `Color`, `Money`, `TimeSpan`.
Приклади, де структура була б помилкою: `Student`, `BankAccount`, `Order` —
це сутності з ідентичністю, які змінюються з часом.

:::info[Цікаво]
Чому `string` — клас, хоч поводиться майже як значення? Бо рядок може бути
дуже великим, і копіювати весь текст при кожному присвоєнні було б надто дорого.
Натомість рядки зробили **незмінними** (immutable): будь-яка «зміна» рядка
створює новий об'єкт. Тому вони виглядають як значення, але фізично лишаються
посилальним типом.
:::

## Типові помилки

**`Student s;` без `new`.** Оголошення змінної не створює об'єкта. Змінна поки
що не вказує ні на що, і компілятор не дасть нею скористатися. Правильно:
`Student s = new Student();`.

**`b = a` як спосіб «зробити копію» об'єкта.** Копіюється посилання, а не об'єкт.
Щоб отримати незалежну копію, треба створити новий об'єкт через `new`
і перенести значення полів.

**Масив об'єктів вважати заповненим.** `new Student[5]` створює п'ять посилань
`null`, а не п'ять студентів. Кожен елемент треба створити окремо в циклі.

**Плутати клас і об'єкт у мовленні.** «Створити клас» означає написати код класу
один раз. «Створити об'єкт» — виконати `new` під час роботи програми. Клас один,
об'єктів може бути мільйон.
